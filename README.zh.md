## 摘要

LAE Lossy（LAEY）允许单个文件同时承载最高 24 位、最高 352.8/384 kHz 的高解析度母带和 16 位 CD 层（LAE Lossless 还可承载 32 位母带）。普通 WAV 播放器可逐位重现 CD 层（已测试的解码器：[spec/COMPATIBILITY.zh.md](spec/COMPATIBILITY.zh.md)）。

- **44.1 kHz 系列。**使用工具 `lae_cdx` 进行 CD-Extra 封装（目前生成 CD-Extra 光盘镜像）。光盘在其音频区段中原样承载 CD 层，在其数据区段中承载扩展，因此所有 CD 播放器都能重现 CD 层。
- **48 kHz 系列（96/192/384 kHz 母带）。**这些母带具有 48 kHz 基础层，面向 DVD、蓝光和文件分发。
- **文件与数据流。**在 CD 之外，音轨也可以作为基础层文件（FLAC 或 WAV）分发，并在其旁边附带一个扩展文件（由规范定义；目前 `lae_cdx` 仅读取 WAV 基础层文件）。

高解析度信息完全存储在 PCM 信号之外，位于单独的扩展中。扩展按三级金字塔组织：

- **CD 层**：由母带确定性地派生，或独立提供；
- **位深层**：在基础采样率下，将 CD 频带从 16 位细化到约 18 位有效位（默认）；
- **频率层**：将 CD 截止频率以上的全部内容编码为每个倍频程一个 MDCT 流。

解码完全通过时域加法完成。可能的解码路径有四种：

- 仅 CD；
- CD 加频率层；
- CD 加位深层；
- 全部三层。

扩展主要使用三种工具编码：

- 形状自适应时频分区；
- 显式精度等级，其量化步长绝不粗于一个 16 位 LSB；
- 自适应二进制范围编码器。

解码器在不同平台上具有确定性。重采样滤波器使用整数运算，逆 MDCT 在严格的 IEEE-754 binary64 算术下按固定顺序计算。启动自检对此进行验证。

在默认工作点下，真实录音中完整 24 位路径的 CD 频带误差中位数约为 −111 dBFS。可选的 20 位位深层（`keep20`）可将其降至约 −124 dBFS。

扩展大小是在开发期间（2026-10-16）使用 v5 候选发布版测得的（第 11.2 节）。对于真实录音，在模式 3 下，其大小中位数约为未压缩 CD 层的 0.24 至 1.23 倍，具体取决于采样率和方案。

编码器可以将母带与独立制作的 CD 组合。它通过波形比较相对于母带定位 CD，在固定的三处核对波形残差，并以亚采样精度将母带（绝不移动 CD）移至 CD 的位置：整数采样部分通过放置完成，不足一个采样的部分通过带限插值完成。在表 4.3 的测量中，0–20 kHz 频带内的对齐误差为 −140 dBFS；在硬截断边缘（声音位于母带第一个或最后一个采样处），误差较大：添加数字静音时为 −66 dBFS，不添加时最高达 −38.5 dBFS。在编码任何内容之前，每个位置均由用户确认。整盘规划器将同一流程应用于发行方的完整光盘。结果是普通的容器版本 5 文件，任何 v5 解码器无需修改即可对其解码。

`lae_cdx` 的读取端可以从以任意驱动器偏移制作的抓轨中恢复原始 LAE 文件。每条音轨单独定位，仅当其全部 CD 采样的 MD5 一致时才接受该音轨。带有 C 接口 `liblae` 的解码器库提供逐位精确的快速定位，基于该库构建的 foobar2000 组件可以最高以母带采样率播放 LAE 文件。

作者尚未、也不会就 LAE 提交任何专利申请，并针对本规范的实现作出不主张专利权的承诺（第 15 节）。

## 1 引言

### 1.1 问题

越来越多的录音以 24 位和 88.2 至 384 kHz 的采样率制作母带。尽管如此，CD（16 位、44.1 kHz）仍然是可在各处播放的格式：旧式播放器、汽车、所有软件播放器，以及作为实体产品。

想要同时提供两者的发行方目前有两种选择：

- 分发两种独立的产品；
- 采用一种旧设备无法获得其高解析度内容的格式。

一些现有方案会改动 PCM 信号本身以承载附加数据。

LAE 在以下约束下解决这一问题：**CD 层是一张普通的、未经改动的 CD。**其他所有内容均为存储在其旁边的附加信息。

### 1.2 目标

1. **逐位精确的 CD 层。**16 位 CD 层按原样精确存储。
   - 在 44.1 kHz 系列中，它是可在任何 CD、WAV 或 FLAC 播放器上播放的 44.1 kHz 层。
   - 48 kHz 系列具有 48 kHz 基础层（CD 频带 0–24 kHz），面向 DVD、蓝光和文件分发。
   - CD-Extra 仅适用于 44.1 kHz 系列。

2. **扩展位于 PCM 之外。**扩展可恢复至最高 24 位，以及最高 352.8 kHz（44.1 kHz 系列）或 384 kHz（48 kHz 系列）。扩展的大小随母带中真实信息的多少而变化，因此信息越多的母带生成的文件越大。

3. **降低精度，而非丢弃内容（LAE Lossy）。**LAE Lossy 可以降低内容的表示精度，但不得丢弃有意义的内容。
   - 持续音、瞬态、乐音、谐波和混响尾音均予以保留。
   - 母带中存在的噪声被视为音乐的一部分，并与其他内容一样编码。这包括噪声底、不可闻的随机噪声和有意添加的噪声。
   - 只有确定不承载信息的内容才会被自动置零：数字静音，以及低于一个 24 位 LSB 的舍入级残留。

   借助 LAE Noise Marker 和编码器选项 `noise=`，用户可以标记噪声区域，编码器随后将其编码为静音（第 8.6 节）。

4. **支持两种采样率系列。**同一算法适用于 44.1 kHz 和 48 kHz 系列。只有倍频程采样率档位是固定的（88.2/176.4/352.8 kHz 和 96/192/384 kHz）；其他一切均为自适应。

5. **确定性解码。**所有符合规范的解码器在任何平台上都生成逐字节相同的输出。

6. **开放性。**该格式依据开放许可证发布（第 16 节）。作者作出不主张专利权的承诺（第 15 节）。

**非目标。**

- 对可听频带进行感知编码。可听频带由 CD 层加上以波形编码的细化部分表示。
- 由编码器规划光盘容量。编码器只负责压缩。发行方选择方案、模式和输出范围，并负责判断结果是否适合给定介质。打包工具 `lae_cdx` 检查光盘镜像能否容纳，若不能容纳则停止；它绝不会自动删除任何音轨或倍频程（第 10.9 节）。

### 1.3 主要特性

- **金字塔分解。**信号被分解为 CD、位深和频率目标。这些目标通过普通时域加法重新组合。CD 层可以由母带派生，也可以独立提供。
- **独立 CD 的对齐。**所提供的 CD 通过两次波形搜索相对于母带定位，一次经过白化，一次不经白化。随后在三个块中核对波形残差，其中包括漂移检查。然后以亚采样精度将母带移至 CD 的时间轴上（整数采样部分通过放置完成，不足一个采样的部分通过带限插值完成；0–20 kHz 频带内误差为 −140 dBFS，在硬截断边缘较大，见表 4.3），CD 的采样保持不变。每个位置均由用户确认（第 4.3 节）。
- **整盘规划器。**`lae_enc plan` 将以一个或多个文件形式给出的母带与发行方的完整光盘进行匹配。它先移动母带，再在 CD 的音轨标记处切分母带（第 4.5 节）。
- **按录音确定频率层起点。**频率层从实际 CD 检测出的截止频率处开始，而不是从 CD 奈奎斯特频率的固定比例处开始。
- **仅由编码器进行泄漏补偿。**频率层的量化噪声可能经 MDCT 窗泄漏到 CD 频带。位深层抵消这种泄漏，解码器无需为此作任何改动。
- **带 16 位下限保障的精度规则。**显式精度等级（B/C/D）相对于每个叶节点的指数定义，并受三条精度规则约束。在全部三条规则下，量化步长均不粗于一个 16 位 LSB。
- **全局码率—精度搜索。**针对整条音轨的搜索选择形状自适应二进制时频分区。该搜索在满足最高精度内容保留比例的前提下使总字节数最小。
- **确定性与一致性。**解码过程在严格 IEEE-754 算术下具有确定性。启动自检指纹和 16 个一致性测试向量对此进行验证。
- **CD-Extra 封装与读取。**`lae_cdx` 写入双区段 CD-Extra 光盘镜像，并读回其抓轨。每条音轨按内容定位，仅当其全部 CD 采样的 MD5 一致时才被接受。交付光盘镜像之前运行闭环自检（第 10.5–10.9 节）。
- **解码器库与播放器组件。**解码器以带有 C 接口 `liblae` 的库形式提供。该库提供逐位精确的快速定位。foobar2000 组件 `foo_input_lae` 基于该库构建（第 13.6 和 13.7 节）。
- **开放许可与不主张专利权的承诺。**规范、参考解码器和参考编码器均依据第 16 节所列许可证发布。

## 2 相关工作

**FLAC** [1] 是一种无损音频格式。

- LAE 的 CD 层是普通 PCM 信号，因此可以由普通 FLAC 流承载。封装规范仅在 FLAC 中承载 CD 层（基础层）；扩展位于其旁边的单独扩展文件中，绝不位于 FLAC 文件内部（第 10.7 节）。
- 封装规范中整轨 MD5 的定义方式，与 FLAC STREAMINFO 块中 16 位立体声音频的音频 MD5 相同。
- LAE 编码器有两个方面受到 FLAC 的启发：
  - 工作模式像压缩等级一样编号；
  - 分区搜索依据实际编码大小选择分区，借鉴了 FLAC 的二次幂分区方式。

**MPEG-4 Audio BSAC 和可扩展无损编码（SLS）** [2] 是较早的分层音频编码实例。

**CD-Extra** [4]（Blue Book，1995 年）定义了多区段光盘：音频区段（Red Book [3]）之后接数据区段。

- LAE 将 CD-Extra 用作 44.1 kHz 系列的实体光盘容器（第 10.5 节）。
- CD 层原样占用音频区段，扩展文件位于数据区段中，处于带 Joliet 扩展 [15] 的 ISO 9660 [5] 文件系统内。
- 使用“CD EXTRA”标志须获得许可。

**时延估计与分数延迟。**独立 CD 的对齐（第 4.3 节）使用两种形式的互相关：普通互相关，以及经广义互相关的相位变换 [12] 白化的互相关。母带的分数移动使用带限加窗 sinc 插值 [13]，这是分数延迟滤波器的一种标准形式 [14]。

## 3 系统概述

### 3.1 符号说明

全文使用以下符号。

| 符号 | 含义 |
|---|---|
| $R_0$ | 基础采样率，44.1 kHz 或 48 kHz。$B = R_0/2$ 为基础奈奎斯特频率。 |
| $R = R_0 \cdot 2^n$ | 母带采样率，$n \in \lbrace 1, 2, 3 \rbrace$（88.2/176.4/352.8 kHz 或 96/192/384 kHz）。 |
| $x$ | 采样率为 $R$ 的母带信号，以 24 位整数单位表示。 |
| $\mathcal{D}$、$\mathcal{U}$ | 抽取器和插值器：使用相同系数表的 $n$ 级级联半带处理级。 |
| $b = \mathcal{D}(x)$ | 采样率为 $R_0$ 的 24 位基础信号。该信号*不*削波至满量程。 |
| $c$ | 16 位 CD 信号（CD16）。 |
| $d$ | 再生成的 TPDF 抖动。仅在设置了抖动标志的块中非零。 |
| $v = 256 c - d$ | 以 24 位单位表示的 CD 路径。任何解码器都可以仅根据 CD 层和抖动标志计算它。 |
| $f_c$ | 检测出的 CD 截止频率。 |

输入母带必须是立体声整数 PCM WAV 文件，每个采样为 16、24 或 32 位。

容器版本 5 最多承载 24 位。对于 32 位输入，编码器按以下方式处理：

- 若每个采样的最低 8 位均为零，则编码高 24 位，不损失任何信息；
- 否则，编码器说明问题并提供两种选择：结束任务且不写入任何文件；或使用高 24 位，最终报告随后注明这一点；
- 在交互式控制台中，编码器询问用户；由脚本调用时无人可以作答，因此除非给出选项 `bits=24`，否则编码器结束任务。

### 3.2 金字塔

编码器形成两个目标：

$$T = \mathrm{LP}_{f_c}\left(b - v\right) \qquad \text{(depth target, base rate)}$$

$$F = x - \mathcal{U}\left(v + T\right) \qquad \text{(frequency target, master rate)}$$

$T$ 和 $F$ 仅存在于编码器中。

- 位深层承载 $T$ 的编码近似 $\hat T$。在 v5 中，$\hat T$ 还包含第 6.5 节所述的泄漏补偿项。
- 频率层承载 $F$ 的编码近似 $\hat F$。

按构造，$x = \mathcal{U}(v + T) + F$：三部分在时域中相加即还原母带。

```
                                master x  (rate R = R0 * 2^n, 24 bit)
                                   |
                     +-------------+----------------------------+
                     |                                          |
            half-band decimation D (n stages)                   |
                     |                                          |
            24-bit base b (rate R0, unclipped)                  |
                     |                                          |
     +---------------+------------------+                       |
     |                                  |                       |
  TPDF dither (flagged blocks only),    |                       |
  round, clip to 16 bit                 |                       |
     |                                  |                       |
  CD16 c ------> v = 256c - d           |                       |
     |               |                  |                       |
     |               +----> T = LP_fc(b - v) ---> depth layer   |
     |               |                  (L/R, base rate, MDCT)  |
     |               |                                          |
     |               +--> U(v + T) -----------> F = x - U(v+T) -+
     |                                               |
     |                                       frequency layer
     |                               (M/S, master rate, MDCT,
     |                                one stream per octave)
     v
  WAV "data" chunk (playable everywhere)    "LAE " chunk (extension)
```

### 3.3 分层

| 层 | 内容 | 频带 | 采样率 | 精度（高电平块） | 播放方 |
|---|---|---|---|---|---|
| CD | WAV `data` 块中的 16 位 PCM | 0–22.05 kHz（48 kHz 系列：0–24 kHz） | 44.1 / 48 kHz | 16 位；仅在需要处使用 TPDF 抖动，数字静音绝不加抖动 | 任意播放器 |
| 位深 | 24 位基础信号相对于 CD 路径的残差；每个声道（L、R）一条流 | 0–22.05 kHz（48 kHz 系列：0–24 kHz） | 44.1 / 48 kHz | 默认：B18/C20/D24；`keep20`：B20/C22/D24 | LAE 解码器 |
| 频率 | CD 截止频率以上的全部内容；M/S 声道；每个声道、每个倍频程片段一条流（使用编码器选项 `g` 时为两条，见第 8.6 节） | 从 $f_c$ 以下 1 kHz 到母带奈奎斯特频率 | 母带采样率 | 方案 1：B18/C20/D24；方案 2：B16/C20/D24 | LAE 解码器 |

位深层和频率层彼此独立。二者共同构成完整的高解析度信号。输出分辨率取决于解码了其中哪些层。

### 3.4 解码路径

| 路径（`lae_dec` 选项） | 使用的层 | 输出 | 重建 |
|---|---|---|---|
| CD（任意播放器） | CD | 44.1/48 kHz，16 位 | $c$ |
| `16` | CD + 频率 | 母带采样率或较低倍频程；CD 频带为 16 位精度 | $\mathcal{U}(v) + \hat F$ |
| `cd24` | CD + 位深 | 44.1/48 kHz，24 位 | $v + \hat T$ |
| `full`（默认） | CD + 位深 + 频率 | 母带采样率或较低倍频程，24 位 | $\mathcal{U}(v + \hat T) + \hat F$ |

```
           CD (16 bit, R0) ............................ any player
            |
            +--- + depth layer ----------------------> cd24 (24 bit, R0)
            |
            +--- + frequency layer ------------------> 16-bit route (R0*2^k)
            |
            +--- + depth layer + frequency layer ----> full (24 bit, R0*2^k)
```

输出分辨率沿两个互相独立的轴选择：

- 输出倍频程：88.2/176.4/352.8 kHz 或 96/192/384 kHz；
- 位深：16 或 24 位。

`lae_dec` 的三种路径都写入 24 位 PCM 文件。16 位路径的区别在于精度，而非文件格式（[SPEC.zh.md](spec/lossy/SPEC.zh.md)，第 11.8 节）。

解码器库 `liblae`（第 13.6 节）和 foobar2000 组件（第 13.7 节）提供同样的四种路径。

工作模式在编码时确定；解码器在播放时不提供模式选择。

选择较低输出倍频程时，解码器：

- 既不读取也不解码该倍频程以上的频率层数据流；
- 使用派生 CD 层时所用的相同半带滤波器，将结果降至所选采样率。

最终输出中超出 24 位范围的采样被硬限幅（第 12.4 节）。

## 4 CD 层

### 4.1 派生 CD

默认情况下，编码器按以下四个步骤由母带确定性地派生 CD 层。

1. **抽取。**通过 $n$ 级级联的二倍抽取半带处理级，将母带从 $R$ 降至 $R_0$。
   - 滤波器是具有固定系数表的整数 FIR 滤波器，系数表存储在参考源码（`src/halfband.h`）中。
   - 滤波器为对称、奇数长度（零相位）半带滤波器，系数采用 Q31 格式。只存储奇数抽头。
   - 中心抽头为 $2^{30}$，每张表中已存储抽头之和恰为 $2^{29}$，因此直流增益恰为 1。
   - 累加使用 64 位整数，每个输出采样舍入一次（[SPEC.md](spec/lossy/SPEC.zh.md)，第 10 节）。
   - 抽取后的输出采样 $m$ 以输入采样 $2m$ 为中心。信号范围之外的输入索引围绕端点采样镜像（[SPEC.md](spec/lossy/SPEC.zh.md)，第 10.2 和 10.4 节）。
   - 插值器 $\mathcal{U}$ 使用相同的系数表。
   - 据开发期间的测量，半带级联在 0 至 19.8 kHz 范围内的通带偏差低于 −120 dB。

2. **不进行中间削波。**任何处理级都不会将 24 位基础信号 $b$ 削波至满量程。高于满量程的带限过冲（例如方波和强瞬态产生的过冲）保留在 $b$ 中，并由位深目标 $T$ 承载。

3. **自适应 TPDF 抖动。**仅在录音自身噪声低于 0.5 LSB16 的块中添加抖动。
   - 抖动为 TPDF，由两个 xorshift32 生成器产生，每个声道一个。左声道生成器的种子为 `0x12345678`，右声道为 `0xB06BD031`。这些种子是格式常量，不予传输。
   - 每个基础采样率采样，每个生成器前进两次抽取，包括未加抖动块中的采样。
   - 两次抽取的高 12 位 $u_1$ 和 $u_2$ 给出抖动值 $u_1 + u_2 - 4096$，单位为 1/16 LSB24，约为 ±1 LSB16（[SPEC.md](spec/lossy/SPEC.zh.md)，第 11.2 节）。
   - 不使用噪声整形。
   - 完全为零的块（数字静音）绝不添加抖动，因此母带中的数字静音在 CD 层中仍为精确的零。

4. **舍入和削波。**将加抖动后的基础信号舍入为 16 位，并削波至 16 位范围。这是 CD 路径中唯一发生削波的位置。

### 4.2 抖动标志与再生成的抖动

容器针对每 4096 个基础采样率采样，为每个声道存储一个标志字节。解码器按以下步骤处理：

1. 根据固定种子再生成抖动序列；
2. 在带有标志的块中应用抖动；
3. 计算 $v = 256 c - d$。

因此，每个解码器仅凭 CD 层和标志即可精确得知 CD 路径。抖动值不予传输。

### 4.3 独立 CD

使用编码器选项 `cd=<file>` 时，现有的 CD 母带逐位成为 CD 层。

- **格式。**CD 必须以 16 位立体声 WAV 文件提供，其采样率为母带所属系列的基础采样率：44.1 kHz 系列为 44.1 kHz，48 kHz 系列为 48 kHz。
- **编码。**扩展对放置在 CD 时间轴上的母带减去 CD 路径的差值进行编码。第 3.2 节的金字塔保持不变；只是 $c$ 不再由编码器派生。
- **抖动。**编码器不对所提供的 CD 添加抖动，因此在此模式下所有抖动标志均为 0。
- **电平与均衡。**编码器既不对 CD 进行均衡，也不补偿其增益。
- **大小。**CD 越接近母带，扩展越小。单独进行过限幅、均衡或电平调整的 CD 会产生显著更大的扩展。
- **截止频率检测。**在此模式下，根据母带与 CD 之间的相干性检测截止频率，因此检测对电平差异不敏感（第 6.3 节）。

由发行方决定将哪一版 CD 与哪一版母带组合。

48 kHz 系列的母带只有经过重采样后才能与 44.1 kHz CD 组合。这属于母带制作工作：编码器不执行有理数比例重采样。

**对齐：目的与原理。**发行方的 CD 很少与母带按采样对齐。它可能在不同的时间开始，可能偏移一个母带采样的小数部分，两端的数字静音也可能多于或少于母带。任何残留的偏移都会在扩展中表现为母带与 CD 之间的差异，并改变扩展的大小。因此，给出 `cd=` 时，编码器执行以下步骤：

1. 在母带中定位 CD；
2. 在三个固定位置核对波形残差；
3. 测量剩余的母带采样小数部分；
4. 将**母带**放置在 CD 的时间轴上，并按该小数部分移动母带。

CD 的采样绝不会被更改，CD 层保持逐位精确。由于母带在派生各层之前即已移动，结果是普通的容器版本 5 文件。文件中不存储任何与对齐有关的信息，每个 v5 解码器无需修改即可对其解码；解码得到的信号是移动后的母带。

**搜索。**搜索只比较波形，并遵循固定的由粗到精的级联。

1. **第 0 级。**以 CD 采样率的 1/16，将 CD 的声音分为两个块（时间上的前后两半）。通过互相关扫描整个允许范围，并对峰值周围的范围再扫描一次。
2. **后续各级。**每一级将块减半，并将采样率加倍。它在上一级峰值周围的固定小范围内搜索：第一个这样的级别为 ±32 个本级采样，其他级别为 ±8 个。
3. **最后一级。**最后一级在母带采样率下，通过波形残差比较与上一级峰值相距两个 CD 采样以内的各个整数母带采样位置。

若峰值位于某一级范围的边缘，搜索以“alignment failed”结束。这样的峰值表明 CD 属于其他版本、经过剪辑或速度不同。

**两次搜索。**搜索运行两次：一次使用白化互相关（带相位变换的广义互相关，GCC-PHAT [12]），一次使用普通的、不加权的能量归一化互相关。白化并不总是更好的选择。例如，在一段缓慢的 79–182 Hz 扫频的 2 s 片段上，只有普通相关找到了位置：白化搜索失败，而普通搜索报告的结果为 +0.3000226 个母带采样，真实偏移为 +0.3。

**检查。**在 CD 声音的三个块上核对波形残差，三个块使用相同的偏移。

- **声音时长为 40 s 或以上。**三个 5 s 块：第一个块在首个声音之后 10 s 开始，最后一个块在最后一个声音之前 10 s 结束，第三个块居中。
- **声音时长为 3 至 40 s。**每个三分之一段的中部，最长 5 s。
- **声音时长不足 3 s。**对整段声音进行一次检查。

对于每个块，编码器计算两个量：

- 每个声道采用一个最小二乘增益之后的波形残差；
- 相对于该段唯一的小数最佳拟合的剩余时间差。

残差高于 −3 dB 的块视为不匹配。

**漂移检查。**每个块还在偏移两侧各两个 CD 采样处进行比较，增益保持不变。任一位置拟合更好，即表明速度不同、经过剪辑或属于另一次录制，编码器随即停止。该比较只会使编码器停止，绝不会移动任何内容。

阈值定义在 `src/cd_align.cpp`（结构体 `Th`）中。

**区间。**剩余时间差的电平决定处理结果。

| 剩余时间差 | 结果 |
|---|---|
| ≤ −40 dB | 已对齐 |
| −40 至 −33 dB | 需要确认 |
| 高于 −33 dB | 需要确认，并警告文件可能显著增大 |
| 无拟合（某个检查块相对于 CD 的残差高于 −3 dB；漂移，即在任一侧相距两个 CD 采样处拟合更好；或未找到位置） | 绝不编码；不可覆盖 |

确认按以下方式处理：

- 在交互式控制台中，编码器询问是结束任务还是继续；
- 由脚本调用时，除非给出选项 `cdaccept`，否则编码器停止；
- 经确认后，输出的最后一行注明 `CONTINUED AFTER CONFIRMATION`。

声道互换或极性反转需要用户确认，与 −40 … −33 dB 区间相同（`cdaccept`）；此时扩展对差异进行编码，因而显著增大。

**由用户确认位置。**每个位置都由用户确认。未给出选项 `cdalign=` 时，编码器按以下步骤处理：

1. 执行两次搜索；
2. 对于每个结果，测量小数部分，尝试包括移动在内的放置，并完全按照手动给出偏移时的方式再次检查；
3. 打印两个结果，每个结果为“aligned at `cdalign=<offset>`”“not aligned within the limit at …”或“alignment failed …”之一；
4. 打印一行 `ALIGN_SUGGEST whitened=<status>:<offset> plain=<status>:<offset>`；
5. 不写入任何内容即停止，退出代码为 1（使用 `cdcheck` 时退出代码为 0）。

编码器既不比较两个结果，也不在二者之间作出选择；由用户作出选择，然后使用 `cdalign=<offset>` 再次运行编码器。之所以需要用户确认，是因为严格周期性的信号可能在相差一个完整周期的位置上被匹配（第 17.2 节）。

**手动给出的偏移。**使用 `cdalign=<offset>` 时，跳过搜索。

- 偏移以母带采样为单位；正值表示 CD 开始得较晚。偏移可为整数，也可带最多 9 位小数，例如 `cdalign=3.4999828`。整数表示小数部分为 0。
- 编码器在最接近的整数位置进行检查，按给定值放置并移动母带，然后再次检查。
- 若附近存在更好的整数位置，确认提示会报告剩余的偏移，并建议一个修正值。
- 将编码器打印的偏移再次给出，会得到相同的文件；这一点已逐字节测试。

**小数部分的测量。**找到整数偏移 $t$ 之后，编码器在相同的检查块上对每一段测量一次小数部分。

- 下降过程是固定的：步长依次为 1/8、1/16、…… 个母带采样，每个步长取三个点，直至一个 $2^{-22}$ CD 采样的单位。
- 测得的小数部分最多为半个母带采样。

**放置。**母带按以下方式放置在 CD 的时间轴上。

- **整数采样。**母带按整数个母带采样移动，且只跨越数字静音（全零采样）移动。
- **长度匹配。**开头较长的一方先播放，结尾较长的一方后结束。较短的一方补充数字静音。任何一方都不会丢失非静音采样。
- **亚采样超前。**若母带的声音比 CD 的声音早开始不到一个 CD 采样，则在 CD 层前面加入一个 CD 帧的数字静音。CD 自身的采样保持不变。
- **只有母带具有的声音（自 v5-2026-11-07 起）。**若母带在 CD 开始之前或结束之后具有一个 CD 采样或以上的声音，编码器报告其位置和时长，并且在用户选定两个选项之一之前不编码任何内容。在交互式控制台中，编码器会询问；由脚本调用时，必须给出该选项（仅给出 `cdaccept` 不够，因为两个选项的结果不同）：
  - `cdedge=pad`：在 CD 层的该端添加数字静音，添加的 CD 帧数恰好覆盖母带的声音。母带完整保留，CD 自身的采样保持不变，但 LAE 文件中的 CD 层，以及由其制作的光盘上的 CD 层，比所给 CD 长出这段静音。
  - `cdedge=cut`：在 CD 开始或结束处切断母带。母带超出 CD 的声音**不会**保留在 LAE 文件中；若切点处母带仍有声音，高解析度播放会在该处突然结束。CD 层与所给 CD 完全相同。
  - 无论哪个选项，每一段都只在该唯一偏移处补一次或切一次，不做淡入淡出，也不做混合。文件中不存储与此有关的任何信息；对齐报告（`<output>.align.txt`）记录所作选择和具体数量。源文件只被读取；补充和切断均在编码器自己的副本上进行。
  - 自动搜索照常报告位置，并在其 `ALIGN_SUGGEST` 行中添加 `edge=needed`。
- **只有 CD 具有的声音。**只有 CD 具有的、长度为一个 CD 采样或以上的声音不受支持，编码器停止并报告其时间范围。

**母带的移动。**按整数偏移 $t$ 放置之后，编码器将母带一次性移动 `move` 个母带采样，$|\mathrm{move}| \le 0.5$。

- 每个输出采样 $i$ 是已放置母带在 $i + \mathrm{move}$ 处的带限值。它由一个 128 抽头的 Kaiser 窗 sinc 插值器（$\beta = 10$）[13][14] 计算，该插值器的抽头由 `move` 通过闭式表达式一次性计算得到。
- 母带之外的采样视为数字静音。
- 结果舍入为 24 位。超出满量程的采样被硬削波，并给出警告和计数。

总偏移为 $t - \mathrm{move}$。随后照常派生各层，并在偏移 0 处以相同的区间再次检查。编码器打印一行 `PHASE t=<whole> phi=0 move=<move> offset=<offset>`；字段 `phi` 始终为 0。

**移动前后的数字静音。**小数移动会将几十个采样带到母带第一个和最后一个采样之外。这些采样按以下方式保留：

1. 移动之前，在已放置母带和 CD 层的两端各添加 128 个 CD 帧的数字静音；
2. 移动之后，在每一端只将仍为数字静音的部分重新移除：最多移除所添加的帧，且绝不移除所给 CD 的帧。

其效果取决于母带的两端：

- 以数字静音开始和结束的母带，所得文件与不执行此步骤时编码的文件逐字节相同；
- 在声音中途被截断的母带，其 CD 层两端会保留若干帧数字静音：352.8 kHz 时为 8 帧，88.2 kHz 时最多 32 帧。

此步骤不存储任何信息，解码器也绝不丢弃任何采样。保留此类帧时，截止频率检测结果可能略有变化。在两个开发片段中，扩展大小分别变化了 +1.5 % 和 −0.4 %，解码质量不变。

**移动报告。**编码成功后，编码器在输出文件旁写入 `<output>.align.txt`。该文件是供用户存档的纯文本文件，内容包括：

- 整数偏移；
- 移动的小数部分，以母带采样和微秒表示；
- 总偏移；
- 哪一方开始得较早；
- 添加和移除的数字静音；
- 移动之后的检查结果。

任何程序都不读取该报告。它既不属于 LAE 文件，也不属于光盘。

### 4.4 逐位精确性

CD 层就是输出 WAV 文件的音频内容。因此，它与派生 CD 逐字节相同。对于独立 CD，CD 层原样包含所提供 CD 的采样；在第 4.3 节所述情况下，其两端还可能带有若干帧数字静音。

在写入任何文件之前，编码器重新解码每一层和每个片段，并验证所有系数平面均匹配。编码之后，编码器还完整解码最终文件，不写出任何无法解码的文件。

若 CD 音频长度与扩展块不一致（第 10.4 节），解码器拒绝该文件。CD 音频被修改但长度不变时，不会被检测到（[SPEC.md](spec/lossy/SPEC.zh.md)，第 3.2 节）。在 WAV 文件之外，封装规范通过整轨 MD5 保护 CD 音频（第 10.6 节）。

### 4.5 整盘规划器

规划器 `lae_enc plan` 将母带与发行方的完整光盘组合。它以 CUE 表加 BIN 或 WAV 音频的形式读取发行方的光盘。母带可以以一个文件或多个文件的形式给出。

**操作顺序。**规划器按以下固定顺序处理：

1. **拼接。**多个母带文件按给定顺序逐采样拼接。不使用这些文件自身的分割点；若这些分割点与 CD 的不同，规划器打印“the master is re-split at the CD's positions”。
2. **检查静音与覆盖。**在任何移动之前，对原样的母带检查静音和覆盖情况。
3. **对齐。**每一段（即 CD 的每条音轨）在母带中围绕其预期位置、在 ± max(60 s, 段长度) 范围内搜索。在 CD 上为数字静音的段不进行搜索，其母带范围必须为数字静音。在各段之间，母带与 CD 只能在数字静音上存在差异。
4. **确认。**用户确认每个位置。
5. **移动。**每个组（见下文）在拼接后的母带内移动。
6. **切分。**之后才在 CD 的音轨标记处切分母带。

**组。**母带范围在 CD 的某个音轨标记处相接的各段构成一个组：CD 在该处分割了连续的母带素材。一个组具有一个整数偏移和一个小数部分，按一段的方式测量；其他段各自构成单独的组。每个组在拼接后的母带内连同其真实的相邻采样一起移动，之后才进行切分。因此，无间隙相接的各段在输出中的拼接结果，与整个组一次性移动的结果完全相同；这一点已逐位测试。

**由用户确认。**未给出 `cdalign=` 时，规划器执行两次搜索，每次均覆盖整个规划。它打印找到的位置和一行 `PLAN_SUGGEST whitened=<status>:<positions> plain=<status>:<positions>`，不写入任何内容，并以退出代码 1 退出。

使用 `cdalign=<p1>,<p2>,…` 时，为每一段给出一个值：

- 该值是该段的 CD 帧 0 所在的母带采样，允许带小数；
- 对于在 CD 上为数字静音的段，给出 `-`；
- 手动给出的值始终优先；
- 为同一组中的各段给出不同的小数部分时，规划器停止。

切分之后，按编码器的规则再次检查每一段。落入需要确认区间的段会被列出，规划器只在确认之后才写入文件，确认可在控制台中进行，也可使用 `cdaccept`。这些段随后也必须使用 `cdaccept` 编码。

**不属于任何段的采样。**移动可能将采样带到没有任何段取用母带采样的位置：母带的最开头或最末尾，或只有母带具有的间隙。规划器报告发生这种情况的位置和涉及的采样数。规划器还说明：在该位置向母带和 CD 同时添加 44 个 CD 帧（约 1 ms）的数字静音，并使其后的音轨标记相应移动，即可保留这些采样。由用户作出决定。

若母带的声音比音轨 1 早开始不到一个 CD 采样，则在音轨 1 的 CD 层前面加入一帧数字静音。该帧位于 pregap 内，光盘的区段 1 保持不变。

**停止。**出现以下任一情况时，规划器停止并报告时间范围：

- 母带具有 CD 所缺少的声音；
- 两个段在同一母带范围内具有声音；
- 各段的顺序不同；
- CD 带有预加重标志（FLAGS PRE）；
- 音轨 1 在 INDEX 00 中具有声音；
- 出现单段对齐（第 4.3 节）的任一停止条件。

**输出。**对于每一段，规划器写入：

- `TRACKnn.master.wav`：移动后的母带，24 位；
- `TRACKnn.cd.wav`：发行方的原样采样，从该段的 INDEX 01 到下一个 INDEX 01。

移动记录在 `plan.align.txt` 中，这是一个任何程序都不读取的纯文本文件。

**制作链。**完整光盘通过以下三个步骤制作：

1. `lae_enc plan` 进行匹配和切分；
2. `lae_enc` 使用 `cdalign=0` 对每一段编码；
3. `lae_cdx image … layout=<publisher.cue>` 写入 CD-Extra 光盘镜像，其区段 1 与发行方的节目逐采样相同（第 10.5 节）。

命令见第 14.5 节。

**测量。**规划器在整盘案例上进行了测试；在这些案例中，发行方的 CD 由母带经过降噪、门限处理和最小相位均衡派生。

- 使用当前构建（位置经确认，先移动母带再切分）：一张由 CD 从连续素材中分割出三条音轨的光盘，经由含降噪、门限处理和最小相位均衡的发行方处理链制作，通过了 13 项检查中的 13 项；其各段以 `cdalign=0` 编码，剩余时间差为 −67.6、−69.0 和 −67.5 dB。在 CD 音轨标记处分割后再拼接的两段，与其所在组一次性移动的结果逐位相同；被数字静音隔开的两个组各自获得自己的小数部分（剩余时间差 −99 dB）。
- 使用发布构建，以规划器打印的位置重复了其中一个案例，通过了 11 项检查中的 11 项。

## 5 位深层

### 5.1 内容

位深层以基础采样率对 $T$ 编码。$T$ 是未削波的 24 位基础信号与 CD 路径之差经过低通滤波的结果。该层左声道一条流，右声道一条流。在 v5 中，编码目标为 $T$ 减去第 6.5 节的泄漏补偿。

尽管 $T$ 在 $f_c$ 处经过低通滤波，位深层始终覆盖整个基础频带，即 0–22.05 kHz（48 kHz 系列为 0–24 kHz）。截止频率以上的单元大多为 A 类，几乎不占开销。

### 5.2 用途与原理

CD 频带承载大部分音乐内容，而位深层是改善该频带最具成本效益的方式。

默认情况下，其精度由精度规则 1 决定；在 `keep20` 中由规则 3 决定（第 8 节）：

- 在安静块中，系数以比块峰值低 2、4 或 8 位的精度表示，从而保留波形形状；
- 在高电平块中，步长在规则 1 下达到 18/20/24 位分辨率，在规则 3 下达到 20/22/24 位分辨率。

### 5.3 过冲

基础信号 $b$ 未经削波，但 CD 路径经过削波。因此，任何高于满量程的带限过冲都会出现在 $T$ 中。

因此，24 位路径可以恢复 CD 必须削去的内容；只有其最终输出被硬限幅。16 位路径不包含 $T$，无法恢复此类内容（第 12.3 节）。

### 5.4 keep20 位深层

模式 `keep20` 以精度规则 3 对位深层编码（高电平块为 B20/C22/D24）。选择 `keep20` 时，编码器打印关于其效果和开销的提示。测量值如下：

- **CD 频带误差。**误差由约 −111 dBFS 改善至约 −124 dBFS（表 12.2）。
- **大小。**每小时音乐的位深层在 44.1 kHz 系列中增加约 84 MB，在 48 kHz 系列中增加约 94 MB。
- **光盘时间。**在 CD-Extra 光盘上，增加的大小相当于每小时音乐约 9 光盘分钟。
- **播放时长。**在表 11.5 的测量中，80 分钟光盘的 24 位路径播放时长中位数减少了 2.0 至 4.8 分钟。

## 6 频率层

### 6.1 变换与倍频程数据流

频率目标 $F$ 在母带采样率下，通过对整个信号执行单个 MDCT 进行变换（第 7.1 节）。

频谱线被划分为若干片段，基础频带以上每个倍频程一个片段。例如，对于 352.8 kHz 母带，这些片段名义上为 22.05–44.1、44.1–88.2 和 88.2–176.4 kHz。每个片段作为独立数据流存储。

在这种组织方式中，每个倍频程是一段频谱线。它不需要频带分割滤波器，其任何部分都不进入 PCM。

输出较低倍频程的解码器跳过其以上的数据流。

### 6.2 中/侧

频率层以中/侧形式编码，每个片段分别设有 M 和 S 数据流。位深层以左/右形式编码。

M/S 通过整数提升形成，其中 $\lfloor\cdot\rfloor$ 以算术右移实现。编码器计算

$$S = L - R, \qquad M = R + \lfloor S/2 \rfloor ;$$

解码器执行逆变换（[SPEC.md](spec/lossy/SPEC.zh.md)，第 11.4 节）：

$$R = M - \lfloor S/2 \rfloor, \qquad L = R + S .$$

该逆变换由 $M$ 和 $S$ 精确还原 $L$ 和 $R$。

### 6.3 截止频率检测与起始谱线

CD 的带宽因制作而异。因此，频率层从所用 CD 实际截止频率稍下方开始，而不是从基础奈奎斯特频率的固定比例处开始。

- **派生 CD。**编码器从基础奈奎斯特频率向下搜索，寻找 CD 仍在 0.1 dB 以内跟随母带的最高频率。母带几乎没有能量的频率箱被跳过。
- **独立 CD。**根据母带与 CD 之间的相干性检测截止频率，与电平无关。相对于母带存在不足一个采样的小数偏移的 CD 会降低检测出的截止频率；第 4.3 节的对齐可消除这一影响（表 4.3）。

频率层从**检测出的截止频率以下 1 kHz** 处开始。

- 其起始和结束谱线写入每个数据流头部。
- 检测出的截止频率也存储在容器头部中，仅用于显示。

### 6.4 精度

| 方案 | 频率层规则 | 高电平块 | 安静块 |
|---|---|---|---|
| 方案 1（高质量，`s1`，默认） | 规则 1 | B18/C20/D24 | 比块峰值低 2/4/8 位 |
| 方案 2（高压缩，`s2`） | 规则 2 | B16/C20/D24 | 同规则 1 |

两种方案使用相同的位深层规则：规则 1，或 `keep20` 中的规则 3。因此，二者的 CD 频带相同，仅在超声区域有所不同。

### 6.5 泄漏补偿（仅编码器）

频率层中的量化噪声通过正弦窗的旁瓣泄漏到 CD 频带。超声内容越强，这一影响越大：它在合成材料上很明显，仅影响少数真实录音。

开发期间的测量将这一 CD 频带误差归因于频率层：

- 不解码频率层时，CD 频带误差回到 −111 dBFS；
- 误差频谱随频率升高，从低频处的 −119 dBFS 上升到 18 kHz 处的 −100 dBFS；
- 半带滤波器的通带偏差低于 −120 dB。

v5 编码器执行以下流程：

1. 频率层确定后，将其解码并形成其量化误差。
2. 将该误差降至基础采样率。
3. 用一个 2047 抽头低通滤波器提取频率层起始频率以下的部分，该滤波器的截止频率比起始频率低 150 Hz。
4. 从位深目标中减去该部分，然后对位深层编码。

起始频率以上的内容由频率层本身编码，不进行第二次补偿。此流程既不改变解码器，也不改变格式。

补偿的效果取决于路径：

- **`full`。**两层都被解码，补偿有效。
- **`16`。**该路径没有位深层，因此补偿无法起作用。
- **`cd24`。**位深层及其中的补偿项被解码，但该项所抵消的泄漏来自的频率层未被解码。该项对 `cd24` 输出的影响尚未测量；这一测量属于未来工作（第 17.3 节）。

开发期间的测量结果：

- 在合成的 `electronic` 片段上，CD 频带误差由 −96 dBFS 改善至 −109 dBFS；
- 所测试的真实录音没有变化；
- 扩展大小增加 0–1 %。

第 12.5 节报告了 12 个来源上的平均效果。

## 7 时频分区与分类

### 7.1 变换

两个编码层都使用相同的 MDCT 结构，按教科书顺序实现。

| 方向 | 步骤 |
|---|---|
| 正向 | 加窗 → 折叠（相加）→ DCT-IV，通过带前、后旋转因子的复数 FFT 计算 |
| 逆向 | DCT-IV → 展开 → 加窗 → 重叠相加 |

**窗。**窗为正弦窗。

**大小。**每个数据流头部都携带变换大小 $N$。在容器版本 5 中，$N$ 必须为 512。

**旋转因子。**前、后旋转因子为

$$w_n = \exp\left(-i \frac{2\pi (n + 1/8)}{2N}\right), \qquad n = 0, \dots, N/2 - 1.$$

这是 FFmpeg `libavcodec/mdct.c` [6] 中使用的旋转因子形式。FFT 的位反转置换使用生成的表 `BITREV`。

**边界扩展。**信号在两端进行镜像扩展。扩展长度记录在头部中（第 10 节）。

### 7.2 单元、根块和叶节点

解码器所需的几何结构定义在 `src/partition_format.h` 中。编码器的搜索位于 `src/partition.h` 中。

**单元。**一个数据流中一个声道的系数平面被划分为若干单元。单元是一帧中一组相邻的频谱线。数据流头部指明单元宽度；在容器版本 5 中，该宽度始终为 8 条谱线。

**根块。**单元按 16 个单元 × 8 帧组织为根块。根块构成固定的规则网格，按时间优先顺序处理。根块几何结构在所有模式中相同。

**分区树。**每个根块通过二叉树进行分区。

- 节点要么是叶节点，要么通过一次频率方向或时间方向的切分分成两个子节点。
- 最小块大小为 1 个单元 × 1 帧。

**切分位置。**存在两种切分位置方案。编码器标志 `equal` 在二者之间进行选择，头部记录该选择。

- **等分切分：**仅对半切分；不传输位置。
- **不等分切分（默认）：**切分位置可以落在最小网格上的任何位置。它以旁路编码的定长整数传输，单位为网格单位。

**叶节点参数。**所有编码参数都在叶节点中携带：类别、指数、零级别索引和系数。中间节点只携带切分信息。

### 7.3 类别

每个叶节点被分配四种类别之一。

| 类别 | 含义 | 编码内容 |
|---|---|---|
| A | 确定不是信息：数字静音，以及低于一个 24 位 LSB 的舍入级残留。此外：由用户显式标记的噪声（`noise=`，第 8.6 节）。 | 无；重建为精确的零 |
| B | 需要最低精度等级的内容 | 指数 + 系数，TB = 2 |
| C | 中间 | TB = 4 |
| D | 需要最高位深的内容 | TB = 8 |

类别分配遵循以下规则。

- **噪声予以编码。**母带中的噪声不属于 A 类。它像其他内容一样编码，大多为 B 类，有时为 C 类。
- **先确定 A 类。**A 类在第一次压缩之前确定，之后不再改变。
- **混合块。**只有所有单元均为 A 类的块才能为 A 类。任何包含保留内容的块至少为 B 类。将 A 类单元混入 B 类叶节点会产生 B 类字节开销，因此分区搜索会自行将 A 类与保留内容分开。
- **跨组单元。**跨越两个分析组的单元，只有在两个组均为 A 类时才为 A 类。在这种情况下，使用两个噪声底中较低者。
- **噪声底估计。**单元组的噪声底取两个值中的较小者：时间方向的第 10 百分位数，以及该组各单元间的频谱中位数。因此，持续音不会被误认为噪声底。

### 7.4 标记与闭环（编码器）

编码器首先扫描整条音轨，并为每个非 A 类单元标记其所需的位深：

- 需要最高位深的单元标记为 D；
- 其次的单元标记为 C；
- 其余非 A 类单元标记为 B。

两个检测器，即持续音检测器和瞬态检测器，确保检测到的结构至少标记为 B。

随后在闭环中细化这些标记：

1. 编码器以每个单元自身的标记进行编码；
2. 对结果进行解码；
3. 在误差上运行检测器；
4. 只提升在其自身等级下仍受损的单元。

持续音检测器（`src/tone_scan.cpp`）没有灵敏度设置。其阈值由平均周期图的噪声统计得出：

- **周期图。**由汉宁窗长 FFT 以 50 % 重叠计算得到。FFT 长度为不短于 0.09 s 的最小二次幂。
- **时间尺度。**周期图分别在 1、2、4、8 和 16 个长 FFT 帧上取平均，因此在五种时间尺度上检验结构。
- **阈值。**每种尺度的阈值为伽马分布分位数，对应每次检验约 $10^{-9}$ 的固定虚警率。
- **噪声底。**局部噪声底取自相邻 32 箱分块的中位数。在闭环误差检查中，它可以取自参考信号的周期图。
- **检测结果。**一次检测要求在其尺度上至少有连续两个窗口，允许 ±1 箱的漂移。相距 3 箱以内且时间上重叠的检测结果会被合并。

瞬态检测器的统计描述属于未来工作（第 17.2 节）。

v5 的结构保留结果尚未发布。使用注入的真实目标（音调和点击声）在 v5 上重新验证属于未来工作（第 17.2 节）。

### 7.5 模式驱动的全局选择（编码器）

工作模式不规定块大小，而是规定在整条音轨范围内测量的、必须保持在自身等级的 D 标记内容和 C 标记内容的比例。其余 C 类和 D 类内容可以降级。

对于每种模式，编码器在整条音轨范围内选择分区和叶节点类别，在满足这些保留比例的条件下使编码总字节数最小。

- **降级代价。**降级的代价以拉格朗日乘数 λ 表示。它通过二分法求得，先针对 C，再针对 D，在一次遍历中完成。
- **根块内的搜索。**对所有子矩形进行的动态规划评估每一个允许的切分。一个 16 个单元 × 8 帧的根块有 136 × 36 = 4,896 个子矩形，每个子矩形最多尝试 22 个切分位置。
- **大小评估。**大小使用与实际范围编码器相同的概率模型进行评估。最后一遍使用实际编码器进行编码。

搜索仅受精度约束；它不对片段或数据包施加字节上限。乘数 λ 和比例目标仅存在于编码器中；解码器只读取分区树。

默认情况下，比例按单元数量测量：

- 选项 `energy` 按能量测量；
- 模式 `max` 始终使用能量；
- 模式 `keep` 和 `keep20` 同时使用单元数量和能量。

对各根块的搜索并行运行。线程数不影响输出：16 线程和 1 线程编码的结果逐字节相同。

## 8 量化

### 8.1 步长

每个非 A 类叶节点携带一个指数 $E$ 和一个等级 $t \in \lbrace B, C, D \rbrace$：

- $E$ 是该叶节点中最大系数绝对值的位长度，以 24 位单位计；
- 各等级的位数为 $\mathrm{TB}(B) = 2$、$\mathrm{TB}(C) = 4$ 和 $\mathrm{TB}(D) = 8$。

量化步长为 $\Delta = 2^s$，以 24 位单位计。指数 $s$ 由三条**精度规则**之一给出。每个数据流头部都记录规则编号。

| 规则 | 用于 | 公式 | 高电平块 | 安静块 |
|---|---|---|---|---|
| 1 | 方案 1（两层）；方案 2 的位深层 | $s = \max(0, \min(E, 8) - \mathrm{TB})$ | B18/C20/D24 | 比块峰值低 TB 位 |
| 2 | 方案 2 的频率层 | $s = \max(0, \min(E - \mathrm{TB}, 8 - \lbrace 0, 4, 8 \rbrace))$ | B16/C20/D24 | 同规则 1 |
| 3 | `keep20` 的位深层 | $s = \max(0, \min(E, 6) - \mathrm{TB})$ | B20/C22/D24 | 比块峰值低 TB 位 |

在规则 2 中，第二项对 B、C 和 D 分别为 8、4 和 0。

- **安静叶节点**（$E$ 低于上限）。步长相对于叶节点峰值设定。于是系数保持固定数量的有效位，无论绝对电平如何都能保持波形相似性。
- **高电平叶节点。**上限确定以位计的绝对分辨率。例如，规则 1 使 B 类叶节点达到 16 + 2 = 18 位。

**16 位下限保障。**每条规则都满足 $s \le 8$，因此步长不会粗于一个 16 位 LSB（以 24 位单位计为 256），即 CD 层的分辨率。因此，16 位电平以上的所有内容都经过波形编码。

上限是固定的格式常量。

**范围。**格式的理论上限为 144 dB，即 24 位采样的范围。主要内容的设计目标为 120 dB。

### 8.2 死区

编码器使用参数 θ = 0.30 的死区标量量化器：

$$|q| = \left\lfloor \frac{|X|}{\Delta} + 0.5 - 0.30 \right\rfloor ,$$

其中 $q$ 取系数 $X$ 的符号。死区是编码器参数；解码器只需要下文的重建规则。

开发期间评估了更小的死区（0.15 和 0）。它们使误差改善约 2–3 dB，代价是总大小分别增加 +3 % 和 +6 %（表 12.5）。它们未被采用。

### 8.3 重建偏移

非零量化索引 $q$ 重建为

$$\hat X = \operatorname{sign}(q)\left(|q| + 0.20\right)\Delta .$$

偏移 0.20 是格式常量。在表 12.5 的开发测量中，与仅使用泄漏补偿相比，该偏移：

- 未改变扩展大小；
- 使平均超声误差改善 1.8 dB；
- 使用 18 位位深层时使平均峰值误差改善 2.0 dB，使用 20 位位深层时改善 2.8 dB。

### 8.4 零系数与可选零级别

**零系数。**默认情况下，零量化索引重建为精确的零。此规则的影响较小：

- 在 CD 频带中，扩展之下有 CD 层，因此不会产生频谱空洞；
- 在超声频带中，只缺失低于步长 0.5–0.8 倍的成分；
- 在开发测量中，解码信号的超声电平比母带低 0.3–1.4 dB。

**可选零级别（`zs`，默认关闭）。**使用 `zs` 时，编码器传输每个量化为零的系数的真实符号。该系数随后重建为符号 × 叶节点级别 × 步长。

- 每个叶节点携带一个 3 位索引 $k$。
- 当 $k = 0$ 时，零系数重建为零。
- 当 $k > 0$ 时，叶节点中的每个零系数之后跟随一个旁路编码位，即其真实符号。它重建为 $\pm \mathrm{ZC}[k] \Delta$。

级别表为

$$\mathrm{ZC} = \lbrace 0, 1/32, 1/16, 3/32, 1/8, 3/16, 1/4, 3/8 \rbrace .$$

编码器根据每个叶节点自身的统计量为其选择 $k$。未使用该选项时，编码器在每个叶节点中写入 $k = 0$。

开发期间测得 `zs` 的以下影响（10 秒片段，模式 3）。

| 量 | 影响 |
|---|---|
| CD 频带误差（24 位路径） | 从约 −111.5 dBFS 改善至约 −115 dBFS（约改善 3.5 dB） |
| 超声误差 | 改善 1–5 dB |
| 峰值误差 | 改善 1–7 dB |
| 位深层大小 | +23–28 % |
| 频率层大小 | +4 % 至 +67 %；超声内容越弱，增幅越大 |
| CD-Extra 播放时长，方案 2，超声内容较弱的 DXD 录音 | 可能从约 45 min 降至约 36 min |
| 确定性 | O2 和 Od 解码结果逐字节相同 |

该选项仍默认关闭。

### 8.5 A 类

A 类叶节点不携带系数。其所有系数都重建为精确的零。

### 8.6 标记的噪声和 G（编码器选项）

两个可选的编码器设置使用 A 类；格式和解码器均不变（[docs/NOISE.md](docs/NOISE.zh.md)）。

- **`noise=<marking file>`。**用户使用 LAE Noise Marker（`plugins/lae_noise_marker/`）在对齐后的母带中标记噪声，该工具只识别并标记噪声。在频率层中，编码器在被标记的单元中将母带视为零；所有频率箱均被标记的单元为 A 类。频率层以下（CD 频带中）的标记只列出，不作改动。
- **G**（镜像的本底噪声；[docs/NOISE.md](docs/NOISE.zh.md)）。在 A 类单元中，解码输出仅为升采样后的 CD 层，即其镜像分量，比音乐低约 120 dB（半带滤波器的阻带）。在其他位置，频率层将其抵消。`g` 以 −G 对频率层进行第二次编码，仅在第一遍中为 A 类、且已被删除或母带本身为静音的单元中进行；第二组数据流与第一组相加（规范第 9.5 节允许这种重叠）。`g=b`、`g=c` 和 `g=d` 选择该遍的步长。
- 不使用任一设置时，编码器输出逐字节不变。

## 9 熵编码

所有叶节点数据都使用自适应二进制范围编码器编码。完整的二值化规定见 [SPEC.md](spec/lossy/SPEC.zh.md) 第 6–8 节。本节概述其结构。

**概率自适应。**每个自适应二进制模型都以固定移位量 5 更新。

**二值化。**多值符号通过固定二叉树二值化：

- 系数位长度使用固定的 5 位树；
- 叶节点零级别索引使用 3 位树。

**系数上下文。**系数的上下文由其叶节点的类别和叶节点指数导出。

**边信息上下文。**

- **类别符号。**以比特流中前一个叶节点的类别作为上下文进行编码。
- **指数。**编码为与前一个非空叶节点指数的差值。
- **零级别索引。**以类别符号作为上下文进行编码。

**树比特。**

- 切分位和方向位为旁路位。
- 切分位置为旁路编码的定长整数。
- 在 `zs` 下传输的符号为旁路位。

**模型状态。**每个数据流都从默认模型状态开始。版本 5 未定义随机访问点（[SPEC.md](spec/lossy/SPEC.zh.md)，第 6.8 节）。解码器库的快速定位（第 13.6 节）使用解码器在解码过程中记录的检查点；不向比特流中添加任何内容。

## 10 容器（v5）

本节为摘要。规范性描述见 [SPEC.md](spec/lossy/SPEC.zh.md) 第 3–5 节。

### 10.1 封装

在容器 v5 中，LAE 文件有两种形式（[SPEC.md](spec/lossy/SPEC.zh.md) 第 3.1 和 3.4 节）：

- **WAV 形式**（默认）：RIFF/WAV 文件，其 `data` 块为 CD 层；扩展位于单独的块中，块 ID 为 `LAE `（末尾带一个空格）。
- **FLAC 形式**（自 v5-2026-11-14 起）：FLAC 文件，其音频帧为 CD 层，左右声道独立编码；扩展（与 `LAE ` 块的主体逐字节相同）切分到 ID 为 `LAE1`（已在 IANA 登记）的 APPLICATION 元数据块中，放在音频帧之前。标签和图片位于这些块之前。两种形式的每条路径都解出相同的样本；在一段 10 秒的测试中，FLAC 形式的大小是 WAV 形式的 61 %。

播放器忽略未知的块并播放 CD 层。`.wav` 表示 WAV 形式，`.flac` 表示 FLAC 形式。`.lae` 是该格式专用的扩展名，两种形式都可以；参考编码器未给 `--form=flac` 时写 WAV 形式。Windows 自带的 FLAC 解码器打不开音频起点位于文件约 4 MiB 之后的 FLAC 文件，因此大多数 FLAC 形式的 LAEY 文件在那里无法播放（[spec/COMPATIBILITY.zh.md](spec/COMPATIBILITY.zh.md)）。

**扩展包**（自 v5-2026-11-14 起；[SPEC.md](spec/lossy/SPEC.zh.md) 第 5.6 节）。一个文件可以有一个 CD 层和最多九个互相独立的扩展：主体和最多八个另加的包，每个包由各自的母带对着同一个 CD 层生成，并可以有名称。解码器用 CD 层加恰好一个包解码，包由用户选择，从不自动选择。不支持扩展包的解码器照旧播放主体。

WAV 文件之外的封装在 v5 容器之外由封装规范定义（第 10.5–10.9 节）：

- **CD-Extra。**封装到 CD-Extra（44.1 kHz 系列）已在工具 `lae_cdx` 中实现。音频区段承载 CD 层，数据区段承载扩展。
- **单独文件与数据流。**该规范还定义了另外两种分发形式：附带扩展文件的基础层文件（FLAC 或 WAV），以及 LAE 流。在这两种形式中，扩展单独成一个文件；把两者放在同一个文件里的，是上面的 FLAC 形式。

### 10.2 扩展块布局

所有头部整数字段均为小端 32 位整数。边界采样为小端 16 位整数。

| 字段组 | 内容 |
|---|---|
| 标识 | 魔数 `LAE1`；容器版本 5 |
| 采样率和长度 | 母带采样率；基础采样率；倍频程级数；母带长度；母带采样率下每侧的填充长度 P |
| 信息字段 | CD 截止频率；模式索引（0 max、1 “1”、2 “3”、3 “5”、4 keep、5 keep20）；等分切分标志；比例度量。这些字段仅用于显示，不影响解码；但模式索引仍必须在 0–5 范围内。 |
| 边界 | 扩展基础层的长度 nb；两端各自的扩展采样数 pb；每端的 pb 个立体声 CD 采样 |
| 抖动标志 | 标志字节数，随后为每个声道、每 4096 个基础采样率采样 1 字节的标志，所有左声道标志在前 |
| 位深层 | L 流、R 流 |
| 频率层 | 片段数 n；n 个 M 流；n 个 S 流 |
| 完整性 | 对此前全部内容计算的 CRC-32 [9] |

### 10.3 数据流布局

每个数据流由字节数、十个头部字段和范围编码数据组成。头部字段为：

- K；
- N；
- 起始谱线；
- 结束谱线；
- 采样率；
- 长度；
- 单元宽度 + 256 × 精度规则编号；
- 模式；
- 等分切分标志；
- 范围编码字节数。

精度规则编号如下：

- 1：B18/C20/D24；
- 2：B16/C20/D24；
- 3：keep20 位深层，B20/C22/D24。

K 是平面中的 MDCT 帧数。K 必须为正数，且应等于 $\lceil L_s/512 \rceil + 1$，其中 $L_s$ 对位深流为填充后的基础采样率长度 nb，对频率流为填充后的母带长度。若 K 较小，缺少的帧解码为零（[SPEC.md](spec/lossy/SPEC.zh.md)，第 5.3 节）。

### 10.4 验证

出现以下任一情况时，解码器拒绝该文件：

- 扩展块的 CRC 不匹配；
- 头部字段彼此不一致；
- CD 音频的长度与扩展块不匹配；
- 任一编码值超出范围；
- 容器版本不为 5。

所有头部字段在使用前均经过验证。参考解码器还提供以下保护：

- 读取边界检查；
- 防止恶意文件造成不终止的循环；
- 采样率参数检查，包括拒绝负的输出采样率；
- 64 位文件大小；
- 防止输出大于 4 GB；
- 溢出保护。

### 10.5 CD-Extra 封装

第 10.5–10.9 节概述封装规范，该规范以草案形式发布于 [spec/cdx/SPEC.md](spec/cdx/SPEC.zh.md)。两者不一致时，以该规范为准。封装完全位于容器 v5 之外：v5 容器和解码器均未改变，封装规范有其自身的版本号。工具 `lae_cdx` 实现了该规范（命令见第 14.6 节）。

**适用范围。**CD-Extra 仅适用于 44.1 kHz 系列，光盘上的每个 CD 层均为 44,100 Hz。DVD 和蓝光数据光盘不使用 CD 布局。它们承载普通文件（第 10.7 节），这些文件可属于任一系列。

**区段 1（音频）。**区段 1 一次写入（disc-at-once 或 session-at-once）。它仅包含以下内容：

- 音轨 1 的 150 扇区 pregap，为数字静音（不支持隐藏音轨）；
- 各音轨的 CD 层，每个 CD 层从该音轨的 INDEX 01 开始，音轨 1 的 INDEX 01 位于 LBA 0；
- 每个 CD 层之后少于 588 个采样（一个扇区）的数字静音，用于补足该音轨的最后一个扇区。

区段 1 遵循以下规则：

- 最后一条音轨之后既无保护音轨，也无其他静音；
- PCM 中不嵌入任何数据或标记；
- 每条音频音轨的长度均为整数个扇区，且至少为 300 个扇区（4 s）；
- 不设置预加重标志；
- 一张光盘最多容纳 98 条音频音轨，因为数据音轨也占用一个音轨编号。

CD 层的两种模式对应不同的布局：

- **派生 CD。**音轨边界为发行方给定的边界。在连续母带中，每个音轨起点都必须位于扇区网格上；否则工具停止，列出这些起点，且不写入任何内容。不添加也不删除任何母带采样。
- **独立 CD**（选项 `layout=<publisher.cue>`）。发行方的 INDEX 条目（包括从音轨 2 起的 INDEX 00，以及 INDEX 02 及以上）、ISRC、FLAGS 和 CATALOG 均保留在其原位置。区段 1 必须与发行方的节目逐采样相同，工具会对此进行检查。工具只接受已经对齐的文件（第 4.3 和 4.5 节）；其本身不执行任何对齐。

**区段 2（数据）。**区段 2 恰好包含一条 CD-ROM XA Mode 2 Form 1 数据音轨，每个扇区含 2048 字节用户数据。光盘上任何位置都不出现 Mode 1 扇区。文件系统及其内容如下：

- 文件系统为 ISO 9660 Level 1 [5] 加 Joliet [15]；不使用 Rock Ridge、UDF 和 El Torito；
- 数据音轨从驱动器报告的下一个可写地址开始。对于一次写入的镜像，起点预先计算为 A2 + 11,400 个扇区，其中 A2 为区段 1 lead-out 的起点，11,400 个扇区包括数据音轨的 150 扇区 pregap。该数值有待通过刻录确认（第 17.3 节）；
- 光盘包含 `/README.TXT`，为中英文纯文本说明，不含哈希、位置、偏移或长度表；
- 目录 `/LAE/` 仅包含 `TRACKnn.LAX`，即每条带扩展的音频音轨各一个扩展文件，其中 nn 为 TOC 中两位数的音轨编号；
- 数据区段不包含 CUE 表、TOC 副本、报告、程序和 `autorun.inf`。其他文件（例如小册子）由发行方自行决定，读取器忽略这些文件；
- 数据音轨以零扇区结尾（默认 150 个，有待通过刻录确认），且长度至少为 300 个扇区。

音轨可不带扩展发布，例如在容量不足时；此类音轨仅作为 CD 播放。可写入 ISRC、MCN 和 CD-Text，但它们只可承载标准元数据。

**交付物。**该工具交付：

- 用于一次写入的镜像：`IMAGE.CUE`、`AUDIO.BIN`（区段 1，从 LBA 0 到 A2，16 位小端立体声，整扇区）以及作为 `DATA.BIN`（每扇区 2352 字节）或 `DATA.ISO`（每扇区 2048 字节）的数据音轨；
- 用于分两步写入的套件：仅针对区段 1 的 CUE 表，以及一条按驱动器实际报告的起始地址重新生成区段 2 的命令。READ TRACK INFORMATION（MMC [17]）报告的地址与 TOC 值 B0 以及 A2 + 11,400 进行核对；若三者中任一与其他不同，工具停止；
- 刻录与验收说明（`BURN.TXT`），附带布局表，给出各 INDEX 01 的 LBA、A2 以及数据音轨的起点。

CUE 表不包含 CRC、MD5 或其他哈希。

### 10.6 扩展文件与尾部记录

扩展文件恰好由两部分组成：

1. 该音轨 `LAE ` 块的正文，共 $n$ 字节，包括其末尾的 CRC-32，与该音轨 v5 WAV 文件中的块逐字节相同；
2. 80 字节的尾部记录。

扩展文件没有文件头，$n$ 等于文件长度减 80。文件扩展名在 CD 上为 `.LAX`，在其他场合为 `.lax`；读取器不区分大小写。

**尾部记录。**所有整数均为小端。

| 偏移 | 字节数 | 字段 | 内容 |
|---|---|---|---|
| 0 | 4 | 标识符 | ASCII `LTVT` |
| 4 | 2 | 版本 | 1 |
| 6 | 2 | 长度 | 80 |
| 8 | 2 | 扩展块类型 | 1 = LAEY 容器 v5；2 = LAES 扩展块（[spec/lossless/SPEC.md](spec/lossless/SPEC.zh.md)，第 9 节）；其他值保留 |
| 10 | 2 | 音轨编号 | 在 CD 上为 TOC 中的音频音轨编号（1–98） |
| 12 | 4 | 采样率 | CD 层的采样率：在 CD 上为 44100；在其他场合为 44100 或 48000 |
| 16 | 4 | ncd | CD 层的采样数，$1 \le \mathrm{ncd} < 2^{28}$ |
| 20 | 16 | MD5 | CD 层的整轨 MD5 |
| 36 | 8 | S1 | 滑动校验和（见下文） |
| 44 | 8 | S2 | 滑动校验和（见下文） |
| 52 | 4 | lead0 | CD 层开头连续数字静音采样的数量 |
| 56 | 4 | tail0 | CD 层结尾连续数字静音采样的数量 |
| 60 | 16 | 保留 | 写入时为零；读取时忽略 |
| 76 | 4 | CRC-32 | 字节 0–75 的 CRC-32 |

各字段定义如下：

- **整轨 MD5。**对 CD 层交错排列的小端 16 位采样计算的 MD5 [16]；其定义与 FLAC STREAMINFO 块中 16 位立体声音频的音频 MD5 相同 [1]。它是读取器接受一条音轨的唯一判据。
- **S1 和 S2。**每个采样读作一个 32 位帧字 $w_i$。则 $S_1 = \sum w_i \bmod M$，$S_2 = \sum (i+1)\,w_i \bmod M$，其中 $M = 2^{61} - 1$。窗口每滑动一个采样，两个和均可在常数时间内更新，因此读取器能以较低代价测试搜索范围内的每个位置。
- **lead0 和 tail0。**二者是对 CD 层内容的计数，而非位置，与刻录、抓轨和偏移无关。它们仅用于音轨的粗定位（第 10.8 节）。其所计数的静音采样属于音轨的一部分：这些采样总是被播放，且包含在整轨 MD5 中。任何程序均不得删除或跳过这些采样。

**排除的内容。**尾部记录和扩展文件不包含任何由扩展字节计算得到的值，也不包含任何同时基于 CD 层和扩展计算的值；扩展仅由其自身的 CRC-32 保护。二者也不包含任何位置、LBA、偏移、延迟或增益，不包含逐扇区或逐帧数据，也不包含寻址表或 cue 表。

**读取时的检查。**读取器按固定顺序检查扩展文件：尾部记录是否存在、其 CRC、其版本和长度、扩展块类型，以及各字段的取值范围。任一检查未通过的文件均不被使用，其音轨作为 CD 音频输出，并附上原因。

### 10.7 CD 之外的分发

**单个 v5 WAV。**编码器和重新封装工具以唯一的规范化布局写入 v5 WAV 文件：`RIFF`/`WAVE`、16 字节的 `fmt ` 块、`data` 块，随后是 `LAE ` 块，并填充至偶数长度。

**基础层加扩展文件。**一条音轨可作为两个文件分发：

- **基础层文件**，为 FLAC [1] 或 WAV，恰好承载该音轨的 CD 层；
- **扩展文件**，与基础层文件同名，扩展名为 `.lax`。若该音轨也以 CD 发布，此文件与光盘上的 `TRACKnn.LAX` 逐字节相同。

普通播放器播放基础层文件。扩展文件及其尾部记录绝不放入基础层文件内部（第 10.1 节的 FLAC 形式是另一种单文件形式）。当解码后的基础层有 ncd 个采样且其整轨 MD5 等于尾部记录中的 MD5 时，读取器将这两个文件配对。配对后的音轨重新封装为规范化 v5 WAV，与编码器的输出逐字节相同。

**LAE 流。**LAE 流逐条音轨传送 CD 层（逐采样，FLAC、WAV 或原始 PCM）和扩展文件（逐字节）。流中不包含任何头部、索引、位置或偏移。CD 层经过有损重新编码（例如 AAC 或 MP3）的流不是 LAE 流：扩展绝不应用于有损解码的音频，此时只播放基础层。

本节所述的所有形式均可使用 48 kHz 系列。

### 10.8 读取抓轨与文件

`lae_cdx` 的读取器（读取器代码：`src/lae_cdx_read.h`）以相同方式处理所有输入：整盘抓轨（BIN 或 WAV，带或不带 CUE 表）、逐轨抓轨（带或不带 CUE 表）、单个文件以及 LAE 流。抓轨可来自任何抓轨程序，可采用任何偏移设置。输入必须为 16 位立体声 PCM（WAV，或带 CUE 表的整盘抓轨为 BIN）。

**光盘流与 TOC。**读取器将其输入组装成光盘流。TOC 按以下优先顺序获取：

1. 从驱动器读取的 TOC（已规定，但 `lae_cdx` 尚未实现；第 17.3 节）；
2. CUE 表；
3. 一组逐轨文件的顺序和长度；报告中醒目标出此来源。

每个文件放在 CUE 表或 TOC 给出的位置。未被任何文件覆盖的位置为未知，按零读取；读取器不尝试其他取值。没有 TOC 时，按内容搜索每个文件，报告中注明 “no TOC”。无法识别的 CUE 结构使读取器停止。

**逐轨定位。**每条音轨独立定位；读取器既不假定、也不需要整张光盘具有共同偏移。对于每个扩展文件，读取器按以下步骤处理：

1. **粗定位。**粗略位置取自 TOC 以及信息范围，即流中第一个和最后一个非零采样的位置，经 lead0 和 tail0 校正。
2. **精定位。**测试距粗略位置半径 $W \ge 5880$ 个采样范围内的每个窗口起点；没有 TOC 时测试整个文件中的每个窗口起点。只有滑动和等于 S1 和 S2 的窗口才成为候选。
3. **接受。**只有当候选的整轨 MD5 等于尾部记录中的 MD5 时，才接受该候选。

音轨内部的滑移（例如丢失或重复一个采样）只改变该音轨的 MD5。该音轨作为 CD 播放，其他音轨不受影响。

**输出与失败。**读取器按以下方式写入输出：

- **已接受的音轨。**每条已接受的音轨重建为 `TRACKnn.lae.wav`，与编码器写出的文件逐字节相同。
- **其他音轨。**其他每条音轨写为 `TRACKnn.cd.wav`，其中包含未经改动的抓轨 CD 音频，并附上原因。原因类别包括：未知采样（文件缺失或被截断）、文件过短、无匹配、无尾部记录、尾部记录损坏、无法识别的版本或扩展块类型、尾部记录字段无效、音轨编号不在 TOC 中、扩展损坏，以及有损基础层。
- **没有音轨被接受。**若没有任何音轨被接受，读取器报告输入可能是另一张光盘或另一个版本。
- **无扩展的音轨。**TOC 中没有扩展文件的音轨作为 CD 输出；这不属于失败。

**禁止事项。**读取器遵守以下限制：

- 绝不修改、修复或替换任何 CD 采样；
- 绝不使用扩展块中的边界采样来定位或拼接音轨；
- 不使用任何外部数据库，也不使用网络；
- 在一条音轨被接受之前，不输出该音轨的任何高解析度数据，并且绝不在一条音轨内部在 CD 与扩展之间切换；
- 测得的偏移仅用于显示，不写入任何文件。以偏移 0 和 +667 制作的抓轨得到了逐字节相同的输出（第 10.9 节）。

### 10.9 自检、容量与测试

**闭环自检。**`lae_cdx` 在交付镜像之前，使用读取器自身的代码回读该镜像，并从镜像的数据区段中获取扩展文件。回读涵盖以下抓轨形式：

- 带 CUE 表的整盘镜像，偏移在 ±5880 个采样以内；
- 不带 CUE 表的整盘抓轨；
- 逐轨抓轨，分别带 CUE 表和仅有文件顺序，覆盖三种间隙模式（间隙附加到前一条音轨、前置到下一条音轨或省略），并分别带和不带音轨 1 的 pregap。

每条音轨都必须通过，并且必须重建出与编码器输出逐字节相同的 v5 WAV。在从音轨 2 起带有 INDEX 00 间隙的独立 CD 光盘上，省略间隙的抓轨无法提供间隙中的采样；此时，除非该间隙为数字静音，自检预期此类间隙之前的音轨回退为 CD。自检还包括故意损坏：更改一个采样、另一张专辑的扩展文件，以及删除尾部记录。上述每种音轨都必须回退为 CD。若任一检查失败，镜像即作废，处理过程停止。

**容量。**工具在写入之前按空白光盘的类型检查容量，并在自检之后再次检查。若镜像放不下，工具停止并列出可选方案：将部分音轨不带扩展发布（选项 `noext=`）、改用其他光盘，或限制倍频程（需要重新编码）。工具绝不自动删除任何音轨或倍频程。

**测试（开发期间，2026-10-21）。**测试使用由同一录音中两条音轨的 10–15 s 片段制作的测试光盘。

| 测试 | 结果 |
|---|---|
| 已知答案测试：规范中的校验和示例、RFC 1321 的 7 个测试字符串、CRC-32、滑动和在 1000 个随机位置上与直接计算结果的对比、尾部记录取值范围 | 全部通过 |
| ISO 9660 / Joliet 写入和读取 | 162 项检查中 162 项通过 |
| 封装规范的一致性用例，在内存中运行（包括读取器的 CUE 解析、自检、故意损坏、缺失文件、GBK 和 UTF-8 CUE 表） | 84 / 84 |
| 使用真实文件的端到端命令行测试（包括在 Windows 上挂载数据区段；偏移 0 和 +667 的输出逐字节相同） | 17 / 17 |

测试套件经过独立审查，审查确认的问题在获得上述结果之前均已修正。尚未刻录真实光盘（第 17.3 节）。

## 11 模式与码率

### 11.1 方案与模式

两种方案和六种模式共组成十二种组合。两种方案为：

- 方案 1（`s1`，高质量，默认）；
- 方案 2（`s2`，高压缩）。

| 模式（`lae_enc` 参数） | D 类保留比例 | C 类保留比例 | 位深层 | 比例度量 |
|---|---|---|---|---|
| `max`（最大压缩） | 10 % | 30 % | 18 位（规则 1） | 能量 |
| `1` | 30 % | 50 % | 18 位（规则 1） | 单元数 |
| `3`（默认） | 50 % | 70 % | 18 位（规则 1） | 单元数 |
| `5` | 70 % | 90 % | 18 位（规则 1） | 单元数 |
| `keep` | 90 % | 100 % | 18 位（规则 1） | 单元数 + 能量 |
| `keep20` | 90 % | 100 % | 20 位（规则 3） | 单元数 + 能量 |

在以噪声为主的录音上，各模式的大小必然相近：模式仅调整 C 类和 D 类内容，而这类录音中此类内容很少。第 11.4 节给出相邻模式之间测得的大小变化。

### 11.2 测量依据

### 11.5 CD-Extra 播放时长

CD-Extra 仅适用于 44.1 kHz 系列。在 CD-Extra 光盘上，CD 层是第一区段中的普通 Red Book 音频，扩展则占用第二区段中的 CD-ROM XA Mode 2 Form 1 数据扇区，每个扇区含 2048 字节用户数据（第 10.5 节）。所用常数列于下表。

| 常数 | 数值 |
|---|---|
| 80 分钟光盘 | 360,000 个扇区，每秒 75 个扇区 |
| 数据扇区（用户数据） | 2048 字节，因此每光盘分钟可存放 9.22 MB 数据 |
| 多区段开销（第一区段 lead-out ≈ 6,750 个扇区，第二区段 lead-in ≈ 4,500 个扇区） | ≈ 11,250 个扇区 ≈ 2.5 分钟。这些是 Blue Book 的常用数值；通过实际刻录进行确认属于未来工作（第 17.3 节）。 |
| ISO 9660 / Joliet 文件系统 [5][15] | 约 1–2 MB（≈ 0.2 分钟），为估算值；每个文件按 2048 字节对齐 |
| 安全余量 | 容量的 1.5 % 或 4 % |

`lae_cdx` 的布局将数据音轨置于 A2 + 11,400 个扇区处，即上述开销加上数据音轨的 150 扇区 pregap，约为 2.53 光盘分钟。下文的播放时长按 2.5 分钟计算；两者相差约 0.03 光盘分钟。

令 $r$ 为每分钟音乐的扩展大小（单位 MB）除以 9.22。专辑时长 $L$ 必须满足

$$L(1 + r) + 2.5 + 0.2 \le C$$

单位为光盘分钟，其中 $C$ 为扣除安全余量后的容量。

### 12.3 合成材料与固有限制

**合成套件。**在候选发布轮次中，生成的合成套件（60 个信号）在 24 位路径下的 CD 频带误差中位数为：

- 在各采样率及 `max` 至 `keep` 各模式下为 −111 至 −115 dBFS；
- 使用 keep20 时为 −121 至 −125 dBFS。

**Synth，16 位路径。**合成压力测试信号 “Synth” 包含方波，其带限形式超过满量程。CD 层必须对其削波，而 16 位路径没有可用于恢复它们的位深层。因此，对于这类信号，其 16 位路径的 CD 频带误差是该路径的固有限制：

- 在 40 秒片段上为 −42 dBFS，为开发期间测得（2026-10-17）；
- 在候选发布轮次的 10 秒片段上为 −35 至 −36 dBFS。

**Synth，24 位路径。**

- 在一项 40 秒的开发对比中，泄漏补偿将 Synth 的 24 位路径 CD 频带误差从 −79 改善至 −112 dBFS。
- 在候选发布轮次中，Synth 在 `max` 至 `keep` 各模式下的 24 位路径 CD 频带误差，在 88.2、96、176.4 和 352.8 kHz 下依次为 −101、−113、−96 和 −82 dBFS。
- 使用 keep20 时，96 kHz 下的数值为 −125 dBFS；其余三项不变。
- 176.4 和 352.8 kHz 下的数值尚未分析（第 17.4 节）。

### 12.4 输出限幅

解码器的最终输出被硬限幅至 24 位范围。

- **过冲有界。**16 位下限保障（第 8.1 节）将任何超过满量程的过冲限制在编码误差范围内。在一项开发测量中，对在 +12 dB 处硬削波的母带，峰值误差最高为 −76.6 dBFS。硬限幅器将这类采样恢复至满量程，即母带在这些采样处自身的值。
- **限幅器动作情况。**在候选发布轮次中，没有任何一次编码会使解码器的硬限幅器动作（已发布数据的 `limiter_samples` 列）。
- **编码器报告。**编码器执行诊断解码，并报告硬限幅器将作用的采样数，供参考。

- 所有模式均使用泄漏补偿和重建偏移 0.20；
- 模式 `keep20` 使用 20 位位深层。

### 12.6 听音测试

LAE Lossy 的可听频带由 CD 层加上波形编码的细化组成。尚未发布任何听音测试结果。

针对差异敏感材料的听音测试属于未来工作（第 17.3 节）。候选流程为 ABX 和 webMUSHRA [11]。

## 13 确定性与一致性

### 13.1 算术

插值和抽取使用整数滤波器表。

系数重建和逆 MDCT 使用 IEEE-754 binary64 算术 [7]，并严格按照参考源码中的运算顺序计算。所有 MDCT 常量均来自 `src/mdct_tables.h` 中的精确十六进制字面值。在这些条件下，所有平台都会生成逐位相同的输出。

禁止使用以下构建选项：

- `-ffast-math`；
- `/fp:fast`；
- 任何允许融合乘加收缩的选项。

在使用 GCC 或 Clang 的 32 位 x86 上，必须使用 `-msse2 -mfpmath=sse`。不支持 x87 构建，解码器的启动自检会拒绝此类构建。

### 13.2 启动自检

每次启动时，解码器都会将固定数据集送入逆 MDCT，并对结果计算 64 位指纹。

- 指纹采用 FNV-1a 风格哈希 [8]，但初始值为非标准值，详见 [SPEC.md](spec/lossy/SPEC.zh.md) 第 13 节。
- 指纹必须等于 `0x729b547fbdbfe203`，即 `src/mdct_tb.h` 中的 `SELFTEST_REF` 值。
- 若不相同，说明该构建改变了浮点求值过程。此时解码器拒绝运行（退出代码 4），而不会生成与其他平台不同的输出。

工具 `tools/selftest_ref.cpp` 打印当前构建的指纹。

编码器在启动时运行逆 MDCT 自检和 MD5 自检。解码器库在调用线程上运行自检（第 13.6 节）。

### 13.3 已验证的配置

已验证的构建列于 [docs/BUILD.md](docs/BUILD.zh.md) 第 3 节。

- **Windows，MSVC 2022。**解码器的 x64 `/O2`、x64 `/Od` 和 x86 SSE2 构建生成相同的结果。参考向量文件由 MSVC 编码器生成。
- **Linux x86，解码器。**解码器使用 GCC 13 x86-64（`-O2` 和 `-O0`）、Clang 18 x86-64（`-O2`）以及 GCC 13 x86 32 位（SSE2）构建。256 项解码结果中有 256 项与参考结果相同。
- **Linux x86，编码器。**使用 GCC 13 x86-64（`-O2` 和 `-O0`）构建的编码器逐字节重现全部 16 个一致性测试向量文件。
- **解码器库。**现已调用解码器库的 `lae_dec`，以及 x64 和 x86 构建的 `liblae`，各自重现了 64 项一致性输出中的 64 项（16 个向量 × 清单中的 4 种输出；对于 88.2 和 96 kHz 的 8 个向量，半采样率输出被正确拒绝）。
- **Linux ARM64。**在 aarch64 上，使用 GCC 13（`-O2` 和 `-O0`）和 Clang 18（`-O2`）构建的解码器通过了启动自检，192 项解码结果中有 192 项与参考结果相同。使用 GCC 13（`-O2`）构建的编码器逐字节重现全部 16 个一致性测试向量文件。
- **尚未覆盖。**其他 ARM 系统（例如 32 位 ARM 和 ARM 上的 macOS）尚未测试。不支持 x87 构建（第 13.1 节）。

开发期间还测得以下结果：

- 使用 `zs` 选项时，优化与未优化的解码结果逐字节相同；
- 在候选发布轮次中，优化与未优化解码器之间的 83 项对比中有 83 项逐字节相同；其中 78 项列于已发布数据的 `o2_equals_od` 列中，该数据不包括 352.8 kHz 的 5 段录音。

### 13.4 其他不变量

- **编码器线程。**编码器线程数不影响比特流。
- **编码器自检。**编码器会重新解码每一层和每个片段，若有任何系数平面不一致，则拒绝写入文件。随后，在交付文件之前，编码器会对最终文件进行完整解码。
- **对齐。**将编码器打印的偏移通过 `cdalign=` 回传，会得到相同的文件。已经对齐、长度相同且无需放置的输入，其输出与引入对齐功能之前相同。
- **开发运行。**开发期间的测量（2026-10-17）中，331 次编码—解码运行均无失败地完成。
- **候选发布轮次。**v5 候选发布版无失败地完成了 996 次编码，且每次编码均通过编码器自检。

### 13.5 一致性测试向量

一致性测试向量及其哈希值列于 [tests/vectors/MANIFEST.md](tests/vectors/MANIFEST.md)。

**材料。**一致性测试向量取自自行生成的合成套件：每种信号从第 5 s 开始取 2 s。未使用任何第三方录音。

**信号。**使用四种信号：`sweep`（88.2 kHz）、`transients`（176.4 kHz）、`imd`（96 kHz）和 `electronic`（352.8 kHz）。每种信号以以下四种配置编码：

- 模式 3，方案 1；
- 模式 max，方案 2；
- keep20，方案 1；
- 模式 3，方案 1，启用 `zs`。

**哈希。**每个向量都是编码器的输出文件。清单列出编码文件的 SHA-256 [10]，以及以下四种路径各自解码所得 WAV 文件的 SHA-256：

- `full`；
- `16`；
- `cd24`；
- 以母带采样率一半运行的 `full`。

对于 88.2 和 96 kHz 的向量，母带采样率的一半等于基础采样率，因此这些向量不支持半采样率 `full` 路径（第 14.3 节）。

清单目前仅列出每个哈希的前 16 个十六进制数字。公布完整数值是 [SPEC.md](spec/lossy/SPEC.zh.md) 附录 C 中的待办事项。

符合规范的解码器必须针对每个向量和每条路径重现所列哈希值。本修订版的编码器逐字节写出全部 16 个向量。

### 13.6 解码器库

参考解码器的各处理级已原样移入库 `src/lae_decoder.h`，该库提供 `Decoder` 类。命令行解码器 `lae_dec` 调用该库。该库采用流式处理：除保存在内存中的 CD 层和扩展块外，其内存占用不随音轨长度增长。

**C 接口。**`liblae`（`src/lae_api.h`，API 版本 9）是面向播放器和插件的 C 接口，提供 x64 和 x86 构建。每个 API 版本只增加函数，因此为较早版本编写的宿主无需改动即可使用：

| API | 新增 |
|---|---|
| 2–3 | `lae_open_reader`（通过宿主回调读取）、`lae_stream_bytes` |
| 4–5 | `laes_*` 函数（LAE Lossless）、`laes_index_save` / `laes_index_load` |
| 6 | `lae_probe_*` 和 `lae_any_*`：两种格式共用的接口，只按内容判断格式（`src/lae_any.cpp`） |
| 7 | LAES 有效载荷版本 2：`laes_master_name`、`laes_master_flags`、`laes_choice_from`、`laes_master_number` |
| 8 | LAEY 扩展包：`lae_pack_count`、`lae_pack_info`、`lae_select_pack`、`lae_selected_pack`、`lae_any_choice_pack` |
| 9 | `laes_default_choice`（文件中存储的默认母带，没有时为核心母带）、`laes_core_flags` |

命令行工具 `lae_udec`（`src/lae_udec.cpp`）建立在 `lae_any_*` 函数之上：它按规范的顺序列出文件提供的每一项及其格式的各项检查，并能解码任一项。

- **打开。**音轨可以从 WAV 形式或 FLAC 形式的 v5 文件、内存中 v5 WAV 文件的字节、通过宿主回调读取的文件，或从基础层（作为 PCM 的 CD 层）及其扩展文件打开。仅当基础层的整轨 MD5 与扩展文件一致，或在基础层中按内容找到该音轨且随后一致时，才接受该基础层。
- **路径与输出。**调用方选择第 3.4 节四种路径之一以及一个输出采样率。输出始终为两个交错声道的 `int32` 值：路径 `cd24`、`16` 和 `full` 为 24 位范围，CD 路径为 16 位范围。
- **统计信息。**该库报告被硬限幅器限制的采样数、是否发生数据流错误，以及已消耗的熵编码字节数。最后一项可用于显示实时码率。
- **线程。**同一条音轨不得同时由两个线程使用。不同音轨可同时在不同线程中解码；测试中，在两个线程中解码两条音轨，所得输出与分别解码时逐位相同。
- **浮点状态。**解码器要求按固定顺序进行的严格 IEEE-754 binary64 算术（第 13.1 节）。若宿主线程可能以不同的浮点状态运行，宿主应在每次调用期间将 MXCSR 设为 `0x1F80`，并在调用后恢复。`lae_selftest()` 检查调用线程；若检查失败，宿主应只播放 CD 层。`lae_start()` 会再次运行自检。

**逐位精确的快速定位。**解码期间，该库约每 4 s 记录一次熵编码器检查点，保存在当前区段的内存中（播放器存储的检查点每 30 s 一个，见下文）。定位时恢复一个检查点，并在目标位置之前不远处对每个信号处理级执行热重启，使定位后的输出与顺序解码逐位相同。

- 向后定位，或定位到已解码过的部分，速度很快。
- 向前定位越过已解码部分时，从播放器自身的检查点（见下文）继续，并从该处追赶到目标位置，所有熵编码流并行处理。v5 未定义随机访问点（第 9 节），此处也不添加：检查点仅来自播放器自身的解码。
- **播放器的检查点（2026-11-06）。**`lae_open_*` 首次遇到一个文件时，对整个文件检查一次：
  - 计算文件全部字节的 SHA-256；
  - 将每条熵编码流从头解码到尾，每条流一个线程。若某条流未恰好在其最后一个字节处结束，则打开失败，与数据块损坏时相同；CD 音频仍可播放。
  - 检查期间，每 30 s 保存一个检查点，以该 SHA-256 为名存放在播放器自身的文件夹中：Windows 上为 `%APPDATA%\LAE\lae_index\<sha256>.idx`，其他系统上为 `$XDG_CACHE_HOME/lae/lae_index` 或 `~/.cache/lae/lae_index`。环境变量 `LAE_INDEX_DIR` 指定其他文件夹；取值 `off` 表示不使用任何文件夹。Android 上的应用设置此变量。
  - 之后的打开读取该记录并跳过检查。记录缺失、损坏或属于其他文件，只会使下一次打开重新检查该文件；输出从不依赖该记录。
  - 该文件夹最多占用 256 MB；最久未使用的记录最先删除（仅删除该文件夹中的 `*.idx` 文件）。
  - 不向媒体文件写入或附加任何内容，也不随媒体文件发送任何内容。
- 在一个 13:22、352.8 kHz 的文件上实测（x64，8 核）：首次检查用时 2.9 s（每 10 分钟 2.2 s；4 核时每 10 分钟 3.2 s），之后的打开用时 0.7 s。定位到从未解码过的音轨 99 % 处用时 0.25 s（含随后 2 s 的读取），此前为 7.8 s。13 分钟的记录约为 0.3 MB。在 full、16 和 cd24 各路径以及 176.4 kHz 下，各 12 个位置均与顺序解码逐位相同。
- 在对 10–15 s 片段的开发测试中，覆盖所有路径和输出采样率的 540 次随机定位（包括定位到此前从未解码过的位置）全部逐位相同；最慢的一次定位连同随后的读取用时 0.2 s。

用法见第 14.7 节。

## 14 使用

### 14.1 构建

代码为标准 C++17，不使用任何第三方库。编码器由 `src/lae_enc.cpp` 构建，解码器由 `src/lae_dec.cpp` 构建。

- **解码器源文件。**解码器使用 `src/lae_dec.cpp`、`src/lae_decoder.h`、`src/part_stream.h`、`src/partition_format.h`、`src/mdct_tb.h`、`src/mdct_tables.h`、`src/halfband.h` 和 `src/wavio.h`（[SPEC.md](spec/lossy/SPEC.zh.md)）。
- **编码器源文件。**编码器将解码器编译进同一可执行文件。此外还使用 `src/partition.h`、`src/fft.h`，分块模块 `src/blk_io.h`、`src/wav_in.h`、`src/pad_blk.cpp`、`src/base_blk.cpp`、`src/routes_blk.cpp`、`src/lossy_blk.cpp` 和 `src/part_blk.cpp`，以及 `src/base_layer.cpp`（对齐用到其抽取）和 `src/cd_align.cpp`。以前的整轨模块 `src/pad_mirror.cpp`、`src/routes.cpp`、`src/lossy_v2.cpp`（含 `src/tone_scan.cpp`）和 `src/part_coder.cpp` 作为独立程序保留在仓库中，并作为与分块模块进行对比的参考；编码器不再使用它们。
- **封装工具源文件。**`lae_cdx` 由 `src/lae_cdx.cpp` 构建，并使用 `src/lae_cdx.h`（尾部记录与校验和）、`src/lae_cdx_read.h`（读取器代码）和 `src/iso9660.h`（ISO 9660 和 Joliet）。
- **解码器库。**`liblae` 由 `src/lae_api.h` 和 `src/lae_api.cpp` 组成，基于 `src/lae_decoder.h` 构建。将其构建为 DLL 时定义 `LAE_API_BUILD`；静态链接时，在宿主和库中均定义 `LAE_STATIC`。

`lae_enc` 和 `lae_dec` 可在 Windows 上用 MSVC 构建，也可在 Linux 上用 GCC 和 Clang 构建；`lae_cdx` 已在 Windows 上用 MSVC 构建并测试。示例命令：

```
cl /O2 /EHsc /std:c++17 /D_USE_MATH_DEFINES src\lae_dec.cpp
g++ -O2 -std=c++17 -ffp-contract=off -D_USE_MATH_DEFINES -pthread -o lae_dec src/lae_dec.cpp
g++ -O2 -std=c++17 -ffp-contract=off -D_USE_MATH_DEFINES -pthread -o lae_enc src/lae_enc.cpp
```

`lae_cdx` 的构建命令（Windows，MSVC；标志见 [docs/BUILD.md](docs/BUILD.zh.md) 第 1 节）为 `cl /nologo /O2 /EHsc /std:c++17 /utf-8 /fp:strict /D_USE_MATH_DEFINES /D_CRT_SECURE_NO_WARNINGS /bigobj src/lae_cdx.cpp`。`liblae` 由 `src/lae_api.cpp` 以 `/fp:precise` 编译；已验证的标志见 `plugins/foo_input_lae/build_fb2k.cmd`。

其他构建说明：

- 使用 MSVC 构建编码器时，添加 `/bigobj`。
- 在使用 GCC 或 Clang 的 32 位 x86 上，添加 `-msse2 -mfpmath=sse`。
- 不得使用 `-ffast-math`、`/fp:fast` 或任何允许 FMA 收缩的选项（第 13.1 节）。

所有选项、已验证的构建和检查脚本见 [docs/BUILD.md](docs/BUILD.zh.md)。

### 14.2 编码

```
lae_enc <master.wav> <output.wav> [mode] [s1 | s2] [zs] [cd=<cd.wav>] [energy] [equal] [cdcheck] [cdalign=<offset>] [cdaccept] [cdedge=pad | cdedge=cut] [bits=24] [mem=<GB>] [noise=<marks.laenoise>] [g | g=b | g=c | g=d] [--tag=KEY=VALUE ...] [--cover=<image>] [--picture=<type>:<image> ...] [--form=wav | --form=flac] [master1name=<name>] [master2=<file> master2align=<offset> [master2name=<name>] [master2accept] [master2edge=pad|cut] ... master9=…] [resume]
lae_enc tag <in.wav> <out.wav> [--tag=KEY=VALUE ...] [--cover=<image>] [--picture=<type>:<image> ...]
```

输出文件名决定形式：`.wav` 为 WAV 形式，`.flac` 为 FLAC 形式，`.lae` 未给 `--form=flac` 时为 WAV 形式（[spec/lossy/SPEC.md](spec/lossy/SPEC.zh.md) 第 3.4 节）。`lae_enc tag` 保持输入文件的形式。

| 参数 | 含义 |
|---|---|
| `master.wav` | 立体声整数 PCM，16/24/32 位（32 位输入见第 3.1 节），格式为 WAV、RF64 或 Sony Wave64。采样率为 88.2/176.4/352.8 kHz（44.1 kHz 系列）或 96/192/384 kHz（48 kHz 系列）。 |
| `mode` | `max`、`1`、`3`（默认）、`5`、`keep`、`keep20`（第 11.1 节）。模式为位置参数：只要使用了其后的任何参数，就必须给出模式。 |
| `s1` / `s2` | 方案 1，高质量（默认）/方案 2，高压缩。两者的 CD 频带相同，差异仅在频率层。 |
| `zs` | 可选零级别（第 8.4 节）；默认关闭 |
| `cd=<file>` | 独立 CD：采样率为母带所属系列基础采样率（44.1/48 kHz）的 16 位立体声 WAV；其采样原样写入 CD 层。CD 按第 4.3 节所述方式对齐。未给出 `cdalign=` 时，编码器报告两次搜索的结果，不写入任何内容。 |
| `cdalign=<offset>` | 已确认的偏移，以母带采样为单位；正值表示 CD 开始得较晚。可为整数，或以 `.` 为小数点、最多 9 位小数的数值（`cdalign=1,5` 会被拒绝）。使用编码器打印的偏移会得到相同的文件。 |
| `cdcheck` | 执行对齐检查但不编码（退出代码 0）。未给出 `cdalign=` 时，报告两次搜索的结果；给出 `cdalign=` 时，最后一行注明 “would encode”、“would ask for confirmation” 或 “would not encode”。 |
| `cdaccept` | 剩余时间差超出 −40 dB（第 4.3 节的确认区间）时，不经询问继续 |
| `cdedge=pad` | 针对只有母带在开头或结尾具有的声音：在 CD 层的该处添加数字静音，并完整保留母带（CD 层比给定的 CD 长） |
| `cdedge=cut` | 针对只有母带在开头或结尾具有的声音：将母带切至 CD 的长度；母带超出 CD 的声音不保留（CD 层与给定的 CD 完全相同） |
| `bits=24` | 对于最低 8 位并非全为零的 32 位母带：不经询问使用高 24 位（第 3.1 节） |
| `energy` | 按能量衡量保留比例（模式 `max`、`keep` 和 `keep20` 使用各自的度量） |
| `equal` | 仅使用等分（对半）切分 |
| `mem=<GB>` | 同时编码一对中的两层时的内存预算（见下文的内存计划） |
| `noise=<file>` | 将该标记文件（LAE Noise Marker，`plugins/lae_noise_marker/`）中标记的单元在频率层中编码为静音（第 8.6 节，[docs/NOISE.md](docs/NOISE.zh.md)）。该文件必须属于此母带。CD 频带中的标记只列出，不删除。 |
| `g`、`g=b`、`g=c`、`g=d` | 将频率层再编码一次，在被删除和静音的单元中抵消 G，即升采样后的 CD 层（第 8.6 节）。`g` = `g=d`（步长 1）；`g=c` 和 `g=b` 更粗、更小。可选；编码器会打印其开销。 |
| `resume` | 继续被中断的运行：已完成的步骤保留在工作文件夹 `<output>.tmp` 中，以相同选项并加 `resume` 再次编码同一母带时不再重复；否则从头开始运行。在写出 `<output>.part` 之后被中断的运行会再次写出该文件。使用 `cd=` 时，对齐会重新执行（结果相同），其后的步骤继续进行。输出与未中断运行的输出相同。 |
| `--tag=KEY=VALUE` | 标签，使用常见名称：`TITLE`、`ARTIST`、`ALBUM`、`ALBUMARTIST`、`DATE`、`GENRE`、`TRACKNUMBER`、`COMPOSER`、`COPYRIGHT`、`COMMENT` 等（UTF-8；同一名称可重复）。写为位于 `fmt ` 和 `data` 之间的 RIFF `LIST/INFO` 块和 `id3 ` 块（ID3v2.4）；CD 音频和 `LAE ` 块不变。 |
| `--cover=<image>` | 正面封面，JPEG 或 PNG，逐字节存储 |
| `--picture=<type>:<image>` | 其他任意图片，使用 ID3 / FLAC 图片类型（4 封底、5 小册子、6 介质、8 艺术家等） |
| `--form=wav`、`--form=flac` | 输出文件的形式（第 10.1 节）。必须与 `.wav` 或 `.flac` 的文件名一致；只有 `.lae` 可以自由选择。不写时，WAV 形式与以前版本的输出逐字节相同。 |
| `master2=<file>` … `master9=<file>` | 另加的母带，每个都对着与主体相同的 CD 层（由第一个母带派生，或用 `cd=` 给出的 CD）编成一个扩展包（[spec/lossy/SPEC.md](spec/lossy/SPEC.zh.md) 第 5.6 节）。每个都需要给出它在 CD 层上的位置 `master<n>align=<offset>`（写法同 `cdalign=`）；不给时报告两次搜索的结果，不写出任何文件。`master<n>accept` 和 `master<n>edge=pad|cut` 对该母带的作用与 `cdaccept`、`cdedge=` 相同。相对 CD 有速度漂移的母带（例如磁带的抖晃），没有手动给出的位置和确认就不继续。另加的母带目前还不能与 `noise=`、`resume` 或 `cdcheck` 同时使用。 |
| `master<n>name=<name>` | 包 n 的名称，在选择包的地方显示（UTF-8，最多 255 字节）；`master1name=` 给主体起名。名称只用于显示。不写时输出不变。 |
| `lae_enc tag` | 无需重新编码即可为已有 LAE 文件设置新标签：写出一个新文件，带有给定的标签（若未给出则不带标签）、相同的 CD 音频和相同的 `LAE ` 块，并检查两者逐字节相同；输入不变。 |

标签选项也可以不带前导 `--` 书写（`tag=`、`cover=`、`picture=`）。不使用这些选项时，输出不变。

编码器说明：

- 输出 WAV 的音频即为 CD 层；扩展位于 `LAE ` 块中。
- 无法识别的参数会报告为错误，编码器随即停止。
- 使用 `cd=` 时，编码器打印对齐结果。未给出 `cdalign=` 时，打印两次搜索的结果以及 `ALIGN_SUGGEST …` 行，退出代码为 1。给出 `cdalign=` 时，打印 `PLACE …`、`ALIGN_RECHECK …` 和 `PHASE t=<whole> phi=0 move=<move> offset=<offset>` 行。编码成功后，写出移动报告 `<output>.align.txt`（第 4.3 节）。
- `LAE ` 块的前 4 个字节标识格式：`LAE1` = LAEY（本层级），`LAE2` = LAES（无损层级，另有规范）。`lae_dec` 报告其识别出的格式：解码 `LAE1`；对于 `LAE2`，说明该文件为 LAES 文件，并指出应使用的工具。
- 编码器使用与逻辑核心数相同的线程数。环境变量 `PARTTHREADS` 可覆盖此值；`PARTTHREADS=1` 使整个编码器单线程运行。线程数不影响结果。
- **内存计划。**启动时，编码器读取一次物理内存，并根据音轨长度决定一对中的两层（位深 L 和 R、频率 M 和 S）是同时编码还是先后编码；它打印该计划（`memory plan: …`），并在整个编码过程中遵循该计划。仅在 64 位构建上、且在内存上限之内时才选择同时编码。默认上限为 min(1/2 × 物理内存, max(1/4 × 物理内存, 物理内存 − 28 GB))，使系统和其他程序保有空间：16 GB 机器上为 4 GB，32 GB 上为 8 GB，48 GB 上为 20 GB，64 GB 上为 32 GB。`mem=<GB>` 手动设置上限，例如在仅用于音频的 32 GB 机器上设为 `mem=20`。块长由上限决定，最长约 32 s：更长的块不会更快，只会占用更多内存。输出文件不依赖于计划、上限或块长。
- **分块编码（2026-10-29）。**编码器逐块读取母带并逐块编码音轨（每块约 32 s）；依赖整条音轨的决定（噪声底、音调和瞬态标记、平均能量、码长统计、模式比例）在编码任何块之前从所有块累积得到。输出与以前的整轨编码器逐字节相同。除每个单元的小记录（每个单元 3 字节）外，内存占用不随音轨长度增长：10 分钟、352.8 kHz 的母带约需 0.5 GB。大型中间数据写入磁盘上的工作文件夹（见下文的磁盘空间）。
- **磁盘空间（2026-10-30 实测；`lae_enc` 数据为 2026-11-05 实测）。**工作文件夹位于输出文件所在的驱动器上，并在结束时删除；除输出文件本身所需空间外，应在该驱动器上保留以下可用空间：
  - `lae_enc`（2026-11-05 起）：对于 10.16 分钟、352.8 kHz、32 位的母带，工作文件夹 `<output>.tmp` 最大达到 8.0 GB（352.8 kHz 下每分钟约 0.8 GB，176.4 kHz 下减半；以前为 13.2 GB）。使用 `g` 时约需多 15 %；使用 `cd=` 时约需多 5 %。编码器打印其工作文件夹达到的最大大小。
  - `laes enc`：对于同样的 10 分钟、四个母带，工作文件夹 `<output>.laes.tmp` 最大达到 38.6 GB（每分钟约 3.8 GB），使用 `--mem=20` 和 `--mem=2` 时相同。
  - `lae_enc` 在开始前检查可用空间；若运行期间磁盘已满，两个工具均干净地停止，且不留下输出文件。
- **长度。**上限为 v5 容器的上限：352.8 kHz 下约 94 分钟，192 kHz 下约 173 分钟，与是否使用 `cd=` 无关。
- **失败处理。**每项文件操作都经过检查。遇到磁盘已满、内部错误、内存不足或中断时，编码器停止并给出原因，不写入输出文件，并删除其临时文件。输出先写为 `<output>.part`，仅在回读并验证之后才重命名；若运行失败，已存在的同名文件保持不变。运行开始前会检查可用磁盘空间。

开发期间测得的编码器性能：

- **当前编码器（2026-10-29，分块；[docs/BUILD.md](docs/BUILD.zh.md) 第 5 节）。**在 32 线程的 Windows x64 机器上（模式 3，s1），10.16 分钟、352.8 kHz、32 位的母带（bits=24）用时 492 s，峰值内存为 475 MB；2026-10-24 的编码器处理该母带约需 12 GB，并写出逐字节相同的文件。352.8 kHz 下 60 s 的母带约需 0.48 GB（2026-10-24 的编码器：177 s，1.83 GB）。用时随长度线性增长；内存占用几乎不增长。
- **单个任务（2026-10-16；[docs/BUILD.md](docs/BUILD.zh.md) 第 5 节）。**在 Windows x64 上，以模式 3 和 16 个线程编码 352.8 kHz、40 s 的立体声母带，用时 113 s（约为实时速度的 0.35 倍）。峰值内存为 1.35 GB。
- **三个并行任务，每个使用 8 个线程（2026-10-17）。**编码 40 s 用时：
  - 352.8 kHz 下 160–260 s；
  - 176.4/192 kHz 下 90–140 s；
  - 96 kHz 下 45–65 s。

  单个任务的速度约快一倍。

### 14.3 解码

```
lae_dec <input.wav | input.flac | input.lae> <output.wav> [full | 16 | cd24] [output rate] [pack=<n>]
lae_udec info <file>
lae_udec dec <file> <output.wav> [--pick=<n> | --pick=<name> | --pick=<rate>:<bits> | --pick=master:<k> | --pick=name:<text> | --pick=pack:<k>]
lae_udec verify <file>
```

`lae_dec` 读取两种形式，按内容区分。`pack=<n>` 解码扩展包 n（默认 0 为主体）；文件中没有该包时拒绝。`lae_udec` 同样读取 LAEY 和 LAES 文件：`info` 列出文件提供的每一项及其编号、名称和该格式的各项检查；`dec` 解码一项，用编号或名称给出（例如 `full_352800`、`pack1_full_176400`、`master_2_352800_32`），不给 `--pick` 时解码母带采样率的 full 路径（LAEY）或文件的默认母带（LAES）；`verify` 执行该格式的全部检查，不写出任何内容。有多个 LAES 母带符合时显示勾选列表，与 `laes dec` 相同。

| 路径 | 使用的层 | 输出 |
|---|---|---|
| `full`（默认） | CD + 位深 + 频率 | 母带采样率或所选较低倍频程，24 位 |
| `16` | CD + 频率 | 母带采样率或所选较低倍频程，16 位（以 24 位字长输出） |
| `cd24` | CD + 位深 | 44.1/48 kHz，24 位 |

在 `full` 和 `16` 路径中，输出采样率可以是母带采样率，或低至基础采样率两倍的任一较低倍频程；其他采样率会被拒绝。所选倍频程以上的频率数据流既不读取也不解码。

解码器（`lae_dec`、`src/lae_decoder.h`）采用单线程流式处理（播放器库 `liblae` 另外提供第 13.6 节所述的多线程首次打开检查和追赶）：

- 每次解码一行根块（8 帧），并逐帧执行重叠相加；
- 重采样级通过短滑动窗口提取采样；
- 除输入数据外，其内存占用不随音轨长度增长。目前 CD 层和扩展块会完整读入内存。

`lae_dec` 使用第 13.6 节的解码器库。

开发期间测得的解码器性能：

- **单个任务（2026-10-16；[docs/BUILD.md](docs/BUILD.zh.md) 第 5 节）。**在 Windows x64 上，以 24 位路径解码 352.8 kHz、40 s 的文件，用时 2.8 s（约为实时速度的 14 倍）。峰值内存为 38 MB。
- **三个并行任务（2026-10-17）。**以 24 位路径解码 40 s 用时：
  - 352.8 kHz 下 3–5 s；
  - 176.4/192 kHz 下 2–3 s；
  - 96 kHz 下约 2 s。

### 14.4 示例

```
lae_enc master_352k.wav track_352k.wav                     # mode 3, scheme 1
lae_enc master_352k.wav track_352k_max.wav max s2          # smallest extension
lae_enc master_192k.wav track_192k.wav keep20 s1           # 20-bit depth layer
lae_enc master_96k.wav track_96k.wav 3 s1 cd=cd_48k.wav    # independent 48 kHz CD: reports both searches, writes nothing
lae_enc master_96k.wav track_96k.wav 3 s1 cd=cd_48k.wav cdalign=<offset>   # encode at the confirmed offset
lae_enc master_96k.wav track_96k.wav 3 s1 cd=cd_48k.wav cdalign=<offset> cdcheck   # check only
lae_dec track_352k.wav out_full.wav                        # 24 bit, 352.8 kHz
lae_dec track_352k.wav out_176k.wav full 176400            # 24 bit, one octave down
lae_dec track_352k.wav out_cd24.wav cd24                   # 24 bit, 44.1 kHz
```

### 14.5 整盘规划器

```
lae_enc plan <master.wav> [<master2.wav> …] <publisher.cue> <out dir> [cdalign=<p1>,<p2>,…] [cdaccept]
```

- `<publisher.cue>` 描述发行方的光盘（CUE 加 BIN 或 WAV）。
- 未给出 `cdalign=` 时，规划器在整个规划范围内执行两次搜索，打印各位置以及一行 `PLAN_SUGGEST whitened=<status>:<positions> plain=<status>:<positions>`，不写入任何内容，并以退出代码 1 退出。
- `cdalign=<p1>,<p2>,…` 为每一段给出一个值：该段 CD 帧 0 所在的母带采样位置，允许带小数；对于在 CD 上为数字静音的段，给出 `-`。
- `cdaccept` 确认落入确认区间的段。
- `<out dir>` 中的输出：每一段的 `TRACKnn.master.wav` 和 `TRACKnn.cd.wav`，以及报告 `plan.align.txt`。

从发行方光盘到 CD-Extra 光盘镜像的处理链（第 4.5 节）如下：

```
lae_enc plan album.wav publisher.cue planned                                  # report both searches; nothing written
lae_enc plan album.wav publisher.cue planned cdalign=<p1>,<p2>,…              # after confirmation: move and cut
lae_enc planned/TRACK01.master.wav planned/TRACK01.v5.wav 3 cd=planned/TRACK01.cd.wav cdalign=0   # each piece
lae_cdx image <image dir> planned/TRACK*.v5.wav layout=publisher.cue                  # CD-Extra image
```

模式（此处为 `3`）必须作为第三个参数给出。在规划器中以 `cdaccept` 确认的段，编码时也必须使用 `cdaccept`。

### 14.6 CD-Extra 封装与读取

`lae_cdx` 提供命令 `pack`、`split`、`repack`、`image`、`data`、`read`、`sim`、`selftest` 和 `test`。

**光盘镜像。**

```
lae_cdx image <image dir> <track1.v5.wav> <track2.v5.wav> … [label=<album>] [noext=<n>,<m>,…] [layout=<publisher.cue>]
              [album=<text>] [performer=<text>] [cdtitle=<n>:<text>,…] [cdperformer=<n>:<text>,…] [cdtext=off]
```

- `<image dir>` 必须是新目录或空目录。
- `label=` 设置数据区段的卷标。
- `noext=` 将所列音轨仅作为 CD 发布，例如在容量不足时。
- `layout=` 选择发行方光盘的独立 CD 布局（第 10.5 节）。
- **CD-Text**（专辑名、演唱者和曲名，由 CD 播放器显示）写为 `IMAGE.CUE` 和 `SESSION1.CUE` 中的 `TITLE` / `PERFORMER` 行，刻录软件将其写为 CD-Text。文字取自文件的标签（`TITLE`、`ARTIST`、`ALBUM`），在独立 CD 模式下取自发行方的 CUE，也取自选项 `album=`、`performer=`、`cdtitle=<n>:<text>` 和 `cdperformer=<n>:<text>`（多条音轨以逗号分隔）。CD-Text 仅接受可打印 ASCII：含中文或其他字符的文字绝不转换；工具会停止，逐项列出此类文字以及可用于输入它的选项（例如以拼音输入），且不写入任何内容。`cdtext=off` 不写入 CD-Text。AUDIO.BIN、DATA.ISO 和扩展文件不依赖于这些文字。

每个输入 v5 文件必须先通过解码器的全部检查。光盘镜像仅在闭环自检（第 10.9 节）之后交付。刻录说明 `BURN.TXT` 描述两种路线：路线 A 一次写入 `IMAGE.CUE`；路线 B 分两步写入，第二步使用 `lae_cdx data` 按驱动器实际报告的起始地址生成区段 2。

**读取。**

```
lae_cdx read <output dir> <disc>\LAE <rip>\RIP.CUE
```

第二个参数是包含扩展文件的文件夹，例如光盘数据区段中的 `LAE` 文件夹或其副本。最后一个参数是抓轨：整盘或逐轨抓轨，带或不带 CUE 表，可采用任意偏移制作。输出见第 10.8 节。

**其他命令。**命令 `pack`、`split` 和 `repack` 在 v5 WAV 文件、基础层文件和扩展文件之间转换（第 10.7 节）。`sim`、`selftest` 和 `test` 用于测试。其参数如下：

```
lae_cdx pack <v5.wav> <out.lax> [track=N]              # the extension file of one track
lae_cdx split <v5.wav> <base.wav> <ext.lax> [track=N]  # base-layer WAV + extension file
lae_cdx repack <base.wav> <ext.lax> <out.v5.wav>       # base-layer file + extension file -> v5 WAV
lae_cdx sim <imagedir> <outdir> <form> [offset=N] [pregap=1] [overread=N] [change=K] [slip=K]   # simulated rips (tests)
lae_cdx selftest                                       # known answers
lae_cdx test <fixturedir>                              # the test cases on the test discs
```

### 14.7 解码器库（liblae）

最简解码流程：

```c
char err[256];
lae_track* t = lae_open_file("track.wav", err, sizeof err);   /* UTF-8 path */
if (t && lae_selftest() && lae_start(t, LAE_ROUTE_FULL, 0, err, sizeof err) == 0) {
    int rate, bits; uint64_t frames;
    lae_output_format(t, &rate, &bits, &frames);
    int32_t buf[2 * 4096];
    int64_t n;
    while ((n = lae_read(t, buf, 4096)) > 0) { /* n interleaved stereo frames */ }
}
lae_close(t);
```

- `out_rate` 为 0 时，对路径 `16` 和 `full` 选择母带采样率，对 CD 和 `cd24` 路径选择基础采样率。
- `lae_seek(t, frame)` 以逐位精确的方式定位到某个输出帧（第 13.6 节）。
- `lae_stats` 返回限幅计数和数据流错误标志；`lae_stream_bytes` 返回已消耗的熵编码字节数。
- `lae_open_memory`、`lae_open_reader`、`lae_open_pair` 和 `lae_open_pair_files` 从内存、通过宿主读取回调，或从基础层及其扩展文件打开音轨。
- `lae_open_file` 也能打开 FLAC 形式。`lae_pack_count`、`lae_pack_info` 和 `lae_select_pack` 列出并选择文件的扩展包；选择对下一次 `lae_start` 生效。
- 要用同一个接口处理两种格式：`lae_probe_file` 按内容判断格式，`lae_any_open_file`、`lae_any_get_info`、`lae_any_get_choice`、`lae_any_start` 和 `lae_any_read` 打开文件、列出各项并解码其中一项（把 `src/lae_any.cpp`、`src/lae_api.cpp` 和 `src/laes_api.cpp` 一起链接）。
- 宿主要求 `lae_api_version()` 不低于其构建时所依据的版本。

完整接口的说明见 `src/lae_api.h`。

### 14.8 播放器插件

安装、设置和构建见各插件的 README（第 13.7 节）。每次发布都提供已构建的软件包：foobar2000 组件（`.fb2k-component`）、VLC 和 DirectShow 的安装程序，以及 zip 文件形式的 Kodi 附加组件。

构建需要不属于本仓库的第三方 SDK 或头文件：foobar2000 SDK、VLC 3.0 SDK 或 Kodi 的 `kodi-dev-kit` 头文件（[THIRD_PARTY.md](THIRD_PARTY.zh.md)）。LAE 解码器以其自身已验证的选项编译。

### 14.9 流媒体导出与数据光盘（LAES）

`laes_export`（`src/laes_export.cpp`）是面向流媒体服务的工具。服务方保存 LAES 文件，并向每位听众发送其所请求版本（核心母带、某个母带或某个采样率档位）的普通 FLAC 文件，因此听众无需 LAES 解码器。该工具只解码所请求的内容；它不会自行选择音质，也不跟踪听众的播放。

```
laes_export <in> --list
laes_export <in> <choice> <out.flac> [--from=<s>] [--len=<s>] [--index=<record>]
laes_export <in> <choice> --seg=<s> --dir=<folder> [--index=<record>]
```

母带的整轨导出在写入任何内容之前对照其 SHA-256 进行检查。每个输出都是普通 FLAC 文件，其采样与所选版本的采样完全相同，STREAMINFO 中带有其 MD5，并带有标识来源的标签（`LAES_CHOICE`、`LAES_FILE_SHA256`、`LAES_MASTER_SHA256`、`LAES_FIRST_FRAME`）。`laes_export` 包含编码器的 FLAC 写入器，其许可方式与编码器相同。

`tools/laes_disc.ps1`（Windows）利用 Windows 的光盘镜像服务（IMAPI2），为一张由 LAES 文件组成的专辑创建 DVD 或 BD 数据光盘镜像。该镜像包含原样的文件、一个播放列表和一个 SHA-256 列表。它是数据光盘，而非 BD-Video 或 DVD-Audio。任何能从光盘读取 FLAC 或 WAV 文件的播放器都会播放每个文件的核心母带；LAES 播放器则播放各母带。

```
powershell -ExecutionPolicy Bypass -File tools\laes_disc.ps1 -Album <folder> -Out <image.iso> -Disc DVD5|DVD9|BD25|BD50|BD100 [-Label <name>] [-Export <laes_export.exe>]
```

### 14.10 演示音频与验证

每次发布都包含作者的三部作品（*Grand*、*Tolled*、*LAES demo*）的各种形式，以及制作它们所用的母带，使任何人都能独立检验这些格式：

- **母带**，以 FLAC 文件提供：高解析度母带，以及 *Grand* 的 CD 母带，后者作为其两个 LAES 文件的核心母带。
- **LAES 文件**：每部作品各有一个 `.flac`（FLAC 形式，24 位核心母带）、一个 `.wav`（WAV 形式，16 位核心母带）和一个 `.lae`（FLAC 形式，16 位核心母带）。
- **LAEY**：三个 CD-Extra 光盘镜像（模式 `max`、`3` 和 `keep`，每个均含三部作品和 CD-Text），以及每条音轨的 LAEY 文件。
- **对比页面和编解码器对比报告**，附有测量结果。

**LAES。**用参考 `flac` 工具将每个 FLAC 母带解码为 WAV，然后与 LAES 文件比较：

```
flac -d Grand_352k8_32bit.flac
laes verify Grand_LAES.flac Grand_352k8_32bit.wav Grand_352k8_24bit.wav Grand_176k4_24bit.wav Grand_352k8_16bit.wav
```

对于每个与解码所得母带逐采样相等的母带，`laes verify` 报告 `IDENTICAL`。`laes dec` 将核心母带写为 `core.wav`；对于 `Grand_LAES.wav` 和 `Grand_LAES.lae`，它与 CD 母带 `Grand_44k1_16bit.flac` 逐采样相等。发布说明列出每个文件以及每个母带采样的 SHA-256。

**LAEY。**由母带派生的 LAEY 文件的 CD 层是编码器自身的派生结果；完整解码通过测量（`cmp_wav`）与母带比较。光盘镜像用 `lae_cdx read`（第 10.8 节）还原为 LAEY 文件，并将还原所得文件与随附的 LAEY 文件比较：二者的 `data` 块（CD 层）和 `LAE ` 块逐字节相同（标签不存储在光盘上）。

这些音频不受代码或文档许可证的约束：可以下载、收听，并用于测试和验证这些格式，不得用于其他用途（[AUDIO_LICENSE.md](AUDIO_LICENSE.zh.md)）。

### 15.2 现有技术

LAE Lossy 基于以下已公开技术构建：

- **MDCT。**教科书形式的 MDCT，其中 DCT-IV 通过带前、后旋转因子 $\exp(-i 2\pi (n + 1/8)/(2N))$ 的复数 FFT 计算。该旋转因子形式于 2002-10-28 发布在 FFmpeg `libavcodec/mdct.c` 中（提交哈希 `bb6f569`）[6]。
- **量化。**死区标量量化。
- **熵编码。**自适应二进制范围编码。
- **重采样。**半带 FIR 抽取和插值。
- **抖动。**TPDF 抖动。
- **立体声。**整数中/侧提升变换。

独立 CD 的对齐和封装使用以下已公开技术：

- **时延估计。**互相关以及带相位变换的广义互相关（GCC-PHAT）[12]，按由粗到精的方式应用。
- **插值。**采用 Kaiser 窗的带限加窗 sinc 插值 [13]。
- **分数延迟。**分数延迟滤波 [14]。
- **文件系统。**ISO 9660 [5] 及 Joliet 扩展 [15]。
- **光盘布局。**音频区段后接数据区段的 CD-Extra（Enhanced CD）多区段布局 [4]。
- **完整性。**MD5 消息摘要 [16]，按 FLAC STREAMINFO 块 [1] 的方式对音频采样计算；以及 CRC-32 [9]。
- **校验和。**窗口沿序列滑动时可增量更新的模加和。

## 17 局限与未来工作

### 17.1 格式与层级

- **LAE Lossless（LAES）。**规定于 [spec/lossless/SPEC.md](spec/lossless/SPEC.zh.md)（正式，有效载荷版本 2，2026-11-12）；参考工具为 `laes`。每个母带（16、24 或 32 位，采样率为基础采样率 × 1、2、4 或 8）及其各采样率档位都逐位重建。载体为 WAV 文件、FLAC 文件（ID 为 `LAE2` 的 APPLICATION 块）和 CD-Extra（扩展块类型 2）。一张 CD-Extra 光盘能容纳多少母带取决于专辑时长。大于 4 GiB 的文件使用 RF64 形式（spec/lossless/SPEC.md 第 7 节）。面向流媒体服务的流式导出已实现（`laes_export`，第 14.9 节）。
- **容器。**WAV 容器和 CD-Extra 封装均已实现。封装规范为草案，将在完成真实刻录的测量之后修订（第 17.3 节）。LAEY 的 `.lae` 文件布局仍未规定；LAES 的 `.lae` 文件是 FLAC 或 WAV 形式的 LAES 文件（`laes enc --form`）。
- **声道。**仅支持立体声。

### 17.2 编码器

- **使用独立 CD 时的内存。**使用 `cd=` 时，母带与其他母带一样按窗口从其文件中读取，但对齐搜索要在 CD 采样率下对整条音轨将 CD 与派生的基础层做互相关（其算法需要整条音轨）。这部分内存随 CD 长度增长：10 分钟约 2.4 GB（对 10 分钟母带及其 CD 运行 `cdcheck`：2.36 GB，以前为 7.5 GB）。整盘规划器将整个母带保存在内存中。
- **对齐搜索的局限。**对于短小或窄带材料，搜索可能失败，此时编码器停止。例如：单一持续音的 2 s 片段、以单个低音为主的 2–3 s 段落，以及完全位于约 1.2 kHz 以上、超出第 0 级频带的内容。此时用户通过 `cdalign=` 手动给出位置。
  - 被数字静音包围的严格周期性合成信号（音调、锯齿波、循环）可能在相差整整一个周期的位置被匹配。因此，每个位置都由用户确认（第 4.3 节）。
  - 当声音长于约 3.6 分钟时，搜索的第 0 级使用较低的采样率；计划对此加以改进。
  - 声音超过约 1 小时 55 分钟时，不执行搜索，必须通过 `cdalign=` 给出位置。
- **内容不同。**只有母带在开头或结尾具有的声音，仅在用户选择 `cdedge=pad` 或 `cdedge=cut` 之后才会编码（第 4.3 节，放置）。只有 CD 具有的声音会使编码器停止。规划器（`lae_enc plan`）遇到只有一方具有的声音时仍会停止。组合其他内容不同的材料属于未来工作。
- **噪声标记。**自 v5-2026-11-07 起已实现：LAE Noise Marker（`plugins/lae_noise_marker/`）提供频谱视图和短试听并写出标记文件，编码器将频率层中被标记的单元编码为 A 类（`noise=`，第 8.6 节；[docs/NOISE.md](docs/NOISE.zh.md)）。不使用 `noise=` 时，母带中的所有噪声都会保留。
- **闭环重新验证。**使用注入音调和点击声的标记闭环结构保留测试，将在 v5 上重新进行。
- **检测器文档。**瞬态检测器的统计特性将补充文档说明（第 7.4 节）。

### 17.4 已知工作限制

- **模式间隔。**在真实录音中，从 `max` 到 `keep` 相邻模式之间的大小变化中位数仅约为 0.3–3.6 %（第 11.4 节）。
- **最差播放时长。**在候选发布轮次中，352.8 kHz、方案 2、max、24 位路径的最差情况在 4 % 余量下比 40 分钟目标少 0.8 分钟。该结果基于不属于已发布数据的录音（第 11.5 节）。
- **被削波的 CD 内容。**16 位路径无法恢复 CD 层必须削波的内容（第 12.3 节）。
- **`full` 路径之外的泄漏。**频率层向 CD 频带的泄漏仅在 `full` 路径中得到补偿（第 6.5 节）。
- **高采样率下的 Synth。**Synth 信号在 176.4 和 352.8 kHz 下 24 位路径的 CD 频带误差（−96 和 −82 dBFS）明显差于 88.2 和 96 kHz 下的误差。其原因尚未分析（第 12.3 节）。
- **层交界处的量化误差（2026-11-05 发现，未修复）。**泄漏补偿（第 6.5 节）作用至截止频率以下 1150 Hz 处。从该处到截止频率，频率层编码的是真实内容，不得减去两次。因此，频率层自身在这一窄带中的量化误差会保留在输出中。
  - 它仅在截止频率附近存在强超声内容时出现，例如合成测试信号，因为强内容会使频率层的步长变大。
  - 在一个带有约 −24 dBFS 超声测试音的 352.8 kHz 测试母带上实测（截止频率 20.48 kHz）：
    - 19 至 20 kHz 的 1 kHz 频带误差为 −117 dBFS；
    - CD 频带其他各 1 kHz 频带的误差，使用 `keep` 时为 −129 至 −145 dBFS，使用 `keep20` 时为 −140 至 −154 dBFS；
    - `keep20` 和 `g` 不改变这一窄带。
  - 在整个 13 分钟测试母带上，解码后的 CD 频带误差在 802 秒中有 767 秒低于母带自身的 CD 频带电平。其余 35 秒是 CD 频带几乎为数字静音（−144 至 −159 dBFS）的测试段落；在这些段落中，误差为 −107 至 −143 dBFS。在音乐上未发现任何影响。
  - 修复只需更改编码器：在这一窄带中，只减去频率层的量化误差，而不减去其内容。格式和所有解码器都将保持不变。
  - 该修复尚未进行：没有含此类内容的真实录音可用，对音乐的收益为零，且更改后的编码器需要新的一致性测试向量。欢迎贡献。
  - 上述 Synth 结果可能出于同一原因；这一点尚未核实。
- **随移动带出的采样。**若母带的移动将采样带到没有任何段取用母带采样的位置（母带的最开头或最末尾，或只有母带具有的间隙），这些采样不会保留。规划器报告发生这种情况的位置以及涉及的采样数；用户可在该位置为母带和 CD 同时添加 44 个 CD 帧（约 1 ms）的数字静音（第 4.5 节）。
- **硬切母带。**声音一直延续到其第一个或最后一个采样的母带，在小数移动之后，CD 层两端会保留若干帧数字静音（第 4.3 节）。
- **向前定位。**v5 未定义随机访问点，因此该库在首次遇到一个文件时检查一次，并将检查点保存在播放器自身的文件夹中（第 13.6 节）。首次打开在 8 核上每 10 分钟约需 2.2 s，在 4 核上约需 3.2 s；核心更少的机器尚未测量。设置 `LAE_INDEX_DIR=off` 或没有可用文件夹时，每次打开都会重新检查该文件。
- **采样率系列。**编码器不执行有理数比例重采样。
  - 48 kHz 系列母带与 48 kHz 基础层组合。将其与 44.1 kHz CD 组合仍属于母带制作工作。
  - 48 kHz 基础层面向 DVD、蓝光和文件分发；CD-Extra 仅适用于 44.1 kHz 系列。
