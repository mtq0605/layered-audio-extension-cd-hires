## 摘要

LAE 允许单个文件同时承载高解析度母带（最高 24 位、最高 352.8/384 kHz）和 16 位 CD 层。所有现有 WAV 播放器都能逐位重现 CD 层。

- **44.1 kHz 系列。**用工具 `lae_cdx` 做 CD-Extra 封装（目前生成 CD-Extra 光盘映像）。光盘将 CD 层原样放在光盘的音频会话中，将扩展放在数据会话中，因此所有 CD 播放器都能播放 CD 层。
- **48 kHz 系列（96/192/384 kHz 母带）。**这些母带具有 48 kHz 基础层，面向 DVD、蓝光和文件分发。
- **文件与数据流。**在 CD 之外，音轨也可以作为基础层文件（FLAC 或 WAV）分发，并在其旁边附带一个扩展文件（规范已定义；`lae_cdx` 目前读取 WAV 基础层文件）。

高解析度信息完全存储在 PCM 信号之外，作为单独的扩展。扩展采用三级金字塔组织：

- **CD 层**：由母带确定性地生成，或独立提供；
- **位深层**：在基础采样率下，将 CD 频带从 16 位细化到约 18 位有效精度（默认值）；
- **频率层**：将 CD 截止频率以上的全部内容编码为每个倍频程一个 MDCT 流。

解码完全通过时域加法完成。共有四种解码路径：

- 仅 CD；
- CD 加频率层；
- CD 加位深层；
- 三层全部解码。

扩展主要使用三种工具编码：

- 形状自适应时频分区；
- 显式精度等级，其量化步长绝不会粗于一个 16 位 LSB；
- 自适应二进制范围编码器。

解码器在不同平台上具有确定性。重采样滤波器使用整数运算；逆 MDCT 则在严格的 IEEE-754 binary64 算术下按固定顺序计算。启动自检会对此进行检查。

在默认工作点下，真实录音中完整 24 位路径的 CD 频带误差中位数约为 −111 dBFS。可选的 20 位位深层（`keep20`）可将误差降至约 −124 dBFS。

扩展大小是在开发期间（2026-10-16）使用 v5 候选发布版测得的（第 11.2 节）。对于真实录音，在模式 3 下，扩展大小中位数约为未压缩 CD 层大小的 0.24 至 1.23 倍，具体取决于采样率和方案。

编码器可以将母带与独立制作的 CD 组合。其处理方式如下：

- 通过波形比较，相对于母带定位 CD；
- 在固定的三处核对波形残差；
- 母带在超精度下位移到 CD 的位置，而绝不移动 CD：整数部分直接放置，不到一个采样的部分按带限插值移动；波形不变，误差低于 −140 dBFS，在物理发声极限以下，现代录音很难达到这个精度。

在编码任何内容之前，每个位置都须经用户确认。整盘规划器将同一流程应用于发行方的完整光盘。结果是普通的容器 v5 文件，任何 v5 解码器无需修改即可对其解码。

`lae_cdx` 的读取端可以从以任意驱动器偏移翻录的结果中恢复原始 LAE 文件。每条音轨单独定位，这一轨全部 CD 采样的 MD5 一致时才接受该音轨。带有 C 接口 `liblae` 的解码器库提供逐位精确的快速定位；基于该库构建的 foobar2000 组件可以最高以母带采样率播放 LAE 文件。

作者尚未、也不会就 LAE 提交任何专利申请，并承诺不对本规范的实现主张专利权（第 15 节）。

## 1 引言

### 1.1 问题

越来越多的录音以 24 位和 88.2 至 384 kHz 的采样率制作母带。尽管如此，CD（16 位、44.1 kHz）仍然是可在各种设备上播放的格式：旧式播放器、汽车音响、所有软件播放器以及实体产品。

如今，想要同时提供两者的发行方有两个选择：

- 分发两种独立产品；
- 采用一种旧设备无法读取其高解析度内容的格式。

一些现有方案会修改 PCM 信号本身，以便承载附加数据。

LAE 在以下约束下解决这一问题：**CD 层必须是未经改动的普通 CD。**其他所有内容均作为附加信息存储在其旁边。

### 1.2 目标

1. **逐位精确的 CD 层。**16 位 CD 层按原样存储。
   - 在 44.1 kHz 系列中，该层的采样率为 44.1 kHz，可由任何 CD、WAV 或 FLAC 播放器播放。
   - 48 kHz 系列具有 48 kHz 基础层（CD 频带为 0–24 kHz），面向 DVD、蓝光和文件分发。
   - CD-Extra 仅适用于 44.1 kHz 系列。

2. **扩展数据位于 PCM 之外。**扩展可恢复至 24 位，以及最高 352.8 kHz（44.1 kHz 系列）或 384 kHz（48 kHz 系列）。扩展量随母带中真实信息的多少而变化，因此信息越多的母带会生成越大的文件。

3. **降低精度，不丢弃内容（LAE Lossy）。**LAE Lossy 可以降低内容的表示精度，但不得丢弃有意义的内容。
   - 持续音、瞬态、乐音、谐波和混响尾音都会保留。
   - 母带中的噪声被视为音乐的一部分，并像其他内容一样编码。这包括噪声底、不可闻的随机噪声和有意添加的噪声。
   - 只有可以确定不承载信息的内容才会自动置零：数字静音，以及低于一个 24 位 LSB 的舍入级残留。

   计划中的导出界面将允许用户标记要移除的噪声区域（第 17.2 节）。

4. **支持两种采样率系列。**同一算法适用于 44.1 kHz 和 48 kHz 系列。只有倍频程采样率等级固定（88.2/176.4/352.8 kHz 和 96/192/384 kHz）；其他内容均自适应。

5. **确定性解码。**所有符合规范的解码器在任何平台上都生成逐字节相同的输出。

6. **开放性。**该格式依据开放许可证发布（第 16 节）。作者作出不主张专利权的承诺（第 15 节）。

**非目标。**

- 对可听频带进行感知编码。可听频带由 CD 层和以波形编码的细化层组成。
- 由编码器规划光盘容量。编码器只负责压缩。发行方选择方案、模式和输出范围，并负责判断结果是否适合目标介质。打包工具 `lae_cdx` 会检查光盘映像能否容纳；若不能容纳，则停止处理。它绝不会自动删除任何音轨或倍频程（第 10.9 节）。

### 1.3 主要特性

- **金字塔分解。**信号被分解为 CD、位深和频率目标，再通过普通时域加法重新组合。CD 层可以由母带生成，也可以独立提供。
- **独立 CD 的对齐。**所提供的 CD 通过两次波形搜索相对于母带定位，一次经过白化，一次不经白化。随后在三个块上核对波形残差，其中包括漂移检查。然后母带在超精度下位移到 CD 的时间轴上（整数部分直接放置，不到一个采样的部分按带限插值移动；波形不变，误差低于 −140 dBFS），CD 的采样保持不变。每个位置都由用户确认（第 4.3 节）。
- **整盘规划器。**`lae_enc plan` 将以一个或多个文件形式给出的母带与发行方的完整光盘进行匹配。它先移动母带，再在 CD 的音轨标记处切分母带（第 4.5 节）。
- **按录音确定频率层起点。**频率层从实际 CD 检测出的截止频率开始，而不是从 CD 奈奎斯特频率的固定比例处开始。
- **仅由编码器进行泄漏补偿。**频率层的量化噪声可能经 MDCT 窗泄漏到 CD 频带。位深层会抵消这种泄漏，解码器无需为此作任何改动。
- **精度规则及 16 位下限保障。**显式精度等级（B/C/D）根据每个叶节点的指数定义，并受三条精度规则约束。在这三条规则下，量化步长都不会粗于一个 16 位 LSB。
- **全局码率—精度搜索。**针对整条音轨的搜索会选择形状自适应二进制时频分区。该搜索在满足最高精度内容保留比例的前提下，使总字节数最小。
- **确定性与一致性。**解码过程在严格 IEEE-754 算术下具有确定性。启动自检指纹和 16 个一致性向量用于检查这一点。
- **CD-Extra 封装与读取。**`lae_cdx` 写入双会话 CD-Extra 映像，并能读回其翻录结果。每条音轨按内容定位，这一轨全部 CD 采样的 MD5 一致时才被接受。交付映像之前会运行闭环自检（第 10.5–10.9 节）。
- **解码器库与播放器组件。**解码器以带有 C 接口 `liblae` 的库形式提供。该库提供逐位精确的快速定位。foobar2000 组件 `foo_input_lae` 基于该库构建（第 13.6 和 13.7 节）。
- **开放许可证和不主张专利权的承诺。**规范、参考解码器和参考编码器均依据第 16 节所列许可证发布。

## 2 相关工作

**FLAC** [1] 是一种无损音频格式。

- LAE 的 CD 层是普通 PCM 信号，因此可以装入普通 FLAC 流。封装规范只在 FLAC 中承载 CD 层（基础层）；扩展位于其旁边的单独扩展文件中，绝不放入 FLAC 文件内部（第 10.7 节）。
- 对于 16 位立体声音频，封装规范中整轨 MD5 的定义方式与 FLAC STREAMINFO 块中的音频 MD5 相同。
- LAE 编码器有两个方面受到 FLAC 启发：
  - 工作模式像压缩等级一样编号；
  - 分区搜索依据实际编码大小选择分区，借鉴了 FLAC 的二次幂分区方式。

**MPEG-4 Audio BSAC 和可扩展无损编码（SLS）** [2] 是较早的分层音频编码实例。

**CD-Extra** [4]（1995 年的 Blue Book）定义了多会话光盘：先是音频会话（Red Book [3]），再是数据会话。

- LAE 将 CD-Extra 用作 44.1 kHz 系列的实体光盘容器（第 10.5 节）。
- CD 层原样放在音频会话中，扩展文件放在数据会话中，位于带 Joliet 扩展 [15] 的 ISO 9660 [5] 文件系统内。
- 使用“CD EXTRA”标志需要许可证。

**时延估计与分数延迟。**独立 CD 的对齐（第 4.3 节）使用两种形式的互相关：一种为普通互相关，另一种经广义互相关的相位变换 [12] 白化。母带的小数移动使用带限加窗 sinc 插值 [13]，这是分数延迟滤波器的一种标准形式 [14]。

## 3 系统概述

### 3.1 符号说明

全文使用以下符号。

| 符号 | 含义 |
|---|---|
| $R_0$ | 基础采样率，44.1 kHz 或 48 kHz。$B = R_0/2$ 为基础奈奎斯特频率。 |
| $R = R_0 \cdot 2^n$ | 母带采样率，$n \in \lbrace 1, 2, 3 \rbrace$（88.2/176.4/352.8 kHz 或 96/192/384 kHz）。 |
| $x$ | 采样率为 $R$ 的母带信号，以 24 位整数单位表示。 |
| $\mathcal{D}$、$\mathcal{U}$ | 抽取器和插值器：使用相同系数表的 $n$ 级级联半带处理级。 |
| $b = \mathcal{D}(x)$ | 采样率为 $R_0$ 的 24 位基础信号。该信号*不会*被削波至满量程。 |
| $c$ | 16 位 CD 信号（CD16）。 |
| $d$ | 再生成的 TPDF 抖动。仅在设置了抖动标志的块中非零。 |
| $v = 256 c - d$ | 以 24 位单位表示的 CD 路径。任何解码器都可以仅根据 CD 层和抖动标志计算它。 |
| $f_c$ | 检测出的 CD 截止频率。 |

输入母带必须是立体声整数 PCM WAV 文件，每个采样为 16、24 或 32 位。

容器 v5 最多承载 24 位。对于 32 位输入，编码器按以下方式处理：

- 若每个采样的最低 8 位均为零，则编码高 24 位，不会损失任何信息；
- 否则，编码器会说明问题并提供两种选择：结束任务且不写入任何文件；或使用高 24 位，此时最终报告会注明这一点；
- 在交互式控制台中，编码器会询问用户。由脚本调用时无人可以作答，因此除非给出选项 `bits=24`，否则编码器会结束任务。

### 3.2 金字塔

编码器会形成两个目标：

$$T = \mathrm{LP}_{f_c}\left(b - v\right) \qquad \text{(位深目标，基础采样率)}$$

$$F = x - \mathcal{U}\left(v + T\right) \qquad \text{(频率目标，母带采样率)}$$

$T$ 和 $F$ 仅存在于编码器中。

- 位深层承载 $T$ 的编码近似值 $\hat T$。在 v5 中，$\hat T$ 还包含第 6.5 节所述的泄漏补偿项。
- 频率层承载 $F$ 的编码近似值 $\hat F$。

按构造可知，$x = \mathcal{U}(v + T) + F$：这三部分通过时域加法即可还原母带。

```
                                master x  (rate R = R0 * 2^n, 24 bit)
                                   |
                     +-------------+----------------------------+
                     |                                          |
            half-band decimation D (n stages)                   |
                     |                                          |
            24-bit base b (rate R0, unclipped)                  |
                     |                                          |
     +---------------+------------------+                       |
     |                                  |                       |
  TPDF dither (flagged blocks only),    |                       |
  round, clip to 16 bit                 |                       |
     |                                  |                       |
  CD16 c ------> v = 256c - d           |                       |
     |               |                  |                       |
     |               +----> T = LP_fc(b - v) ---> depth layer   |
     |               |                  (L/R, base rate, MDCT)  |
     |               |                                          |
     |               +--> U(v + T) -----------> F = x - U(v+T) -+
     |                                               |
     |                                       frequency layer
     |                               (M/S, master rate, MDCT,
     |                                one stream per octave)
     v
  WAV "data" chunk (playable everywhere)    "LAE " chunk (extension)
```

### 3.3 分层

| 层 | 内容 | 频带 | 采样率 | 精度（高电平块） | 播放设备 |
|---|---|---|---|---|---|
| CD | WAV `data` 块中的 16 位 PCM | 0–22.05 kHz（48 kHz 系列：0–24 kHz） | 44.1 / 48 kHz | 16 位；仅在需要时使用 TPDF 抖动，数字静音绝不加抖动 | 任意播放器 |
| 位深 | 相对于 CD 路径的 24 位基础残差；每个声道（L、R）各一条流 | 0–22.05 kHz（48 kHz 系列：0–24 kHz） | 44.1 / 48 kHz | 默认 B18/C20/D24；keep20 为 B20/C22/D24 | LAE 解码器 |
| 频率 | CD 截止频率以上的所有内容；M/S 声道；每个声道、每个倍频程片段一条流 | 从 $f_c$ 以下 1 kHz 到母带奈奎斯特频率 | 母带采样率 | 方案 1：B18/C20/D24；方案 2：B16/C20/D24 | LAE 解码器 |

位深层和频率层彼此独立。二者共同构成完整的高解析度信号。输出分辨率取决于解码了其中哪些层。

### 3.4 解码路径

| 路径（`lae_dec` 选项） | 使用的层 | 输出 | 重建结果 |
|---|---|---|---|
| CD（任意播放器） | CD | 44.1/48 kHz，16 位 | $c$ |
| `16` | CD + 频率 | 母带采样率或较低倍频程；CD 频带为 16 位精度 | $\mathcal{U}(v) + \hat F$ |
| `cd24` | CD + 位深 | 44.1/48 kHz，24 位 | $v + \hat T$ |
| `full`（默认） | CD + 位深 + 频率 | 母带采样率或较低倍频程，24 位 | $\mathcal{U}(v + \hat T) + \hat F$ |

```
           CD (16 bit, R0) ............................ any player
            |
            +--- + depth layer ----------------------> cd24 (24 bit, R0)
            |
            +--- + frequency layer ------------------> 16-bit route (R0*2^k)
            |
            +--- + depth layer + frequency layer ----> full (24 bit, R0*2^k)
```

输出分辨率沿两个互相独立的轴选择：

- 输出倍频程：88.2/176.4/352.8 kHz 或 96/192/384 kHz；
- 位深：16 或 24 位。

三种解码路径都会写入 24 位 PCM 文件。16 位路径在精度上不同，文件格式则相同（[SPEC.md](spec/lossy/SPEC.md)，第 11.8 节）。

解码器库 `liblae`（第 13.6 节）和 foobar2000 组件（第 13.7 节）提供同样的四种路径。

工作模式在编码时固定；解码器在播放时不提供模式选择。

选择较低输出倍频程时，解码器会：

- 不读取也不解码该倍频程以上的频率层数据流；
- 使用生成 CD 层时所用的相同半带滤波器，将结果降至所选采样率。

最终输出中超出 24 位范围的采样会被硬限幅（第 12.4 节）。

## 4 CD 层

### 4.1 生成的 CD

默认情况下，编码器通过以下四个步骤从母带确定性地生成 CD 层。

1. **抽取。**通过 $n$ 级级联的二倍抽取半带处理级，将母带从 $R$ 降至 $R_0$。
   - 滤波器是整数 FIR 滤波器，具有固定系数表，存储在参考源码（`src/halfband.h`）中。
   - 滤波器为对称、奇数长度（零相位）半带滤波器，系数采用 Q31 格式。只存储奇数抽头。
   - 中心抽头为 $2^{30}$，每张表中的已存储抽头之和恰为 $2^{29}$，因此直流增益恰为 1。
   - 累加使用 64 位整数，每个输出采样舍入一次（[SPEC.md](spec/lossy/SPEC.md)，第 10 节）。
   - 抽取后的输出采样 $m$ 以输入采样 $2m$ 为中心。信号范围之外的输入索引围绕端点采样镜像扩展（[SPEC.md](spec/lossy/SPEC.md)，第 10.2 和 10.4 节）。
   - 插值器 $\mathcal{U}$ 使用相同的系数表。
   - 开发期间的测量显示，半带级联在 0 至 19.8 kHz 通带内的偏差低于 −120 dB。

2. **不进行中间削波。**任何处理级都不会将 24 位基础信号 $b$ 削波至满量程。高于满量程的带限过冲（例如方波和强瞬态产生的过冲）会保留在 $b$ 中，并由位深目标 $T$ 承载。

3. **自适应 TPDF 抖动。**仅在录音自身噪声低于 0.5 LSB16 的块中添加抖动。
   - 抖动采用 TPDF，由两个 xorshift32 生成器产生，每个声道一个。左声道生成器的种子为 `0x12345678`，右声道为 `0xB06BD031`。这些种子是格式常量，不会传输。
   - 每个生成器针对每个基础采样率采样前进两次，包括未加抖动块中的采样。
   - 两次抽取的高 12 位 $u_1$ 和 $u_2$ 产生抖动值 $u_1 + u_2 - 4096$，单位为 1/16 LSB24，约为 ±1 LSB16（[SPEC.md](spec/lossy/SPEC.md)，第 11.2 节）。
   - 不使用噪声整形。
   - 完全为零的块（数字静音）绝不添加抖动，因此母带中的数字静音在 CD 层中仍然是精确的零。

4. **舍入和削波。**将加过抖动的基础信号舍入为 16 位，并削波至 16 位范围。这是 CD 路径中唯一发生削波的位置。

### 4.2 抖动标志与再生成的抖动

容器针对每 4096 个基础采样率采样，为每个声道存储一个标志字节。解码器按以下步骤处理：

1. 根据固定种子重新生成抖动序列；
2. 在带有标志的块中应用抖动；
3. 计算 $v = 256 c - d$。

因此，所有解码器都能仅依据 CD 层和标志精确得知 CD 路径。抖动值本身不会传输。

### 4.3 独立 CD

使用编码器选项 `cd=<file>` 时，现有 CD 母带会逐位成为 CD 层。

- **格式。**必须以 16 位立体声 WAV 形式提供 CD，其采样率为母带所属系列的基础采样率：44.1 kHz 系列为 44.1 kHz，48 kHz 系列为 48 kHz。
- **编码。**扩展对放置在 CD 时间轴上的母带减去 CD 路径的差值进行编码。第 3.2 节的金字塔保持不变；唯一变化是 $c$ 不再由编码器生成。
- **抖动。**编码器不会对提供的 CD 添加抖动，因此此模式下所有抖动标志均为 0。
- **电平与均衡。**编码器既不会对 CD 做均衡，也不会补偿其增益。
- **大小。**CD 越接近母带，扩展越小。单独进行过限幅、均衡或电平调整的 CD 会导致扩展显著增大。
- **截止频率检测。**在此模式下，根据母带与 CD 之间的相干性检测截止频率，因此检测不受电平差异影响（第 6.3 节）。

由发行方决定将哪一版 CD 与哪一版母带组合。

48 kHz 系列的母带只有经过重采样后才能与 44.1 kHz CD 组合。这属于母带制作工作：编码器不执行有理数比例重采样。

**对齐：目的与原理。**发行方的 CD 很少与母带按采样对齐，可能存在以下差异：

- 开始时间不同；
- 偏移不足一个母带采样的小数部分；
- 两端的数字静音多于或少于母带。

任何残留的偏移都会在扩展中表现为母带与 CD 之间的差异，并改变扩展的大小。因此，给出 `cd=` 时，编码器执行以下步骤：

1. 在母带中定位 CD；
2. 在固定的三处核对波形残差；
3. 测量剩余的母带采样小数部分；
4. 将**母带**放置在 CD 的时间轴上，并按该小数部分移动母带。

CD 的采样绝不会被更改，CD 层保持逐位精确。由于母带在生成各层之前就已移动，结果是普通的容器 v5 文件。文件中不存储任何与对齐相关的信息，任何 v5 解码器无需修改即可对其解码；解码得到的信号是移动后的母带。

**搜索。**搜索只比较波形，按固定的由粗到精级联进行。

1. **第 0 级。**CD 的声音在 CD 采样率的 1/16 处被分为两半。用互相关扫描整个允许范围，并对峰值周围的范围再扫描一次。
2. **后续各级。**每一级将块减半、采样率加倍，并在上一级峰值周围的固定小范围内搜索：第一个这样的级别为 ±32 个本级采样，其他级别为 ±8 个。
3. **最后一级。**最后一级在母带采样率下，通过波形残差比较与上一级峰值相距不超过两个 CD 采样的各个整数母带采样位置。

若峰值落在某一级搜索范围的边缘，搜索以“alignment failed”结束。这种峰值表明 CD 属于其他版本、经过剪辑或速度不同。

**两次搜索。**搜索运行两次：

- 一次使用白化互相关（带相位变换的广义互相关，GCC-PHAT [12]）；
- 一次使用普通的、不加权的能量归一化互相关。

白化并不总是更好的选择。例如，在一段缓慢的 79–182 Hz 扫频的 2 s 片段上，只有普通相关找到了位置：白化搜索失败，而普通搜索报告的结果为 +0.3000226 个母带采样，真实偏移为 +0.3。

**检查。**在 CD 声音的三个块上核对波形残差，三个块使用相同的偏移。

- **声音时长为 40 s 或以上。**使用三个 5 s 块：第一个块在首个声音之后 10 s 开始，最后一个块在最后一个声音之前 10 s 结束，第三个块居中。
- **声音时长为 3 至 40 s。**取每三分之一段的中部，最长 5 s。
- **声音时长不足 3 s。**对整段声音进行一次检查。

对于每个块，编码器计算两个量：

- 每个声道采用一个最小二乘增益之后的波形残差；
- 相对于该段唯一的小数最佳拟合的剩余时间差。

残差高于 −3 dB 的块视为不匹配。

**漂移检查。**每个块还会在偏移两侧各两个 CD 采样处进行比较，增益保持不变。若任一位置拟合更好，则表明速度不同、经过剪辑或属于另一次录制，编码器随即停止。该比较只会使编码器停止，绝不会移动任何内容。

阈值定义在 `src/cd_align.cpp`（结构体 `Th`）中。

**区间。**剩余时间差的电平决定处理结果。

| 剩余时间差 | 结果 |
|---|---|
| ≤ −40 dB | 已对齐 |
| −40 至 −33 dB | 需要确认 |
| 高于 −33 dB | 需要确认，并警告文件可能显著增大 |
| 无拟合（某个核对块的残差高于 −3 dB（相对 CD）；漂移，即向两侧各偏两个 CD 采样反而更合；或未找到位置） | 绝不编码；不可覆盖 |

确认方式如下：

- 在交互式控制台中，编码器询问是结束任务还是继续；
- 由脚本调用时，除非给出选项 `cdaccept`，否则编码器停止；
- 经确认后继续时，输出的最后一行注明 `CONTINUED AFTER CONFIRMATION`。

声道互换或极性反转需要用户确认，与 −40 … −33 dB 那一档相同（`cdaccept`）；确认后扩展会对差异编码，因而显著增大。

**由用户确认位置。**每个位置都由用户确认。未给出选项 `cdalign=` 时，编码器按以下步骤处理：

1. 执行两次搜索；
2. 对于每个结果，测量小数部分，尝试包括移动在内的放置，并完全按照手动给出偏移时的方式再次检查；
3. 打印两个结果，每个结果为“aligned at `cdalign=<offset>`”“not aligned within the limit at …”或“alignment failed …”之一；
4. 打印一行 `ALIGN_SUGGEST whitened=<status>:<offset> plain=<status>:<offset>`；
5. 不写入任何内容即停止，退出代码为 1（使用 `cdcheck` 时退出代码为 0）。

编码器不会比较两个结果，也不会在二者之间作出选择；由用户作出选择，然后使用 `cdalign=<offset>` 再次运行编码器。之所以需要用户确认，是因为严格周期性的信号可能在相差一个完整周期的位置上被匹配（第 17.2 节）。

**手动给出的偏移。**使用 `cdalign=<offset>` 时，跳过搜索。

- 偏移以母带采样为单位；正值表示 CD 开始得较晚。偏移可以是整数，也可以带最多 9 位小数，例如 `cdalign=3.4999828`。整数表示小数部分为 0。
- 编码器在最接近的整数位置进行检查，按给定值放置并移动母带，然后再次检查。
- 若附近存在更好的整数位置，确认提示会报告剩余的偏移，并建议一个修正值。
- 将编码器打印的偏移再次给出，会得到相同的文件；这一点已逐字节测试。

**小数部分的测量。**找到整数偏移 $t$ 之后，编码器在相同的检查块上对每一段测量一次小数部分。

- 下降过程是固定的：步长依次为 1/8、1/16、…… 个母带采样，每个步长取三个点，直至 $2^{-22}$ 个 CD 采样的单位。
- 测得的小数部分最多为半个母带采样。

**放置。**母带按以下方式放置在 CD 的时间轴上。

- **整数采样。**母带按整数个母带采样移动，且只跨越数字静音（全零采样）移动。
- **长度匹配。**开头较长的一方先播放，结尾较长的一方后结束。较短的一方补充数字静音。任何一方都不会丢失非静音采样。
- **亚采样超前。**若母带的声音比 CD 的声音早开始不到一个 CD 采样，则在 CD 层前面加入一个 CD 帧的数字静音。CD 自身的采样保持不变。
- **不匹配的声音。**仅一方具有且长度为一个 CD 采样或以上的声音不受支持，编码器会停止并给出相应的时间范围。

**母带的移动。**按整数偏移 $t$ 放置之后，编码器将母带一次性移动 `move` 个母带采样，$|\mathrm{move}| \le 0.5$。

- 每个输出采样 $i$ 是已放置母带在 $i + \mathrm{move}$ 处的带限值。它由一个 128 抽头的 Kaiser 窗 sinc 插值器（$\beta = 10$）[13][14] 计算；该插值器的抽头由 `move` 通过闭式公式一次性计算得到。
- 母带之外的采样视为数字静音。
- 结果舍入为 24 位。超过满量程的采样会被硬削波，并给出警告和计数。

总偏移为 $t - \mathrm{move}$。随后照常生成各层，并在偏移 0 处以相同的区间再次检查。编码器打印一行 `PHASE t=<whole> phi=0 move=<move> offset=<offset>`；字段 `phi` 始终为 0。

**移动前后的数字静音。**小数移动会将几十个采样带到母带第一个和最后一个采样之外。这些采样按以下方式保留：

1. 移动之前，在已放置母带和 CD 层的两端各添加 128 个 CD 帧的数字静音；
2. 移动之后，在每一端只将仍为数字静音的部分重新移除，最多移除所添加的帧，且绝不移除所给 CD 的帧。

其效果取决于母带两端的情况：

- 以数字静音开始和结束的母带，所得文件与不执行此步骤时编码的文件逐字节相同；
- 在声音中途被截断的母带，其 CD 层两端会保留若干帧数字静音：352.8 kHz 时为 8 帧，88.2 kHz 时最多 32 帧。

此步骤不存储任何信息，解码器也绝不丢弃任何采样。保留此类帧时，截止频率检测结果可能略有变化。在两个开发片段中，扩展分别变化了 +1.5% 和 −0.4%，解码质量不变。

**移动报告。**编码成功后，编码器会在输出文件旁写入 `<output>.align.txt`。该文件是供用户存档的纯文本文件，内容包括：

- 整数偏移；
- 移动的小数部分，以母带采样和微秒表示；
- 总偏移；
- 哪一方开始得较早；
- 添加和移除的数字静音；
- 移动之后的检查结果。

没有任何程序读取该报告。它不属于 LAE 文件，也不属于光盘。

### 4.4 逐位精确性

CD 层就是输出 WAV 文件的音频内容。因此，它与生成的 CD 逐字节相同。对于独立 CD，CD 层原样包含所提供 CD 的采样；在第 4.3 节所述情况下，其两端还可能带有若干帧数字静音。

在写入任何文件之前，编码器会重新解码每一层和每个片段，并验证所有系数平面都匹配。编码之后，编码器还会完整解码最终文件，不会写出任何无法解码的文件。

如果 CD 音频长度与扩展块不一致（第 10.4 节），解码器会拒绝该文件。若 CD 音频被修改但长度不变，则不会检测到这种更改（[SPEC.md](spec/lossy/SPEC.md)，第 3.2 节）。在 WAV 文件之外，封装规范通过整轨 MD5 保护 CD 音频（第 10.6 节）。

### 4.5 整盘规划器

规划器 `lae_enc plan` 将母带与发行方的完整光盘组合。它以 CUE 表单加 BIN 或 WAV 音频的形式读取发行方的光盘。母带可以以一个文件或多个文件的形式给出。

**操作顺序。**规划器按以下固定顺序处理：

1. **拼接。**多个母带文件按给定顺序逐采样拼接。不使用这些文件自身的分割点；若这些分割点与 CD 的不同，规划器会打印“the master is re-split at the CD's positions”。
2. **检查静音与覆盖。**在任何移动之前，对原样的母带检查静音和覆盖情况。
3. **对齐。**每一段（即 CD 的每条音轨）在母带中围绕其预期位置、在 ± max(60 s, 段长度) 范围内搜索。在 CD 上为数字静音的段不进行搜索，其对应的母带范围必须为数字静音。在各段之间，母带与 CD 只能在数字静音上存在差异。
4. **确认。**用户确认每个位置。
5. **移动。**每个组（见下文）在拼接后的母带内移动。
6. **切分。**之后才在 CD 的音轨标记处切分母带。

**组。**母带范围在 CD 的某个音轨标记处相接的各段构成一个组：CD 在此处分割了连续的母带素材。一个组具有一个整数偏移和一个小数部分，作为一段进行测量；其他段各自构成单独的组。每个组在拼接后的母带内连同其真实的相邻采样一起移动，之后才进行切分。因此，无间隙相接的各段在输出中的拼接结果，与整个组一次性移动的结果完全相同；这一点已逐位测试。

**由用户确认。**未给出 `cdalign=` 时，规划器执行两次搜索，每次均覆盖整个规划。随后，规划器：

- 打印找到的位置；
- 打印一行 `PLAN_SUGGEST whitened=<status>:<positions> plain=<status>:<positions>`；
- 不写入任何内容，并以退出代码 1 退出。

使用 `cdalign=<p1>,<p2>,…` 时，为每一段给出一个值：

- 该值是该段的 CD 帧 0 所在的母带采样位置，允许带小数；
- 对于在 CD 上为数字静音的段，给出 `-`；
- 手动给出的值始终优先；
- 若为同一组中的各段给出不同的小数部分，规划器会停止。

切分之后，按编码器的规则再次检查每一段。落入需要确认区间的段会被列出，规划器只在确认之后才写入文件；确认可在控制台中进行，也可使用 `cdaccept`。这些段随后也必须使用 `cdaccept` 编码。

**不属于任何段的采样。**移动可能把采样带到没有任何段取用母带采样的位置：母带的最开头或最末尾，或仅母带具有的间隙。规划器会报告发生这种情况的位置和涉及的采样数。规划器还会说明：在该位置向母带和 CD 同时添加至少 1 ms（44 个 CD 帧）的数字静音，并使其后的音轨标记随之移动，即可保留这些采样。由用户作出决定。

若母带的声音比音轨 1 早开始不到一个 CD 采样，则在音轨 1 的 CD 层前面加入一帧数字静音。该帧位于前间隙（pregap）内，光盘的会话 1 保持不变。

**停止。**出现以下任一情况时，规划器会停止并报告时间范围：

- 母带含有 CD 所没有的声音；
- 两个段在同一母带范围内都有声音；
- 各段的顺序不同；
- CD 带有预加重标志（FLAGS PRE）；
- 音轨 1 在 INDEX 00 中有声音；
- 出现单段对齐（第 4.3 节）的任一停止条件。

**输出。**对于每一段，规划器写入：

- `TRACKnn.master.wav`：移动后的母带，24 位；
- `TRACKnn.cd.wav`：发行方的原样采样，从该段的 INDEX 01 到下一个 INDEX 01。

移动情况记录在 `plan.align.txt` 中；该文件是纯文本文件，没有任何程序读取。

**处理链。**完整光盘通过以下三个步骤制作：

1. `lae_enc plan` 进行匹配和切分；
2. `lae_enc` 使用 `cdalign=0` 对每一段编码；
3. `lae_cdx image … layout=<publisher.cue>` 写入 CD-Extra 映像，其会话 1 与发行方的节目逐采样一致（第 10.5 节）。

命令见第 14.5 节。

**测量结果。**规划器在整盘案例上进行了测试；在这些案例中，发行方的 CD 由母带经过降噪、门限处理和最小相位均衡生成。

- 用当前构建（位置经确认，先移动母带再切割）：一张由 CD 从连续素材中切出三轨的盘（发行方链路含降噪、静音门和最小相位均衡），13 项检查全部通过；各段以 `cdalign=0` 编码，剩余时间差为 −67.6、−69.0 和 −67.5 dB。在 CD 分轨点切开的两段重新接起来，与整组一次移动的结果逐位相同；被数字静音隔开的两组各有自己的小数（剩余时间差 −99 dB）。
- 使用发布构建，以规划器打印的位置重复了其中一个案例，11 项检查全部通过。

## 5 位深层

### 5.1 内容

位深层以基础采样率对 $T$ 编码。$T$ 是未削波的 24 位基础信号与 CD 路径之差经过低通滤波后的结果。该层为左、右声道各设一条流。在 v5 中，编码目标为 $T$ 减去第 6.5 节的泄漏补偿项。

即使 $T$ 在 $f_c$ 处经过低通滤波，位深层仍始终覆盖整个基础频带，即 0–22.05 kHz（48 kHz 系列为 0–24 kHz）。截止频率以上的单元大多属于 A 类，几乎不占空间。

### 5.2 用途与原理

CD 频带承载大部分音乐内容，而位深层是提升该频带质量最划算的方式。

默认情况下，其精度由精度规则 1 控制；在 keep20 下由规则 3 控制（第 8 节）：

- 在安静块中，系数以比块峰值低 2、4 或 8 位的精度表示，从而保留波形形状；
- 在高电平块中，规则 1 下的步长对应 18/20/24 位分辨率；规则 3 下则对应 20/22/24 位分辨率。

### 5.3 过冲

基础信号 $b$ 不会削波，但 CD 路径会削波。因此，所有超过满量程的带限过冲都会出现在 $T$ 中。

因此，24 位路径可以恢复 CD 必须削掉的内容；只有最终输出会进行硬限幅。16 位路径不包含 $T$，无法恢复这类内容（第 12.3 节）。

### 5.4 keep20 位深层

`keep20` 模式使用精度规则 3 对位深层编码（高电平块为 B20/C22/D24）。选择 keep20 时，编码器会提示其影响和开销。测量结果如下：

- **CD 频带误差。**误差由约 −111 dBFS 改善至约 −124 dBFS（表 12.2）。
- **大小。**44.1 kHz 系列中，每小时音乐的位深层约增加 84 MB；48 kHz 系列中约增加 94 MB。
- **光盘时长。**在 CD-Extra 光盘上，这一额外大小相当于每小时音乐约占用 9 分钟光盘时间。
- **播放时长。**根据表 11.5 的测量，80 分钟光盘的 24 位路径中位播放时长减少了 2.0 至 4.8 分钟。

## 6 频率层

### 6.1 变换与倍频程数据流

频率目标 $F$ 在母带采样率下，通过对整个信号执行一次 MDCT 变换得到（第 7.1 节）。

频谱线被划分为若干片段，每个片段对应基础频带以上的一个倍频程。例如，对于 352.8 kHz 母带，这些片段名义上为 22.05–44.1、44.1–88.2 和 88.2–176.4 kHz。每个片段都作为独立数据流存储。

在这种组织方式中，每个倍频程都是一段频谱线。无需使用频带分割滤波器，其任何部分也都不会进入 PCM。

输出较低倍频程的解码器会跳过其以上的数据流。

### 6.2 中/侧

频率层采用中/侧（M/S）形式编码，每个片段分别设有 M 和 S 数据流。位深层则采用左/右（L/R）形式编码。

M/S 通过整数提升计算。这里的 $\lfloor\cdot\rfloor$ 以算术右移实现。编码器计算：

$$S = L - R, \qquad M = R + \lfloor S/2 \rfloor ;$$

解码器执行逆变换（[SPEC.md](spec/lossy/SPEC.md)，第 11.4 节）：

$$R = M - \lfloor S/2 \rfloor, \qquad L = R + S .$$

该逆变换可以从 $M$ 和 $S$ 精确还原 $L$ 和 $R$。

### 6.3 截止频率检测与起始谱线

不同制作的 CD 带宽各不相同。因此，频率层从当前 CD 实际截止频率稍低处开始，而不是从基础奈奎斯特频率的固定比例处开始。

- **生成的 CD。**编码器从基础奈奎斯特频率开始向下搜索，寻找 CD 仍能在 0.1 dB 以内跟随母带的最高频率。母带能量极低的频率箱会跳过。
- **独立 CD。**根据母带与 CD 之间的相干性检测截止频率，不受电平影响。若 CD 相对于母带存在不足一个采样的小数偏移，检测出的截止频率会降低；第 4.3 节的对齐可消除这一影响（表 4.3）。

频率层从**检测截止频率以下 1 kHz**处开始。

- 起始和结束谱线会写入每个数据流头部。
- 检测到的截止频率也会存储在容器头部，仅用于显示。

### 6.4 精度

| 方案 | 频率层规则 | 高电平块 | 安静块 |
|---|---|---|---|
| 方案 1（高质量，`s1`，默认） | 规则 1 | B18 / C20 / D24 | 比块峰值低 2/4/8 位 |
| 方案 2（高压缩，`s2`） | 规则 2 | B16 / C20 / D24 | 同规则 1 |

两种方案都使用相同的位深层规则：规则 1，或 keep20 下的规则 3。因此它们的 CD 频带相同，差异仅在超声波区域。

### 6.5 泄漏补偿（仅编码器端）

频率层中的量化噪声会通过正弦窗的旁瓣泄漏到 CD 频带。超声内容越强，这种影响越明显：在合成材料上影响突出，仅影响少数真实录音。

开发期间的测量表明，CD 频带误差来自频率层：

- 不解码频率层时，CD 频带误差回到 −111 dBFS；
- 误差频谱随频率升高，从低频处的 −119 dBFS 上升到 18 kHz 处的 −100 dBFS；
- 半带滤波器的通带偏差低于 −120 dB。

v5 编码器执行以下流程：

1. 频率层定稿后，将其解码并计算其量化误差。
2. 将该误差降至基础采样率。
3. 使用 2047 抽头低通滤波器提取频率层起始频率以下的部分；该滤波器的截止频率比起始频率低 150 Hz。
4. 从位深目标中减去该部分，然后对位深层编码。

起始频率以上的内容由频率层本身编码，不会再次补偿。此流程既不改变解码器，也不改变格式。

补偿的效果取决于解码路径：

- **`full`。**两层都会解码，因此补偿有效。
- **`16`。**此路径没有位深层，因此补偿不起作用。
- **`cd24`。**位深层及其补偿项会被解码，但产生被抵消泄漏的频率层并未解码。该项对 `cd24` 输出的影响尚未测量；这项测量属于未来工作（第 17.3 节）。

开发期间的测量结果：

- 对合成 `electronic` 片段，CD 频带误差由 −96 改善至 −109 dBFS；
- 真实录音没有变化；
- 扩展大小增加 0–1%。

第 12.5 节报告了 12 个来源的平均影响。

## 7 时频分区与分类

### 7.1 变换

两个编码层都使用相同的 MDCT 结构，并按教科书式顺序实现。

| 方向 | 步骤 |
|---|---|
| 正向 | 加窗 → 折叠（相加）→ DCT-IV，通过带前、后旋转因子的复数 FFT 计算 |
| 逆向 | DCT-IV → 展开 → 加窗 → 重叠相加 |

**窗函数。**使用正弦窗。

**大小。**每个数据流头部都携带变换大小 $N$。在容器 v5 中，$N$ 必须为 512。

**旋转因子。**前、后旋转因子为：

$$w_n = \exp\left(-i \frac{2\pi (n + 1/8)}{2N}\right), \qquad n = 0, \dots, N/2 - 1.$$

这是 FFmpeg `libavcodec/mdct.c` [6] 使用的旋转因子形式。FFT 的位反转置换使用生成的 `BITREV` 表。

**边界扩展。**信号两端均采用镜像扩展。扩展长度记录在头部中（第 10 节）。

### 7.2 单元、根块和叶节点

解码器所需的几何布局由 `src/partition_format.h` 定义。编码器的搜索实现位于 `src/partition.h`。

**单元。**一个数据流的一个声道的系数平面被划分为若干单元。单元是某一帧中一组相邻频谱线。数据流头部会指明单元宽度；在容器 v5 中，该宽度始终为 8 条频谱线。

**根块。**单元按 16 个单元 × 8 帧组成根块。根块构成固定规则网格，并按时间优先顺序处理。所有模式下的根块几何布局相同。

**分区树。**每个根块通过二叉树进行分区。

- 一个节点要么是叶节点，要么通过一条频率或时间切分线分成两个子节点。
- 最小块大小为 1 个单元 × 1 帧。

**切分位置。**有两种切分位置方案。编码器标志 `equal` 用于选择方案，头部会记录选择结果。

- **等分切分（Equal cuts）：**仅能对半切分；无需传输位置。
- **不等分切分（默认）：**切分位置可以位于最小网格上的任意位置。位置以固定长度的旁路编码整数（以网格单位表示）传输。

**叶节点参数。**所有编码参数都在叶节点中携带：类别、指数、零级别索引和系数。中间节点只携带切分信息。

### 7.3 类别

每个叶节点会分配四种类别之一。

| 类别 | 含义 | 编码内容 |
|---|---|---|
| A | 确定不承载信息：数字静音，以及低于一个 24 位 LSB 的舍入级残留。计划支持：由用户显式移除的噪声。 | 不编码任何内容；重建为精确的零 |
| B | 需要最低精度等级的内容 | 指数 + 系数，TB = 2 |
| C | 中等精度 | TB = 4 |
| D | 需要最高精度的内容 | TB = 8 |

类别分配遵循以下规则。

- **噪声也要编码。**母带中的噪声不属于 A 类。噪声与其他内容一样编码，大多为 B 类，有时为 C 类。
- **先确定 A 类。**第一次压缩之前就固定 A 类，之后不再更改。
- **混合块。**只有所有单元均为 A 类时，块才能归为 A 类。任何包含保留内容的块至少为 B 类。将 A 类单元混入 B 类叶节点会增加 B 类字节开销，因此分区搜索会自行把 A 类与保留内容分开。
- **跨组单元。**跨越两个分析组的单元，只有在两个组都为 A 类时才属于 A 类。在此情况下，采用两者中较低的噪声底。
- **噪声底估计。**单元组的噪声底取以下两个值中较小者：时间方向的第 10 百分位数，以及该组单元之间的频谱中位数。因此，持续音不会被误判为噪声底。

### 7.4 标记与闭环（编码器）

编码器首先扫描整条音轨，并为每个非 A 类单元标记所需的位深：

- 需要最高位深的单元标为 D；
- 其次标为 C；
- 其余非 A 类单元标为 B。

持续音检测器和瞬态检测器这两个检测器会确保检测到的结构至少标记为 B 类。

随后通过闭环细化这些标记：

1. 编码器根据每个单元自身的标记进行编码；
2. 解码该结果；
3. 在误差上运行检测器；
4. 仅提升在其自身等级下仍受损的单元。

持续音检测器（`src/tone_scan.cpp`）没有灵敏度设置。其阈值根据平均周期图的噪声统计确定：

- **周期图。**周期图由汉宁窗长 FFT 计算，重叠率为 50%。FFT 长度取不短于 0.09 s 的最小二次幂。
- **时间尺度。**周期图分别在 1、2、4、8 和 16 个长 FFT 帧上取平均，因此会在五种时间尺度下检测结构。
- **阈值。**每种尺度的阈值都是伽马分布分位数，对应每次检测约 $10^{-9}$ 的固定虚警率。
- **噪声底。**局部噪声底取自相邻 32 箱分块的中位数。在闭环误差检查中，也可以根据参考信号的周期图计算。
- **检测结果。**每个尺度至少需要连续两个窗口满足条件，允许 ±1 箱的漂移。时间上重叠且相隔不超过 3 箱的检测结果会合并。

瞬态检测器的统计描述属于未来工作（第 17.2 节）。

v5 的结构保留结果尚未发布。使用注入的真实目标（音调和点击声）对 v5 重新验证也属于未来工作（第 17.2 节）。

### 7.5 模式驱动的全局选择（编码器）

工作模式不会规定块大小，而是规定：在整条音轨范围内，D 类和 C 类内容必须有多少比例保持在自身等级。其余 C 类和 D 类内容可以降级。

对于每种模式，编码器都会在整条音轨范围内选择分区和叶节点类别，使编码总字节数最小，同时满足这些保留比例。

- **降级代价。**使用拉格朗日乘数 λ 表示降级代价。通过二分法找到该乘数，先处理 C 类，再处理 D 类，一次遍历即可完成。
- **根块内搜索。**动态规划会评估所有子矩形和每个允许的切分位置。一个由 16 个单元 × 8 帧组成的根块包含 136 × 36 = 4,896 个子矩形，每个矩形最多尝试 22 个切分位置。
- **大小评估。**大小评估使用与实际范围编码器相同的概率模型。最后再用实际编码器编码。

搜索只受精度约束，不对片段或数据包的字节数设上限。乘数 λ 和比例目标仅存在于编码器中；解码器只读取分区树。

默认按单元数量测量比例：

- 选项 `energy` 按能量测量；
- 模式 `max` 始终按能量测量；
- 模式 `keep` 和 `keep20` 同时按单元数量和能量测量。

根块搜索以并行方式运行。线程数不会影响输出：16 线程和 1 线程编码所得文件逐字节相同。

## 8 量化

### 8.1 步长

每个非 A 类叶节点都携带指数 $E$ 和等级 $t \in \lbrace B, C, D \rbrace$：

- $E$ 是该叶节点中最大系数绝对值（以 24 位单位表示）的位长度；
- 各等级的位数为 $\mathrm{TB}(B) = 2$、$\mathrm{TB}(C) = 4$、$\mathrm{TB}(D) = 8$。

量化步长 $\Delta = 2^s$，以 24 位单位表示。指数 $s$ 根据三条**精度规则**之一计算。每个数据流头部都会记录规则编号。

| 规则 | 用途 | 公式 | 高电平块 | 安静块 |
|---|---|---|---|---|
| 1 | 方案 1（两层）；方案 2 的位深层 | $s = \max(0, \min(E, 8) - \mathrm{TB})$ | B18 / C20 / D24 | 比块峰值低 TB 位 |
| 2 | 方案 2 的频率层 | $s = \max(0, \min(E - \mathrm{TB}, 8 - \lbrace 0, 4, 8 \rbrace))$ | B16 / C20 / D24 | 同规则 1 |
| 3 | keep20 的位深层 | $s = \max(0, \min(E, 6) - \mathrm{TB})$ | B20 / C22 / D24 | 比块峰值低 TB 位 |

规则 2 中，第二项对 B、C、D 分别为 8、4 和 0。

- **安静叶节点**（$E$ 低于上限）。步长根据叶节点峰值设定。随后系数会保留固定数量的有效位，因此无论绝对电平如何，都能保持波形相似度。
- **高电平叶节点。**上限确定绝对位深分辨率。例如，规则 1 使 B 类叶节点达到 16 + 2 = 18 位。

**16 位下限保障。**所有规则均满足 $s \le 8$，因此步长不会粗于一个 16 位 LSB（以 24 位单位计为 256），也就是 CD 层的分辨率。因此，所有高于 16 位等级的内容均采用波形编码。

上限是固定的格式常量。

**动态范围。**该格式理论上限为 144 dB，即 24 位采样的范围。主要内容的设计目标为 120 dB。

### 8.2 死区

编码器使用参数为 θ = 0.30 的标量死区量化器：

$$|q| = \left\lfloor \frac{|X|}{\Delta} + 0.5 - 0.30 \right\rfloor ,$$

其中 $q$ 的符号与系数 $X$ 相同。死区是编码器参数；解码器只需要使用下文的重建规则。

开发期间还评估了更小的死区（0.15 和 0）。这使误差改善约 2–3 dB，但总大小分别增加 +3% 和 +6%（表 12.5），因此未采用。

### 8.3 重建偏移

非零量化索引 $q$ 按以下方式重建：

$$\hat X = \operatorname{sign}(q)\left(|q| + 0.20\right)\Delta .$$

偏移量 0.20 是格式常量。在表 12.5 的开发测量中，与仅使用泄漏补偿相比，该偏移：

- 未改变扩展大小；
- 使平均超声误差改善 1.8 dB；
- 使用 18 位位深层时使平均峰值误差改善 2.0 dB，使用 20 位位深层时改善 2.8 dB。

### 8.4 零系数与可选零级别

**零系数。**默认情况下，零量化索引会重建为精确的零。此规则影响较小：

- 在 CD 频带中，扩展下方有 CD 层，因此不会产生频谱缺口；
- 在超声频带中，仅缺失低于步长 0.5–0.8 倍的成分；
- 开发测量显示，解码信号的超声电平比母带低 0.3–1.4 dB。

**可选零级别（`zs`，默认关闭）。**启用 `zs` 后，编码器会传输每个量化为零的系数的真实符号。随后该系数将重建为“符号 × 叶节点级别 × 步长”。

- 每个叶节点携带一个 3 位索引 $k$。
- 当 $k = 0$ 时，零系数重建为零。
- 当 $k > 0$ 时，叶节点中的每个零系数后跟一个旁路编码位，用于表示其真实符号。该系数重建为 $\pm \mathrm{ZC}[k] \Delta$。

级别表为：

$$\mathrm{ZC} = \lbrace 0, 1/32, 1/16, 3/32, 1/8, 3/16, 1/4, 3/8 \rbrace .$$

编码器根据叶节点自身的统计量为每个叶节点选择 $k$。未启用此选项时，编码器会为每个叶节点写入 $k = 0$。

开发期间测得 `zs` 的影响如下（10 秒片段，模式 3）。

| 数值 | 影响 |
|---|---|
| CD 频带误差（24 位路径） | 从约 −111.5 改善至约 −115 dBFS（约改善 3.5 dB） |
| 超声误差 | 改善 1–5 dB |
| 峰值误差 | 改善 1–7 dB |
| 位深层大小 | +23–28% |
| 频率层大小 | +4% 至 +67%；超声内容越弱，增幅越大 |
| CD-Extra 播放时长，方案 2，超声内容较弱的 DXD 录音 | 可能从约 45 分钟降至约 36 分钟 |
| 确定性 | O2 和 Od 解码结果逐字节相同 |

该选项默认仍为关闭状态。

### 8.5 A 类

A 类叶节点不携带系数。其所有系数都重建为精确的零。

## 9 熵编码

所有叶节点数据都使用自适应二进制范围编码器编码。完整的二值化定义见 [SPEC.md](spec/lossy/SPEC.md) 第 6–8 节。本节概述其结构。

**概率自适应。**每个自适应二进制模型都使用固定移位量 5 更新。

**二值化。**多值符号通过固定二叉树二值化：

- 系数位长度使用固定的 5 位树；
- 叶节点零级别索引使用 3 位树。

**系数上下文。**系数上下文根据其叶节点类别和叶节点指数确定。

**边信息上下文。**

- **类别符号。**使用比特流中前一个叶节点的类别作为上下文进行编码。
- **指数。**编码为与前一个非空叶节点指数的差值。
- **零级别索引。**使用类别符号作为上下文进行编码。

**树比特。**

- 切分和方向标志位采用旁路位编码。
- 切分位置采用固定长度旁路编码整数。
- `zs` 下传输的符号采用旁路位编码。

**模型状态。**每个数据流均从默认模型状态开始。版本 5 未定义随机访问点（[SPEC.md](spec/lossy/SPEC.md)，第 6.8 节）。解码器库的快速定位（第 13.6 节）使用解码器在解码过程中记录的检查点；比特流中不添加任何内容。

## 10 容器（v5）

本节为摘要。规范性描述见 [SPEC.md](spec/lossy/SPEC.md) 第 3–5 节。

### 10.1 封装

在容器 v5 中，LAE 文件为 RIFF/WAV 文件：

- 其 `data` 块是 CD 层；
- 扩展位于单独的块中，块 ID 为 `LAE `（末尾带一个空格）。

播放器会忽略未知块并播放 CD 层。文件以 `.wav` 扩展名分发。`.lae` 是该格式专用扩展名；容器 v5 尚未规定 `.lae` 文件布局。

WAV 文件之外的封装不属于 v5 容器，由封装规范定义（第 10.5–10.9 节）：

- **CD-Extra。**封装到 CD-Extra（44.1 kHz 系列）已在工具 `lae_cdx` 中实现。音频会话承载 CD 层，数据会话承载扩展。
- **单独文件与数据流。**以基础层文件（FLAC 或 WAV）加并列的扩展文件进行分发，以及 LAE 流，也在该规范中定义。扩展不承载于 FLAC 文件内部。

### 10.2 扩展块布局

所有头部整数字段均为小端 32 位整数。边界采样为小端 16 位整数。

| 字段组 | 内容 |
|---|---|
| 标识 | 魔数 `LAE1`；容器版本 5 |
| 采样率和长度 | 母带采样率；基础采样率；倍频程级数；母带长度；母带采样率下每侧的填充长度 P |
| 信息字段 | CD 截止频率；模式索引（0 max、1 “1”、2 “3”、3 “5”、4 keep、5 keep20）；等分切分标志；比例度量。这些字段仅用于显示，不影响解码；但模式索引仍必须在 0–5 范围内。 |
| 边界 | 扩展基础层长度 nb；两端各有的扩展采样数 pb；每端的 pb 个立体声 CD 采样 |
| 抖动标志 | 标志字节数；随后为每个声道、每 4096 个基础采样率采样的 1 字节标志，先存放所有左声道标志 |
| 位深层 | L 流、R 流 |
| 频率层 | 片段数 n；n 个 M 流；n 个 S 流 |
| 完整性 | 对此前所有内容计算的 CRC-32 [9] |

### 10.3 数据流布局

每个数据流由字节数、十个头部字段和范围编码数据组成。头部字段为：

- K；
- N；
- 起始谱线；
- 结束谱线；
- 采样率；
- 长度；
- 单元宽度 + 256 × 精度规则编号；
- 模式；
- 等分切分标志；
- 范围编码字节数。

精度规则编号如下：

- 1：B18/C20/D24；
- 2：B16/C20/D24；
- 3：keep20 位深层，B20/C22/D24。

K 是平面中的 MDCT 帧数，必须为正数，且应等于 $\lceil L_s/512 \rceil + 1$。其中 $L_s$ 对位深流来说是填充后的基础层长度 nb；对频率流来说是填充后的母带长度。若 K 较小，缺少的帧会解码为零（[SPEC.md](spec/lossy/SPEC.md)，第 5.3 节）。

### 10.4 验证

发生以下任一情况时，解码器会拒绝该文件：

- 扩展块的 CRC 不匹配；
- 头部字段彼此不一致；
- CD 音频长度与扩展块不匹配；
- 任一编码值超出范围；
- 容器版本不为 5。

所有头部字段都会在使用前进行验证。参考解码器还提供以下保护：

- 读取边界检查；
- 防止恶意文件造成循环不终止；
- 采样率参数检查，包括拒绝负输出采样率；
- 支持 64 位文件大小；
- 防止输出大于 4 GB；
- 溢出保护。

### 10.5 CD-Extra 封装

第 10.5–10.9 节概述封装规范；该规范以草案形式发布于 [spec/cdx/SPEC.md](spec/cdx/SPEC.md)。两者不一致时，以该规范为准。封装完全位于容器 v5 之外：v5 容器和解码器均未改变，封装规范有其自身的版本号。工具 `lae_cdx` 实现了该规范（命令见第 14.6 节）。

**适用范围。**CD-Extra 仅适用于 44.1 kHz 系列，光盘上的每个 CD 层均为 44,100 Hz。DVD 和蓝光数据光盘不使用 CD 布局。它们承载普通文件（第 10.7 节），这些文件可以属于任一采样率系列。

**会话 1（音频）。**会话 1 一次写入（disc-at-once 或 session-at-once）。它仅包含以下内容：

- 音轨 1 的 150 扇区 pregap，为数字静音（不支持隐藏音轨）；
- 各音轨的 CD 层，每个 CD 层从该音轨的 INDEX 01 开始，音轨 1 的 INDEX 01 位于 LBA 0；
- 每个 CD 层之后少于 588 个采样（一个扇区）的数字静音，用于补足该音轨的最后一个扇区。

会话 1 遵循以下规则：

- 最后一条音轨之后既无保护音轨，也无其他静音；
- PCM 中不嵌入任何数据或标记；
- 每条音频音轨均为整数个扇区，且长度至少为 300 个扇区（4 s）；
- 不设置预加重标志；
- 一张光盘最多容纳 98 条音频音轨，因为数据音轨也占用一个音轨编号。

CD 层的两种模式对应不同布局：

- **派生 CD。**音轨边界为发行方给定的边界。在连续母带中，每个音轨起点都必须位于扇区网格上；否则工具会停止，列出这些起点，且不写入任何内容。不会添加或删除任何母带采样。
- **独立 CD**（选项 `layout=<publisher.cue>`）。发行方的 INDEX 条目（包括从音轨 2 起的 INDEX 00，以及 INDEX 02 及更高编号）、ISRC、FLAGS 和 CATALOG 均保留在原位置。会话 1 必须与发行方的节目逐采样相同，工具会对此进行检查。工具只接受已经对齐的文件（第 4.3 和 4.5 节）；其本身不执行任何对齐。

**会话 2（数据）。**会话 2 恰好包含一条 CD-ROM XA Mode 2 Form 1 数据音轨，每个扇区含 2048 字节用户数据。光盘上任何位置都不出现 Mode 1 扇区。文件系统及其内容如下：

- 文件系统为 ISO 9660 Level 1 [5] 加 Joliet [15]；不使用 Rock Ridge、UDF 和 El Torito；
- 数据音轨从驱动器报告的下一个可写地址开始。对于一次写入的映像，起点预先计算为 A2 + 11,400 个扇区，其中 A2 为会话 1 lead-out 的起点，11,400 个扇区包括数据音轨的 150 扇区 pregap。该数值有待通过刻录确认（第 17.3 节）；
- 光盘包含 `/README.TXT`，为中英文纯文本说明，不含哈希、位置、偏移或长度表；
- 目录 `/LAE/` 仅包含 `TRACKnn.LAX`，即每条带扩展的音频音轨各一个扩展文件，其中 nn 为 TOC 中两位数的音轨编号；
- 数据会话不包含 CUE 表、TOC 副本、报告、程序和 `autorun.inf`。其他文件（例如小册子）由发行方自行决定，读取器会忽略这些文件；
- 数据音轨以零扇区结尾（默认 150 个，有待通过刻录确认），且长度至少为 300 个扇区。

音轨可以不带扩展发布，例如在容量不足时；此类音轨仅作为 CD 播放。可以写入 ISRC、MCN 和 CD-Text，但只能承载标准元数据。

**交付物。**该工具交付：

- 用于一次写入的映像：`IMAGE.CUE`、`AUDIO.BIN`（会话 1，从 LBA 0 到 A2，16 位小端立体声，整扇区）以及作为 `DATA.BIN`（每扇区 2352 字节）或 `DATA.ISO`（每扇区 2048 字节）的数据音轨；
- 用于分两步写入的套件：仅针对会话 1 的 CUE 表，以及一条按驱动器实际报告的起始地址重新生成会话 2 的命令。READ TRACK INFORMATION（MMC [17]）报告的地址会与 TOC 值 B0 以及 A2 + 11,400 进行核对；若三者不一致，工具会停止；
- 刻录与验收说明（`BURN.TXT`），附带布局表：各 INDEX 01 的 LBA、A2 以及数据音轨起点。

CUE 表中不包含 CRC、MD5 或其他哈希。

### 10.6 扩展文件与尾部记录

扩展文件恰好由两部分组成：

1. 该音轨 `LAE ` 块的正文，共 $n$ 字节，包括其末尾的 CRC-32，与该音轨 v5 WAV 文件中的块逐字节相同；
2. 80 字节的尾部记录。

扩展文件没有文件头，$n$ 等于文件长度减 80。扩展名在 CD 上为 `.LAX`，在其他场合为 `.lax`；读取器不区分大小写。

**尾部记录。**所有整数均为小端。

| 偏移 | 字节数 | 字段 | 内容 |
|---|---|---|---|
| 0 | 4 | 标识符 | ASCII `LTVT` |
| 4 | 2 | 版本 | 1 |
| 6 | 2 | 长度 | 80 |
| 8 | 2 | 扩展块类型 | 1 = LAEY 容器 v5；2 = 为 LAES 保留；其他值保留 |
| 10 | 2 | 音轨编号 | 在 CD 上为 TOC 中的音频音轨编号（1–98） |
| 12 | 4 | 采样率 | CD 层的采样率：在 CD 上为 44100；在其他场合为 44100 或 48000 |
| 16 | 4 | ncd | CD 层的采样数，$1 \le \mathrm{ncd} < 2^{28}$ |
| 20 | 16 | MD5 | CD 层的整轨 MD5 |
| 36 | 8 | S1 | 滑动校验和（见下文） |
| 44 | 8 | S2 | 滑动校验和（见下文） |
| 52 | 4 | lead0 | CD 层开头连续数字静音采样的数量 |
| 56 | 4 | tail0 | CD 层结尾连续数字静音采样的数量 |
| 60 | 16 | 保留 | 写入时为零；读取时忽略 |
| 76 | 4 | CRC-32 | 字节 0–75 的 CRC-32 |

各字段定义如下：

- **整轨 MD5。**对 CD 层交错排列的小端 16 位采样计算的 MD5 [16]，其定义与 FLAC STREAMINFO 块中 16 位立体声音频的音频 MD5 相同 [1]。它是读取器接受一条音轨的唯一判据。
- **S1 和 S2。**每个采样读作一个 32 位帧字 $w_i$。于是 $S_1 = \sum w_i \bmod M$，$S_2 = \sum (i+1)\,w_i \bmod M$，其中 $M = 2^{61} - 1$。窗口每滑动一个采样，两个和都可在常数时间内更新，因此读取器能以较低代价测试搜索范围内的每个位置。
- **lead0 和 tail0。**二者是对 CD 层内容的计数，而非位置，与刻录、抓轨和偏移无关。它们仅用于音轨的粗定位（第 10.8 节）。其所计数的静音采样属于音轨的一部分：这些采样总会播放，且包含在整轨 MD5 中。任何程序都不得删除或跳过这些采样。

**排除的内容。**尾部记录和扩展文件不包含任何由扩展字节计算得到的值，也不包含任何同时基于 CD 层和扩展计算的值；扩展仅由其自身的 CRC-32 保护。二者也不包含任何位置、LBA、偏移、延迟或增益，不包含逐扇区或逐帧数据，也不包含寻址表或 cue 表。

**读取时的检查。**读取器按固定顺序检查扩展文件：尾部记录是否存在、其 CRC、其版本和长度、扩展块类型，以及各字段的取值范围。任一检查未通过的文件均不会被使用，其音轨将作为 CD 音频输出，并附上原因。

### 10.7 CD 之外的分发

**单个 v5 WAV。**编码器和重新封装工具以唯一的规范化布局写入 v5 WAV 文件：`RIFF`/`WAVE`、16 字节的 `fmt ` 块、`data` 块，随后是 `LAE ` 块，并填充至偶数长度。

**基础层加扩展文件。**一条音轨可以作为两个文件分发：

- **基础层文件**，为 FLAC [1] 或 WAV，恰好承载该音轨的 CD 层；
- **扩展文件**，与基础层文件同名，扩展名为 `.lax`。若该音轨也以 CD 发布，此文件与光盘上的 `TRACKnn.LAX` 逐字节相同。

普通播放器播放基础层文件。扩展和尾部记录绝不放入 FLAC 文件内部。当解码后的基础层有 ncd 个采样且其整轨 MD5 等于尾部记录中的 MD5 时，读取器将这两个文件配对。配对后的音轨会重新封装为规范化 v5 WAV，与编码器的输出逐字节相同。

**LAE 流。**LAE 流逐条音轨传送内容：逐采样传送 CD 层（FLAC、WAV 或原始 PCM），并逐字节传送扩展文件。流中不包含任何头部、索引、位置或偏移。若流中的 CD 层经过有损重新编码（例如 AAC 或 MP3），则该流不是 LAE 流：扩展绝不会应用于有损解码的音频，此时只播放基础层。

本节中的所有形式均可使用 48 kHz 系列。

### 10.8 读取抓轨与文件

`lae_cdx` 的读取器（核心：`src/lae_cdx_read.h`）以相同方式处理所有输入：整盘抓轨（BIN 或 WAV，带或不带 CUE 表）、逐轨抓轨（带或不带 CUE 表）、单个文件以及 LAE 流。抓轨可以来自任何抓轨程序，可采用任何偏移设置。输入必须为 16 位立体声 PCM WAV。

**光盘流与 TOC。**读取器将输入组装成光盘流。TOC 按以下优先顺序获取：

1. 从驱动器读取的 TOC（规范要求；`lae_cdx` 尚未实现，见第 17.3 节）；
2. CUE 表；
3. 一组逐轨文件的顺序和长度；报告中会醒目标出此来源。

每个文件放在 CUE 表或 TOC 给出的位置。未被任何文件覆盖的位置为未知，按零读取；读取器不会尝试其他取值。没有 TOC 时，按内容搜索每个文件，并在报告中注明 “no TOC”。无法识别的 CUE 结构会使读取器停止。

**逐轨定位。**每条音轨都独立定位；读取器既不假定、也不需要整张光盘具有共同偏移。对于每个扩展文件，读取器按以下步骤处理：

1. **粗定位。**粗略位置取自 TOC，以及信息范围：流中第一个和最后一个非零采样的位置，经 lead0 和 tail0 校正。
2. **精定位。**测试距粗略位置半径 $W \ge 5880$ 个采样范围内的每个窗口起点；没有 TOC 时测试整个文件。只有滑动和等于 S1 和 S2 的窗口才成为候选。
3. **接受。**只有当候选的整轨 MD5 等于尾部记录中的 MD5 时，才接受该候选。

音轨内部的滑移（例如丢失或重复一个采样）只会改变该音轨的 MD5。该音轨将作为 CD 播放，其他音轨不受影响。

**输出与失败。**读取器按以下方式写入输出：

- **已接受的音轨。**每条已接受的音轨都重建为 `TRACKnn.lae.wav`，与编码器写出的文件逐字节相同。
- **其他音轨。**其他每条音轨都写为 `TRACKnn.cd.wav`，即未经改动的抓轨 CD 音频，并附上原因。原因类别包括：未知采样（文件缺失或被截断）、文件过短、无匹配、无尾部记录、尾部记录损坏、无法识别的版本或扩展块类型、尾部记录字段无效、音轨编号不在 TOC 中、扩展损坏，以及有损基础层。
- **没有音轨被接受。**若没有任何音轨被接受，读取器会报告输入可能是另一张光盘或另一个版本。
- **无扩展的音轨。**TOC 中没有扩展文件的音轨作为 CD 输出；这不属于失败。

**禁止事项。**读取器遵守以下规定：

- 绝不修改、修复或替换任何 CD 采样；
- 绝不使用扩展块中的边界采样来定位或拼接音轨；
- 不使用任何外部数据库，也不使用网络；
- 在一条音轨被接受之前，不输出该音轨的任何高解析度数据，并且绝不在一条音轨内部在 CD 与扩展之间切换；
- 测得的偏移仅用于显示，不写入任何文件。以偏移 0 和 +667 制作的抓轨得到了逐字节相同的输出（第 10.9 节）。

### 10.9 自检、容量与测试

**闭环自检。**`lae_cdx` 在交付映像之前，会使用读取器自身的代码回读该映像，并从映像的数据会话中获取扩展文件。回读涵盖以下抓轨形式：

- 带 CUE 表的整盘映像，偏移在 ±5880 个采样以内；
- 不带 CUE 表的整盘抓轨；
- 逐轨抓轨，分别带 CUE 表和仅有文件顺序，覆盖三种间隙模式（间隙附加到前一条音轨、前置到下一条音轨或省略），并分别带和不带音轨 1 的 pregap。

每条音轨都必须通过，并且必须重建出与编码器输出逐字节相同的 v5 WAV。在从音轨 2 起带有 INDEX 00 间隙的独立 CD 光盘中，省略间隙的抓轨无法提供间隙中的采样；此时，除非该间隙为数字静音，自检预期此类间隙之前的音轨会回退为 CD。自检还包括故意损坏：更改一个采样、使用另一张专辑的扩展文件，以及删除尾部记录。上述每种情况下的音轨都必须回退为 CD。若任一检查失败，映像即作废，处理过程停止。

**容量。**工具在写入之前按空白光盘的类型检查容量，并在自检之后再次检查。若映像放不下，工具会停止并列出可选方案：将部分音轨不带扩展发布（选项 `noext=`）、改用其他光盘，或限制倍频程（需要重新编码）。工具绝不会自动删除任何音轨或倍频程。

**测试（开发期间，2026-10-21）。**测试使用由同一录音中两条音轨的 10–15 s 片段制作的测试光盘。

| 测试 | 结果 |
|---|---|
| 已知答案测试：规范中的校验和示例、RFC 1321 的 7 个测试字符串、CRC-32、滑动和在 1000 个随机位置上与直接计算结果的对比、尾部记录取值范围 | 全部通过 |

两种方案和六种模式共组成十二种组合。两种方案为：

### 11.5 CD-Extra 播放时长

CD-Extra 仅适用于 44.1 kHz 系列。在 CD-Extra 光盘上，CD 层是第一会话中的普通 Red Book 音频，扩展则占用第二会话中的 CD-ROM XA Mode 2 Form 1 数据扇区，每个扇区含 2048 字节用户数据（第 10.5 节）。以下为计算所用常数。

| 常数 | 数值 |
|---|---|
| 80 分钟光盘 | 360,000 个扇区，每秒 75 个扇区 |
| 数据扇区（用户数据） | 2048 字节，因此每分钟光盘空间可存放 9.22 MB 数据 |
| 多会话开销（第一会话 lead-out ≈ 6,750 个扇区，第二会话 lead-in ≈ 4,500 个扇区） | ≈ 11,250 个扇区 ≈ 2.5 分钟。这些是 Blue Book 常用数值；通过实际刻录进行确认属于未来工作（第 17.3 节）。 |
| ISO 9660 / Joliet 文件系统 [5][15] | 约 1–2 MB（≈ 0.2 分钟），为估算值；每个文件均按 2048 字节对齐 |
| 安全余量 | 容量的 1.5% 或 4% |

`lae_cdx` 的布局将数据音轨置于 A2 + 11,400 个扇区处，即上述开销加上数据音轨的 150 扇区 pregap，约 2.53 光盘分钟。下文的播放时长按 2.5 分钟计算；两者相差约 0.03 光盘分钟。

令 $r$ 为每分钟音乐的扩展大小（单位 MB）除以 9.22。专辑时长 $L$ 必须满足：

$$L(1 + r) + 2.5 + 0.2 \le C$$

单位为光盘分钟，其中 $C$ 是扣除安全余量后的容量。

**上限。**若超声内容全部为 A 类，频率层几乎为空。此时播放时长约为：

|---|---|---|---|
| 超声内容全部为 A 类 | 约 73–76 分钟 | 约 64–66 分钟 | 约 57–58 分钟 |

### 12.1 指标

- 以 dBFS 表示，数值越负越好；
- 根据解码输出与母带之间的差值计算；
- 对左右两个声道取平均。

### 12.3 合成材料与固有限制

**合成套件。**在候选发布轮次中，生成的合成套件（60 个信号）在 24 位路径下的 CD 频带误差中位数为：

- 在不同采样率及 `max` 至 `keep` 模式下为 −111 至 −115 dBFS；
- 使用 keep20 时为 −121 至 −125 dBFS。

**Synth，16 位路径。**合成压力测试信号 “Synth” 包含方波，其带限形式会超过满量程。CD 层必须对这些信号削波，而 16 位路径没有位深层可用于恢复。因此，对于这类信号，该路径的 CD 频带误差属于固有限制：

- 在 40 秒片段上为 −42 dBFS，这是开发期间测得的（2026-10-17）；
- 在候选发布轮次的 10 秒片段上为 −35 至 −36 dBFS。

**Synth，24 位路径。**

- 在一项 40 秒开发对比中，泄漏补偿将 Synth 的 24 位路径 CD 频带误差从 −79 改善至 −112 dBFS。
- 在候选发布轮次中，Synth 在 `max` 至 `keep` 模式下的 24 位路径 CD 频带误差，在 88.2、96、176.4 和 352.8 kHz 下依次为 −101、−113、−96 和 −82 dBFS。
- 使用 keep20 时，96 kHz 下的数值为 −125 dBFS；其余三项不变。
- 176.4 和 352.8 kHz 下的数值尚未分析（第 17.4 节）。

### 12.4 输出限幅

解码器的最终输出会被硬限幅至 24 位范围。

- **过冲受限。**16 位下限保障（第 8.1 节）将任何超过满量程的过冲限制在编码误差范围内。开发测量中，对 +12 dB 硬削波母带进行测试，峰值误差最高为 −76.6 dBFS。硬限幅器会将这类采样恢复至满量程，也就是母带在这些采样位置上的值。
- **限幅器触发情况。**候选发布轮次中，没有任何一次编码会触发解码器的硬限幅器（已发布数据的 `limiter_samples` 列）。
- **编码器报告。**编码器会执行诊断解码，并报告将被硬限幅的采样数量，供参考。

## 13 确定性与一致性

### 13.1 算术

插值和抽取使用整数滤波器表。

系数重建和逆 MDCT 使用 IEEE-754 binary64 算术 [7]，并严格按照参考源码中的运算顺序计算。所有 MDCT 常量均来自 `src/mdct_tables.h` 中的精确十六进制字面值。在这些条件下，所有平台都会生成逐位相同的输出。

禁止使用以下构建选项：

- `-ffast-math`；
- `/fp:fast`；
- 任何允许融合乘加收缩的选项。

在使用 GCC 或 Clang 的 32 位 x86 上，必须使用 `-msse2 -mfpmath=sse`。不支持 x87 构建，解码器的启动自检会拒绝此类构建。

### 13.2 启动自检

每次启动时，解码器都会将固定数据集送入逆 MDCT，并对结果计算 64 位指纹。

- 指纹采用 FNV-1a 风格哈希 [8]，但初始值为非标准值，详见 [SPEC.md](spec/lossy/SPEC.md) 第 13 节。
- 指纹必须等于 `0x729b547fbdbfe203`，即 `src/mdct_tb.h` 中的 `SELFTEST_REF` 值。
- 若不相同，说明构建改变了浮点求值过程。解码器将拒绝运行（退出代码 4），而不会生成与其他平台不同的输出。

工具 `tools/selftest_ref.cpp` 会打印当前构建的指纹。

编码器在启动时运行逆 MDCT 自检和 MD5 自检。解码器库在调用线程上运行自检（第 13.6 节）。

### 13.3 已验证的配置

已验证的构建列在 [docs/BUILD.md](docs/BUILD.md) 第 3 节。

- **Windows，MSVC 2022。**解码器的 x64 `/O2`、x64 `/Od` 和 x86 SSE2 构建结果完全一致。MSVC 编码器生成了参考向量文件。
- **Linux x86，解码器。**解码器使用 GCC 13 x86-64（`-O2` 和 `-O0`）、Clang 18 x86-64（`-O2`）以及 GCC 13 x86 32 位（SSE2）构建。256 项解码结果全部与参考结果一致。
- **Linux x86，编码器。**使用 GCC 13 x86-64（`-O2` 和 `-O0`）构建的编码器逐字节重现了全部 16 个一致性向量文件。
- **解码器库。**现已调用解码器库的 `lae_dec`，以及 x64 和 x86 构建的 `liblae`，各自重现了 64 项一致性输出中的全部 64 项（16 个向量 × 4 种路径）。
- **Linux ARM64。**在 aarch64 上，使用 GCC 13（`-O2` 和 `-O0`）和 Clang 18（`-O2`）构建的解码器通过了启动自检，192 项解码结果全部与参考一致。使用 GCC 13（`-O2`）构建的编码器逐字节重现了全部 16 个一致性向量文件。
- **尚未覆盖。**其他 ARM 系统（例如 32 位 ARM 和 ARM 上的 macOS）尚未测试。不支持 x87 构建（第 13.1 节）。

开发期间还测得以下结果：

- 使用 `zs` 选项时，优化和未优化的解码结果逐字节相同；
- 在候选发布轮次中，83 项优化与未优化解码器的对比结果逐字节相同（已发布数据中的 `o2_equals_od` 列；该数据不包括 352.8 kHz 录音）。

### 13.4 其他不变量

- **编码器线程。**编码器线程数不会影响比特流。
- **编码器自检。**编码器会重新解码每一层和片段；如有任何系数平面不匹配，则拒绝写入文件。随后，在发布文件之前，编码器会对最终文件进行完整解码。
- **对齐。**将编码器打印的偏移通过 `cdalign=` 回传，会得到相同的文件。已经对齐、长度相同且无需放置的输入，其输出与引入对齐功能之前相同。
- **开发运行。**开发期间的测量（2026-10-17）显示，331 次编码—解码运行均顺利完成。
- **候选发布轮次。**v5 候选发布版成功完成 996 次编码，且每次编码均通过编码器自检。

### 13.6 解码器库

参考解码器的各处理级已原样移入库 `src/lae_decoder.h`，该库提供 `Decoder` 类。命令行解码器 `lae_dec` 调用该库。该库采用流式处理：除保存在内存中的 CD 层和扩展块外，其内存占用不会随音轨长度增长。

**C 接口。**`liblae`（`src/lae_api.h`，API 版本 3）是面向播放器和插件的 C 接口，提供 x64 和 x86 构建。

- **打开。**可以从 v5 WAV 文件、内存中 v5 WAV 文件的字节、通过宿主回调读取的文件，或从基础层（作为 PCM 的 CD 层）及其扩展文件打开一条音轨。仅当基础层的整轨 MD5 与扩展文件匹配，或在基础层中按内容找到该音轨且随后匹配时，才接受该基础层。
- **路径与输出。**调用方选择第 3.4 节四种路径之一以及一个输出采样率。输出始终为两个交错声道的 `int32` 值：路径 `cd24`、`16` 和 `full` 为 24 位范围，CD 路径为 16 位范围。
- **统计信息。**该库报告被硬限幅器限制的采样数、是否发生数据流错误，以及已消耗的熵编码字节数。最后一项可用于显示实时码率。
- **线程。**同一条音轨不得同时由两个线程使用。不同音轨可以同时在不同线程中解码；测试中，在两个线程中解码两条音轨，所得输出与分别解码时逐位相同。
- **浮点状态。**解码器需要按固定顺序进行的严格 IEEE-754 binary64 算术（第 13.1 节）。若宿主线程可能以其他浮点状态运行，宿主应在每次调用期间将 MXCSR 设为 `0x1F80`，并在调用后恢复原值。`lae_selftest()` 检查调用线程；若检查失败，宿主应只播放 CD 层。`lae_start()` 会再次运行自检。

**逐位精确的快速定位。**解码时，该库约每 4 s 记录一次熵编码器检查点。定位时恢复一个检查点，并在目标位置之前不远处对每个信号处理级执行热重启，使定位后的输出与顺序解码逐位相同。

- 向后定位，或定位到已经解码过的部分，速度很快。
- 向前定位越过已解码部分时，必须熵解码到目标位置，因为 v5 未定义随机访问点（第 9 节）。在测试机器上，352.8 kHz 下每跳过一分钟约需 1.6 s。
- 在对 10–15 s 片段的开发测试中，覆盖所有路径和输出采样率的 540 次随机定位（包括此前从未解码过的位置）全部逐位相同；最慢的一次定位连同随后的读取用时 0.2 s。

用法见第 14.7 节。

### 13.7 播放器组件

foobar2000 组件 `foo_input_lae` 0.3 基于 `liblae` 构建，`liblae` 被编译进组件 DLL。该组件以所有层播放 LAE v5 文件，输出最高可达母带采样率，例如 352.8 kHz / 24 位。

- **宿主。**32 位 foobar2000 1.4、1.5 和 2.x。计划推出适用于 foobar2000 2.x 的 64 位版本。
- **文件。**组件接受带有 `LAE ` 块的 `.wav` 文件，以及将这些文件重命名为 `.lae` 后的文件。这种重命名的文件是 v5 WAV 文件，而不是仍未规定的 `.lae` 布局。不带 `LAE ` 块的 WAV 文件会立即被拒绝，交由内置 WAV 解码器处理。
- **层选择。**母带采样率下的所有层（默认）；所有层，输出为不超过 192 kHz 或不超过 96 kHz 的最高倍频程；CD 层 + 位深层（基础采样率下 24 位）；或仅 CD 层。播放期间的更改从当前位置生效。
- **验证。**组件在播放前检查整个文件：扩展块的 CRC，以及头部和数据流的结构。未通过检查的文件将全部作为 CD 层播放，原因写入控制台和文件属性。
- **音轨内不切换。**组件绝不在一条音轨内部在 CD 层与扩展之间切换。播放期间的数据流错误会作为错误报告，并停止播放。只有用户选择的层更改会在音轨中途生效。
- **确定性。**解码期间固定浮点状态，解码后恢复，x87 和 SSE 均如此。
- **内存。**每条音轨约等于文件大小。由于 32 位宿主受 4 GB 限制，352.8 kHz 下长于约一小时的音轨需要计划中的 64 位版本。
- **解码器优先级。**由于内置 WAV 解码器也接受 `.wav`，组件在必要时会将自身置于解码器列表中内置 WAV 解码器之前，并请求重启 foobar2000 一次。可在高级设置中禁用这一调整。

该组件尚不能直接打开 CD-Extra 抓轨；需先使用 `lae_cdx read` 还原抓轨（第 10.8 节）。用法见第 14.8 节；安装方法和所显示的信息见 [plugins/foo_input_lae/README.zh.md](plugins/foo_input_lae/README.zh.md)。

## 14 使用

### 14.1 构建

代码为标准 C++17，不使用第三方库。编码器由 `src/lae_enc.cpp` 构建，解码器由 `src/lae_dec.cpp` 构建。

- **解码器源文件。**解码器使用 `src/lae_dec.cpp`、`src/lae_decoder.h`、`src/part_stream.h`、`src/partition_format.h`、`src/mdct_tb.h`、`src/mdct_tables.h`、`src/halfband.h` 和 `src/wavio.h`（[SPEC.md](spec/lossy/SPEC.md)）。
- **编码器源文件。**编码器会将解码器编译到同一可执行文件中。此外还使用 `src/partition.h`、`src/fft.h`、`src/pad_mirror.cpp`、`src/base_layer.cpp`、`src/routes.cpp`、`src/lossy_v2.cpp`（其中包含 `src/tone_scan.cpp`）、`src/part_coder.cpp` 以及 `src/cd_align.cpp`。
- **封装工具源文件。**`lae_cdx` 由 `src/lae_cdx.cpp` 构建，并使用 `src/lae_cdx.h`（尾部记录与校验和）、`src/lae_cdx_read.h`（读取器核心）和 `src/iso9660.h`（ISO 9660 和 Joliet）。
- **解码器库。**`liblae` 由 `src/lae_api.h` 和 `src/lae_api.cpp` 组成，基于 `src/lae_decoder.h` 构建。将其构建为 DLL 时定义 `LAE_API_BUILD`；静态链接时，在宿主和库中均定义 `LAE_STATIC`。

`lae_enc` 和 `lae_dec` 可在 Windows 上使用 MSVC 构建，也可在 Linux 上使用 GCC 和 Clang 构建；`lae_cdx` 已在 Windows 上用 MSVC 构建并测试。示例命令：

```
cl /O2 /EHsc /std:c++17 /D_USE_MATH_DEFINES src\lae_dec.cpp
g++ -O2 -std=c++17 -ffp-contract=off -D_USE_MATH_DEFINES -pthread -o lae_dec src/lae_dec.cpp
g++ -O2 -std=c++17 -ffp-contract=off -D_USE_MATH_DEFINES -pthread -o lae_enc src/lae_enc.cpp
```

构建命令（Windows，MSVC；与 `lae_enc` 使用相同标志）：`lae_cdx` 使用 `cl /nologo /O2 /EHsc /std:c++17 /utf-8 /D_USE_MATH_DEFINES /D_CRT_SECURE_NO_WARNINGS /bigobj src/lae_cdx.cpp`。`liblae` 由 `src/lae_api.cpp` 以 `/fp:precise` 编译；已验证的标志见 `plugins/foo_input_lae/build_fb2k.cmd`。

其他构建说明：

- 使用 MSVC 构建编码器时，添加 `/bigobj`。
- 使用 GCC 或 Clang 构建 32 位 x86 时，添加 `-msse2 -mfpmath=sse`。
- 不要使用 `-ffast-math`、`/fp:fast` 或任何允许 FMA 收缩的选项（第 13.1 节）。

所有选项、已验证的构建和检查脚本见 [docs/BUILD.md](docs/BUILD.md)。

### 14.2 编码

```
lae_enc <master.wav> <output.wav> [mode] [s1 | s2] [zs] [cd=<cd.wav>] [energy] [equal] [cdcheck] [cdalign=<offset>] [cdaccept] [bits=24]
```

| 参数 | 含义 |
|---|---|
| `master.wav` | 立体声整数 PCM WAV，16/24/32 位（32 位输入见第 3.1 节）。采样率为 88.2/176.4/352.8 kHz（44.1 kHz 系列）或 96/192/384 kHz（48 kHz 系列）。 |
| `mode` | `max`、`1`、`3`（默认）、`5`、`keep`、`keep20`（第 11.1 节）。模式为位置参数：只要使用任何后续参数，就必须提供模式。 |
| `s1` / `s2` | 方案 1，高质量（默认）/方案 2，高压缩。两者的 CD 频带相同，差异仅在频率层。 |
| `zs` | 可选零级别（第 8.4 节）；默认关闭 |
| `cd=<file>` | 独立 CD：母带所属系列基础采样率（44.1/48 kHz）的 16 位立体声 WAV；其采样原样写入 CD 层。CD 按第 4.3 节所述方式对齐。未提供 `cdalign=` 时，编码器报告两种搜索的结果，不写入任何内容。 |
| `cdalign=<offset>` | 已确认的偏移，以母带采样为单位；正值表示 CD 起点较晚。可以是整数，或以 `.` 为小数点、最多 9 位小数的数值（`cdalign=1,5` 会被拒绝）。使用编码器打印的偏移会得到相同的文件。 |
| `cdcheck` | 执行对齐检查但不编码（退出代码 0）。未提供 `cdalign=` 时，报告两种搜索的结果；提供 `cdalign=` 时，最后一行注明 “would encode”、“would ask for confirmation” 或 “would not encode”。 |
| `cdaccept` | 当剩余时间差超出 −40 dB（第 4.3 节的确认区间）时，不经询问继续 |
| `bits=24` | 对于最低 8 位并非全为零的 32 位母带：不经询问直接使用高 24 位（第 3.1 节） |
| `energy` | 按能量衡量保留比例（模式 `max`、`keep` 和 `keep20` 使用各自的度量方式） |
| `equal` | 只使用等分（对半）切分 |

编码器说明：

- 输出 WAV 的音频就是 CD 层；扩展位于 `LAE ` 块中。
- 无法识别的参数会报告为错误，编码器随即停止。
- 使用 `cd=` 时，编码器会打印对齐结果。未提供 `cdalign=` 时，打印两种搜索的结果以及 `ALIGN_SUGGEST …` 行，退出代码为 1。提供 `cdalign=` 时，打印 `PLACE …`、`ALIGN_RECHECK …` 和 `PHASE t=<whole> phi=0 move=<move> offset=<offset>` 行。编码成功后，写入移动报告 `<output>.align.txt`（第 4.3 节）。
- 编码器使用与逻辑核心数相同数量的线程。环境变量 `PARTTHREADS` 可覆盖此值。线程数不会影响结果。
- 编码器会将整条音轨载入内存处理。Windows 构建目前接受的母带长度上限为：352.8 kHz 下约 12.7 分钟，192 kHz 下约 23 分钟，96 kHz 下约 46 分钟（按采样数计，与位深无关）；对于更长的母带，编码器会停止并给出说明（第 17.2 节）。
- **失败处理。**每项文件操作都会经过检查。遇到磁盘已满、内部错误、内存不足或中断时，编码器会停止并给出原因，不写入输出文件，并删除其临时文件。输出先写为 `<output>.part`，只有在回读并验证之后才会重命名；若运行失败，已存在的同名文件保持不变。运行开始前会检查可用磁盘空间。

开发期间测得的编码性能：

- **单个任务（2026-10-16；[docs/BUILD.md](docs/BUILD.md)，第 5 节）。**在 Windows x64 上，以 16 线程对 352.8 kHz、40 s 的立体声母带进行模式 3 编码，用时 113 s（约为实时速度的 0.35 倍）。峰值内存为 1.35 GB。
- **三个并行任务，每个任务使用 8 个线程（2026-10-17）。**编码 40 s 音频用时：
  - 352.8 kHz：160–260 s；
  - 176.4/192 kHz：90–140 s；
  - 96 kHz：45–65 s。

  单个任务的速度约快一倍。

### 14.3 解码

```
lae_dec <input.wav> <output.wav> [full | 16 | cd24] [output rate]
```

| 路径 | 使用的层 | 输出 |
|---|---|---|
| `full`（默认） | CD + 位深 + 频率 | 母带采样率或所选较低倍频程，24 位 |
| `16` | CD + 频率 | 同上；CD 频带为 16 位精度 |
| `cd24` | CD + 位深 | 44.1/48 kHz，24 位 |

在 `full` 和 `16` 路径中，输出采样率可以是母带采样率，或低至基础采样率两倍的任意较低倍频程；其他采样率会被拒绝。所选倍频程以上的频率数据流不会读取或解码。

解码器采用单线程流式处理：

- 每次解码一行根块（8 帧），并逐帧执行重叠相加；
- 重采样级通过短滑动窗口提取采样；
- 除输入数据外，其内存占用不会随音轨长度增长。目前会将 CD 层和扩展块整体读入内存。

`lae_dec` 使用第 13.6 节的解码器库。

开发期间测得的解码性能：

- **单个任务（2026-10-16；[docs/BUILD.md](docs/BUILD.md)，第 5 节）。**在 Windows x64 上，以 24 位路径解码 352.8 kHz、40 s 的文件，用时 2.8 s（约为实时速度的 14 倍）。峰值内存为 38 MB。
- **三个并行任务（2026-10-17）。**以 24 位路径解码 40 s 音频用时：
  - 352.8 kHz：3–5 s；
  - 176.4/192 kHz：2–3 s；
  - 96 kHz：约 2 s。

### 14.4 示例

```
lae_enc master_352k.wav track_352k.wav                     # mode 3, scheme 1
lae_enc master_352k.wav track_352k_max.wav max s2          # smallest extension
lae_enc master_192k.wav track_192k.wav keep20 s1           # 20-bit depth layer
lae_enc master_96k.wav track_96k.wav 3 s1 cd=cd_48k.wav    # independent 48 kHz CD: reports both searches, writes nothing
lae_enc master_96k.wav track_96k.wav 3 s1 cd=cd_48k.wav cdalign=<offset>   # encode at the confirmed offset
lae_enc master_96k.wav track_96k.wav 3 s1 cd=cd_48k.wav cdalign=<offset> cdcheck   # check only
lae_dec track_352k.wav out_full.wav                        # 24 bit, 352.8 kHz
lae_dec track_352k.wav out_176k.wav full 176400            # 24 bit, one octave down
lae_dec track_352k.wav out_cd24.wav cd24                   # 24 bit, 44.1 kHz
```

### 14.5 整盘规划器

```
lae_enc plan <master.wav> [<master2.wav> …] <publisher.cue> <out dir> [cdalign=<p1>,<p2>,…] [cdaccept]
```

- `<publisher.cue>` 描述发行方的光盘（CUE 加 BIN 或 WAV）。
- 未提供 `cdalign=` 时，规划器在整个规划范围内执行两种搜索，打印各位置以及一行 `PLAN_SUGGEST whitened=<status>:<positions> plain=<status>:<positions>`，不写入任何内容，并以退出代码 1 退出。
- `cdalign=<p1>,<p2>,…` 为每个分段给出一个值：该分段 CD 帧 0 所在的母带采样，允许带小数；对于在 CD 上为数字静音的分段，给出 `-`。
- `cdaccept` 确认落入确认区间的分段。
- `<out dir>` 中的输出：每个分段的 `TRACKnn.master.wav` 和 `TRACKnn.cd.wav`，以及报告 `plan.align.txt`。

从发行方光盘到 CD-Extra 映像的处理链（第 4.5 节）：

```
lae_enc plan album.wav publisher.cue planned                                  # report both searches; nothing written
lae_enc plan album.wav publisher.cue planned cdalign=<p1>,<p2>,…              # after confirmation: move and cut
lae_enc planned/TRACK01.master.wav planned/TRACK01.v5.wav 3 cd=planned/TRACK01.cd.wav cdalign=0   # each piece
lae_cdx image <image dir> planned/TRACK*.v5.wav layout=publisher.cue                  # CD-Extra image
```

模式（此处为 `3`）必须作为第三个参数给出。在规划器中以 `cdaccept` 确认的分段，编码时也必须使用 `cdaccept`。

### 14.6 CD-Extra 封装与读取

`lae_cdx` 提供命令 `pack`、`split`、`repack`、`image`、`data`、`read`、`sim`、`selftest` 和 `test`。

**映像。**

```
lae_cdx image <image dir> <track1.v5.wav> <track2.v5.wav> … [label=<album>] [noext=<n>,<m>,…] [layout=<publisher.cue>]
```

- `<image dir>` 必须是新目录或空目录。
- `label=` 设置数据会话的卷标。
- `noext=` 将所列音轨仅作为 CD 发布，例如在容量不足时。
- `layout=` 选择发行方光盘的独立 CD 布局（第 10.5 节）。

每个输入 v5 文件首先须通过解码器的全部检查。只有在闭环自检（第 10.9 节）之后才交付映像。刻录说明 `BURN.TXT` 描述两种路线：路线 A 一次写入 `IMAGE.CUE`；路线 B 分两步写入，第二步使用 `lae_cdx data` 按驱动器实际报告的起始地址生成会话 2。

**读取。**

```
lae_cdx read <output dir> <disc>\LAE <rip>\RIP.CUE
```

第二个参数是包含扩展文件的文件夹，例如光盘数据会话中的 `LAE` 文件夹或其副本。最后一个参数是抓轨：整盘或逐轨抓轨，带或不带 CUE 表，可采用任何偏移。输出见第 10.8 节。

**其他命令。**命令 `pack`、`split` 和 `repack` 在 v5 WAV 文件、基础层文件和扩展文件之间进行转换（第 10.7 节）。`sim`、`selftest` 和 `test` 用于测试。其参数如下：

```
lae_cdx pack <v5.wav> <out.lax> [track=N]              # the extension file of one track
lae_cdx split <v5.wav> <base.wav> <ext.lax> [track=N]  # base-layer WAV + extension file
lae_cdx repack <base.wav> <ext.lax> <out.v5.wav>       # base-layer file + extension file -> v5 WAV
lae_cdx sim <imagedir> <outdir> <form> [offset=N] [pregap=1] [overread=N] [change=K] [slip=K]   # simulated rips (tests)
lae_cdx selftest                                       # known answers
lae_cdx test <fixturedir>                              # the test cases on the test discs
```

### 14.7 解码器库（liblae）

最简解码流程：

```c
char err[256];
lae_track* t = lae_open_file("track.wav", err, sizeof err);   /* UTF-8 path */
if (t && lae_selftest() && lae_start(t, LAE_ROUTE_FULL, 0, err, sizeof err) == 0) {
    int rate, bits; uint64_t frames;
    lae_output_format(t, &rate, &bits, &frames);
    int32_t buf[2 * 4096];
    int64_t n;
    while ((n = lae_read(t, buf, 4096)) > 0) { /* n interleaved stereo frames */ }
}
lae_close(t);
```

- `out_rate` 为 0 时，对路径 `16` 和 `full` 选择母带采样率，对 CD 和 `cd24` 路径选择基础采样率。
- `lae_seek(t, frame)` 以逐位精确的方式定位到某个输出帧（第 13.6 节）。
- `lae_stats` 返回限幅计数和数据流错误标志；`lae_stream_bytes` 返回已消耗的熵编码字节数。
- `lae_open_memory`、`lae_open_reader`、`lae_open_pair` 和 `lae_open_pair_files` 用于从内存、通过宿主读取回调，或从基础层及其扩展文件打开音轨。
- 宿主要求 `lae_api_version()` 不低于其构建时所依据的版本。

完整接口的说明见 `src/lae_api.h`。

### 15.2 现有技术

LAE Lossy 基于以下已公开技术构建：

- **MDCT。**采用教科书形式的 MDCT，其中 DCT-IV 通过带前、后旋转因子 $\exp(-i 2\pi (n + 1/8)/(2N))$ 的复数 FFT 计算。该旋转因子形式于 2002-10-28 发布在 FFmpeg `libavcodec/mdct.c` 中（提交 `bb6f569`）[6]。
- **量化。**标量死区量化。
- **熵编码。**自适应二进制范围编码。
- **重采样。**半带 FIR 抽取和插值。
- **抖动。**TPDF 抖动。
- **立体声。**整数中/侧提升变换。

独立 CD 的对齐和封装使用以下已公开技术：

- **时延估计。**互相关以及带相位变换的广义互相关（GCC-PHAT）[12]，按由粗到精的方式应用。
- **插值。**采用 Kaiser 窗的带限加窗 sinc 插值 [13]。
- **分数延迟。**分数延迟滤波 [14]。
- **文件系统。**ISO 9660 [5] 及 Joliet 扩展 [15]。
- **光盘布局。**音频会话后接数据会话的 CD-Extra（Enhanced CD）多会话布局 [4]。
- **完整性。**MD5 消息摘要 [16]，按 FLAC STREAMINFO 块 [1] 的方式对音频采样计算；以及 CRC-32 [9]。
- **校验和。**窗口沿序列滑动时可增量更新的模加和。

## 17 局限与未来工作

### 17.1 格式与等级

- **LAE Lossless（LAES）。**存在全部层时，无损等级将逐位精确地重建母带；规范性规范尚未编写。2026-10-18 设计文档（[spec/lossless/DESIGN.md](spec/lossless/DESIGN.md)，复核中）之后已定的方向：LAES 与 LAEY 使用同一条对齐、封装和读取链，扩展块类型为 2（已保留）；CD-Extra 只放得下其中"CD + 24 位 / 44.1 kHz"的子集，完整无损版以 BD 或文件发行；与 FLAC 兼容的封装形式在设计中（未定）。
- **容器。**WAV 容器和 CD-Extra 封装均已实现。封装规范为草案，将在完成真实刻录的测量之后修订（第 17.3 节）。`.lae` 文件布局仍未规定。
- **声道。**目前仅支持立体声。

### 17.2 编码器

- **流式编码器。**由于模式比例属于整条音轨范围的统计值，编码器会处理整条音轨。其内存随长度线性增长：352.8 kHz、40 s 音频约需 1.35 GB。因此，Windows 构建只接受最长约 12.7 分钟的 352.8 kHz 母带（192 kHz 约 23 分钟，96 kHz 约 46 分钟）。整盘规划器会将整个母带保存在内存中。后续将设计分段流式编码器，编码器的速度和内存问题也有待解决。
- **对齐搜索的局限。**对于短小或窄带材料，搜索可能失败，此时编码器会停止。例如：单一持续音的 2 s 片段、以单个低音为主的 2–3 s 段落，以及完全位于约 1.2 kHz 以上、超出第 0 级频带的内容。此时用户需通过 `cdalign=` 手动给出位置。
  - 被数字静音包围的严格周期性合成信号（音调、锯齿波、循环）可能在相差整整一个周期的位置被匹配。这正是每个位置都须由用户确认的原因（第 4.3 节）。
  - 当声音长于约 3.6 分钟时，搜索的第 0 级使用较低的采样率；计划对此加以改进。
  - 声音超过约 1 小时 55 分钟时，不执行搜索，必须通过 `cdalign=` 给出位置。
- **内容不同。**非静音内容不同的母带和 CD 不会被组合：只有一方具有的声音（长度达一个 CD 采样或以上）会使编码器和规划器停止。组合此类材料属于未来工作。
- **噪声移除导出界面。**该界面尚未实现。该界面计划：
  - 显示波形和频谱视图；
  - 提供试听；
  - 允许用户移除选定的噪声区域（A 类）。

  在该功能实现之前，母带中的所有噪声都会保留。
- **闭环重新验证。**使用注入音调和点击声，对标记闭环的结构保留测试将在 v5 上重新进行。
- **检测器文档。**瞬态检测器的统计特性将补充文档说明（第 7.4 节）。

### 17.3 工具与验证

- **真实独立 CD 组合。**目前仅使用由母带派生、并施加了均衡、限幅、增益变化、延迟、降噪、门限处理、剪辑和漂移的 CD 测试对齐。使用市售真实独立 CD 与母带组合的测试尚待进行。
- **CD-Extra。**封装工具尚未在真实刻录上测试。以下事项待完成：
  - 通过第 14.6 节的两种路线对映像进行刻录测试；
  - 确认第 11.5 节的多会话开销以及数据音轨起点 A2 + 11,400 个扇区；
  - 数据音轨末尾零扇区的数量；
  - 数据会话中 CD-ROM XA 标记（工具目前不写入该标记）的影响；
  - 使用真实 CD 播放器，以及在 Windows、macOS 和 Linux 上读取数据会话的兼容性测试。
- **lae_cdx。**为整张 74 分钟光盘生成映像时，内存峰值约为 3.5–4 GB。规范也定义了 FLAC 基础层文件和从驱动器读取的 TOC，`lae_cdx` 尚未实现：读取器拒绝 FLAC 输入，并从 CUE 表或文件的顺序和长度获取 TOC。
- **播放器组件。**适用于 foobar2000 2.x 的 64 位构建尚待完成。该组件尚不能直接打开 CD-Extra 抓轨。
- **待完成的测量和测试。**
  - 为规范编制半带滤波器特性说明；
  - 在其他 ARM 系统（32 位 ARM、ARM 上的 macOS）上构建并检查自检指纹；
  - 测量泄漏补偿项对 `cd24` 路径的影响（第 6.5 节）；
  - 分析 176.4 和 352.8 kHz 下 Synth 的 CD 频带数值（第 12.3 节）；
  - 播放器兼容性测试；
  - 听音测试。
- **音质估算器。**第 12.1 节所用音质指标的精确定义将写入测试文档。
- **规范性文本。**SPEC.md 规定了 M/S 提升变换、抖动生成器及其种子、熵编码器的二值化、数据流头部字段 K 和滤波器表。其待办事项（[SPEC.md](spec/lossy/SPEC.md)，附录 C）包括：
  - 测试向量的完整 SHA-256 数值；
  - 将 `src/mdct_tables.h` 作为规范性附录；
  - 解码器是否必须拒绝采样率与基础采样率不同的 `fmt `；
  - 数据流头部字段 `rate` 和 `L` 的取值，以及最后一个数据流之后是否允许有字节；
  - 半带累加器的 64 位溢出保证上界；
  - 是否必须检查整个数据流的损坏情况，还是只需检查所选路径需要的部分；
  - `.lae` 文件布局和 FLAC 封装（封装规范已在其适用范围内解答 FLAC 问题：基础层采用 FLAC，扩展位于单独文件中；第 10.7 节）；
  - 编码器的边界填充方式及其叶节点指数定义。

### 17.4 已知工作限制

- **模式间隔。**真实录音中，从 `max` 到 `keep` 的相邻模式大小变化中位数仅约为 0.3–3.6%（第 11.4 节）。
- **最差播放时长。**在候选发布轮次中，352.8 kHz、方案 2、max 模式、24 位路径的最差结果在 4% 余量下比 40 分钟目标少 0.8 分钟。该结果基于未包含在已发布数据中的录音（第 11.5 节）。
- **被削波的 CD 内容。**16 位路径无法恢复 CD 层必须削波的内容（第 12.3 节）。
- **`full` 路径之外的泄漏。**频率层向 CD 频带的泄漏仅在 `full` 路径中得到补偿（第 6.5 节）。
- **高采样率下的 Synth。**Synth 信号在 176.4 和 352.8 kHz 下的 24 位路径 CD 频带误差（−96 和 −82 dBFS）明显差于 88.2 和 96 kHz。原因尚未分析（第 12.3 节）。
- **随移动带出的采样。**若母带的移动将采样带到没有任何分段取用母带采样的位置（母带的最开头或最末尾，或仅母带具有的间隙），这些采样不会保留。规划器会报告发生这种情况的位置以及涉及的采样数；用户可在该位置为母带和 CD 同时添加至少 1 ms（44 个 CD 帧）的数字静音（第 4.5 节）。
- **硬切母带。**声音一直延续到第一个或最后一个采样的母带，在分数移动之后，CD 层两端会保留若干帧数字静音（第 4.3 节）。
- **向前定位。**向前定位越过已解码部分时，需要熵解码到目标位置，因为 v5 未定义随机访问点（第 13.6 节）。
- **采样率系列。**编码器不执行有理数比例重采样。
  - 48 kHz 系列母带与 48 kHz 基础层组合。若要与 44.1 kHz CD 组合，仍需在母带制作阶段处理。
  - 48 kHz 基础层面向 DVD、蓝光和文件分发；CD-Extra 仅适用于 44.1 kHz 系列。
