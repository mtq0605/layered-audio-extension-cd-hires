# Measurement data

## Contents

- [SIZES.md](SIZES.md): Readable size tables (MB per minute) for every mode, scheme and sample rate, generated from the CSV file described below.

`loop10_v5_release_candidate.csv` contains the results of the test round for the release candidate of the LAE Lossy codec for container version 5 (the "v5 release candidate"). This round is named "loop10" in the file name and is called the "release-candidate round" in the [README](../README.md). It was measured during development on 2026-10-16.

The procedure was as follows:

1. 10-second stereo excerpts were encoded with both schemes (`s1`, `s2`) and in all six modes;
2. each encoded file was decoded;
3. each decoded file was compared with its source excerpt.

## Build

The release candidate differs from the published codec for container version 5 in the reconstruction of zero coefficients. Because the encoder decodes its own layers while encoding, this also changes the encoded sizes: on the same excerpts, the published v5 encoder produces frequency-layer sizes that are 0.01–0.3 % smaller and an SNR that is 0–0.6 dB higher.

## Coverage

- **Recordings.** The measurements of recordings at 88.2–192 kHz are included, anonymised. The recordings themselves are third-party recordings and are not distributed.
- **Synthetic signals.** These are generated by `src/gen_suite.cpp`.
- **352.8 and 384 kHz.** At these rates, the data contain synthetic signals only. The README figures for recordings at 352.8 kHz are therefore not part of these data.
- **Classes.** The `type` column distinguishes only between recordings and synthetic signals. The README classes "DSD-converted" (recordings) and "Synth" (a synthetic stress signal) are not marked separately within these two types.

## Columns

- `item`, `type`: Recordings are anonymised (`rec01`, `rec02`, …) and have the type `recording`. Synthetic test signals keep their names and have the type `synthetic`.
- `rate`: Sample rate of the master, in Hz.
- `scheme`, `mode`: Encoder settings ([README](../README.md), Section 11).
- `cd_bytes`, `depth_bytes`, `frequency_bytes`: Size of the PCM of the CD layer and of the two extension layers (the depth layer and the frequency layer).
- `encode_s`, `encode_MB`, `decode_s`: Encoding time, peak encoder memory and decoding time. The encoder ran three jobs in parallel, with 8 threads each. `decode_s` is the time of one decode on the 24-bit route (`lae_dec`, single-threaded), run inside the same jobs, so up to two other jobs ran at the same time.
- `cdband_err_24bit_dB`, `cdband_err_16bit_dB`: Error level in the CD band on the 24-bit and 16-bit decode routes ([README](../README.md), Section 3.4: with and without the depth layer).
- `hf1_err_dB` … `hf3_err_dB`: Error level in the ultrasonic bands (octaves of the rate family; see the note below for the 48 kHz family). A cell is empty where the master has no such band.
- All error levels are relative to full scale and are the mean of the two channels. They are computed by `src/cmp_wav.cpp`.
- `snr_dB`, `peak_err_dBFS`, `worst10ms_err_dBFS`: Waveform match of the decoded output against the source excerpt.
- `limiter_samples`: Number of samples on which the final hard limiter of the decoder acted.
- `o2_equals_od`: Whether the optimised and unoptimised decoder builds produced byte-identical output. This was checked for scheme `s1`, mode `3`; the column is empty for the other schemes and modes.

## Note on the ultrasonic bands of the 48 kHz family

In this round, `src/cmp_wav.cpp` placed the upper ultrasonic band edges at 44.1, 88.2 and 176.4 kHz for every master. For 96 kHz and 192 kHz
masters, the columns `hf1_err_dB` … `hf3_err_dB` therefore cover 24–44.1, 44.1–88.2 and 88.2–176.4 kHz rather than the octaves of the
48 kHz family; a band ends at the master's Nyquist frequency where that is lower (for example, `hf2_err_dB` of a 96 kHz master covers
44.1–48 kHz). The tool has since been corrected; the CSV keeps the values of this round, and the other columns are not affected.
