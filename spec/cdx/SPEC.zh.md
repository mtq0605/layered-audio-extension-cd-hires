**范围。** 本文件规定 LAE Lossy（LAEY）容器版本 5 的扩展层如何封装于以下三类载体并从中读取：CD-Extra 光盘、普通文件（包括 DVD 和 BD 数据光盘上的文件）以及 LAE 流。本文件规定：

- CD-Extra 布局；
- 扩展文件（.LAX）及其尾部记录的字节格式；
- 基础层文件与扩展文件的配对；
- 将经过验证的 CD 层及其扩展块重新封装为 v5 WAV 文件；
- 对封装工具和读取器的要求；
- 一致性测试用例。

v5 比特流及其解码由 [SPEC] 规定，本文件不对其作任何改动。封装工具 `lae_cdx`（子命令 `pack`、`split`、`repack`、`image`、`data`、`read`、`sim`、`selftest` 和 `test`；`image` 执行 5.5 的闭环自检）及其读取器核心实现本草案。附录 A 所列的实际刻录和抓取测量完成后，本草案将予以修订。

## 1. 范围与术语

### 1.1 范围

本规范规定：

- CD-Extra 的布局（第 2 章）；
- 扩展文件 .LAX 的字节格式（第 3 章）；
- CD 以外的形式，即普通文件（包括 DVD 和 BD 数据光盘上的文件）和 LAE 流，以及它们重新封装为 v5 WAV 的方式（第 4 章）；
- 封装工具和读取器必须达到的结果（第 5 章和第 6 章）；
- 一致性测试用例（第 7 章）。

44.1 kHz 的限制仅适用于 CD（CD-Extra，红皮书）。DVD、BD 及其他数据光盘不采用第 2 章的布局，而是按第 4 章的规定存储普通文件，并且可以使用 44.1 kHz 系列或 48 kHz 系列。

本规范不规定：

- v5 比特流及其解码（见 [SPEC]）；
- LAE Lossless（LAES）扩展块的内容。尾部记录将此类扩展块标识为类型 2（[X2]，第 8 章）；其内容及其与 CD 层的关系由 LAES 规范（spec/lossless/SPEC.md，第 9 章）规定，本规范的布局和读取规则原样适用于它；
- 逐层来源信息（见第 8 章）；
- 放置、搜索及其他算法的具体实现；
- LAE 流的传输（协议、分段、缓冲）；
- 用户界面。

### 1.2 与容器版本 5 的关系

- 本规范不要求对容器版本 5 或解码器（[DEC]）作任何改动。
- 扩展文件中的扩展块与 v5 WAV 文件中 `LAE ` 块的主体逐字节相同（[SPEC] 3.3）。
- 此处规定的全部内容均位于容器版本 5 之外：CD 布局、尾部记录、文件配对以及 LAE 流的交付。本规范有其自身的版本号（第 8 章）。
- `.lae` 仍保留用于 [SPEC] 1.1 的完整文件布局。`.LAX` 是另一类文件。
- [SPEC] 附录 C 第 7 项问的是 FLAC 如何承载 LAE；该项现已标为"已完成"：[SPEC] 3.4 的单文件 FLAC 形式把扩展放在 `LAE1` APPLICATION 块里。本规范另加 4.2 的分文件形式：FLAC 或 WAV 文件仅承载基础层，扩展层置于随附的 .lax 文件中，该文件的格式与 CD 上的扩展文件相同。

### 1.3 关键词与条款标识

- 本文件中的关键词"必须"、"不得"、"应"、"不应"和"可"分别对应英文版中以全大写形式出现的"MUST"、"MUST NOT"、"SHOULD"、"SHOULD NOT"和"MAY"，按 BCP 14（RFC 2119、RFC 8174）所述解释。
- 每条规范性条款均带有方括号内的标识，例如 [L1]。第 7 章的测试用例逐条覆盖这些条款。
- 标注为"资料性"的段落仅作说明，不施加任何要求。

### 1.4 术语

| 术语 | 定义 |
|---|---|
| 样本 | 一个立体声帧：L 和 R 各一个 int16 |
| 扇区 | 588 个样本（2352 字节），1/75 s |
| 数字静音 | L 和 R 均精确为 0 的样本。仅含抖动噪声的段落不是静音，而是内容 |
| CD 层 | 一条音轨的 16 位 PCM，即该音轨 v5 文件中 data 块的内容。其长度为 ncd 个样本 |
| 扩展层 | v5 的 `LAE ` 块：位深层加频率层，编码"母带 − CD" |
| 扩展块 | `LAE ` 块的完整主体，共 n 字节，包括主体末尾的 CRC-32。注：[SPEC] 3.3 的有效载荷仅包括第 0 … n−5 字节，不含 CRC，因此与扩展块不同 |
| 扩展文件 | 扩展块加尾部记录。文件扩展名在 CD 上为 .LAX，在文件分发和 LAE 流中为 .lax（第 3 章） |
| 尾部记录 | 占据扩展文件最后 80 字节的固定记录（3.2） |
| 整轨 MD5、S1、S2 | 见 3.3 和 3.4 的定义 |
| lead0、tail0 | CD 层开头和结尾连续数字静音样本的数量，存储于尾部记录中（3.2） |
| 信息区间 | CD 层中从第一个非零样本到最后一个非零样本的部分，即 CD 层的第 lead0 … ncd − tail0 − 1 个样本 |
| 区段 1 / 区段 2 | CD-Extra 的音频区段 / 数据区段。CD 播放机仅读取区段 1 |
| LBA | CD 的逻辑块地址（MMC），两个区段通用。LBA 0 = 绝对时间 00:02:00。[L4] 要求音轨 1 的 INDEX 01 位于 LBA 0 |
| 绝对位置 | LBA × 588 + 样本在扇区内的序号，以样本计 |
| TOC | CD 的目录 |
| p_k | 音轨 k 的 INDEX 01 的绝对位置 |
| A2 | 区段 1 导出区起点的 LBA（扇区）。对应的绝对位置为 A2 × 588 |
| 标称位置 q_k | 音轨 k 的 CD 层第一个样本的绝对位置；q_k = p_k，但在 [L6] 的例外情形下 q_1 = −L |
| 填充 z_k | 音轨 k 的 CD 层之后、将该音轨补足为整扇区的数字静音，0 ≤ z_k < 588（[L7]） |
| 起始保护区 | 音轨 1 的 CD 层之前的数字静音：至少 5880 个样本 = 10 个扇区 = 0.133 s。由音轨 1 的前间隙提供（[L5]） |
| 偏移 o | 光盘上音轨 k 的 CD 层第一个样本出现在光盘流的 q_k + o 位置。o > 0 表示在光盘流中靠后。o 综合了读取偏移和写入/压制偏移，各音轨之间可能不同。读取器不假定存在统一的整盘偏移 |
| 光盘流 | 读取器由其输入组装而成的样本序列（6.2）。有 TOC 时，按绝对位置寻址。无 TOC 时，由单个文件的样本构成，位置从该文件第一个样本起计 |
| 粗定位 / 精定位 | 粗定位：由 TOC 或信息区间得出的音轨近似起点。精定位：用 S1 和 S2 筛查粗定位附近的每个位置（无 TOC 时为文件的每个位置），并以整轨 MD5 确认结果（[R7]） |
| W | 精定位的搜索半径，W ≥ 5880 个样本（10 个扇区） |
| 滑移 | 音轨内样本的丢失或插入，例如由读取错误导致 |
| 派生模式 | CD 层由编码器从母带派生。这是当前的默认模式 |
| 独立 CD 模式 | 使用出版方现有的 CD 作为 CD 层（编码器选项 `cd=`，[ENC]） |
| CD 路线（回退） | 音轨验证失败时，仅输出抓取的 CD 音频，不使用扩展层 |
| LAE 流 | 逐轨交付逐样本未改动的 CD 层及其扩展文件（4.5） |
| 封装工具 | 生成 CD 镜像和分发文件的程序 |
| 读取器 | 读取抓取结果、文件或 LAE 流并输出高分辨率音频的程序；包括播放器插件 |

### 1.5 通用约定

- 所有多字节整数均为小端序，与 [SPEC] 2.1 相同。
- M = 2^61 − 1。
- CRC-32 与 [SPEC] 3.3 相同：
  - 反射多项式 0xEDB88320；
  - 初始值 0xFFFFFFFF，最终异或 0xFFFFFFFF；
  - 校验值：CRC-32("123456789") = 0xCBF43926；
  - 参考实现：src/part_stream.h 中的 `crc32`。
- 位置和长度以样本（立体声帧）计。

## 2. CD 布局

### 2.1 总则

**[L1]** CD 必须为双区段 CD-Extra。区段 1 为音频（2.2）；区段 2 为一条数据音轨（2.3）。

- CD 仅用于 44.1 kHz 系列。每个 CD 层的采样率必须为 44 100 Hz。
- 此限制仅适用于 CD。DVD 和 BD 数据光盘按第 4 章的规定存储普通文件，两个系列均允许使用。

**[L2]** 设 n 为音频音轨数，则必须满足 n + 1 ≤ 99。数据音轨也占用一个音轨号，因此音频音轨最多为 98 条。CD 最多提供 99 个音轨号；98 这一数字为推导值。

### 2.2 区段 1（音频）

```
absolute position  −150×588                 0 = p_1 = q_1               p_2 = q_2            p_n = q_n                 A2×588
                   | pregap 150 sectors, silence | CD layer 1 | padding z_1 | CD layer 2 … | CD layer n | padding z_n | lead-out
                   |<---- track 1 INDEX 00 ----->|<------ TOC track 1 ------->|<- track 2 … |<------ TOC track n ------>|
```

只有一条音轨（n = 1）时，TOC 音轨 1 = CD 层 + 填充 z_1。在 [L6] 的例外情形下，音轨 1 的 CD 层提前 L 帧，在前间隙内的 q_1 = −L 处开始。

**[L3]** 区段 1 必须一次写入（DAO/SAO）。除本节规定的内容外，区段 1 不得包含任何其他样本或间隙。

**[L4]** 音轨 1 的前间隙和 INDEX 01：

- 音轨 1 的 INDEX 01 必须位于 LBA 0。
- 音轨 1 的前间隙（INDEX 00）为 150 个扇区 = 88,200 个样本（推导），其内容必须为数字静音。
- 因此不支持隐藏音轨。
- 在独立 CD 模式下，若出版方音轨 1 的 INDEX 00 包含非静音内容，封装工具停止（[P10]）。

**[L5]** 起始保护区：音轨 1 的 CD 层之前必须有至少 5880 个数字静音样本。音轨 1 的前间隙（[L4]）满足此要求；因此不得在音轨 1 内（自其 INDEX 01 起）添加零。[L6] 例外情形中的前导帧位于 INDEX 01 之前的前间隙内，并在 CD 层之前保留前间隙中至少 5880 个样本。

**[L6]** 每条音轨的 CD 层均从 INDEX 01 开始：q_k = p_k（k = 1 … n），且 q_1 = 0，但以下情形除外。

例外（独立 CD 模式，仅限音轨 1）：音轨 1 的 CD 层可以 L 帧数字静音开始，这些帧位于音轨 1 的前间隙内、INDEX 01 之前，其中 0 ≤ L ≤ 82,320（= 150 × 588 − 5880，以保留 [L5] 的起始保护区）。此时 q_1 = −L，音轨 1 的 CD 层由这 L 帧以及其后出版方从音轨 1 的 INDEX 01 到音轨 2 的 INDEX 01 的样本构成（ncd_1 = p_2 − p_1 + L，其中 p_{n+1} = A2 × 588，与 [L7] 相同）。对于其他每条音轨，CD 层必须恰好从 INDEX 01 开始。若 L 超出此范围，或 L 帧中任何一帧不是数字静音，封装工具停止。

- 这 L 帧位于音轨 1 前间隙的数字静音之内，因此 [L4] 和 [L5] 仍然成立。它们不写入 AUDIO.BIN；刻录程序将前间隙写为数字静音（[P12]）。
- 从 LBA 0 起的区段 1 仍与出版方节目逐样本相同（[P11]）。
- 读取器在 −L 处找到音轨 1 的 CD 层：其尾部记录满足 lead0 ≥ L，因此基于信息区间的粗定位给出 −L（[R7]）；当 L ≤ W 时，围绕 p_1 的精定位也能覆盖该位置。若前间隙未被抓取，这些位置未知并按 0 读取，与静音相同。

*资料性。* 当母带的声音起点比出版方音轨 1 早不到一个 CD 样本时，整盘规划器添加一帧此类静音（[P9]）；编码器选项 `cdedge=pad` 可在 CD 层之前添加更多帧数字静音。

**[L7]** 音轨末尾填充：每条音轨的 CD 层必须完全位于 TOC 所给出的该音轨范围之内。

- 设 z_k = p_{k+1} − q_k − ncd_k（k = 1 … n），其中 p_{n+1} = A2 × 588。必须满足 0 ≤ z_k < 588。
- 这 z_k 个填充样本必须为数字静音。其数量至多为 587 个，即 13.3 ms（推导）。

**[L8]** 结尾：最后一条音轨的 CD 层与导出区之间只有最后一条音轨的填充 z_n（[L7]）。不得添加保护音轨，也不得在此处添加其他静音。最后一条音轨 CD 层的结尾由其长度 ncd_n 给出（[R6]）。

**[L9]** 音轨 1 的前间隙和填充均不属于任何音轨的 CD 层，但 [L6] 例外情形中的 L 个前导帧除外，它们属于音轨 1 的 CD 层。前间隙的其余部分和填充不包含在 v5 文件或扩展文件中，也不改变解码长度。

**[L10]** 每条 TOC 音频音轨必须由整数个扇区构成，且不得短于 300 个扇区（4 s）。读取器不要求 ncd 为 588 的倍数。

**[L11]** 不得设置预加重标志（FLAGS PRE）。若出版方 CD 使用预加重，封装工具停止（[P10]）。

**[L12]** 区段 1 的 PCM 仅包含 CD 层、音轨 1 前间隙的数字静音和填充。不得在 PCM 中嵌入任何形式的数据或标记。

**[L13]** 派生模式：

- 自音轨 2 起不设置 INDEX 00；前间隙为 0。
- 对于连续母带（[P5]），除最后一条音轨外每条音轨的 z_k = 0，各 CD 层首尾相接，无间隙。
- 对于最后一条音轨以及逐轨母带（[P6]）的每条音轨，z_k 按 [L7] 确定。

**[L14]** 独立 CD 模式：

- 出版方 CD 的 INDEX 标记、ISRC 和 FLAGS 必须保留在与出版方 CD 相同的位置。INDEX 标记包括自音轨 2 起的 INDEX 00 以及每条音轨的 INDEX 02 及以上。音轨 1 的前间隙始终按 [L4] 处理。
- 音轨 k 的 CD 层由出版方音轨 k 的 INDEX 01 到音轨 k+1 的 INDEX 01 之间的全部样本构成，包括音轨 k+1 的 INDEX 00。因此 z_k = 0。
- 最后一条音轨的 CD 层从最后一条音轨的 INDEX 01 延伸到出版方节目的结尾。出版方的每条音频音轨均由整数个扇区构成。因此 z_n = 0。

*资料性。*

- 有 TOC 时，读取仅使用 INDEX 01 的位置。INDEX 00、INDEX 02 及以上以及 ISRC 不影响读取。
- 保护区不改变任何音轨的音频：
  - 起始保护区是每张 CD 都有的音轨 1 前间隙，结尾不添加静音；
  - 区段 1 的每条音轨由其 CD 层加不足一个扇区的填充构成；
  - 逐轨抓取的文件除音轨末尾不足一个扇区的填充 z_k（[L7]）外，不含任何添加的零。
- 区段 1 超出各 CD 层总长度的部分仅为填充，每条音轨不足一个扇区。

### 2.3 区段 2（数据）

**[D1]** 区段 2 必须恰好包含一条数据音轨，采用 CD-ROM XA Mode 2 Form 1 格式，每扇区 2048 字节用户数据。CD 上任何位置均不得出现 Mode 1 扇区。Joliet 规范（1995-05-22）不允许在多区段光盘上使用 Mode 1 扇区（一手来源）。

**[D2]** 文件系统：

- 文件系统必须为 ISO 9660 Level 1 + Joliet。
- 卷描述符从数据音轨 INDEX 01 的 LBA 起计：
  - +16：主卷描述符；
  - +17：Joliet 补充卷描述符；
  - +18：终止符。
- 所有地址均为绝对 LBA。
- 不使用 Rock Ridge、UDF 和 El Torito。

**[D3]** 区段 2 数据音轨 INDEX 01 的 LBA（ISO 9660 卷的扇区 0）必须等于写入时驱动器报告的下一个可写地址。

- 对于一次写入的镜像，该 LBA 预先计算为 A2 + 11,400 个扇区。11,400 = 6,750 + 4,500 + 150，依次为区段 1 的导出区、区段 2 的导入区和数据音轨 150 个扇区的前间隙（一手来源；待实测，附录 A.1 第 1 项）。
- 对于两步写入，该 LBA 依据实际报告的地址生成（[P15]）。

**[D4]** 目录：

- 必须存在 `/README.TXT`。
- 目录 `/LAE/` 仅包含 `TRACKnn.LAX` 文件：每条带扩展的音频音轨一个。nn 为该音轨在 TOC 中的两位音轨号（01–98）。
- 数据区段不得包含 CUE 文件、TOC 副本、报告、程序或 autorun.inf。
- 其他文件（例如内页册子或封面）由出版方自行决定。读取器忽略它们。

**[D5]** README.TXT：

- 应为中英文说明，采用 UTF-8 编码。说明该光盘是什么、区段 1 可在任何 CD 播放机上播放，以及如何获得高分辨率音频。
- 不得包含哈希、位置、偏移或长度表。
- *资料性：参考工具（自 2026-11-15 起）。*工具写出的 README.TXT 和 BURN.TXT 写明：音轨要抓成 WAV 或 FLAC（16 位、44.1 kHz），MP3 之类的有损格式不能用。

**[D6]** 数据音轨的结尾：

- 数据音轨的结尾应以零扇区填充，初始为 150 个（估计，待实测；附录 A.1 第 2 项）。零扇区不属于任何文件。
- 数据音轨（包括末尾零扇区）不得短于 300 个扇区。若会短于此值，则增加末尾的零填充。以轨道一次写入（track-at-once）方式追加的音轨须至少为 300 个扇区（二手来源）。

**[D7]** 音频音轨可没有扩展文件。容量不足时，出版方可以作此选择（见 [P18]）。此类音轨仅作为 CD 播放（[R19]）。

*资料性。*

- 卷标不影响读取。建议由专辑名派生卷标，若转换失败则使用 LAE_EXT。
- Windows 资源管理器显示最后一个区段，因此扩展文件可作为普通文件读取（二手来源，待实测；附录 A.1 第 10 项）。

### 2.4 子码与元数据

**[M1]** 可写入 ISRC、MCN（UPC/EAN）和 CD-Text。它们仅包含标准元数据；不得包含哈希或位置数据。

### 2.5 容量（资料性）

**以扇区计：** N1 + 11,400 + N2 ≤ C，其中：

- N1 = A2：区段 1 自 LBA 0 起的扇区数，含填充。
- N2 = 文件系统扇区数 + Σ ceil(文件字节数 / 2048) + 末尾零扇区数。文件较少时，文件系统仅占几十个扇区（估计）。
- C = 由空白盘 ATIP 得出的容量，以自 LBA 0 起的扇区计，减去制作方选定的安全余量。80 分钟光盘的容量为 359,849 个扇区：ATIP 最大值 79:59:74 为 359,999 个绝对时间扇区，减去 LBA 0 之前的 150 个扇区（二手来源；待实测，附录 A.1 第 9 项）。除非另行给定容量，封装工具使用 359,849。

**以光盘分钟计**（1 光盘分钟 = 4500 个扇区；各项均以光盘分钟计）：L·(1 + r) + 填充 + 2.533 + 文件系统 + 末尾零扇区 ≤ C / 4500，其中：

- L 为音乐长度，以分钟计。
- 填充每条音轨不足一个扇区，即每条音轨不足 0.00023 光盘分钟。常数 2.533 = 11,400 / 4500（均为推导值）。
- r = （每分钟音乐的扩展层大小，以 MB 计）÷ 9.216。常数 9.216 = 2048 × 4500 / 10^6（推导；四舍五入为 9.22）。

## 3. 扩展文件（.LAX）

### 3.1 字节布局

**[X1]** 扩展文件必须恰好由以下两部分构成：

| 字节 | 内容 |
|---|---|
| 0 … n−1 | 扩展块：v5 `LAE ` 块的完整 n 字节主体，包括主体末尾的 CRC-32，与该音轨 v5 WAV 中的相应内容逐字节相同。不包括块标识、块长度以及任何 RIFF 填充字节 |
| n … n+79 | 尾部记录（3.2） |

- 没有文件头。
- 扩展块长度 n = 文件长度 − 80。该长度不单独记录，且 n ≥ 8（[SPEC] 3.3）。
- 文件扩展名在 CD 上为 .LAX（大写，符合 ISO 9660 要求），在 CD 以外为 .lax。读取器对扩展名不区分大小写。

### 3.2 尾部记录

**[X2]** 尾部记录长 80 字节，包含以下字段：

| 偏移 | 字节数 | 类型 | 字段 | 规定 |
|---|---|---|---|---|
| 0 | 4 | bytes | 标识 | ASCII `LTVT`（4C 54 56 54） |
| 4 | 2 | uint16 | 版本 | 1 |
| 6 | 2 | uint16 | 长度 | 80，即整个尾部记录的字节数 |
| 8 | 2 | uint16 | 扩展块类型 | 1 = LAEY 容器版本 5 的 `LAE ` 块主体（以魔数 `LAE1` 开头）；2 = LAES 扩展块（以魔数 `LAE2` 开头）；其他值保留 |
| 10 | 2 | uint16 | 音轨号 | 在 CD 上：TOC 音频音轨号，1–98。在 CD 以外：若该音轨也以 CD 发行，则为其在 CD TOC 中的音轨号；否则为其在专辑内的音轨号（≥ 1）；单曲为 1 |
| 12 | 4 | uint32 | 采样率 | CD 层的采样率。在 CD 上必须为 44100；在 CD 以外为 44100 或 48000。对于扩展块类型 1，必须等于扩展块中的 base |
| 16 | 4 | uint32 | ncd | CD 层的样本数，1 ≤ ncd < 2^28。对于扩展块类型 1，必须等于扩展块的 nb − 2·pb |
| 20 | 16 | bytes | MD5 | 整轨 MD5（3.3），按 MD5 输出的字节顺序存储 |
| 36 | 8 | uint64 | S1 | 见 3.4；0 ≤ S1 < M |
| 44 | 8 | uint64 | S2 | 见 3.4；0 ≤ S2 < M |
| 52 | 4 | uint32 | lead0 | CD 层开头连续数字静音样本的数量，0 ≤ lead0 ≤ ncd |
| 56 | 4 | uint32 | tail0 | CD 层结尾连续数字静音样本的数量，0 ≤ tail0 ≤ ncd。若 CD 层全部为数字静音，则 lead0 = tail0 = ncd；否则 lead0 + tail0 < ncd |
| 60 | 16 | bytes | 保留 | 写入时必须全为 0；读取时忽略 |
| 76 | 4 | uint32 | CRC-32 | 第 0–75 字节的 CRC-32（1.5） |

*资料性。*

- 限制 ncd < 2^28 在 44.1 kHz 下约相当于 101 分钟，在 48 kHz 下约相当于 93 分钟（推导）。它确保 3.4 中的所有计算均可在 64 位无符号整数内完成。
- lead0 和 tail0 描述 CD 层本身的内容：其开头和结尾包含多少数字静音。
  - 它们与刻录、抓取和偏移无关，也不是位置（[X6]）。
  - 读取器仅将其用于粗定位（[R7]）。
  - 错误的值只会导致粗定位失败，而不会使错误的音频通过，因为接受与否仅取决于整轨 MD5。
- 这些静音样本是音轨的一部分：它们始终被播放，并计入整轨 MD5。任何程序（解码器、播放器、封装或读取工具）都不可删除或跳过它们，也不可将 lead0 和 tail0 用作或传递为可删除的量或"无效"数据。

### 3.3 整轨 MD5

整轨 MD5 是检查 CD 音频是否已损坏或被改动的简单手段。音轨对齐后，读取器用它确认该音轨的音频与制作时的音频相同（[R7]）。

**[X3]** 整轨 MD5 是对 ncd × 4 字节计算的 MD5（RFC 1321）。对 i = 0 … ncd−1，样本 i 的字节按以下顺序取用：

1. L 的低字节；
2. L 的高字节；
3. R 的低字节；
4. R 的高字节。

即交错的小端序 int16。该定义与 16 位立体声音频的 FLAC STREAMINFO 中音频 MD5 的定义相同（RFC 9639）。参考实现为 [AH] 中的 `cdMd5`。

### 3.4 S1 和 S2

**[X4]** 先定义帧字，再定义 S1 和 S2：

- **帧字：** w_i = b0 + 2^8·b1 + 2^16·b2 + 2^24·b3，其中 b0 … b3 是 3.3 字节流中样本 i 的四个字节。
  - 等价地，w_i = (L_i mod 2^16) + 2^16·(R_i mod 2^16)，且 0 ≤ w_i < 2^32。
  - 帧字必须逐字节组装，与平台的字节序无关。
- **S1** = (Σ_{i=0}^{ncd−1} w_i) mod M
- **S2** = (Σ_{i=0}^{ncd−1} (i+1)·w_i) mod M

**滑动更新。** 设 x_j 为光盘流的帧字，t 为窗口起点，n = ncd 为窗口长度。则：

- A(t) = Σ_{i=0}^{n−1} x_{t+i} mod M
- B(t) = Σ_{i=0}^{n−1} (i+1)·x_{t+i} mod M

窗口右移一个样本时：

- B(t+1) = (B(t) − A(t) + n·x_{t+n}) mod M
- A(t+1) = (A(t) − x_t + x_{t+n}) mod M

先用旧值 A(t) 更新 B，再更新 A。

**[X5]** 通过滑动更新得到的 A 和 B 必须等于按定义直接计算的值。

*资料性：不会溢出。*

- A, B < 2^61，且 n·x < 2^28 · 2^32 = 2^60。
- 因此 B + (M − A) + n·x < 2^63，64 位无符号整数即可满足。
- 模 M 约简可计算为 (v AND M) + (v >> 61)，随后至多减去一次 M（推导）。

**已知答案（本草案计算）**

示例 1：

- 输入：3 个样本 (1, −1)、(−32768, 32767)、(0, 0)。
- 字节流：01 00 FF FF 00 80 FF 7F 00 00 00 00。
- 帧字：w = 4294901761, 2147450880, 0。
- S1 = 6442352641；S2 = 8589803521；MD5 = 08b7bb4b0c7432f1c9e94e3c493f236e。
- lead0 = 0；tail0 = 1（最后一个样本为 (0, 0)）。
- 滑动检查：
  - 将这 3 个样本置于光盘流 x = 0, w0, w1, w2, 0 中，n = 3。
  - 初始窗口：A(0) = 6442352641，B(0) = 15032156162。
  - 右移一步后：A(1) = 6442352641 = S1，B(1) = 8589803521 = S2。

示例 2（移出窗口和移入窗口的帧字均非零，因此滑动公式的每一项都得到检验）：

- 输入：3 个样本 (1, −1)、(−32768, 32767)、(32767, −32768)。
- 字节流：01 00 FF FF 00 80 FF 7F FF 7F 00 80。
- 帧字：w = 4294901761, 2147450880, 2147516415。
- S1 = 8589869056；S2 = 15032352766；MD5 = e5e4df0d69a7afa36b20e70c5c09fc82。
- lead0 = tail0 = 0。
- 滑动检查：
  - 光盘流 x = 131071（即样本 (−1, 1)）, w0, w1, w2，n = 3。
  - 初始窗口：A(0) = 6442483712，B(0) = 15032287233。
  - 右移一步后：A(1) = 8589869056 = S1，B(1) = 15032352766 = S2。

示例 3（全零）：3 个样本 (0, 0) 得出 lead0 = tail0 = 3，S1 = S2 = 0（推导）。

### 3.5 扩展文件中排除的内容

**[X6]** 尾部记录和扩展文件不得包含以下任何内容：

- 由扩展层派生的值：
  - 由扩展层字节计算出的任何值（CRC、哈希、大小）；
  - 同时覆盖 CD 层和扩展层的任何值；
  - 由两层共同计算出的任何值。

  扩展层仅由其自身的 CRC-32 保护（[SPEC] 3.3）。
- 任何位置、LBA、偏移、延迟或增益。lead0 和 tail0 是描述 CD 层内容的计数，不在此项之列。
- 任何逐扇区或逐帧数据；入口表、寻址表或提示点表。
- 任何头部。在扩展文件中，整轨 MD5 仅存储于尾部记录中。

### 3.6 读取时的检查顺序

**[X7]** 读取器必须按以下顺序检查扩展文件。任何一项检查失败，均不使用该文件，并报告括号中给出的原因：

1. 文件长度 ≥ 88，且最后 80 字节以 `LTVT` 开头（"无尾部记录"；见 [R14]）。
2. CRC-32 匹配（"记录已损坏"）。
3. 版本为 1，且长度为 80（"未知记录版本"）。
4. 扩展块类型为 1，且扩展块以 `LAE1` 开头（"未知扩展块类型"；若类型为 2 且扩展块以 `LAE2` 开头，则为"LAES 扩展块，本读取器不支持"；若类型与魔数不符，则为"扩展块与其尾部类型不符"）。
5. 音轨号、采样率、ncd、S1、S2、lead0 和 tail0 均在 3.2 规定的范围内（"记录字段无效"）。

扩展块本身由解码器检查：CRC 以及 V1–V13（[SPEC] 4.3）。读取器可预先检查扩展块的 CRC，若不匹配则报告"扩展层已损坏"。

*资料性。* 制作方保证（[P2]）：

- ncd 等于扩展块的 nb − 2·pb；
- lead0 和 tail0 与 CD 层相符。

读取后，解码器的检查 V13 覆盖解码过程，因此读取器无需再次检查这些项。

## 4. CD 以外的文件和流

本章适用于 CD 以外的所有形式：普通文件下载、DVD 或 BD 数据光盘上的文件以及 LAE 流。这些形式不采用第 2 章的布局。基础层的采样率可以为 44 100 Hz 或 48 000 Hz（[P1]）。

### 4.1 单文件 v5 WAV（现行形式）

**[F1]** 在单个 v5 WAV 文件中，CD 层位于 data 块中，`LAE ` 块位于音频之后（[SPEC] 3.1）。

- 编码器在不带标签时写出的 v5 WAV，以及重新封装工具写出的每个 v5 WAV，必须采用以下规范布局。给了标签时（例如 `lae_enc --tag=` 或 `--cover=`），编码器在 `fmt ` 和 `data` 之间写入一个 `LIST`/`INFO` 块和一个 `id3 ` 块；这样的文件是有效的 v5 WAV（[SPEC] 3.1），但不采用这种布局。
- 该布局与 wavio::writeCD 的输出相同（[WV]）。
- 设 D = ncd × 4。

| 偏移 | 内容 |
|---|---|
| 0 | `RIFF` |
| 4 | uint32: 36 + D + 8 + n + (n mod 2) |
| 8 | `WAVE` |
| 12 | `fmt `；uint32 16；uint16 1；uint16 2；uint32 采样率；uint32 4 × 采样率；uint16 4；uint16 16 |
| 36 | `data`；uint32 D；随后为 D 字节 PCM |
| 44 + D | `LAE `；uint32 n；随后为 n 字节扩展块；若 n 为奇数，再加一个 0 字节 |

版本 0 未定义附加在 WAV 文件内部的尾部记录。

### 4.2 基础层文件加扩展文件

**[F2]** 一条音轨也可以两个文件的形式发行：

- **基础层文件：** FLAC（RFC 9639）或 WAV。
  - 其内容恰为该音轨的 CD 层：ncd 个样本，16 位，2 声道，采样率为尾部记录中给出的值。
  - 基础层 WAV 不含 `LAE ` 块。
  - 普通播放器仅播放此文件。
- **扩展文件：** 与基础层文件同名，文件扩展名为 .lax，格式为第 3 章所规定的格式。若同一音轨也以 CD 发行，该文件必须与 CD 上的 TRACKnn.LAX 逐字节相同。
- 在这种分文件形式中，不得将扩展层和尾部记录置于基础层 FLAC 文件内部：它的任何元数据块均不承载它们。（带有扩展的单个 FLAC 文件是 [SPEC] 3.4 的 FLAC 形式，不是基础层文件。）
- 应将音频 MD5 写入 FLAC STREAMINFO。

### 4.3 配对与抓取文件

**[F3]** 读取器首先查找同名（不区分大小写）的 .lax 文件，然后可尝试同一文件夹中的其他 .lax 文件。

**配对条件：** 从基础层文件解码得到的样本数等于 ncd，且解码 PCM 的整轨 MD5 等于尾部记录中的 MD5。详细规则：

- 若 STREAMINFO MD5 不为 0，可先用它筛选候选文件。
- 但接受与否必须以解码的 PCM 为依据：或者由读取器自行计算 MD5，或者由 FLAC 解码器验证 STREAMINFO MD5 且该 MD5 等于尾部记录的 MD5。
- 若 STREAMINFO MD5 为 0，读取器必须自行计算 MD5。
- 若多个 .lax 文件均配对成功但其扩展块不同，读取器必须拒绝该音轨并报告此情况。
- 若配对失败，适用 [F4]。

配对成功时，无需查找偏移，也不使用 S1 和 S2。

**[F4]** [F3] 的配对适用于出版方分发的基础层文件和 LAE 流（4.5）。抓取文件（WAV、FLAC 等，包括逐轨抓取）通常无法按 [F3] 配对：抓取结果带有偏移，文件包含填充，且音轨 1 的文件可能包含前间隙。因此：

- 读取器首先尝试 [F3]；
- 若配对失败，读取器必须按第 6 章的规定逐条定位音轨（[R2]、[R7]）：
  - 若有 CUE/TOC 或一组有序的逐轨文件，则使用 TOC；
  - 若只有单个文件，则按内容搜索整个文件；
- 若第 6 章的处理也失败，则仅播放基础层。

### 4.4 重新封装

**[F5]** 重新封装（针对扩展块类型 1）：

- 输入：经过验证的 CD 层，加上扩展文件中的扩展块。CD 层来自以下之一：
  - 抓取结果或 LAE 流（[R8]）；
  - 配对成功的基础层文件（[F3]）。
- 输出：采用 4.1 规范布局的 v5 WAV。编码器最初写出的文件不带标签时，结果必须与它逐字节相同。标签不属于扩展文件：从带标签的文件重新封装，得到的是不带标签的规范布局，其中的 `data` 块（CD 层）和 `LAE ` 块与带标签文件中的逐字节相同。

### 4.5 LAE 流

**[F6]** LAE 流（LAEY 或 LAES）逐轨交付。每条音轨由两项构成：

- 该音轨的 CD 层，逐样本未改动，形式为 FLAC、WAV 或原始 PCM。原始 PCM 为小端序 16 位立体声，采样率为尾部记录中给出的值；
- 该音轨的扩展文件（第 3 章），逐字节未改动。

流不携带任何附加的头部、索引、位置或偏移。

播放器以相同方式处理流和抓取结果：

1. 每条音轨首先按 [F3] 配对；
2. 若配对失败，按第 6 章定位该音轨。由于没有 TOC，搜索在为该音轨交付的音频内进行；
3. 用整轨 MD5 验证结果。

**[F7]** CD 层经过有损重新编码（AAC、MP3 等）的流不是 LAE 流。扩展层无法使用，仅播放基础层。

- 若基础层为有损格式，读取器不尝试定位，并报告"基础层为有损格式"。
- 读取器不得将扩展层应用于有损解码的音频。经有损解码后再以无损形式交付的音频与整轨 MD5 不符；这种情况下同样仅播放基础层（[R11]）。

## 5. 制作要求（封装工具）

### 5.1 总则

**[P1]** 采样率系列：

- 制作 CD 时，母带必须属于 44.1 kHz 系列（88.2 / 176.4 / 352.8 kHz），CD 层为 44 100 Hz。
- 仅制作 CD 以外的形式（文件、DVD 或 BD 数据光盘上的文件以及 LAE 流）时，母带也可属于 48 kHz 系列（96 / 192 / 384 kHz），此时 CD 层为 48 000 Hz。
- 若不满足这些条件，工具停止并说明原因。

**[P2]** 每条音轨的 v5 文件和尾部记录：

- 每条音轨的 v5 文件必须通过解码器的全部检查（[SPEC] 4.3，V1–V13）。
- *资料性：参考工具（自 2026-11-15 起）。*打包工具在写出任何文件之前把每个输入文件完整解码一遍：LAEY 文件的每个扩展包（主体是包 0）解到最后一帧，每个熵编码流必须正好在最后一个字节结束；LAES 文件的每个母带都解码并和它的 SHA-256 比对。解不出的文件被拒绝，不写镜像。
- 尾部记录必须由该文件的 CD 层计算得出：
  - ncd = nb − 2·pb；
  - 采样率 = base；
  - MD5、S1、S2、lead0 和 tail0 按第 3 章的规定。

**[P3]** 封装和对齐均不改变 CD 层。对每条音轨，区段 1 中 [q_k, q_k + ncd_k) 范围的 MD5 必须同时等于尾部记录的 MD5 和该音轨 v5 文件 data 块的 MD5。

**[P4]** 测得的偏移、位置差、移位量以及裁剪或填充量可显示。它们不得写入任何文件，包括镜像、CUE 文件、扩展文件、报告和日志。报告和 CUE 文件仅提供给制作方，不放到光盘上。

### 5.2 派生模式

**[P5]** 连续母带是一个文件，或出版方声明为无缝且按顺序拼接的一组逐轨文件。

- 音轨边界置于出版方给出的位置，哪怕一个样本也不移动。特别是，工具不将起点移至扇区网格上的最近点。
- 每条音轨的起点必须位于扇区网格上。
  - 网格单位为 G = 588 × 2^s 个母带样本，即 588 个 CD 样本，其中 s 为 stages。
  - 以 CUE"分:秒:帧"表示法给出的起点总在网格上，因为一帧即一个扇区。
- 若有任何起点不在网格上，工具必须停止且不写任何文件。它列出这些起点，并要求出版方在网格上给出它们。
- 不得删除或添加母带样本。因此：
  - 除最后一条音轨外，每条音轨的 ncd 均为 588 的倍数；
  - z_k = 0；
  - 在区段 1 中，各音轨的 CD 层首尾相接，无间隙。

*资料性。* 编码器可以使用实际相邻的母带样本作为音轨边缘（ctx），使高分辨率输出在音轨边界处无缝。这属于编码器事项，既不影响封装也不影响读取。ctx 是计划中的编码器功能，尚未实现；当前编码器在每条音轨两端使用镜像填充（[ENC]）。

**[P6]** 对于非连续的逐轨母带，每条音轨独立编码，ncd 无需为 588 的倍数。在镜像中，每条音轨按 [L7] 的规定以 z_k 个数字零填充为整扇区。

**[P7]** 音轨划分完全由出版方决定：

- 工具不得添加、删除或移动任何音轨边界。
- 若一部完整的长作品构成一条音轨，其 ncd 无需为 588 的倍数。扇区的剩余部分由填充吸收（[L7]）。
- 每条音轨必须满足 ncd < 2^28。

### 5.3 独立 CD 模式

**[P8]** 对齐在生成每个片段的 v5 文件时进行（[ENC]）：

- 对于单个片段，使用编码器选项 `cd=`；
- 对于整张光盘，整盘规划器 `lae_enc plan` 首先在 CD 的音轨标记处切分母带。

封装工具仅接受已对齐的文件，本身不进行对齐。适用以下规则：

- 不得提供跳过对齐检查的选项（`cdalign=none` 已撤销）。
- 每个片段在编码时必须通过对齐检查。该检查包括：
  - 仅基于波形的由粗到精搜索；
  - 三块检查；
  - 漂移检查；
  - 误差分档。
- 每个片段的位置必须由用户确认：
  - 未给出 `cdalign=` 时，编码器运行两次搜索，一次使用白化互相关，一次使用普通互相关。它报告两个结果，不写任何内容。
  - 片段仅以 `cdalign=` 给出的偏移进行编码。对于整张光盘，整盘规划器为每个片段打印该偏移。
- 落入确认档的片段仅在确认后编码，确认可在控制台进行，也可使用 `cdaccept`。编码器在其结果中说明这一点。
- 若结果为"警告"（例如极性反转或声道互换），必须显示警告，处理继续进行。
- 若 CD 片段及对应的母带段均全部为数字零，必须使用逐样本比较代替统计判定。

**[P9]** 仅当母带与 CD 之间的每处差异都完全由数字静音构成时，整盘规划器才自动放置母带。这包括两端的差异以及片段之间的差异。

- 母带按其原有顺序铺放到 CD 的时间轴上，静音视为空白段落。
- 母带可以由多个文件构成，按给定顺序逐样本拼接。不使用这些文件本身的分割点。若这些分割点与 CD 的不同，整盘规划器报告母带已按 CD 的位置重新分割。

放置结果必须满足以下全部条件：

- 母带的每个非零样本恰好进入一条音轨的 v5 文件，且各音轨的母带段按音轨号顺序排列。
- 被舍去的母带样本全部为数字零。
- 对齐即长度匹配：
  - 开头较长的一方先播放，结尾较长的一方后结束；
  - 较短的一方以数字静音补齐，任何一方的非静音样本都不被截去。
- 亚样本差异：
  - 若母带的声音起点比 CD 早不到一个 CD 样本（例如经最小相位均衡处理的 CD），则在 CD 层之前添加一帧数字静音。这正是每次封装开头本来就有的静音。此时母带从其自身的第一个样本开始播放。
  - 若母带的结尾比 CD 晚不到一个 CD 样本，格式本身可容纳这一差异；母带长度无需为 2^stages 的倍数。
  - 仅母带含有的一个 CD 样本或更长的声音按 [P10] 导致停止。
- 为对齐而添加到母带的样本全部为数字零，且仅添加在 CD 也为数字零的位置。

具体的放置算法属于实现事项。若母带或 CD 含有对方所没有的非静音内容，则不进行自动放置；仅由抖动噪声构成的内容也算作内容。版本 0 按 [P10] 停止，并说明该内容只有一方具有。单个段的开头或结尾处只有母带具有的声音，在编码该段时处理：由出版方在参考编码器中选择 `cdedge=pad` 或 `cdedge=cut`。

**[P10]** 在以下任一情形下，工具必须停止，不写任何文件，说明原因并列出相关的时间范围：

- 某片段的对齐检查结果为"停止"（[P8]），或某片段落入确认档但未经确认。"停止"包括：未找到位置、不匹配、漂移或剪辑，以及 CD 错误。
- 无法按 [P9] 放置。这包括仅存在于母带和 CD 之一中的非静音内容（例如在母带文件拼接处重复或缺失的段落），以及片段顺序不同。
- 出版方 CD 音轨 1 的 INDEX 00 包含非静音内容（[L4]）。
- 出版方 CD 使用预加重（[L11]）。

**[P11]** CD 层即出版方 CD，哪怕一个样本也不改动。区段 1 从 LBA 0 到 A2 的全部样本必须与出版方 CD 的节目逐样本相同。节目从音轨 1 的 INDEX 01 延伸到节目结尾。[L6] 例外情形中的 L 个前导帧位于 LBA 0 之前的前间隙内，不属于此范围。

### 5.4 镜像与交付物

**[P12]** AUDIO.BIN 必须包含区段 1 位于绝对位置 [0, A2 × 588) 的全部样本，即从 LBA 0 到 A2。

- 格式为小端序 16 位立体声，文件由整数个扇区构成。
- 音轨 1 的 150 个扇区前间隙不在文件中。它由刻录程序按 CUE 写为数字静音（附录 A.1 第 7 项）。

**[P13]** IMAGE.CUE 遵循 ImgBurn（以及 CDRWIN 和 EAC）所使用的 CUE 惯例，按照该惯例，文件的扇区 0 为 LBA 0，且文件不包含音轨 1 的 150 个扇区前间隙：

- 写入 `FILE "AUDIO.BIN" BINARY`。文件的扇区 0 为 LBA 0。音轨 1 为 `INDEX 01 00:00:00`，不写 PREGAP。
- 派生模式：自音轨 2 起仅写 INDEX 01。独立 CD 模式：按 [L14] 写入。
- 两个区段以 `REM SESSION 01` / `REM SESSION 02` 分隔。在 `REM SESSION 02` 之后依次写入：
  - `FILE "DATA.BIN" BINARY`，使用 DATA.ISO 时为 `FILE "DATA.ISO" BINARY`；
  - `TRACK nn MODE2/2352`，使用 DATA.ISO 时为 `TRACK nn MODE2/2048`（封装工具写出的形式；刻录程序是否接受待实测，附录 A.1 第 4 项）；
  - `INDEX 01 00:00:00`。
- `REM LEAD-OUT` 给出 AUDIO.BIN 的长度。
- CUE 不得包含任何 CRC、MD5 或其他哈希。

**[P14]** 交付物必须包括：

- 用于一次写入的镜像：IMAGE.CUE、AUDIO.BIN，以及 DATA.BIN（每扇区 2352 字节）或 DATA.ISO（每扇区 2048 字节，绝对地址）；
- 两步写入套件：仅含区段 1 的 CUE，以及针对给定起始地址重新生成区段 2 的命令和说明；
- 中英文刻录与验收说明。其中包含一张布局表，列出每条音轨 INDEX 01 的 LBA、A2 以及区段 2 数据音轨 INDEX 01 的 LBA（用于附录 A.2 的核对）。

还可另外提供每条音轨的 v5 WAV（4.1），用于文件分发。

**[P15]** 对于两步写入，下一个可写地址必须取自驱动器的 READ TRACK INFORMATION 报告（MMC 52h）。该地址与 TOC 的 B0 条目以及 A2 + 11,400 两者进行核对。若三个值中任一与其他值不同，工具必须停止。已发布的关于 B0 条目的描述互相矛盾，单独使用 B0 可能偏差 150 个扇区（二手来源）。

*资料性：参考工具（自 2026-11-15 起）。*`lae_cdx data` 和带 `iso:…@N` 的 `lae_cdx read` 在起始地址 N 不等于 A2 + 11,400 时停止。A2 取自选项 `a2=`，没有该选项时取自镜像的 BURN.TXT（`data`：在 .lax 文件夹旁边或里面；`read`：在 DATA.ISO 旁边）；两者都没有时，工具停止。N = 0 生成的是供在电脑上挂载的副本（C34），不作核对。

### 5.5 闭环自检

**[P16]** 镜像发布之前，工具必须用与读取器相同的代码读取一次镜像，扩展文件取自镜像的数据区段。读取以下组合：

- 带 CUE 的整盘镜像，偏移在 ±5880 内选取；
- 偏移为 0 时：
  - 不带 CUE、作为单个文件的整盘；
  - 逐轨文件，分别带 CUE 和仅有文件顺序，采用三种间隙模式（附加到前一音轨、前置到后一音轨、省略），音轨 1 的文件分别含和不含前间隙。

每条音轨必须通过，并且必须重建为与编码器输出逐字节相同的 v5 WAV。

例外：自音轨 2 起带 INDEX 00 间隙的独立 CD 模式。在省略间隙的抓取结果中，读取器得不到间隙样本。

- 带 CUE（PREGAP）时，这些位置未知并按 0 读取。
  - 若间隙为数字静音，前一音轨仍然通过。
  - 若不是，前一音轨以"未知样本"回退（与 C30 一致）。
- 仅有文件顺序时，这些位置无法得知，前一音轨一般会回退。
  - 若间隙为数字静音，且后一音轨恰好以至少同样长的数字静音开头，使窗口不变，则该音轨可能通过。
  - 在这种情况下，它必须重建为逐字节相同的 v5。
- 自检按此预期判定每条音轨。其他所有组合仍要求每条音轨通过。

若不满足这些条件，镜像作废。具体的偏移和抓取组合见 7.2 的 C02、C06、C23 和 C25。

**[P17]** 自检还必须包括故意损坏的情形：

- 改动 1 个样本；
- 替换为另一专辑的扩展文件；
- 删除尾部记录。

这些音轨都必须回退。若其中任何一条未回退，镜像作废，流程停止。

### 5.6 容量

**[P18]** 容量检查：

- 必须首先依据空白盘的 ATIP 或空白盘类型检查容量（2.5）。
- 若内容放不下，工具停止并列出可选方案：
  - 省略部分音轨的扩展；
  - 使用其他光盘；
  - 限制倍频程数，这需要重新编码。
- 不得自动删除音轨或倍频程。
- 自检之后必须再次检查容量。

## 6. 读取器要求（读取器、插件和流播放器）

*资料性：概述。*

- 读取器以相同方式处理所有输入：整盘抓取（带或不带 CUE/TOC）、逐轨抓取、单个文件和 LAE 流（4.5）。
- 每条音轨按内容独立定位（6.3）：
  1. 粗定位，依据 TOC 位置和/或由尾部记录中 lead0 和 tail0 给出的信息区间；
  2. 精定位，用 S1 和 S2 筛查每个位置；
  3. 用整轨 MD5 确认。
- 既不假定也不需要统一的整盘偏移。
- 音轨内的滑移（丢失或多出样本）只会导致该音轨的 MD5 失败。该音轨作为 CD 播放，其他音轨不受影响（[R10]）。

### 6.1 输入

**[R1]** 读取器有三类输入：

- **抓取结果：** 整盘镜像（BIN、WAV 或 FLAC，带或不带 CUE）、逐轨文件（带或不带 CUE）或单个逐轨文件。它们可以来自任何抓取软件和任何偏移设置；读取器必须只使用无损保存的音频（例如 WAV、FLAC 或 BIN，16 位、44.1 kHz；接受的形式见下文）。
- **LAE 流：** 逐轨交付的 CD 层，加上扩展文件（4.5）。
- **扩展文件：** 来自 CD 区段 2 的 `/LAE/` 目录、复制的文件夹，或随 LAE 流交付。

对音频格式的要求：

- 读取器必须接受 16 位 2 声道 PCM WAV：抓取结果为 44 100 Hz，CD 以外的文件和 LAE 流为尾部记录中给出的采样率。
- 读取器可接受其他无损形式：FLAC、AIFF、原始 PCM，以及存储在低字节全为 0 的 24 位容器中的 16 位抓取结果。
- 有损格式（MP3、AAC 等）不得与扩展层一起使用（[F7]）。读取器不尝试定位；它仅播放或输出基础层，并报告"基础层为有损格式"。

**[R2]** TOC 的来源按优先级依次为：

1. 从驱动器读取的 TOC；
2. CUE；
3. 一组逐轨文件的文件顺序加文件长度。

若只有最后一种来源可用，报告必须醒目地突出这一点。

单个文件（单音轨文件，或不带 CUE 的整盘抓取）没有 TOC，LAE 流的任何音轨也没有 TOC。读取器按 6.3 按内容搜索此类文件，报告必须注明"无 TOC"。

**[R3]** 遇到无法识别的 CUE 结构时，读取器必须停止，不作猜测。

### 6.2 光盘流

**[R4]** 光盘流的组成：

- 有 TOC 时，每个文件必须置于光盘流中由 CUE/TOC 给出的位置：文件的第一个样本置于其对应的绝对位置。
  - 不得通过累加文件长度来定位文件。
  - 唯一的例外是本身按 [R2] 由文件顺序推导出的 TOC。
- 无 TOC 时，每个文件构成一个单独的光盘流，位置从该文件第一个样本处的 0 起计。

**[R5]** 未知位置与冲突：

- 光盘流中未被任何文件覆盖的位置记为"未知"。无 TOC 时，这包括文件以外的位置。
  - 未知位置始终视为 0。
  - 读取器不得为使 MD5 匹配而用其他值重试。
- 若两个文件在同一位置给出不同的值，读取器报告冲突，该位置视为未知。

**[R6]** 每条音轨 CD 层的长度始终为尾部记录中的 ncd。对于最后一条音轨，仅从 TOC 获取起点。不得将数据音轨的起点或 A2 用作最后一条音轨 CD 层的结尾；A2 仅用于记录核对。

### 6.3 逐轨定位与验证

**[R7]** 每条音轨独立定位。每个通过 [X7] 检查的扩展文件都有音轨号 k 和 CD 层长度 ncd。

有 TOC 时，k 必须是 TOC 中的音频音轨。否则不使用该文件，并报告"音轨号不在 TOC 中"。

每个扩展文件按以下步骤处理：

1. **粗定位：** 确定一组粗定位位置 c。
   - 有 TOC 时：c = q_k（[L6]）。
   - 依据信息区间，若 lead0 < ncd 且范围 R 包含非零样本：
     - 找出 R 中第一个和最后一个非零样本的位置 f 和 l；
     - 由此得出 c = f − lead0 和 c = l + 1 + tail0 − ncd；
     - 有 TOC 时，R = [q_k − W, q_k + ncd + W)，并以 R = [q_k, q_k + ncd + W) 重复计算。当该音轨的文件以静音间隙开头时需要第二个范围：此时第一个范围中的首个声音是前一音轨的结尾，粗定位会落在边界上；
     - 无 TOC 时，R 为整个文件；
     - 未知位置按 0 计。
2. **精定位：** 检查每个窗口 [t, t + ncd)。
   - 有 TOC 时，t 覆盖每个粗定位位置 W 范围内的每个位置：c − W ≤ t ≤ c + W。
   - 若 TOC 仅由文件顺序推导，且以上窗口均不匹配，则 t 另外覆盖从 q_k − W 到下一文件起点 + W 的范围，因为该音轨的文件可能以其 INDEX 00 间隙开头，而无论该间隙包含什么内容。
   - 无 TOC 时，t 覆盖整个文件：−W ≤ t ≤ 文件长度 − ncd + W。粗定位位置仅决定搜索从何处开始。
3. 用 S1 和 S2 的滑动值进行筛查（[X4]）。只有 A = S1 且 B = S2 的位置才是候选窗口。
4. 仅当某候选窗口的整轨 MD5 等于尾部记录中的 MD5 时，该音轨才通过。

W ≥ 5880。W 可更大，例如 44 100。对于全零的窗口，MD5 可只计算一次。

*资料性。*

- 粗定位和精定位仅决定在何处查找音轨。一旦找到音轨，整轨 MD5 就作为检查音频是否已损坏或被改动的简单手段：它逐轨确认音轨与制作时的音频相同。接受与否仅取决于它。
- 信息区间对开头或结尾有静音的音轨最为有用。即使偏移超过 W，此类音轨仍可借助静音与声音之间的边界找到。相互衔接、中间无静音的音轨仅依赖 TOC。
- 不带 CUE 且无相邻文件的单个逐轨文件受偏移影响：
  - 音轨一端的 |o| 个样本被推出文件，相邻音轨的 |o| 个样本被拉入。
  - 若被推出的样本仅为 CD 层开头或结尾的填充或数字静音，音轨仍可找到并通过。否则，该音轨回退。
  - 有 CUE 或一组完整的逐轨文件时，相邻文件提供被推出的样本（[R4]）。

**[R8]** 通过的音轨按以下方式处理：

- 其 CD 层由匹配窗口内的 ncd 个样本构成，不含前间隙或填充。
- 对于扩展块类型 1，按 4.4 重建 v5 WAV，并将其交给未经修改的解码器。
- 若解码器拒绝该文件，该音轨走 CD 路线，原因为"扩展层已损坏"。
- *资料性：参考工具（自 2026-11-15 起）。*读取器用和打包工具相同的方法（[P2]）把每一条通过验证的音轨完整解码一遍；内存放不下的 LAES 块由流式解码器借助临时文件解码，绝不只凭整轨 MD5 就接受。解码器拒绝的音轨走 CD 路线；检查无法进行时，读取停止。每条音轨打印一行，说明解码了什么。

**[R9]** 若多个候选均通过，则除 MD5 碰撞外（例如在全静音音轨中），它们的窗口内容相同。可使用其中任何一个，结果相同。

**[R10]** 每条音轨独立搜索和判定。

- 音轨内的滑移只会导致该音轨的整轨 MD5 失败。该音轨走 CD 路线，作为 CD 播放。
- 其他音轨不受影响。滑移之后的音轨在其移位后的位置被找到，因为移位远小于 W。

*资料性。* 为加快搜索，实现可以先尝试已为其他音轨确认的偏移。接受与否仅取决于该音轨自身的 MD5（[R7]）。将来的专用直接读取器可以重新读取有滑移的音轨（第 8 章）。

### 6.4 失败与报告

**[R11]** 未通过的音轨走 CD 路线。该音轨抓取的 CD 音频原样输出（无 TOC 时按 [R19]），不使用扩展层。

报告必须给出原因类别。原因仅依据计数判定，不使用扩展数据：

- **未知样本（文件缺失或文件被截断）**（有 TOC 时）：在标称窗口的 W 范围内，即 [q_k − W, q_k + ncd + W) 中出现未知样本。报告其数量。
- **文件过短**（无 TOC 时）：文件短于 ncd。
- **不匹配：** 以上情况均不适用，且未找到匹配窗口。可能的原因包括：
  - 音轨内的滑移或读取错误；
  - 不同的压制版本或母带；
  - 经过处理（增益等）的抓取结果；
  - 不属于该音轨的扩展文件；
  - 单个文件在一端缺少被偏移推出的样本。
- **无尾部记录 / 记录已损坏 / 未知记录版本或扩展块类型 / 记录字段无效 / 音轨号不在 TOC 中 / 扩展层已损坏 / 基础层为有损格式。**

**[R12]** 若没有任何音轨通过，读取器必须报告"可能是另一张光盘或另一版本"。无 TOC 时，"没有任何音轨通过"指没有任何扩展文件找到匹配。

**[R13]** 多个扩展文件的处理：

- 读取器读取文件夹中所有 .LAX 文件，并按尾部记录中的音轨号而非文件名对其分组。
- 若同一音轨号有多个扩展文件，则依次尝试，由 MD5 决定。
- 若多个均通过但其扩展块不同，读取器必须拒绝该音轨并报告此情况。
- 无 TOC 时：
  - 在输入文件中搜索每个扩展文件，优先尝试同名文件；
  - 在任何文件中都未找到的扩展文件在报告中列为"未使用"，不计为失败音轨。

**[R14]** 不得使用无尾部记录或尾部记录未通过 [X7] 的文件。没有可用扩展文件的音轨作为 CD 输出。

### 6.5 禁止事项

**[R15]** 不得修改、修复或替换 CD 样本。不得用以下任何来源填补 CD 样本：

- 扩展数据；
- 扩展块中的边缘样本；
- 校验值；
- 另一次读取的数据。

**[R16]** 测得的偏移可显示。它们不得写入任何输出文件，包括 v5 WAV 文件、高分辨率文件、CUE 文件、报告和日志。

**[R17]** 在音轨被接受或拒绝之前，读取器不得输出该音轨的任何高分辨率数据。在一条音轨内，读取器不得在 CD 与扩展层之间切换。

**[R18]** 定位和验证仅使用 TOC 以及尾部记录中的 lead0、tail0、S1、S2 和整轨 MD5。特别是：

- 不使用短于整条音轨的窗口进行验证；
- 不查询外部数据库；
- 不需要网络访问；
- 扩展块中的边缘样本仅由解码器按 [SPEC] 4.1 使用。读取器不得用它们查找偏移、进行验证或连接相邻音轨。

### 6.6 输出与插件

**[R19]** 输出：

- 通过的音轨：读取器可输出重建的 v5 WAV（4.4）或解码结果。
- 走 CD 路线的音轨：输出 16 位 CD 音频，文件名必须标明 CD。
- TOC 中没有对应扩展文件的音频音轨作为 CD 输出。这不是失败，不作为错误报告。
- 无 TOC 时：
  - 通过的音轨在其被找到的位置从文件中提取；
  - 文件中不属于任何通过音轨且并非全为数字静音的部分原样作为 CD 输出，文件名必须标明 CD；
  - 若单个文件中没有任何音轨通过，整个文件作为 CD 输出。
- 可另外提供专辑 CUE，用于无缝播放。

**[R20]** 播放器插件和 LAE 流播放器必须遵守本章的全部规则：

- 在开始高分辨率播放一条音轨之前，必须已验证整条音轨；
- 可在播放当前音轨时验证下一音轨；
- 未通过或未能及时完成验证的音轨，整条作为 CD 播放。

## 7. 一致性

### 7.1 方法

- 模拟工具（`lae_cdx sim`）生成镜像、整盘和逐轨抓取结果、CUE 文件以及模拟的 LAE 流。在逐一比较各用例之前，先写下每个用例的预期结果。
- 测试素材：
  - 同一录音中两首曲目的 10–15 s 节选，即 Track A 和 Track B；
  - 由这些节选派生的测试光盘；
  - 合成的 CC0 一致性测试向量。

  中间文件用后删除。
- 除另有说明外，各用例的默认条件：
  - W = 5880；
  - 偏移 0；
  - 带 CUE 的整盘镜像，读取节目前后的样本。
- 禁止性条款由代码审查（CR1）覆盖。真实 CD 的行为由附录 A（BT1）覆盖。
- 每个"必须"和每个"不得"至少由一个测试用例覆盖。

**测试光盘**（352.8 kHz 节选）

- **光盘 X**（逐轨母带，2 条音轨）：
  - 音轨 1 = Track A 的 10 s 节选缩短 1000 个母带样本。ncd = 440,875，不是 588 的倍数（mod 588 = 463，z_1 = 125）。
  - 音轨 2 = Track B 的 10 s 节选。ncd = 441,000 = 750 个扇区，z_2 = 0。
  - p_2 = 441,000，A2 = 1500（均为推导值）。
- **光盘 Y**（"另一专辑"）：以与光盘 X 相同的方式，由 Track A 和 Track B 的另外 10 s 节选制作。
- **光盘 S**（连续母带，3 条音轨）：
  - Track A 的连续 15 s 节选，在 5 s 和 10 s 处划分音轨。音乐在划分处连续。
  - 5 s = 1,764,000 个母带样本 = 220,500 个 CD 样本 = 375 个扇区，位于网格上。
  - 三条音轨均为 ncd = 220,500；z_k = 0；A2 = 1125（均为推导值）。
- **光盘 T**（逐轨母带，2 条音轨，首尾带静音）：
  - 音轨 1 = 1 s 数字零 + Track A 的 10 s 节选。音轨 2 = Track B 的 10 s 节选 + 1 s 数字零。
  - 两条音轨均为 ncd = 485,100 = 825 个扇区；z_k = 0；A2 = 1650（推导）。
  - 制作后必须检查：音轨 1 的 lead0 ≥ 30,000；音轨 2 的 tail0 ≥ 30,000；音轨 1 的 tail0 = 0 且音轨 2 的 lead0 = 0，因为两条音轨的衔接处为音乐。若不满足这些条件，则加长数字零或另选节选。
- **独立 CD 模式：** 以下用例 I1–I10。出版方 CD 由当前编码器从光盘 S 的母带派生，然后按各用例要求修改。

## 8. 版本与扩展

- **规范版本。**
  - 本规范为草案版本 0。附录 A 的测量完成后将予以修订。
  - 本规范以 spec/cdx/SPEC.md 发布，采用 CC BY 4.0。
- **尾部记录版本。**
  - 当前版本为 1。
  - lead0 和 tail0 是在尾部记录首次发布之前放入原保留字节中的。因此该记录仍为版本 1。
  - 发布之后，任何新字段或任何改动都需要新的尾部记录版本。这包括尾部记录的布局以及 MD5、S1、S2、lead0 和 tail0 的定义。
  - 读取器拒绝未知版本（[X7]）。
  - 保留字节写为 0，读取时忽略。
- **扩展块类型。**
  - 1 = LAEY 容器版本 5。
  - 2 = 为 LAES 保留。扩展块与 CD 层之间的关系由 LAES 规范定义。
  - 以后的 LAEY 容器版本（如有）使用新的类型代码。
  - 类型代码仅标识容器或层级。
  - 读取器将扩展块视为不透明字节，原样交给相应的解码器。因此，加入 LAES 时，本规范的 CD 布局、尾部记录和读取规则无需改动。
- **容器版本 5 不变。** 本规范不要求 v6。
- **版本 0 不包括、留待以后规定的内容：**
  - 逐层来源信息。这是本规范未涉及的将来任务；
  - 独立 CD 模式下母带与 CD 在非静音内容上存在差异时的自动放置（版本 0 停止；[P10]）。CD 层在任何情况下都是出版方的 CD（[P11]）；
  - 专用直接读取器（插入光盘即一步操作）。它只是 [R1] 的另一类输入，同样遵守第 6 章。它可以重新读取有滑移的音轨（[R10]）。细节留待以后规定；
  - 插件的接口和宿主；
  - LAE 流的传输（协议、分段、缓冲）；
  - `.lae` 完整文件布局（[SPEC] 1.1）；
  - LAES 扩展块的定义，以及将 LAES 的哪个子集置于 CD-Extra 上；
  - 用于压制的交付（PQ 列表、压制厂的最大时长）；
  - Linux 上使用 cdrecord 的刻录命令示例；
  - DDP 交付，以及专用刻录工具。

### A.2 验收程序

**成功标准：**

- 能够生成镜像；
- CD 能被识别并读取；
- 扩展能够还原为封装前的文件。

1. **制作方。** 生成镜像并通过自检（[P16]、[P17]）。
2. **检查镜像。**
   - 在 ImgBurn 2.5.8.0 中打开 IMAGE.CUE。
   - 将"镜像信息"中显示的各音轨 LBA 及区段 2 数据音轨的起点，逐一与刻录与验收说明中的布局表（[P14]）比较。
   - 若有差异，不要刻录。
3. **刻录。**
   - 首先一次刻录（路线 A）。
   - 若失败，或区段 2 位置错误，则使用两步写入套件（路线 B）。
   - 光盘仍处于未关闭状态时，Windows 可能提示"将文件刻录到光盘"；不要接受此提示。
4. **识别与读取。**
   - 重新插入 CD。预期 Windows 资源管理器显示 README.TXT 和 LAE\TRACKnn.LAX。
   - 用 `fc /b` 将这些文件与镜像中的源文件比较；预期两者相同。
5. **检查 TOC。**
   - 读取 TOC 并检查三项：音轨 1 的 INDEX 01 位于 LBA 0；A2；区段 2 数据音轨 INDEX 01 的 LBA。
   - 此步骤需要计划中的 TOC 读取工具（discinfo）。
6. 在至少一台普通 CD 播放机上**播放区段 1**。
7. **还原封装。**
   - 用 EAC 抓取光盘两次：一次作为整盘镜像，一次逐轨抓取。
   - 运行读取器。预期每条音轨通过。
   - 预期重建的 v5 WAV 文件与提供给封装工具的逐轨 v5 WAV 文件具有相同的 SHA-256（用 `certutil -hashfile <file> SHA256` 检查）。
8. **反馈测量值。**
   - 记录 A.1 每一项的测量结果，包括驱动器和刻录机型号、偏移以及 ImgBurn 显示的地址。
   - 将其反馈，用于本规范的修订。

**注**

- 测试光盘仅包含由 Track A 和 Track B 派生的素材。它们不予分发，测试者在验收后将其销毁。
- 第三方软件（ImgBurn、EAC 等）由测试者自行获取和安装。它们仅用于刻录和抓取测试，不属于 LAE 代码或代码仓库的一部分。
