# LAES 简介

[English](OVERVIEW.md) | **中文**（以英文版为准）

**LAES**（LAE Lossless，ID `LAE2`）在一个普通的 FLAC 或 WAV 文件中存储一个**核心母带**以及其他若干**无损母带**。未安装 LAE 软件的播放器播放核心母带。安装了 LAE 软件的播放器还能够播放其他母带，每个母带在核对其 SHA-256 之后方可播放。所存储的每个母带均为无损母带，并逐位还原。

- **核心母带**本身即为一个无损母带：整数 PCM，44.1 或 48 kHz，16、24 或 32 位。为 16 位时，核心母带可以是 CD 兼容的。CD 播放器无法读取 24 位或 32 位的核心母带，也无法读取 FLAC 形式的核心母带。
- **其他母带**的采样率为基础采样率的 1、2、4 或 8 倍（最高 352.8 / 384 kHz），位深为 16、24 或 32 位。每个母带或者以相对于文件中已有信号（核心母带或较早的母带）的差值形式存储，或者完整存储，取二者中较小者。
- **派生母带**（16 位）按来源提供，每个高于 16 位的来源一个：核心母带、每个母带及其每个采样率档位；发行方可以关掉（[SPEC.zh.md](SPEC.zh.md) 第 10.1 节）。派生母带相对于其定义是无损的：每个解码器均逐位还原该派生母带。派生母带相对于其所派生自的母带不是无损的：该母带经 TPDF 抖动重新量化为 16 位，无法从派生母带中恢复。派生母带不是原始母带。

规范性文本：[SPEC.zh.md](SPEC.zh.md)。未安装 LAE 软件时哪些软件能够播放哪种形式：[COMPATIBILITY.zh.md](../COMPATIBILITY.zh.md)。

## 与 FLAC 和 WAV 的比较

测量于 2026-11-05，使用两个 10 秒片段（2L 02 和 05）。对于每个片段，文件包含一个核心母带和另外三个母带：352.8 kHz / 32 位、352.8 kHz / 24 位和 176.4 kHz / 24 位。单独的 FLAC 文件使用 FFmpeg 以压缩级别 8 生成。

| 同样四个版本的存储方式 | 片段 02 | 片段 05 |
|---|---|---|
| 一个 LAES 文件，FLAC 形式（24 位核心母带） | **13.9 MB** | **15.2 MB** |
| 四个 FLAC 文件（24 位核心母带 + 三个母带） | 24.8 MB | 28.7 MB |
| 一个 LAES 文件，WAV 形式（16 位核心母带） | 16.6 MB | 17.5 MB |
| 四个 WAV 文件（16 位核心母带 + 三个母带） | 61.7 MB | 61.7 MB |
| 作为参照：仅核心母带的 FLAC 文件（2026-11-05；其字长未记录） | 1.1 MB | 1.5 MB |

上述数据适用于如本次测试那样由同一源制作的母带。混音、电平或剪辑不同的母带彼此共同之处很少，此时编码器会将其基本完整地存储。

## 优点

- **一个文件，包含所有版本。** 发行方只分发一个文件。由听者选择版本，或由播放器在听者设定的限制范围内选择一个版本。
- **小于分别存储的文件。** 在上述测试中，LAES 文件比同样版本分别存储为 FLAC 文件小 44 % 至 47 %，其 WAV 形式比同样版本分别存储为 WAV 文件小 72 % 至 73 %。
- **无需 LAE 软件即可播放。** 该文件是标准的 FLAC 或 WAV 文件，因此任何完整的 FLAC 或 WAV 解码器均能播放核心母带，但受下列限制（Windows 内置 FLAC 解码器、RF64、32 位 FLAC；[COMPATIBILITY.zh.md](../COMPATIBILITY.zh.md)）。已测试：libFLAC、FFmpeg、Kodi、VLC、foobar2000 以及 Android 内置解码器。
- **无损且经校验。** 每个母带均携带其 SHA-256。播放器仅在某一母带已完整解码且其 SHA-256 核对相符之后才使用该母带。
- **标签和图片。** 在 FLAC 形式中，标签和图片存储在母带之前（Vorbis comments、PICTURE）；在 WAV 形式中，存储为 RIFF INFO 加 ID3v2.4。所有标签和图片均以 UTF-8 编码。修改标签和图片（`laes tag`）不改变音频。
- **配套工具。** `laes_export` 将任意单个版本写为普通 FLAC 文件，供流媒体服务器使用；`laes_disc.ps1` 为一张专辑创建数据光盘镜像。

## 缺点和限制

- **其他母带需要 LAE 软件。** 若无 LAE 软件，只能播放核心母带。
- **FLAC 形式：母带位于前部。** FLAC 要求所有元数据位于音频帧之前。因此：
  - Windows 内置解码器（Media Foundation、资源管理器）无法识别该文件；
  - 通过网络直接读取该文件的播放器必须在开始播放前加载这些母带；
  - 没有跳转表，因此在某些播放器中跳转比普通 FLAC 文件慢。
- **WAV 形式：超过 4 GiB 时使用 RF64。** 许多 WAV 读取器（包括 Android 的读取器）无法打开 RF64 文件。
- **32 位核心母带的可播放范围不广。** 许多解码器无法播放 32 位核心母带：Windows 和 Android 不解码 32 位 FLAC。因此，除非另行指定，参考编码器使用不超过 24 位的核心母带。
- **编码需要时间、内存和临时磁盘空间。** 对 30 分钟、含 12 个母带的音乐进行编码（FLAC 形式，在 32 线程计算机上；[SPEC.zh.md](SPEC.zh.md) 第 11.5 节）约耗时 36 分钟，占用 1.4 GB 内存和约 28 GB 临时磁盘空间（2026-11-05）。
- **文件远大于仅含核心母带时的大小。** 该文件携带所有母带。

## 选用哪种形式

- **FLAC 形式**（`.flac`，或 `.lae` 加 `--form=flac`）：最小的形式。核心母带可以为 24 位，标签的存储方式与任何 FLAC 文件相同。不适用于 Windows 内置播放器。
- **WAV 形式**（`.wav`，或 `.lae` 加 `--form=wav`）：核心母带位于 `data` 块中（默认 16 位，可以是 CD 兼容的）。Windows 资源管理器能够读取其时长（已测试）；在 Windows 内置播放器中的播放未经测试。文件较大，超过 4 GiB 时使用 RF64。
- **用于流媒体时，** 应提供以 `laes_export` 生成的普通 FLAC 文件，而不是 LAES 文件本身。
