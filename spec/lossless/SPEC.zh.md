## 1. 范围与一致性

### 1.1 LAES 的内容

LAES 在一个文件或一张光盘中存放：

* 一个**核心母带**：双声道整数 PCM，**基础采样率**为 44 100 Hz 或 48 000 Hz，16、24 或 32 位，普通播放器无需任何处理即可播放；
* 1 至 255 个**母带**（有效载荷版本 1 最多 16 个，第 6.1 节）：双声道整数 PCM，16、24 或 32 位，采样率各为基础采样率 × 1、2、4 或 8。各母带相互独立：每个母带都能来自不同的制作（例如同一作品的一个 88.2 kHz 的 16 位母带和一个 352.8 kHz 的 24 位母带）。每个采样率、每种字长都可以放真正的独立母带，同一采样率和字长也可以有多个母带。每个母带可以带一个由发行方写的**名称**（第 6.2 节）。

每个母带均**逐位**还原。解码器还由每个母带通过第 3 节的提升得到其**采样率档位**：该母带在其采样率 / 2、/ 4 和 / 8 上的信号，直至基础采样率。采样率档位是精确定义的整数信号，不单独存储。

LAES 的存储全程无损：有效载荷中没有任何近似内容。（第 10.1 节的派生 16 位母带是一种输出，不是存储内容。）每个母带或者存储为相对文件中已有的另一信号（核心母带或更早的母带）的差值，或者完整存储，由编码器选取较小者（第 6.4 节）。

### 1.2 载体

| 载体 | 核心母带 | LAES 有效载荷 | 节 |
|---|---|---|---|
| **WAV 形式** | RIFF/WAVE 文件的 `data` 块 | 同一文件中的 `LAE ` 块（末尾带一个空格） | 7 |
| **FLAC 形式** | FLAC 文件的音频帧 | 一个或多个 ID 为 `LAE2` 的 APPLICATION 元数据块 | 8 |
| **CD-Extra** | 区段 1 的音轨（16 位，44 100 Hz） | 数据区段中每轨一个扩展文件 | 9 |

三种载体存放相同的有效载荷（第 6 节），仅核心母带的存放位置不同。

### 1.3 一致性

符合本规范的解码器：

1. 必须按第 6.7 节的规定检查有效载荷，并按第 7 至 9 节的规定检查载体；
2. 必须按第 6.6 节的规定精确还原每个母带；
3. 必须将每个还原出的母带与其 SHA-256（第 6.5 节）比对，并且不得将哈希不符的母带作为该母带提供。播放器在播放一个母带（以及它的采样率档位、派生版本）之前，必须先把这个母带和它参照链上的每个母带完整解码一遍，SHA-256 全部相符才可以播放；同一份文件内容的核对结果可以记下来（例如按整个文件的 SHA-256），下次直接播放；
4. 在有效载荷缺失、损坏或未通过检查时，必须仍按原样播放核心母带（“仅核心母带”），但 FLAC 形式中核心母带的 STREAMINFO MD5 缺失或错误的情形（第 8 节）除外：此时不得使用有效载荷，参考工具拒绝该文件；播放器可在向用户给出警告后播放核心母带，或拒绝该文件；
5. 可提供第 10 节中的任何输出。

符合本规范的编码器所写出的有效载荷，能被符合本规范的解码器接受，并能逐位还原编码器的输入母带。留给编码器选择的事项列于第 11 节。

### 1.4 术语

| 术语 | 含义 |
|---|---|
| 基础采样率 | 44 100 Hz（CD 族）或 48 000 Hz（DVD 族） |
| 核心母带 | 普通播放器播放的信号（第 1.1 节）。作为 16 位信号（例如在 CD 上）时，它相当于 LAE Lossy 所称的 CD 层；在 WAV 形式和 FLAC 形式中，它也能为 24 位或 32 位 |
| 级数 | 对于采样率为基础 × 2^S 的母带，指数值 S（0 至 3） |
| 第 k 级 | 对于级数为 S 的母带，指其在采样率基础 × 2^k 上的信号，0 ≤ k ≤ S。第 S 级即母带本身（去除其未用低位之后，第 6.3 节）；第 0 级为其**基础级别** |
| 倍频程层 k | 将第 k 级拆分为第 k − 1 级时产生的细节信号（第 3 节） |
| 参照档 | 母带据以存储的信号：核心母带或有效载荷中更早的一个母带（不要与格式系列的有损等级和无损等级混淆） |
| T | 母带相对其参照档的**时间位置**，以基础采样率样点为单位，由整数部分和以 2^−32 个基础采样率样点为单位的小数部分给出 |
| w | 母带每个样点中均为零的低位个数（“未用低位”）；若每个样点均为 0，则 w = 0 |

### 1.5 设计特性（说明性）

* 有效载荷及其载体中不包含索引、seek 表、cue 表或层偏移表。时间位置只能通过解码获知。
* 有效载荷作为单一整块存放，不与核心母带交错。
* 每个母带在其整个长度上只有一种存储方式和一个参照档。不存储任何权重或增益。
* 两个声道始终分别编码：母带的左声道只由左声道信号还原，右声道只由右声道信号还原。

## 2. 记号与运算

### 2.1 整数

* `int64` 和 `uint64` 分别表示 64 位有符号（二进制补码）整数和无符号整数；8、16 和 32 位使用相同的记号。
* 有效载荷、WAV 块和 CD-Extra 尾部记录中的所有多字节量均为**小端**。FLAC 结构遵循 RFC 9639（大端位序）。
* 对有符号值，`a >> s` 为算术右移（除以 2^s 后向下取整）。
* **精确求和。**本规范中凡写出乘积之和之处，该和必须精确求得。对于第 3 节和第 4 节中的所有求和，128 位二进制补码累加器均已足够。
* **回绕。**第 3、4.2、5.1 和 6.6 节中产生的每个值（预测值、还原的样点、提升输出、参照值、`x << w`）均按 int64 取模 2^64（二进制补码）。正确的有效载荷不会需要更宽的值；需要更宽值的有效载荷只会在 SHA-256 比对时失败。
* **舍入。**对精确整数 A 和 s ≥ 1，`round_s(A) = (A + 2^(s−1)) >> s`，在精确值上计算。该运算将 A / 2^s 舍入到最接近的整数，恰居中间时向 +∞ 舍入。
* **对称延拓。**对长度为 n ≥ 1 的信号 x 和任意整数下标 i：
  若 n = 1，则 `m(i, n) = 0`；否则令 p = 2(n − 1)，`j = i mod p`（0 ≤ j < p），若 j < n 则 `m(i, n) = j`，否则为 `p − j`。
  `x[m(i, n)]` 为 x 按整样点镜像延拓后在下标 i 处的值。下标为 64 位。
* `levLen(n, k)`：将 n 减半 k 次，每次向上取整（`n = (n + 1) / 2`，执行 k 次）。

### 2.2 浮点（仅用于第 4.1 节）

参照抽头以 IEEE-754 binary64 计算。每个 `+ − × ÷` 和 `sqrt` 运算必须单独舍入（就近舍入，恰居中间时取偶），并按书写顺序进行。不得使用融合乘加、扩展精度中间值或重新排序。除 `sqrt` 和 `floor` 外，不得使用其他库函数。*说明性：*MSVC 使用 `/fp:strict`；GCC/Clang 使用 `-ffp-contract=off` 且不使用 `-ffast-math`。

## 3. 采样率档位：提升 L

### 3.1 一级

一级将长度为 n 的信号 x 拆分为低频部分 s（长度 ⌈n / 2⌉；即下一较低级）和细节信号 d（长度 ⌊n / 2⌋；即倍频程层）：

```
xe[i] = x[2i]          0 ≤ i < ⌈n/2⌉
xo[i] = x[2i + 1]      0 ≤ i < ⌊n/2⌋
d[i]  = xo[i] − P(xe, i)
s[i]  = xe[i] + U(d, i)

P(xe, i) = round_30( Σ_{t=0..39} H0[t] · ( xe[m(i − t, ne)] + xe[m(i + 1 + t, ne)] ) )          ne = ⌈n/2⌉
U(d, i)  = round_31( Σ_{t=0..59} U0[t] · ( d[m(i − 1 − t, no)] + d[m(i + t, no)] ) )            no = ⌊n/2⌋; U = 0 if no = 0
```

H0 为表 `kHalf0`，U0 为表 `kU0`（附录 A）。每个乘积单独计算，求和精确（第 2.1 节）。

已知 s、d 和 n 时，逆运算为：

```
xe[i]     = s[i] − U(d, i)
x[2i]     = xe[i]
x[2i + 1] = d[i] + P(xe, i)
```

逆运算精确还原 x。

### 3.2 母带的全部级别

对于级数为 S 的母带，第 S 级为去除其未用低位之后的母带（第 6.3 节）。对 k 从 S 到 1，对第 k 级施加一级运算，得到第 k − 1 级和倍频程层 k。因此：

* 第 k 级每声道有 `levLen(F, S − k)` 个样点，其中 F 为母带的帧数；
* 倍频程层 k 每声道有 `⌊levLen(F, S − k) / 2⌋` 个样点。

## 4. 参照：时间位置与字长

母带（或其某一级）存储为相对**参照**的差值。参照是将参照档信号移至母带的时间位置并缩放到母带字长所得的信号。

### 4.1 参照抽头

对于一个样点的小数 f ∈ [0, 1)（以无符号 32 位值 F 给出，f = F / 2^32），256 个参照抽头 h[q]（q = −127 … 128）按如下方式计算（以 binary64；第 2.2 节）：

```
PI    = 3.141592653589793115997963468544185161590576171875       (the binary64 value nearest to π)
sin(x) for |x| ≤ π/2:  y = x·x; s = 1; for k = 15 down to 1: s = 1 − s·y / ((2k)·(2k + 1)); result x·s
I0(x):                 y = x·x / 4; term = 1; s = 1; for k = 1 to 80: term = term·y / (k·k); s = s + term; result s

g   = f if f ≤ 0.5, else 1 − f
sf  = sin(PI·g)
i0b = I0(14)
for q = −127 … 128:
    u = f − q
    sinc = 1 if u = 0, else (q even ? +1 : −1) · sf / (PI·u)
    r = u / 128
    w = I0(14 · sqrt(1 − r·r)) / i0b   if −1 < r < 1, else 0
    h[q] = floor(sinc · w · 2^31 + 0.5)                              (as int64)
c = the smallest q with the smallest |u| (q scanned upwards, strict comparison; matters for f = 0.5)
h[c] = h[c] + 2^31 − Σ_q h[q]
```

各抽头均为整数，其和恰为 2^31。当 f = 0 时，h[0] = 2^31，其余抽头均为 0。

### 4.2 参照值

设 `src` 为参照档在相应级别上的信号（长度 n），`W` 为时间位置的整数部分，F 为其小数部分，两者均以该级别的样点为单位，`up` 为栅格差（第 6.6 节）。参照的长度等于母带在该级别上的信号长度（`nOut` 个值）：

```
A_i     = Σ_{q=−127..128} h[q] · src[m(i + W + q, n)]          exact
ref[i]  = round_{31−up}(A_i)            if 31 − up > 0
ref[i]  = A_i · 2^(up−31)               if 31 − up ≤ 0 (taken modulo 2^64 as int64)
```

*说明性：*`up` 为母带比参照档多出的有效位数。当母带位数较少时，`up` 为负；此时参照将参照档向下舍入到母带的字长。

### 4.3 第 j 级上的时间位置

时间位置 T = W + F / 2^32 个基础采样率样点，在第 j 级（采样率基础 × 2^j）上对应于该级别的 T · 2^j 个样点：

```
W_j = W · 2^j + (F >> (32 − j))        for j ≥ 1;   W_0 = W
F_j = (F · 2^j) mod 2^32
```

## 5. 层编码器

层编码器将每个存储的信号（基础级别、级别差值或倍频程层，每次一个声道）编码为一个字节串。位按最高有效位在前的顺序写入。一个含 n 个样点的**层**是一系列长度为 B 的**块**（最后一块容纳余下的样点），块与块首尾相接写入，块之间不作字节对齐；层以零位填充至下一字节边界。

### 5.1 块

| 字段 | 位数 | 含义 |
|---|---|---|
| type | 2 | 0 = 常数，1 = 原样，2 = 固定预测器，3 = LPC |
| W | 6 | 所存常数、原样值和预热值的宽度（W 位二进制补码）；1 ≤ W ≤ 62。编码器选择 W，使块中每个样点均能容纳；解码器不按 W 检查解出的样点 |

对于含 n 个样点 x[0 … n−1] 的块，其后内容按类型而定：

* **常数：**一个 W 位值 v；x[i] = v。
* **原样：**n 个 W 位值。
* **固定预测：**阶数 o（3 位；0 ≤ o ≤ 4，o < n）；o 个预热样点（各 W 位）；含 n − o 个值的残差。仅当 W ≤ 58 时允许。预测（与 FLAC 相同）：o = 0：0；o = 1：x[i−1]；o = 2：2x[i−1] − x[i−2]；o = 3：3x[i−1] − 3x[i−2] + x[i−3]；o = 4：4x[i−1] − 6x[i−2] + 4x[i−3] − x[i−4]。
* **LPC：**阶数 − 1（5 位；阶数 o = 1 … 32，o < n）；精度 − 1（4 位；p = 1 … 16）；移位（5 位；0 … 31）；o 个系数 c[0 … o−1]（各为 p 位二进制补码）；o 个预热样点（各 W 位）；含 n − o 个值的残差。仅当 W ≤ 44 时允许。预测：`pred_i = floor( Σ_{j=0..o−1} c[j] · x[i−1−j] / 2^shift )`，求和精确（shift = 0 时即为和本身）。

还原：对 i ≥ o，x[i] = residual[i] + pred_i。

### 5.2 残差

| 字段 | 位数 | 含义 |
|---|---|---|
| 分区阶 po | 4 | 0 ≤ po ≤ 8，2^po ≤ m（m = 残差值的个数） |

m 个值分为 2^po 个分区：分区 0 … 2^po − 2 各含 ⌊m / 2^po⌋ 个值，最后一个分区含 m − (2^po − 1) · ⌊m / 2^po⌋ 个值。每个分区由以下内容组成：

* 一个 6 位参数 k。对 k = 0 … 62，各值采用 Rice 编码：v ≥ 0 时 u = 2v，v < 0 时 u = −2v − 1；商 q = u >> k 写为 q 个零位后接一个一位，其后为 u 的低 k 位。值 u 必须能容纳于 64 位。
* k = 63 为转义：其后为一个 6 位宽度 r（1 … 63），然后将每个值写为 r 位二进制补码数。

所有附加信息均为定长。

### 5.3 块长

| 信号 | 块长 B |
|---|---|
| 基础级别（存储方式 1）和基础级别差值（存储方式 0） | 4096 |
| 第 j 级差值（存储方式 2） | 4096 · 2^j |
| 倍频程层 k | 4096 · 2^(k−1) |

### 5.4 检查

当某字段超出上述范围、某种预测器类型用于超过其上限的 W、阶数不小于块长，或数据提前结束时，解码器必须拒绝该层（第 6.7 节）。所存层长度内位于最后一块之后的字节以及填充位不作检查；解码器必须忽略它们。

## 6. LAES 有效载荷

有效载荷是一个字节串，其后为它的 CRC-32（4 字节）。CRC-32 为 IEEE 802.3 CRC（反射多项式 0xEDB88320，初始值和最终异或值均为 0xFFFFFFFF），对其之前的全部有效载荷字节计算。

### 6.1 头部（64 字节）

| 偏移 | 长度 | 字段 | 值 |
|---|---|---|---|
| 0 | 4 | 魔数 | `LAE2` |
| 4 | 2 | 版本 | 1 或 2（见第 6.2 节） |
| 6 | 2 | 头部长度 | 64 |
| 8 | 4 | 基础采样率 | 44 100 或 48 000 |
| 12 | 1 | 核心母带位深 | 16、24 或 32 |
| 13 | 1 | 声道数 | 2 |
| 14 | 1 | 母带数 M | 版本 1：1 … 16；版本 2：1 … 255 |
| 15 | 1 | 核心母带方式 | 0 = 核心母带位于 WAV `data` 块中或 CD 音轨上；1 = 核心母带位于 FLAC 音频帧中 |
| 16 | 8 | 核心母带帧数 | 核心母带每声道的样点数 |
| 24 | 32 | 核心母带 SHA-256 | 第 6.5 节 |
| 56 | 1 | 默认母带 | 版本 2：0 = 核心母带，k = 有效载荷顺序中的母带 k（1 … M）：用户没有选择时播放器播放的项（第 10.3 节）；版本 1：保留，0 |
| 57 | 1 | 核心母带标志 | 版本 2：位 0 = 1：核心母带不提供派生 16 位版本（第 10.2 节）；位 1 … 7 为 0；版本 1：保留，0 |
| 58 | 6 | 保留 | 0 |

第 56、57 字节由编码器按发行方的选择写入；没有选择时都为 0。

### 6.2 母带记录（72 字节），其后为该母带的各层

| 偏移 | 长度 | 字段 | 值 |
|---|---|---|---|
| 0 | 1 | 位深 | 16、24 或 32 |
| 1 | 1 | 级数 S | 0 … 3（采样率 = 基础 × 2^S） |
| 2 | 1 | w | 未用低位，w < 位深 |
| 3 | 1 | 存储方式 | 0、1 或 2（第 6.4 节） |
| 4 | 1 | 参照档 | 0 = 核心母带；k = 本有效载荷中的第 k 个母带（从 1 起计） |
| 5 | 1 | 名称长度 N | 版本 2：0 … 255（0 = 没有名称）；版本 1：保留，0 |
| 6 | 1 | 标志 | 版本 2：位 0 = 1：这个母带不提供派生 16 位版本（第 10.2 节）；位 1 … 7 为 0；版本 1：保留，0 |
| 7 | 1 | 菜单位置 | 版本 2：0，或 1 … M（见下）；版本 1：保留，0 |
| 8 | 4 | 采样率 | 基础 × 2^S |
| 12 | 4 | 保留 | 0 |
| 16 | 8 | 帧数 F | 每声道样点数，≥ 1 |
| 24 | 8 | T 整数部分 | int64，T 的整数部分（以基础采样率样点为单位，相对参照档） |
| 32 | 4 | T 小数部分 | uint32，以 2^−32 个基础采样率样点为单位 |
| 36 | 4 | 保留 | 0 |
| 40 | 32 | 母带 SHA-256 | 第 6.5 节 |

存储方式 1 时，T 字段存放这个母带相对核心母带的 T；解码器不使用它们（第 6.6 节）。2026-11-15 以前写的文件在这些字段中是 0。

版本 2 时，每个母带记录之后紧跟它的 N 字节**名称**，然后才是它的各层；版本 1 没有名称。

各母带按有效载荷顺序依次排列：母带 1 的记录（版本 2 时带名称）、其各层，母带 2 的记录、其各层，依此类推。CRC-32 位于最后一个母带的各层之后。母带的参照档必须是核心母带或有效载荷中位于其前的母带。

**版本。**有效载荷能写成版本 1（母带不超过 16 个，没有名称，标志和菜单位置都为 0，头部第 56、57 字节都为 0）时，写入方必须写版本 1，这时有效载荷和有效载荷版本 1 的写入方写出的逐字节相同；否则写版本 2。只认版本 1 的解码器遇到版本 2 会拒绝有效载荷，只播放核心母带（第 1.3 节）。

**菜单位置。**文件中母带的顺序由编码器决定（为了文件最小；母带只能参照位于其前的母带）；菜单和选择的顺序由发行方标记，两者互不相关。菜单位置要么全部为 0（菜单顺序就是文件顺序），要么是 1 … M 的一个排列，每个值恰好出现一次。母带在菜单中的编号就是它的菜单位置；没有标记时是它在文件中的序号。菜单位置只是顺序，不带任何种类、优先级或自动选择的含义，也不决定哪个母带是默认（默认由头部第 56 字节决定）。

**名称。**名称是发行方写的自由文本：合法的 UTF-8（最短形式，不含代理项，不超过 U+10FFFF），最多 255 字节，不含控制字符 U+0000 … U+001F 和 U+007F。读取方原样显示，不解析、不改写。名称不参与还原、参照、存储方式、哈希和任何自动选择（第 10.3 节）；修改名称不改变任何母带的样点。没有名称的母带只用编号称呼。

### 6.3 母带的各层

对于存储方式 0 和 1，令 j = 0；对于存储方式 2，令 j = min(S, S_t)，其中 S_t 为参照母带的级数。对每个声道（先左后右），存储以下内容：

1. 一个 uint32 字节长度，其后为以下信号的层编码（第 5 节）：
   * 存储方式 0 或 2：第 j 级上的**差值**，`levLen(F, S − j)` 个值：母带的第 j 级减去参照（第 6.6 节）；
   * 存储方式 1：母带本身的基础级别，`levLen(F, S)` 个值；
2. 对每个 k = j + 1 … S：一个 uint32 字节长度，其后为倍频程层 k 的层编码。

母带的样点取**去除其未用低位之后**的值：`x = sample >> w`。第 3 节的各级和倍频程层均由 x 计算。

### 6.4 存储方式取值

| 存储方式 | 参照档 | 存储所在级别 | 含义 |
|---|---|---|---|
| 0 | 核心母带或任一更早的母带 | j = 0 | 在基础级别上相对参照档的差值 |
| 1 | 0（无） | j = 0 | 完整存储基础级别 |
| 2 | 一个更早的母带 | j = min(S, S_t) | 在两者共有的最高级别上相对参照母带的差值；仅存储 j 以上的倍频程层 |

### 6.5 哈希

* **母带 SHA-256：**按文件顺序 L、R、L、R、… 对母带的样点计算，每个样点取其 int32 二进制补码值，4 字节，小端。
* **核心母带 SHA-256：**对于 16 位核心母带，按 int16 小端、L、R、L、R、… 对样点计算（即 16 位 `data` 块的字节内容）；对于 24 位或 32 位核心母带，按与母带相同的方式计算（int32 小端）。

### 6.6 还原

对每个母带 m 按有效载荷顺序，并对每个声道分别进行：

```
j  = 0 (storage 0, 1) or min(S, S_t) (storage 2)
x_j = decoded first layer                               (levLen(F, S − j) values)
if storage ≠ 1:
    tier signal src = the core master channel (tier 0), or level j of tier master t (tier t ≥ 1)
    up  = (bits − w) − (core master bits)                       for tier 0
          (bits − w) − (bits_t − w_t)                    for a tier master t
    (W_j, F_j) = T at level j (Section 4.3)
    x_j = x_j + reference(src, W_j, F_j, up)             (Section 4.2, nOut = levLen(F, S − j))
for k = j + 1 … S:
    x_k = inverse stage(x_{k−1}, octave layer k, levLen(F, S − k))
master sample = x_S << w
```

参照母带 t 的第 j 级由其还原出的样点得到：x_t = sample >> w_t 为其第 S_t 级，每施加一次一级运算（第 3.1 节）即得到下一较低级。

### 6.7 检查

出现下列任一情况时，解码器必须拒绝有效载荷（并仅播放核心母带）：

* CRC-32 不符；
* 魔数、版本（1 或 2）或头部长度（64）不同；基础采样率不是 44 100 或 48 000，或与载体中核心母带的采样率不同；核心母带位深与载体中核心母带的位深不同；声道数 ≠ 2；核心母带方式 > 1；M 不在 1 … 16（版本 1）或 1 … 255（版本 2）之内；
* 版本 2：菜单位置既不全为 0，也不是 1 … M 的一个排列；
* 版本 2：某个母带的标志位 1 … 7 不为 0；名称不是合法的 UTF-8、含控制字符，或超出有效载荷的末尾；
* 核心母带帧数与载体中核心母带的长度不同，或核心母带 SHA-256 不符；
* 对某个母带：位深不是 16、24 或 32；S > 3；w ≥ 位深；存储方式 > 2；采样率 ≠ 基础 × 2^S；F < 1；`levLen(F, S)` > 核心母带帧数 + 2^24；|T 整数部分| ≥ 2^40。核心母带帧数和 F 均为 uint64，比较时必须不作截断；无法容纳 F 个样点之母带的解码器必须拒绝有效载荷，而不是截断该母带；
* 对某个母带：T（T 整数部分 + T 小数部分 · 2^−32）超出 −N … N，N 是核心母带的帧数（超出整轨的偏移没有意义）；
* 存储方式 0 或 2 的参照档在有效载荷中不位于其前；存储方式 2 的参照档为 0；存储方式 1 的参照档不为 0；
* 某层未通过第 5.4 节的检查，或有效载荷提前结束；
* 最后一个母带的各层与 CRC-32 之间仍有剩余字节。

还原结果与其 SHA-256 不符的母带不得作为该母带提供，其采样率档位亦然。核心母带和其他母带不受影响，但参照链中包含该失败母带的母带除外：这些母带由错误的值还原，除非发生 SHA-256 碰撞，其 SHA-256 比对也将失败。

保留字段：写入方必须写入 0，读取方必须忽略。核心母带方式不与载体进行比较。

## 7. WAV 形式

LAES WAV 文件是包含下列块的 RIFF/WAVE 文件（超过 4 GiB 时为 RF64 文件；见下文）：

* `fmt `：整数 PCM（格式标记 1，或 0xFFFE 加 PCM 子格式），2 声道，基础采样率，16、24 或 32 位；
* `data`：核心母带；
* `LAE `：LAES 有效载荷及其 CRC-32（第 6 节），核心母带方式为 0；
* 类型为 `INFO` 的 `LIST` 块和 `id3 ` 块（ID3v2 标签），均为可选：标签和图片。写入方将它们置于 `fmt ` 之后、`data` 之前。一套标签描述核心母带和每个母带；本规范定义的任何哈希均不覆盖它们，它们也不参与输出的选择或检查（第 10 节）。

文件必须恰好包含一个 `data` 块，且至多包含一个 `LAE ` 块：写入方不得对二者中的任一种写入多于一个。读取方若发现多于一个 `data` 块或 `LAE ` 块，则对每种类型各取最后一个，参考解码器即如此处理。读取方跳过其不使用的每个块。*说明性：*参考解码器将超出文件末尾的块长度截至文件末尾。

任何 WAV 播放器均播放核心母带（32 位核心母带仅在支持 32 位 PCM 的播放器中播放）。`LAE ` 块的前 4 个字节标识格式：`LAE1` = LAE Lossy（LAEY），`LAE2` = LAE Lossless（LAES）（本规范）。读取方应告知用户其识别出的格式；LAEY 解码器遇到 `LAE2` 时报告这是 LAES 文件且不对其解码，播放器则播放核心母带。

**超过 4 GiB 的文件（RF64）。**当文件的 RIFF 大小（RIFF 大小字段的值：文件长度减 8）将超过 0xFFFFFFFF 时，写入方使用 RF64 形式（EBU Tech 3306，ITU-R BS.2088）；否则使用 RIFF 形式。RF64 形式与 RIFF 形式仅有以下区别：

* 字节 0–3 为 `RF64`，偏移 4 处的 32 位大小字段为 0xFFFFFFFF；
* 偏移 12 处的第一个块为 `ds64`，其主体为 40 字节：以 `uint64` 表示的 RIFF 大小（文件长度减 8）、以 `uint64` 表示的 `data` 主体大小、以 `uint64` 表示的核心母带帧数、以 `uint32` 表示的表长度 1，以及一个表项：块 ID `LAE ` 及以 `uint64` 表示的其主体大小；
* `data` 块和 `LAE ` 块的 32 位大小字段为 0xFFFFFFFF；其大小为 `ds64` 中给出的大小。

读取方必须接受 RF64 形式，并接受字节 0–3 为 `BW64` 的相同布局。在此类文件中，第一个块必须为 `ds64`，其主体至少为 28 字节；32 位大小字段为 0xFFFFFFFF 的块从 `ds64` 取得其大小：`data` 块取 `data` 大小，其他块取具有相同块 ID 的表项。

## 8. FLAC 形式

LAES FLAC 文件是具有以下结构的 FLAC 流（RFC 9639）：

```
"fLaC" | STREAMINFO | VORBIS_COMMENT, PICTURE (optional) | APPLICATION blocks with ID "LAE2" (1 or more) | other metadata blocks (optional) | audio frames = the core master
```

* STREAMINFO：2 声道，基础采样率，16、24 或 32 位，核心母带的样点数（不得为 0）以及核心母带的 MD5（必须存在且正确）。发现 MD5 缺失或错误的解码器不得使用有效载荷：此核心母带并非该有效载荷所对应的核心母带。此时，参考工具拒绝该文件；播放器可在向用户给出警告后播放核心母带，或拒绝该文件（第 1.3 节第 4 项）。
* LAES 有效载荷（含其 CRC-32；核心母带方式为 1）被切分为每段至多 2^24 − 5 字节的片段。每个片段为一个 APPLICATION 块的数据，该块的 4 字节 ID 为 `LAE2`（0x4C 0x41 0x45 0x32），已由 IANA 在 FLAC Application Metadata Block IDs 登记表中登记（RFC 9639 第 12.2 节；2026-10-31）。写入方将这些块置于 STREAMINFO 之后以及 VORBIS_COMMENT 和 PICTURE 块（如有）之后，连续排列，中间不夹其他块。读取方按文件顺序拼接所有 ID 为 `LAE2` 的 APPLICATION 块，不论它们位于元数据块中的何处。
* 标签和图片（可选）：至多一个 VORBIS_COMMENT 块和任意数量的 PICTURE 块（RFC 9639 第 8.6 节和第 8.8 节）。写入方将它们置于 `LAE2` 块之前，以便播放器读取它们时无需跳过有效载荷。一套标签描述核心母带和每个母带；本规范定义的任何哈希均不覆盖它们，它们也不参与输出的选择或检查（第 10 节）。
* 音频帧存放核心母带，以左右声道独立的方式编码：每个帧头中的声道分配为 0b0001，不作声道间去相关。在此声道分配之内，允许对核心母带采用任何有效的 FLAC 编码。以后的修订版有可能加入对声道间去相关的支持。
* 不写入 SEEKTABLE 或 CUESHEET 块。
* 其他软件写入的标签：读取方接受 `fLaC` 之前的 ID3v2 标签，以及最后一个音频帧之后（即达到 STREAMINFO 给出的样点数之后）的 APEv2 和 ID3v1 标签。读取方不解读它们；由这种文件写出新文件的工具原样保留它们。

每个完整实现 RFC 9639 的 FLAC 解码器均播放核心母带并跳过 APPLICATION 块（2026-11-05 以 libFLAC 和 FFmpeg 验证）。仅部分实现该规范的解码器未必如此：Windows 内置的 FLAC 解码器（Media Foundation，资源管理器也使用它）不解码 32 位 FLAC，并且不识别第一个音频帧起始于文件约 4 MiB 之后的文件，而有效载荷大于该值的 LAES FLAC 文件正属此情形。经测试的解码器及变通办法见 [COMPATIBILITY.zh.md](../COMPATIBILITY.zh.md)。

*说明性：*参考编码器的 FLAC 写入器（`src/laes_flac_enc.h`）使用固定块长 4096、两个独立编码的声道、至多 12 的 LPC 阶数、至多 15 的精度以及至多 8 的 Rice 分区阶。在 44.1 / 48 kHz 下，这符合 FLAC 的可流式子集。许多较旧的播放器不播放 32 位 FLAC；因此，除非另有指示，参考编码器在 FLAC 形式中不使用 32 位核心母带（它使用至多 24 位的最高母带字长；第 11.1 节）。参考解码器仅解码声道独立编码的核心母带。

## 9. CD-Extra

在以 LAE CD-Extra 封装（`spec/cdx/SPEC.md`）制作的 CD-Extra 光盘上，每轨的扩展文件（`.LAX`）为：

```
LAES payload with its CRC-32 (core master mode 0) | 80-byte trailer record
```

尾部记录即 `spec/cdx/SPEC.md` 第 3.2 节所定义的尾部记录，**扩展块类型为 2**。读取方必须检查扩展块的前 4 个字节在类型 2 时为 `LAE2`（在类型 1 时为 `LAE1`）；否则，读取方必须拒绝该扩展，并仅播放 CD 音轨。CD-Extra 规范的所有其他规则（整轨 MD5、滑动校验和、抓轨偏移搜索、检查顺序）照常适用。核心母带即 CD 音轨（16 位，44 100 Hz）。

## 10. 解码器输出

解码器对每个文件可提供的输出（第 1.3 节第 5 项）为：

| 输出 | 无损 | 定义 |
|---|---|---|
| 核心母带 | 是 | 按存储原样 |
| 每个母带 | 是 | 第 6.6 节 |
| 母带的每个采样率档位 | 在母带字长范围内按定义逐位精确（第 k 级，第 3.2 节）；超出该字长的值在输出时被限定在该字长内 | 第 k 级（第 3.2 节），样点为 `x_k << w`，按母带的字长写出 |
| 派生 16 位母带 | 相对其定义：**是**（每个解码器均逐位复现它）；相对其所取自的母带：**否**（以 TPDF 抖动重新量化至 16 位） | 第 10.1 节 |

### 10.1 派生 16 位版本

解码器可以由下面每个**来源**（b 位，b > 16，s = b − 16）各派生一个 16 位版本，即派生母带：

* 核心母带（核心母带位深大于 16，并且头部第 57 字节的位 0 为 0 时）；
* 每个字长大于 16、SHA-256 相符、并且标志位 0 为 0 的母带：母带本身，以及它的每个采样率档位（限定之后）。

每个派生版本只属于它的来源：同一采样率上已有的 16 位输出（16 位核心母带、16 位母带或其档位），或者别的母带的派生版本，都不影响它；派生版本也从不顶替或遮住任何母带。（2026-11-11 以前，解码器每个采样率最多提供一个派生版本，取自该采样率上位数最多的第一个输出，并且只在该采样率没有 16 位输出时提供。按现行规则，母带 1 的派生版本与那些版本逐位相同。）

```
per channel, a xorshift64 generator with state st = 20261029 + 0x9E3779B97F4A7C15 · (channel + 1)  (mod 2^64; channel 0 = left)
next():  st ^= st << 13;  st ^= st >> 7;  st ^= st << 17;  return st >> (64 − s)
for each sample v in order:  r1 = next(); r2 = next();  y = clamp((v + r1 − r2 + 2^(s−1)) >> s, −32768, 32767)
```

*说明性（从第 n 帧开始，用于跳转）：*状态只和声道、n 有关，和声音无关，就是调用 2n 次 next() 之后的状态（先 r1 后 r2，同上）。next() 在 GF(2) 上是线性的，解码器可以直接算出这个状态，例如把 64 × 64 位矩阵求 2n 次幂。这样从第 n 帧起的输出和从第 0 帧解码逐位相同。

结果为一个派生 16 位母带（±1 LSB 的 TPDF 抖动）：

* **相对本定义无损：**每个解码器在每次运行、每个平台上均逐位复现它。对其再次解码，或以另一解码器解码，均不会改变任何样点。
* **相对其所取自的母带不是无损的：**其低 b − 16 位被舍弃，并加入了 TPDF 抖动。无法由它恢复该母带。

它不是原始母带。解码器在提供它的任何地方都必须写明它是由哪个母带派生的（例如 `由母带 3「名称」派生 · 88.2 kHz / 16 位`）；输出的说明文字写明它相对其定义无损、相对其所取自的母带不是无损。

### 10.2 编码时关掉派生版本

母带记录的标志位 0（版本 2）为 1 时，解码器不提供这个母带的任何派生 16 位版本；头部第 57 字节的位 0 对核心母带起同样的作用。这个标志只决定是否列出这些派生版本：它不带任何参数，不在几种派生方法之间选择，也不影响母带本身、它的采样率档位、还原、检查和退路。

### 10.3 选择与显示（播放器和工具）

**列出的项和顺序：**

1. 核心母带；核心母带位深大于 16、并且它的标志（头部第 57 字节）允许时，紧接着是它的派生 16 位版本。
2. 每个母带一组，按菜单顺序（第 6.2 节；没有标记时按有效载荷顺序）：母带本身；它的采样率档位，从高到低；它的派生 16 位版本（先是母带自己的采样率，再从高到低是各档位）。

**菜单：**第一层只列核心母带和各母带本身；采样率档位和派生版本放在各自母带的子菜单里，不和别的母带的混在一起。只能显示一层的界面（例如命令行）按上面的顺序列出，并标明每个子项属于哪个母带。

**显示文字：**

* 编号总是显示。名称可以重复，也可以没有；编号保证每一项都不同。
* 第一层显示每个母带的完整信息，不显示任何派生项：编号、名称（有就显示）、采样率、字长、时长、"无损"，默认项加标记，例如 `母带 3「XX 唱片 2019 重制」· 176.4 kHz / 24 位 · 13:23 · 无损 · 默认`。核心母带同样。
* 只有核心母带和母带本身写"无损"。采样率档位和派生 16 位版本都写"由母带派生"，并带来源母带的编号和名称：`由母带 3「XX 唱片 2019 重制」派生 · 88.2 kHz / 24 位`、`由母带 3「XX 唱片 2019 重制」派生 · 88.2 kHz / 16 位`。采样率和字长后面不再写别的内容。
* 名称太长时界面可以截短显示，但必须能看到完整名称（例如提示框或属性页）。
* SHA-256 不符的母带标为"不可用"，不得悄悄去掉；参照链上包含它的每个母带同样标出。
* 中文界面写"核心母带"，不单独写"核心"。

**默认和自动选择：**

* 默认项（用户没有选择时播放的项）是头部第 56 字节记录的母带，由发行方在编码时选定；该字节为 0、或者是版本 1 的文件时，默认项是核心母带。默认项只能是母带本身或核心母带，不能是采样率档位或派生版本。播放器放不出它（解码失败，或 SHA-256 不符）时，播放核心母带。默认项从不按码率、大小、设备能力、网络或负载选择。本规范不给任何编号、菜单位置或名称规定种类含义。
* 母带的编号（显示的"母带 k"、`master:<k>`、文件名 `master_<k>_…`）一律是它在菜单中的编号。
* 用户设定的上限（最高采样率、最长字长）只在选中的母带之内起作用：取这个母带不超过上限的最高一档；字长超过上限时，取它自己的派生 16 位版本。上限不得导致换到别的母带。
* 不按设备能力、名称、文件类别或配置文件中的默认值自动选择，也不把名称从一个文件套用到另一个文件。播放器要记住用户的选择时，只按文件记住用户选的编号。

**命令行（参考工具的 `laes dec --pick`）：**`<n>` = 列表的第 n 项；`<rate>:<bits>` 和 `name:<text>` 只匹配母带本身（从不匹配采样率档位或派生版本），只匹配到一个时写出它；匹配到多个时由用户勾选：每个候选显示编号、采样率、位数和名称，可以逐个勾选，也可以在列表下方输入编号和范围（`6,12`、`6-12`）；不在控制台中时什么都不写出，只列出候选；`<a>-<b>` = 第 a 到第 b 项；`master:<k>` = 母带 k。

## 11. 编码器（说明性）

### 11.1 核心母带

核心母带或者是给定的（例如已发行的 CD 或 DVD），或者由某个母带的基础级别按选定字长派生。参考编码器在 WAV 形式中使用 16 位；在 FLAC 形式中使用至多 24 位的最高母带字长。来源母带是字长与核心母带相同的母带（此时其基础级别恰为核心母带），若不存在此类母带，则为字长最长的母带，经 TPDF 抖动降低位数。

派生的核心母带与任何其他核心母带一样存储于文件中：文件所存的是核心母带，由其 SHA-256 检查（第 6.5 节）。下述规则使任何人都能逐位检查核心母带是否由给定母带派生；参考编码器（`laes enc --derive-core`，`src/laes_stream_enc.h`）即按此规则派生核心母带。

```
source:  among the masters in the order given to the encoder, the first whose word length equals b (the core master's bits);
         if there is none, the first with the longest word length (the encoder prints which: "core master: b-bit base level of …")
x      = the source's level 0 (Section 3.2, after removing its unused low bits w), per channel
drop   = (bits − w) − b
if drop ≤ 0:  core sample = x << (−drop)                                     (no dither)
else:         one xorshift64 generator for both channels, state st = 20261028 · 2654435761 + 88172645463325252 (mod 2^64)
              next():  st ^= st << 13;  st ^= st >> 7;  st ^= st << 17;  return st
              u():     (next() >> 11) / 2^53 − 0.5                            (IEEE-754 double)
              for channel = left, then right; for each sample x in order:
                  t = x / 2^drop;  t = t + u();  t = t + u();  t = t + 0.5   (double, round to nearest, in this order;
                  core sample = clamp(⌊t⌋, −2^(b−1), 2^(b−1) − 1)             the first u() is added first)
```

除两次加 u() 和一次加 0.5 外，运算均为精确的；这三次加法在 IEEE-754 双精度运算中于每个平台上的舍入结果相同。左声道使用生成器的前 `levLen(F, S)` × 2 个值，右声道使用其后的值。

### 11.2 存储方式、参照档与顺序

对每个母带，参考编码器尝试：存储方式 1；相对核心母带和相对每个更早母带的存储方式 0；以及在两者均有高于基础级别的级别时，相对每个更早母带的存储方式 2。它保留最小的结果，每个母带只作一种选择。它按以下两种顺序中较小的一种写出各母带：或者字长较长者在前，其次采样率较高者在前；或者，当核心母带由一个尚未位于首位的母带派生时，将该母带置于首位，其余母带按前一种顺序排列。母带只能参照更早的母带，而字长较短的母带相对字长较长的母带存储时代价很小。

母带超过 16 个时（2026-11-11 起），每个候选先在 4 段短片段上试编（每段 2^15 个基础采样率样点，第 j 级乘以 2^j），片段位于整首四等分后各段的中点，并向下对齐到块长；位置只由长度决定，不看内容。候选按试编大小换算到整首长度后排序，只把最小的 3 个完整编码，保留其中最小的一个；文件顺序只用两种中的第一种。这些都只是编码器自己的方法，文件中不记录试编片段、候选或排序。在 10 秒片段上实测：20 个母带时，得到的文件和完整搜索的结果逐字节相同；64 个母带时，每个母带都逐位还原。

### 11.3 时间位置

与核心母带来自同一制作的母带，其 T = 0。对于独立制作的核心母带（已发行的 CD），参考工具 `laes align` 使用 LAE Lossy 编码器的自动搜索，并将测得的位置连同小数部分存为 T；母带本身从不移动。对齐误差（对齐后的残余能量相对信号能量之比，按 LAE Lossy 的搜索所测）不超过 −60 dB 时予以接受。否则显示该误差，由用户决定继续还是停止。整张专辑由 LAE Lossy 的整盘规划器（`lae_enc plan … laes`）按 CD 的音轨边界切分，该规划器原样写出每轨的母带，并带有各自的 T。

十进制给出的 T 这样拆：整数部分 = floor(T)，q = round((T − 整数部分) · 2^32)；q 等于 2^32 时整数部分加一、小数部分为 0，否则小数部分就是 q。参考编码器拒绝超出 −N … N 的 T（第 6.7 节）；母带相对某个参照档的 T 超出这个范围时，不采用这个参照档。

### 11.4 实测大小

在两段 352.8 kHz 的 2L 测试录音（02 和 05）以及一段用于 48 kHz 族的 192 kHz 录音的 10 秒片段上测得。每项比较均以 `flac -8` 为对象。

| 内容 | LAES FLAC 形式，相对于 |
|---|---|
| 一个 24 位母带及其全部采样率档位 | 仅含该母带的 FLAC 的 93.5–98.4 % |
| 同一混音在 352.8 kHz 上的 16、24 和 32 位母带，各含全部四种采样率（母带及其三个采样率档位；共 12 个版本） | 仅含 32 位母带的 FLAC 的 99.6–99.8 % |
| 相同的 12 个版本 | 12 个单独 FLAC 文件的约 30 % |

### 11.5 资源与续跑

以下各项描述参考编码器（`laes enc`）。其中任何一项都不改变所写出的文件：相同的母带和选项给出相同的字节。

* **母带。**母带为 16、24 或 32 位的立体声 WAV 文件（RIFF，超过 4 GiB 时为 RF64），就地读取；或为 FLAC 文件。FLAC 母带被解码一次到工作文件夹中，并与其 STREAMINFO 中的 MD5 核对。
* **工作文件夹。**中间数据写入输出旁边的 `<output>.laes.tmp`。运行完成时删除该文件夹；中途停止的运行保留该文件夹，使用 `--disk-stop-remove` 时除外（见下文）。
* **内存。**中间信号逐段处理。内存预算（`--mem=<GB>`，默认 2 GB，在内存较小的机器上更低）仅决定段长。核心母带以每样点每声道 4 字节的方式保存在内存中。
* **磁盘。**在创建工作文件夹之前，编码器估算其所需的磁盘空间。若超过剩余空间，则不启动；`--force-disk` 可覆盖此行为。
  * 运行期间，剩余空间低于 2 GB 时编码器**等待**：不删除任何内容，空间恢复后运行自动继续。
  * 使用 `--disk-stop` 时，编码器改为停止，并保留工作文件夹。
  * 使用 `--disk-stop-remove` 时，编码器停止并删除工作文件夹；此前已完成的工作丢失。
* **续跑。**中途停止的运行（磁盘已满、程序被关闭、崩溃）保留其工作文件夹。再次运行同一命令，即从停止处继续。
  * 工作文件夹记录文件所依赖的内容：参数、每个母带的大小和修改时间，以及编码器构建版本。若其中任一项发生变化，运行从头开始。
  * 续跑的运行写出与不中断的运行相同的字节。
* **`--small-disk`。**用于小容量磁盘。每个母带的最大采样率档位不予存储；每次读取时由母带重新计算。FLAC 母带不复制到工作文件夹中；读取时重新解码其帧（帧的位置仅保存在内存中）。编码变慢；内存占用不增加。
* **`--timing`。**打印每个阶段的用时和峰值内存，以及工作文件夹的最大占用。

在 32 线程机器上以默认 2 GB 预算、FLAC 形式测得。除另有注明外，母带均以 WAV 给出。

| 内容 | 方式 | 时间 | 峰值内存 | 工作文件夹最大占用 |
|---|---|---|---|---|
| 6:41，2 个母带（352.8 kHz 32 位、176.4 kHz 24 位），以 FLAC 给出 | 普通 | 72 s | 0.72 GB | 3.1 GB |
| | `--small-disk` | 82 s | 0.57 GB | 1.1 GB |
| 10:05，4 个母带（352.8 kHz 32、24 和 16 位，176.4 kHz 24 位） | 普通 | 312 s | 1.03 GB | 5.3 GB |
| | `--small-disk` | 386 s | 0.69 GB | 2.7 GB |
| 30:13，12 个母带（16、24 和 32 位 × 44.1、88.2、176.4 和 352.8 kHz） | 普通 | 2181 s | 1.41 GB | 27.8 GB |
| | `--small-disk` | 3047 s | 1.53 GB (*) | 15.0 GB |

(*) 以一个一次性派生整个核心母带的较早构建版本测得；该构建版本的普通运行同样需要 1.53 GB。当前构建版本将普通运行降至 1.41 GB；`--small-disk` 尚未以当前构建版本重新测量。

峰值内存随时长增加（核心母带整体保存在内存中）；磁盘占用随时长以及母带的数量和采样率增加。

## 附录 B. 相对 2026-10-18 设计文档的变更（说明性）

* 采样率档位采用第 3 节的提升 L（固定的表，精确逆运算）。
* 母带存储为相对参照档（核心母带或更早的母带）的差值，或完整存储。存储方式 2（在共有的最高级别上的差值）为新增内容。
* 时间位置 T 取代了对母带的任何移动：母带均原样存储。
* 核心母带可为 16、24 或 32 位。规定了 FLAC 形式和 CD-Extra 扩展类型 2。
* 解码器输出包括一个派生 16 位母带，并标明为派生（相对第 10.1 节无损，相对其所取自的母带不是无损）。
* 2026-11-11 和 2026-11-12：有效载荷版本 2：最多 255 个母带，每个母带有名称、关掉派生版本的标志和菜单位置；头部有默认母带和核心母带标志。能写成版本 1 的有效载荷照旧写成版本 1，逐字节不变。派生 16 位版本改为每个来源（核心母带、每个母带及其每个档位）各一个；第 10.3 节规定了选择和显示。文件顺序仍是编码器找到的最小顺序，菜单顺序由发行方标记。播放器只在母带及其参照链的 SHA-256 全部相符后才播放该母带（第 1.3 节）。
