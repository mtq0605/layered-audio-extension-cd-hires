## 1 范围与符合性

### 1.1 范围

LAE Lossy 文件是 RIFF/WAVE 文件，包含两部分：

* **CD 层。**`data` 块保存普通的 16 位双声道 PCM，基础采样率为 44 100 Hz 或 48 000 Hz。任何 WAV 播放器都可以原样播放。
* **扩展数据。**音频数据之后有一个标识符为 `LAE ` 的块，其中包含两个层：
  * **位深层**：在基础采样率下，将 CD 层扩展至 24 位分辨率；左右声道 L 和 R 各有一个平面；
  * **频率层**：将带宽扩展至基础采样率的 2、4 或 8 倍。数据以中/侧（M、S）平面存储，并按频率片段拆分为多个数据流。

**分发方式与文件扩展名**

* 文件以 `.wav` 扩展名分发，使所有播放器都能播放其中的 CD 层。之后可以选择增加 `.flac` 分发方式；但容器版本 5 尚未规定如何在 FLAC 中承载扩展数据。
* `.lae` 是该格式专用的文件扩展名。容器版本 5 尚未规定 `.lae` 文件布局，后续修订版将予以规定。

解码器可生成以下输出，均以 24 位双声道 PCM 写入。

| 路径 | 内容 | 输出采样率 |
|---|---|---|
| 24 位路径 | CD + 位深层 + 频率层 | 母带采样率 / 2^d，其中 0 <= d < stages（d = 0 时为母带采样率） |
| 16 位路径 | CD + 频率层 | 母带采样率 / 2^d，其中 0 <= d < stages |
| CD + 位深路径（“cd24”） | CD + 位深层 | 基础采样率 |

选择低于母带采样率的输出采样率时，会跳过起始频率达到或超过输出奈奎斯特频率的频率层数据流，不对其解码（第 5.4 节）。随后使用第 10 节的半带抽取器将结果降至所选采样率。

LAE Lossless（LAES）无损层未在本文中规定。其状态为：设计文档已发布（[spec/lossless/DESIGN.md](../lossless/DESIGN.md)），规范性规范尚未编写。

### 1.2 解码模型（说明性内容）

所有重建都在时域中进行。操作顺序如下：

1. 对每个编码平面进行范围解码，每次处理 8 帧中的一行，并对其系数反量化（第 6 至 8 节）。
2. 使用严格的 IEEE-754 双精度算术，按教科书定义的方式执行逆 MDCT，并进行重叠相加（第 9 节）。
3. 形成基础信号：4096 × CD - 再生成的 TPDF 抖动 + 16 × 位深层。结果以 1/16 LSB24 为单位（第 11.2 节）。
4. 使用整数半带滤波器逐级进行 2 倍插值，直至达到母带采样率。滤波器使用 Q31 系数、64 位累加，并对每个输出采样舍入一次。
5. 执行整数 M/S 逆变换后，加上 16 × 频率层。
6. 可选地使用相同的半带系数表进行抽取，降至所选采样率。
7. 最后统一舍入到 24 位，然后应用硬限幅器。

在 `cd24` 路径中，省略步骤 4 至 6。

### 1.3 符合性

符合规范的解码器 MUST 满足第 3 至 13 节中所有适用于解码器的要求，包括第 4.3 和 12 节规定的验证与拒绝规则，以及对任意输入均保持内存安全的要求。此外，对于 [tests/vectors/MANIFEST.md](../../tests/vectors/MANIFEST.md)（附录 B）中列出的每个测试向量和每条路径，解码器 MUST 生成一个输出 WAV 文件（包括文件头和样本，见第 11.8 节），其 SHA-256 必须与清单所列值匹配。

清单目前仅列出每个 SHA-256 值开头的 16 个十六进制数字。完整的 64 位十六进制值将在后续修订版中公布。

这些测试向量覆盖第 3 至 13 节定义的流程。准确遵循这些章节的实现会产生所列输出。

只要每个输出字节都完全一致，解码器内部结构 MAY 不同。例如，解码器可以处理整条音轨而非采用流式处理，也可以并行解码多个数据流。

### 1.4 术语

关键词 “MUST”、“MUST NOT”、“REQUIRED”、“SHALL”、“SHALL NOT”、“SHOULD”、“SHOULD NOT”、“RECOMMENDED”、“MAY” 和 “OPTIONAL” 的解释遵循 BCP 14（RFC 2119 和 RFC 8174），且仅当它们以此处所示的大写形式出现时适用。

### 1.5 浮点与伪随机元素（说明性内容）

* 仅系数重建（第 8.3 节）和逆 MDCT（第 9 节）这两个阶段使用浮点运算，且均采用严格的 IEEE-754 双精度。
* 量化为零的系数会重建为零，除非启用了可选零级（第 8.4 节）。
* 解码器中唯一的伪随机序列用于重新生成抖动（第 11.2 节），以重现编码器加入 CD 层的抖动。

## 2 符号与算术

### 2.1 整数算术

* `int16`、`int32` 和 `int64` 分别表示 16、32 和 64 位二进制补码有符号整数。`uint8`、`uint16`、`uint32` 和 `uint64` 表示无符号整数。
* 文件中的所有多字节数值均采用**小端序**。
* 对有符号值执行 `a >> k` 表示算术右移，即向下取整除以 2^k；对无符号值执行时表示逻辑右移。
* 整数运算 `a / b` 表示截断除法。本规范使用该运算时，操作数均为非负数，或该除法为精确除法。
* 对正整数，`ceil(a / b)` 等于 `(a + b - 1) / b`。
* `uint32` 运算按模 2^32 进行；`uint64` 运算按模 2^64 进行。
* 本规范注明为 `int64` 的运算，MUST 至少使用 64 位有符号算术执行。
* `min`、`max` 和 `clamp(x, lo, hi) = min(max(x, lo), hi)` 均采用通常含义。

### 2.2 浮点算术

系数重建（第 8 节）和逆 MDCT（第 9 节）使用 IEEE-754 binary64（“double”）。适用以下规则：

* 每次加法、减法和乘法 MUST 分别舍入至 binary64，并采用“舍入到最近值，遇中间值取偶数”模式。
* MUST NOT 使用融合乘加收缩。
* MUST NOT 使用扩展精度中间值（例如 x87 80 位寄存器）。
* MUST NOT 进行重新结合、重排或任何“快速数学”变换。
* MUST 按本规范中给出的顺序求值：从左至右，并遵循括号优先级。
* `int32` 到 double 的转换是精确的。
* `2^s` 表示 2 的 s 次幂的精确 double 值。

*说明性内容。*对于 C 和 C++，使用以下编译器设置即可满足上述规则：

* GCC 和 Clang：使用 `-ffp-contract=off`，且不使用 `-ffast-math`。
* GCC 和 Clang 在 32 位 x86 上：还需添加 `-msse2 -mfpmath=sse`。
* MSVC：使用 `/fp:precise`（MSVC 默认设置）；不得使用 `/fp:fast`。在 32 位 x86 上，使用 `/arch:SSE2`（MSVC 默认设置）。

不支持会生成 x87 浮点代码的构建（第 13 节）。参考实现的构建命令见 [docs/BUILD.md](../../docs/BUILD.md)。
### 2.3 舍入函数

* `llround(x)` 将 double 舍入至最接近的整数；恰在中点时远离零。这是 C 语言的 `llround` 函数。
* 对 `int64` 值，`rq31(a) = (a + 2^30) >> 31`。它将 a / 2^31 舍入至最接近的整数；恰在中点时向正无穷方向舍入。
* 最终输出舍入为 `int64` 上的 `(x + 8) >> 4`（见第 11.7 节）。

### 2.4 单位

* `LSB24` 表示 24 位信号的一个量化步长。满量程为 ±2^23 LSB24。
* `LSB16` 等于 256 LSB24。
* **精细单位**（FU）等于 1/16 LSB24。一个 LSB16 等于 4096 FU。
* 第 11 节的所有时域阶段均以 FU 为单位。
* 位深层和频率层的逆 MDCT 输出以 LSB24 为单位。

## 3. 文件结构

### 3.1 RIFF/WAVE

LAE Lossy 文件是 RIFF/WAVE 文件。前 4 个字节 MUST 为 `RIFF`，第 8 至 11 字节 MUST 为 `WAVE`。从偏移量 12 开始依次排列各个块。每个块由以下部分组成：

* 4 字节标识符；
* 一个表示主体大小 n 的 `uint32`；
* n 个主体字节；
* 若 n 为奇数，则附加一个填充字节。

**解码器解析规则**（参考读取器的行为）：

* MUST 从偏移量 12 开始，按顺序解析至文件末尾。不会使用偏移量 4 处的 RIFF 大小字段。
* 如果块主体超出文件末尾，则将其截断为实际可用的字节数。
* MUST 跳过未知块。
* 如果某个块标识符出现多次，则使用最后一次出现的块。
* `fmt ` 块主体长度 MUST 至少为 16 字节。字段如下：
  * 格式标记：主体偏移量 0 处的 `uint16`；
  * 声道数：偏移量 2 处的 `uint16`；
  * 采样率：偏移量 4 处的 `uint32`；
  * 每样本位数：偏移量 14 处的 `uint16`。
* 如果格式标记为 0xFFFE（WAVE_FORMAT_EXTENSIBLE），且主体长度至少为 26 字节，则将格式标记替换为主体偏移量 24 处的 `uint16`。该值是子格式 GUID 的前两个字节。
* 有效格式标记 MUST 为 1（整数 PCM）。每样本位数 MUST 为 16，声道数 MUST 为 2。文件 MUST 包含 `data` 块。

**编码器要求。**编码器 MUST 按以下顺序写入：

1. `fmt ` 块（PCM、2 个声道、基础采样率、16 位）；
2. 保存 CD 层的 `data` 块；
3. `LAE ` 块。

RIFF 大小字段 MUST 覆盖所有块。不识别 `LAE ` 块的播放器会跳过该块并播放 CD 层。

参考解码器不会比较 `fmt ` 中的采样率与第 4 节的 `base` 字段。编码器 MUST 在该字段中写入 `base`。是否要求解码器拒绝二者不匹配的文件，将在后续修订版中规定。

### 3.2 CD 层（`data` 块）

`data` 块保存交错排列的小端序 `int16` 样本，顺序为 L、R、L、R，依此类推。立体声帧数为：

`ncd = floor(floor(dlen / 2) / 2)`

其中 `dlen` 是 `data` 块主体的大小。无法组成完整立体声帧的尾部字节会被忽略。`ncd` MUST 等于 `nb - 2*pb`（见第 4 节）。

CD 层是普通 PCM，扩展数据绝不会对其进行修改。

CD 层与扩展数据之间唯一有约束力的检查是上述长度检查。如果 CD 层被修改但长度未变，则无法检测出这种修改。

### 3.3 `LAE ` 块

块标识符为四个字节 `0x4C 0x41 0x45 0x20`（`LAE `）。其 n 字节主体布局如下：

| 字节 | 内容 |
|---|---|
| `0 ... n-5` | 主头部、边缘样本、抖动标志和编码流（第 4、5 节） |
| `n-4 ... n-1` | 对字节 `0 ... n-5` 计算所得的 `uint32` CRC-32，小端序 |

块主体长度 MUST 至少为 8 字节。若块主体长度为 0，参考解码器会将其视为不存在 `LAE ` 块（见第 12 节）。

CRC-32 使用 IEEE 802.3 CRC，参数如下：

* 反射多项式 `0xEDB88320`（常规形式为 `0x04C11DB7`）；
* 初始值 `0xFFFFFFFF`；
* 输入和输出均反射；
* 最终异或值 `0xFFFFFFFF`。

ASCII 字符串 `123456789` 的 CRC 为 `0xCBF43926`。参考算法如下：

```
crc = 0xFFFFFFFF
for each byte b: crc = T[(crc XOR b) AND 0xFF] XOR (crc >> 8)
crc = crc XOR 0xFFFFFFFF
where T[i] = i iterated 8 times through: c = (c AND 1) ? 0xEDB88320 XOR (c >> 1) : (c >> 1)
```

解码器 MUST 在解释块主体中的任何其他字节之前验证 CRC。CRC 对整个扩展数据计算一次，不设逐帧校验和。

本文其余部分所称的**有效载荷**，是指字节 `0 ... n-5`，即不含 CRC 的块主体。偏移量均相对于有效载荷起始位置。

如果某字段超出有效载荷末尾，则视为错误。参考读取器会对此类字段返回 0，后续验证必定失败。

## 4. 主头部

有效载荷以 13 个小端序 `int32` 字段开头。

| 偏移量 | 名称 | 含义 | 有效值 |
|---|---|---|---|
| 0 | `magic` | 块魔数，字节为 `L A E 1` | `0x3145414C` |
| 4 | `version` | 容器版本 | `5` |
| 8 | `rate` | 主采样率（Hz） | `base * 2^stages` |
| 12 | `base` | 基础（CD 层）采样率（Hz） | `44100` 或 `48000` |
| 16 | `stages` | 基础采样率与主采样率之间的倍频程级数 | `1 ... 3` |
| 20 | `Lm` | 主采样率下每声道的样本数 | `1 ... 2 000 000 000 - 2*P` |
| 24 | `P` | 主采样率下每侧填充的样本数 | `1 ... 65536`，且为 `2^stages` 的倍数 |
| 28 | `fc` | 检测到的 CD 截止频率（Hz） | 仅供参考 |
| 32 | `mi` | 分区模式索引（第 14 节） | `0 ... 5` |
| 36 | `eq` | 编码器使用的切分类型（0 = 不等长，非 0 = 等长） | 仅供参考 |
| 40 | `wm` | 编码器使用的占比度量（0 = 单元，1 = 能量，2 = 单元 + 能量） | 仅供参考 |
| 44 | `nb` | 基础采样率下填充后的每声道样本数 | `(Lm + 2*P) >> stages` |
| 48 | `pb` | 基础采样率下每侧的填充样本数 | `P >> stages` |

主头部之后依次为：

| 偏移量 | 大小（字节） | 内容 |
|---|---|---|
| 52 | `8*pb` | 边缘样本：`4*pb` 个小端序 `int16` 值（第 4.1 节） |
| `52 + 8*pb` | 4 | `ndf`，`int32`：抖动标志字节数 |
| `56 + 8*pb` | `ndf` | 抖动标志（第 4.2 节） |
| `56 + 8*pb + ndf` | 可变 | 流记录（第 5 节） |

### 4.1 边缘样本

基础采样率信号定义在填充后的时间轴上，每声道有 `nb` 个样本。索引 `[pb, pb + ncd)` 对应 CD 样本。

两侧各有 `pb` 个样本，存放在边缘区域，按交错立体声 `int16` 对排列，记为 `edge[2*j + c]`：

* `j in [0, pb)` 对应前置填充；
* `j in [pb, 2*pb)` 对应后置填充。

填充会扩展信号两端，具体内容由编码器决定。解码器使用已存储的值，不进行计算。

*说明性内容。* 参考编码器会在母带两端各进行 `P = 4096` 个样本的镜像填充，并围绕端点样本反射（整样本对称，`src/pad_mirror.cpp`）。随后，它从填充后的母带生成 16 位基础采样率信号（第 14 节），并将该信号最前和最后的 `pb` 个立体声样本存为边缘样本（`src/lae_enc.cpp`）。

### 4.2 抖动标志

令 `nbk = ndf / 2`。标志是字节 `dfl[c*nbk + b]`，其中声道 `c in {0, 1}`，块 `b in [0, nbk)`。声道 0 的所有标志排在最前。

块 `b` 覆盖基础采样率下的填充索引 `[4096*b, 4096*b + 4096)`。

* 值为零表示该块未添加抖动。
* 任意非零值表示该块添加了 TPDF 抖动（第 11.2 节）。

编码器 SHOULD 写入 0 或 1。

### 4.3 解码器 MUST 执行的验证

在使用任何字段访问数据之前，解码器 MUST 按下表顺序检查以下条件。如果任一检查失败，解码器 MUST 拒绝解码扩展数据（见第 12 节）。

| # | 条件 |
|---|---|
| V1 | `LAE ` 块主体 >= 8 字节，且 CRC-32 校验匹配（第 3.3 节） |
| V2 | `magic == 0x3145414C` 且 `version == 5` |
| V3 | `base in {44100, 48000}` |
| V4 | `1 <= stages <= 3` |
| V5 | `rate == base << stages` |
| V6 | `0 < P <= 65536`，且 `P mod 2^stages == 0` |
| V7 | `pb == P >> stages` |
| V8 | `0 < Lm <= 2 000 000 000 - 2*P` |
| V9 | `nb == (Lm + 2*P) >> stages` |
| V10 | `0 <= mi < 6` |
| V11 | 偏移量 52 之后至少还剩 `8*pb` 字节 |
| V12 | `ndf == 2 * ceil(nb / 4096)`，且 `ndf` 字段之后还剩 `ndf` 字节 |
| V13 | `ncd == nb - 2*pb`（第 3.2 节） |

*说明性内容。* V6、V7 和 V9 意味着 `nb - 2*pb = floor(Lm / 2^stages)`。因此，结合 V13 可得 `ncd = floor(Lm / 2^stages)`。

**派生量：**

* `Lp = Lm + 2*P`，即填充后的主采样率长度；
* `N = 512`；
* `ncd`（第 3.2 节）；
* `nbk`（第 4.2 节）。

## 5. 流记录与流顺序

### 5.1 流记录

抖动标志之后，有效载荷按固定顺序包含流记录。每条**流记录**由以下部分构成：

* 一个 `int32` 值 `nbytes`，其值 MUST 至少为 40；
* `nbytes` 个流数据字节，且这些字节 MUST 完全位于有效载荷范围内。

流数据由 40 字节的流头部，以及其后的 `nbytes - 40` 个范围编码有效载荷字节组成。

### 5.2 流顺序

| # | 内容 |
|---|---|
| 1 | 深度流，L 声道（0） |
| 2 | 深度流，R 声道（1） |
| 3 | `nseg`，`int32`：每个声道的频率区段数。MUST 满足 `1 <= nseg <= 8` |
| 4 | `nseg` 条 M 平面频率流记录，区段为 0 ... nseg-1 |
| 5 | `nseg` 条 S 平面频率流记录，区段为 0 ... nseg-1 |

解码器 MUST 按顺序解析每条记录，包括不解码其内容的记录，因为每条记录的位置取决于前一条记录的结束位置。

参考解码器会忽略最后一条 S 记录结束位置与 CRC 之间的任何字节。参考编码器不会写入此类字节；CRC 会紧接最后一条 S 记录（`src/lae_enc.cpp`）。编码器 SHOULD NOT 写入任何此类字节。

### 5.3 流头部

流头部由 10 个小端序 `int32` 字段组成。

| 偏移量 | 名称 | 含义 | 有效值 |
|---|---|---|---|
| 0 | `K` | 平面中的帧数 | `> 0`（须检查） |
| 4 | `N` | 每帧系数数 | `== 512`（须检查） |
| 8 | `k0` | 第一个编码频点 | `>= 0`（须检查） |
| 12 | `k1` | 最后一个编码频点之后的位置 | `k0 < k1 <= 512`（须检查） |
| 16 | `rate` | 平面信号的采样率 | 解码器不使用 |
| 20 | `L` | 平面信号长度 | 解码器不使用 |
| 24 | `cw` | `CW + 256 * rule` | 编码器 MUST 在低字节中写入 `CW = 8`（不检查）。`rule = (cw >> 8) & 255`（第 8.2 节） |
| 28 | `lv` | 分区模式索引 | 解码器不使用 |
| 32 | `eq` | 切分类型：0 = 不等长切分，非 0 = 等长切分（第 7 节） | 任意值 |
| 36 | `plen` | 范围编码有效载荷长度 | `== nbytes - 40`（须检查） |

关于流头部字段的说明：

* 参考解码器不检查 `cw` 的低字节。它始终使用宽度为 8 的单元。
* `K` SHOULD 等于 `frames(Ls)`（第 9.1 节）。深度流中的 `Ls` 为 `nb`，频率流中的 `Ls` 为 `Lp`。
* 如果 `K` 小于 `frames(Ls)`，缺少的帧按零解码。如果 `K` 较大，则不会请求额外帧。
* 参考编码器写入 `rate` 和 `L` 的确切值将在后续修订版中说明。

对每条实际解码的流，MUST 执行标记为“须检查”的检查。跳过的流（第 5.4 节）只检查 `nbytes >= 40`，以及该流是否完全位于有效载荷范围内。

### 5.4 按解码路径选择流

**深度流**在 24 位路径和 `cd24` 路径中解码，在 16 位路径中跳过。

**频率流**在 `cd24` 路径中跳过。在 24 位和 16 位路径中，若输出采样率为 `rate >> d`，则当且仅当 `k0` 小于 `kcut` 时解码该频率流，其中：

`kcut = 512 >> d`。

参考解码器计算的值与 `lround(512 * (orate/2) / (rate/2))` 相同。

参考解码器会在读取并消费该记录之前，从流头部读取 `k0`。如果记录位置剩余字节少于 16，则将 `k0` 视为 0。此类记录必定无法通过第 5.1 节的记录检查。

选中的 M 流构成 M 信号，选中的 S 流构成 S 信号（第 9.5 节）。如果**没有选中任何 M 流**，则完全省略频率层，包括任何已选中的 S 流（第 11.5 节）。

*说明性内容。* 频率频点以主采样率表示：512 个频点中的第 k 个频点中心位于 `(k + 1/2) * (rate/2) / 512`。参考编码器每个倍频程存储一条流（`src/lae_dec.cpp` 中的注释）。解码器仅依赖 `k0 < kcut` 测试。

### 5.5 系数平面几何结构

一条流描述平面 `X[m][k]`，其中 `m in [0, K)`，`k in [0, 512)`。`[k0, k1)` 之外的频点均为零。几何结构定义于 `src/partition_format.h`。

* `[k0, k1)` 中的频点分组为 `nc = ceil((k1 - k0) / 8)` 个宽度为 `CW = 8` 个频点的**单元**。
* 单元 `cc` 覆盖频点 `kb = k0 + 8*cc` 至 `min(k1, kb + 8) - 1`。因此，最后一个单元可以少于 8 个频点。
* 单元按 `ROOTF = 16` 个单元 × `ROOTT = 8` 帧分组成**根块**。高频边缘处以及音轨末尾处的根块可能更小。

## 6. 范围解码器

每条被解码的流都使用独立的范围解码器（`src/part_stream.h` 中的 `struct Dec`）。解码器在该流编码有效载荷的起始位置初始化；该位置是流数据偏移量 40 处，长度为 `plen`。

### 6.1 状态与字节输入

* `range` 为 `uint32`，初始值为 `0xFFFFFFFF`。
* `code` 为 `uint32`，初始值为 0。
* `next()` 返回下一个有效载荷字节。所有 `plen` 个字节都读取完后，返回 0。

### 6.2 初始化

```
repeat 5 times: code = (code << 8) | next()        // uint32: the first byte is shifted out
```

*说明性内容。* 参考编码器会写入一个前导 `0x00` 字节，该字节会被移出。

### 6.3 自适应二元判决

概率 `p` 为 `uint16`，以 1/2048 为单位保存 0 比特的概率。初始值为 1024。

```
bit(p):
  bound = (range >> 11) * p                         // uint32
  if code < bound:  range = bound;  p = p + ((2048 - p) >> 5);  b = 0
  else:             code = code - bound;  range = range - bound;  p = p - (p >> 5);  b = 1
  while range < 2^24:  range = range << 8;  code = (code << 8) | next()
  return b
```

适应移位固定为 5。

### 6.4 旁路（直接）比特

```
direct(n):                                          // n >= 1, most significant bit first
  v = 0
  repeat n times:
    range = range >> 1
    b = (code >= range) ? 1 : 0
    if b: code = code - range
    v = (v << 1) | b
    while range < 2^24:  range = range << 8;  code = (code << 8) | next()
  return v
```

### 6.5 二叉树

`tree(pr, nbits)` 通过概率数组 `pr`，按最高有效位优先的顺序解码一个 `nbits` 位数值。它使用节点 `1 ... 2^nbits - 1`：

```
node = 1
repeat nbits times:  node = 2*node + bit(pr[node])
return node - 2^nbits
```

### 6.6 整数模型 `U`

`U` 模型包含两个数组 `tree[64]` 和 `mant[64]`，所有概率初始为 1024。`U(model)` 根据位长解码一个小于 `2^31` 的非负整数 `v`：

```
len = tree(model.tree, 5)                           // 0 ... 31
if len <= 1: return len
top  = bit(model.mant[len])
nr   = len - 2
rest = (nr > 0) ? direct(nr) : 0
return 2^(len-1) + top*2^nr + rest                  // uint32
```

### 6.7 终止

参考编码器会在流末尾刷新四个字节。解码器 MUST NOT 要求任何终止模式，也 MUST NOT 检查已读取的字节数。超出 `plen` 的读取会返回 0（第 6.1 节）。

### 6.8 模型持久性

流的所有自适应模型都会在打开流时创建一次，并在整条流中持续使用，跨越根块和行的边界。

版本 5 未定义随机访问点。每条流都从开头开始解码。

## 7. 分区语法

符号遍历由 `src/part_stream.h` 中的 `Walker` 实现。几何结构辅助函数位于 `src/partition_format.h`。

### 7.1 每条流的模型与状态

| 名称 | 数量 | 初始值 | 用途 |
|---|---|---|---|
| `TierP` | 4 个上下文 × 4 个节点 | 1024 | 层级，2 位树。上下文 = 前一叶节点的层级 |
| `ExpZero[t]` | 4 个（使用 t = 1...3） | 1024 | 指数差是否为零 |
| `ExpSign[t]` | 4 个（使用 t = 1...3） | 1024 | 指数差的符号 |
| `ExpU[t]` | 4 个 `U` 模型（使用 t = 1...3） | 1024 | 指数差绝对值 - 1 |
| `ZlP` | 4 个上下文 × 8 个节点 | 1024 | 零级索引，3 位树。上下文 = 层级 |
| `CoefU` | 3 × 13 个 `U` 模型 | 1024 | 系数幅值 |
| `prevTier` |  | 0 | 前一叶节点的层级，包括 A 层叶节点 |
| `prevE` |  | 12 | 前一非 A 层叶节点的指数 |

### 7.2 辅助函数

```
cuts(w, equal):                    // admissible cut positions of an extent w
  if w < 2:   return []
  if equal:   return [floor(w / 2)]
  return [1, 2, ..., w - 1]

posBits(n): smallest b >= 0 with 2^b >= n
```

### 7.3 流遍历

根块按行遍历，时间顺序递增，每行 8 帧。在每行内，根块按频率顺序递增。

```
decode_plane(hdr):
  nc = ceil((k1 - k0) / 8)
  for M0 = 0; M0 < K; M0 += 8:
    rt = min(8, K - M0)
    set X[M0 ... M0+rt-1][0 ... 511] = 0
    for C0 = 0; C0 < nc; C0 += 16:
      rf = min(16, nc - C0)
      node(0, rf, 0, rt)           // cell range [f0, f1), frame range [t0, t1), relative to the root
```

### 7.4 节点

每个节点要么沿一个方向切分为两部分，要么作为叶节点。切分、方向和位置比特均为旁路比特。

```
node(f0, f1, t0, t1):
  cf = cuts(f1 - f0, eq != 0);  ct = cuts(t1 - t0, eq != 0)
  if cf != [] or ct != []:
    split = direct(1)
    if split = 1:
      if ct = []:      dir = 0                   // frequency cut
      else if cf = []: dir = 1                   // time cut
      else:            dir = direct(1)
      cc = (dir = 0) ? cf : ct
      nb = posBits(|cc|)
      pi = (nb > 0) ? direct(nb) : 0
      if pi >= |cc|: CORRUPT; pi = |cc| - 1
      p = cc[pi]
      if dir = 0: node(f0, f0+p, t0, t1); node(f0+p, f1, t0, t1)
      else:       node(f0, f1, t0, t0+p); node(f0, f1, t0+p, t1)
      return
  leaf(f0, f1, t0, t1)
```

### 7.5 叶节点

每个叶节点都有自己的层级、指数和零级索引。这些值只在叶节点处传送；内部节点不携带任何信息。

```
leaf(f0, f1, t0, t1):
  tier = tree(TierP[4*prevTier ...], 2)          // 0 = A, 1 = B, 2 = C, 3 = D
  prevTier = tier
  if tier = 0: return                            // all coefficients of the leaf stay 0

  if bit(ExpZero[tier]) = 1:  d = 0
  else:
    neg = bit(ExpSign[tier])
    a   = U(ExpU[tier])
    d   = neg ? -(a + 1) : (a + 1)
  if prevE + d < 0 or prevE + d > 34: CORRUPT; d = clamp(prevE + d, 0, 34) - prevE
  E = prevE + d;  prevE = E

  z = tree(ZlP[8*tier ...], 3)                   // zero-level index 0 ... 7
  s    = shift(E, tier, rule)                    // Section 8.2
  step = 2^s
  cm   = CoefU[(tier - 1)*13 + min(12, floor(E / 2))]

  for m = M0+t0 ... M0+t1-1:                     // frames
    for cell = C0+f0 ... C0+f1-1:                // cells, increasing frequency
      kb = k0 + 8*cell;  nbins = min(k1, kb + 8) - kb
      for j = 0 ... nbins-1:
        a = U(cm)
        if a > 0: neg = direct(1); q = neg ? -a : a
        else:     q = 0
        zs = (q = 0 and z > 0) ? direct(1) : 0
        X[m][kb + j] = dequant(q, z, zs, step)   // Section 8.3
```

上下文选择：

* 系数模型由叶节点的层级和指数决定。
* 层级上下文是解码顺序中前一叶节点的层级。
* 指数编码为与前一非 A 层叶节点指数的差值。

### 7.6 损坏流处理

`CORRUPT` 表示该流已损坏。参考解码器会按所示方式钳制有问题的值，并继续处理且不会导致内存越界。解码结束时，解码器会丢弃输出（第 12 节）。由于此时绝不会交付输出，钳制后的值没有规范性影响。对于任何输入，解码器仍 MUST 保证内存安全。

参考解码器只解码所需数据流的根块行，并且只计算所请求路径和输出采样率所需的逆 MDCT 输出采样。因此，未实际用到部分中的 CORRUPT 情况可能无法检测。是否必须检测整条流中的 CORRUPT，还是只检测所需部分，将在后续修订版中规定。
## 8. 系数解码与反量化

本节中的系数表和函数定义于 `src/partition_format.h`。

### 8.1 层级

| 层级 | 编码 | `TB[tier]`（相对于叶节点指数的位数） |
|---|---|---|
| A | 0 | 0（不编码系数；全部为零） |
| B | 1 | 2 |
| C | 2 | 4 |
| D | 3 | 8 |

### 8.2 精度规则

步长指数 `s` 根据叶节点指数 `E`、层级以及数据流中的 `rule = (cw >> 8) & 255` 计算。常量为 `TB = {0, 2, 4, 8}`、`TB16 = {0, 0, 4, 8}` 和 `STEPMAX = 8`。

| `rule` | `s = shift(E, tier, rule)` | 预期用途（说明性内容） |
|---|---|---|
| 1 | `max(0, min(E, 8) - TB[tier])` | 方案 1 的两层；方案 2 的位深层。高电平块：B 18 / C 20 / D 24 位 |
| 2 | `max(0, min(E - TB[tier], 8 - TB16[tier]))` | 方案 2 的频率层。高电平块：B 16 / C 20 / D 24 位 |
| 3 | `max(0, min(E, 6) - TB[tier])` | `keep20` 模式的位深层。高电平块：B 20 / C 22 / D 24 位 |
| 0 或其他任意值 | `min(8, max(0, E - TB[tier]))` | 默认规则（即容器版本 4 所用公式） |

版本 5 编码器写入规则 1、2 或 3。其他值均保留。尽管如此，解码器 MUST 按表格最后一行处理这些值，与参考解码器一致。

`rule` 值是每条流各自的字段。表格最后一行会为该字段的所有取值定义解码方式，其公式是容器版本 4 中使用的公式。根据第 4.3 节的检查 V2，容器版本 4 文件本身会被拒绝。保留的 `rule` 值是否应改为拒绝，将在后续修订版中规定。

所有规则均满足 `0 <= s <= 8`。因此，量化步长不会粗于 CD 层的 1 LSB16 步长。

*说明性内容。*编码器根据叶节点峰值推导 `E`。在参考编码器中，`E` 是叶节点内各单元指数的最大值（`src/partition.h`）。每个单元指数的计算方式将在后续修订版中说明。
### 8.3 重建

`dequant(q, z, zs, step)` 计算 `v`，并将 `llround(v)` 作为 `int32` 存入平面：

```
if q > 0:       v = ((double)q + 0.20) * step
else if q < 0:  v = ((double)q - 0.20) * step
else if z > 0:  v = (zs = 1 ? -1.0 : 1.0) * ZC[z] * step      // evaluated left to right
else:           v = 0.0
if v > 1073741823.0 or v < -1073741823.0: CORRUPT; v = clamp(v, -1073741823.0, 1073741823.0)
X = llround(v)
```

* `0.20` 是与 0.20 最接近的 binary64 值（`0x1.999999999999ap-3`）。重建偏移量 `RECOFF = 0.20` 是格式常量。
* 上述每次加法、减法和乘法都要单独舍入至 binary64（第 2.2 节）。
* `llround` 在恰逢中点时远离零。对于 0.5 等零级值，这一点十分重要。

量化器的死区仅供编码器使用，不会传送，也不会影响解码。参考编码器使用 0.30 的死区（第 14 节）。

### 8.4 零级

叶节点的零级索引 `z` 从二进制定值表中选择 `ZC[z]`；表中所有值均可用二进制精确表示：

| `z` | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| `ZC[z]` | 0 | 1/32 | 1/16 | 3/32 | 1/8 | 3/16 | 1/4 | 3/8 |

* 如果 `z = 0`，量化为零的系数重建为 0。
* 如果 `z > 0`，叶节点中每个零系数都带有一个旁路比特 `zs`。该比特表示系数的实际符号（1 = 负）。若 `zs = 1`，系数重建为 `-ZC[z] * step`；否则重建为 `ZC[z] * step`。

只有启用可选 `zs` 编码器选项时，参考编码器才会写入 `z > 0`。该选项默认关闭。解码器 MUST 支持 `z` 的所有取值。

## 9. 逆 MDCT

该变换由 `src/mdct_tb.h` 实现。

### 9.1 帧布局

该变换为正弦窗 MDCT，每帧有 `N = 512` 个系数，重叠率为 50%。

对于长度为 `Ls` 的信号：

* 填充序列为 `[N 个零 | Ls 个信号样本 | 后续零]`；
* 帧数为 `frames(Ls) = ceil(Ls / N) + 1`；
* 帧 `m` 覆盖填充位置 `[m*N, m*N + 2N)`；
* 信号样本 `i` 位于填充位置 `i + N`。

| 信号 | `Ls` | 采样率 |
|---|---|---|
| 深度，声道 c | `nb` | 基础采样率 |
| M、S | `Lp` | 主采样率 |

### 9.2 常量表

令 `M = N/2 = 256`。各表按以下生成公式定义（`tools/gen_mdct_tables.cpp`）：

| 表 | 大小 | 公式 |
|---|---|---|
| `WIN[n]` | 1024 | `sin(pi (n + 1/2) / (2N))` |
| `PRE_C[n]`、`PRE_S[n]` | 256 | 对 `-2pi (n + 1/8) / (2N)` 取 `cos`、`sin` |
| `POST_C[k]`、`POST_S[k]` | 256 | 对 `-2pi (k + 1/8) / (2N)` 取 `cos`、`sin` |
| `FFT_C[k]`、`FFT_S[k]` | 128 | 对 `-2pi k / M` 取 `cos`、`sin` |
| `BITREV[i]` | 256 | 将 `i` 的 8 个二进制位逆序后的整数 |
| `SCALE` | 1 | `1 / sqrt(M) = 2^-4 = 0x1p-4`（精确值） |

前置和后置旋转因子均为 `exp(-i 2pi (n + 1/8) / 2N)`。PRE 和 POST 表由同一表达式生成，因此两者的值完全相同。

*说明性内容。* 这种旋转因子形式发表于 2002-10-28 的 FFmpeg `libavcodec/mdct.c` 中。

精确值是 `src/mdct_tables.h` 中的十六进制 double 字面值，由 `tools/gen_mdct_tables.cpp` 生成。使用主机数学库重新计算的值，最低有效位可能不同。解码器 MUST 使用 `src/mdct_tables.h` 中的值。后续修订版会将 `src/mdct_tables.h` 的内容作为规范性附录重列。

### 9.3 通过 M 点复数 FFT 计算 DCT-IV

`DCT4` 是正交 DCT-IV，具有自反性，即其逆变换为自身：

$$
X[k] = \sqrt{\frac{2}{N}} \sum_{n=0}^{N-1} u[n] \cos\left(\frac{\pi}{N}\left(n + \frac{1}{2}\right)\left(k + \frac{1}{2}\right)\right)
$$

MUST 严格按以下方式计算。每个乘积 `x*y` 都单独舍入；每次加法或减法也都单独舍入，并按所写顺序执行。

```
DCT4(c[0 ... N-1]) -> u[0 ... N-1]:
  for n = 0 ... M-1:
    a = c[2n];  b = c[N-1-2n]
    re[n] = a*PRE_C[n] - b*PRE_S[n]
    im[n] = a*PRE_S[n] + b*PRE_C[n]
  FFT(re, im)
  for k = 0 ... M-1:
    yr = (re[k]*POST_C[k] - im[k]*POST_S[k]) * SCALE
    yi = (re[k]*POST_S[k] + im[k]*POST_C[k]) * SCALE
    u[2k]     = yr
    u[N-1-2k] = -yi

FFT(re, im):                                     // radix-2, decimation in time, M = 256
  for i = 0 ... M-1:                             // bit-reversal permutation
    j = BITREV[i]
    if i < j: swap(re[i], re[j]); swap(im[i], im[j])
  for len = 2, 4, ..., M:
    step = M / len;  h = len / 2
    for i = 0; i < M; i += len:
      for k = 0 ... h-1:
        wr = FFT_C[k*step];  wi = FFT_S[k*step]
        xr = re[i+k+h];  xi = im[i+k+h]
        tr = xr*wr - xi*wi
        ti = xr*wi + xi*wr
        re[i+k+h] = re[i+k] - tr;  im[i+k+h] = im[i+k] - ti
        re[i+k]   = re[i+k] + tr;  im[i+k]   = im[i+k] + ti
```

### 9.4 逆变换、重叠相加与输出舍入

累加器 `y` 是覆盖填充位置的 double 数组，初始值为 `+0.0`。帧按递增的 `m` 顺序处理。每个位置按帧顺序累加其贡献：

```
for m = 0 ... frames(Ls)-1:
  c[k] = sum over planes of (double) X_plane[m][k]   // exact (Section 9.5); 0 if no plane has frame m
  u = DCT4(c);  s = m*N
  for n = 0 ... N/2-1:                               // unfold [u2, -u2r, -u1r, -u1], window, add
    y[s + n]        += u[N/2 + n]       * WIN[n]
    y[s + N/2 + n]  += (-u[N-1-n])      * WIN[N/2 + n]
    y[s + N + n]    += (-u[N/2-1-n])    * WIN[N + n]
    y[s + 3N/2 + n] += (-u[n])          * WIN[3N/2 + n]
```

帧 `m` 加入后，位置 `[s, s + N)` 中的样本即为最终值。输出样本 `i in [0, Ls)` 为：

```
v = y[i + N]
if v > 1073741823.0 or v < -1073741823.0: CORRUPT; v = clamp(v, -1073741823.0, 1073741823.0)
o[i] = (int32) llround(v)
```

窗系数表中仅包含窗函数，不会将任何旋转因子或缩放因子合并进来。该变换 MUST 严格按照第 9.3、9.4 节给出的结构计算。使用其他因式分解通常会改变输出位值。

*说明性内容。* 编码器使用的正向变换流程如下：

1. 对 2N 个样本加窗；
2. 将它们折叠为 `[-c_r - d, a - b_r]`，即 `u[n] = -z[3N/2-1-n] - z[3N/2+n]`，`u[N/2+n] = z[n] - z[N-1-n]`；
3. 执行 `DCT4` 并进行 `llround`。

### 9.5 平面求和

每个 IMDCT 信号都在变换前对选定平面求和：

* 深度声道 c：其唯一的深度平面；
* M：选中的 M 区段；
* S：选中的 S 区段。

这些区段按设计在频率上互不重叠。每个平面值为 `int32`，其绝对值不超过 1073741823，且最多有 8 个平面。因此，对它们进行 double 求和是精确的，求和顺序不影响结果。

如果某平面所在流的帧数少于 `m + 1`，该平面对帧 `m` 的贡献为零。全零帧的变换结果也全为零，因此 MAY 跳过该变换。

## 10. 半带插值与抽取

### 10.1 系数表

半带滤波器为对称、奇数长度 FIR 滤波器。仅将奇数抽头 `h[1], h[3], ..., h[half]` 以 Q31 格式的 `int32` 值存储。中心抽头为 `2^30`。下列存储抽头记作 `ht[t] = h[2t+1]`（`src/halfband.h`）。

```
Table 0 (base*1 <-> base*2), half = 79, 40 values:
 682938002, -225979149, 133607419, -93347908, 70491357, -55579122, 44978765, -36999032,
 30747123, -25707634, 21562088, -18102637, 15187220, -12714693, 10610315, -8816912,
 7289329, -5990851, 4890848, -3963205, 3185274, -2537151, 2001191, -1561677,
 1204578, -917388, 688994, -509581, 370536, -264370, 184638, -125854,
 83405, -53473, 32940, -19306, 10605, -5322, 2321, -771
Table 1 (base*2 <-> base*4), half = 15, 8 values:
 668035431, -184994700, 75935913, -29954182, 10005932, -2547898, 417025, -26609
Table 2 (base*4 <-> base*8), half = 11, 6 values:
 656183834, -156920197, 47052629, -10858972, 1477097, -63479
Table 3 (base*8 <-> base*16), half = 9, 5 values (defined in halfband.h; not used in container v5):
 644456397, -132671512, 28454516, -3484033, 115544
```

每个表中的存储抽头之和都精确等于 2^29，因此每个插值器和抽取器的直流增益都恰为 1。

对于给定的一对采样率，插值器和抽取器使用同一张表。表 `k` 连接 `base*2^k` 与 `base*2^(k+1)`。

### 10.2 边界延拓

输入长度为 `n` 时，对于 `[0, n)` 之外的输入索引，先围绕端点样本进行反射（整样本对称），然后钳制：

```
mirror(i, n):
  if i < 0:   i = -i
  if i >= n:  i = 2*(n - 1) - i
  return clamp(i, 0, n - 1)
```

### 10.3 二倍插值

输入 `x` 长度为 `n`，输出 `y` 长度为 `2n`。表 `k` 有 `T` 个存储抽头。

```
y[2m]     = x[m]
y[2m + 1] = rq31(2 * A),   A = sum_{t=0}^{T-1} ht[t] * ( x[mirror(m - t, n)] + x[mirror(m + 1 + t, n)] )      // int64
```

### 10.4 二分抽取

输入 `x` 长度为 `n`，输出 `y` 长度为 `floor(n / 2)`。

```
y[i] = rq31( x[2i]*2^30 + sum_{t=0}^{T-1} ht[t] * ( x[mirror(2i - 1 - 2t, n)] + x[mirror(2i + 1 + 2t, n)] ) )      // int64
```

每个输出样本仅舍入一次。整数累加是精确的，因此求和顺序无关紧要。

第 8.3 和 9.4 节中的数值范围本身并不能排除这些累加器发生 `int64` 溢出：

* 当 `|D_c[i]| <= 1073741823` 时，`B_c[i]`（第 11.2 节）的绝对值可能超过 2^34 FU；
* 表 0 抽头绝对值之和超过 2^30；
* 因此，第 10.3 节的最坏情况累加值会超过 2^63。

参考解码器不会检测 `int64` 溢出；可能导致溢出的流，其结果未作规定。是否必须拒绝此类流，以及有效流应满足的保证上限，将在后续修订版中说明。

## 11. 重建流程

除非另有说明，本节中的所有信号均按声道 `c in {0 = L, 1 = R}` 分别处理，单位为 FU，并使用 `int64` 计算。

### 11.1 路径与输出采样率

| 路径 | `d` | 输出采样率 | `Po`（输出偏移） | `Lo`（输出长度） |
|---|---|---|---|---|
| 24 位、16 位 | `0 <= d < stages` | `rate >> d` | `P >> d` | `Lm >> d` |
| `cd24` | — | `base` | `pb` | `nb - 2*pb`（即 `ncd`） |

对于 24 位和 16 位路径，若请求的输出采样率不符合 `rate >> d`（其中 `0 <= d < stages`）的形式，则 MUST 拒绝该请求。

### 11.2 基础信号与抖动再生成

每个声道使用一个 xorshift32 生成器。其状态为 `uint32`：

* `g_0` 的种子为 `0x12345678`；
* `g_1` 的种子为 `0x12345678 + 0x9E3779B9 = 0xB06BD031`。

这些种子是格式常量，不会传送。

```
xs(g): g = g XOR (g << 13); g = g XOR (g >> 17); g = g XOR (g << 5); return g
```

对于每个声道 `c`，按顺序遍历每个填充后的基础索引 `i = 0, 1, ..., nb - 1`：

```
g_c = xs(g_c);  u1 = (g_c >> 20) AND 0xFFF
g_c = xs(g_c);  u2 = (g_c >> 20) AND 0xFFF
delta_c[i] = (dfl[c*nbk + floor(i / 4096)] != 0) ? (u1 + u2 - 4096) : 0
```

对**每个**索引，生成器均前进两步，包括填充部分以及标志为 0 的块。生成的抖动具有三角概率密度函数，范围为 `[-4096, 4094]` FU，约为 ±1 LSB16。

CD 样本 `x_c[i]` 为：

* 当 `i < pb` 时，取 `edge[2i + c]`；
* 当 `pb <= i < pb + ncd` 时，取 `cd[2(i - pb) + c]`；
* 其他情况取 `edge[2pb + 2(i - pb - ncd) + c]`。

其中 `cd` 是第 3.2 节所述交错排列的 `int16` 数据。基础信号为：

```
B_c[i] = 4096 * x_c[i] - delta_c[i] + 16 * D_c[i]         for i in [0, nb)
```

* `D_c` 是声道 `c` 深度平面的逆 MDCT 输出（第 9 节，`Ls = nb`），单位为 LSB24。
* 在 16 位路径中省略 `16 * D_c[i]` 项，但仍减去抖动。

### 11.3 插值至主采样率

在 24 位和 16 位路径中，对 `B_c` 执行 `stages` 次插值（第 10.3 节）。第 `k = 0, 1, ..., stages-1` 级使用表 `k`。结果为 `U_c`，其长度 `nU = nb * 2^stages`。

### 11.4 频率层（M/S 逆变换）

`m[i]` 和 `s[i]` 分别是选定 M 平面与 S 平面求和后再经逆 MDCT 得到的输出（`Ls = Lp`），单位为 LSB24。对于 `i in [0, Lp)`：

```
r      = m[i] - (s[i] >> 1)
F_0[i] = 16 * (r + s[i])                              // L
F_1[i] = 16 * r                                       // R
```

如果未选中任何 S 平面，则 `s[i] = 0`。

### 11.5 混合

对于 `i in [0, Lp)`：

```
Z_c[i] = (i < nU ? U_c[i] : 0) + F_c[i]
```

如果未选中任何 M 平面，则 `F_c[i] = 0`。频率层在此处以时域方式相加。

### 11.6 抽取至输出采样率

在 24 位和 16 位路径中，对 `Z_c`（长度为 `Lp`）执行 `d` 次抽取（第 10.4 节）。第 `k = 0, 1, ..., d-1` 次抽取使用表 `stages - 1 - k`。结果为 `Y_c`。

在 `cd24` 路径中，`Y_c = B_c`。

### 11.7 最终舍入与硬限幅

对于 `i in [0, Lo)`：

```
v = (Y_c[Po + i] + 8) >> 4                             // FU -> LSB24, round half up
o_c[i] = clamp(v, -8388608, 8388607)                   // hard limiter
```

### 11.8 输出文件

输出由 44 字节的规范 WAV 文件头和其后的 `Lo` 个立体声帧组成。每帧依次包含 `o_0[i]`、`o_1[i]`。每个值写为 3 个小端序字节，即其二进制补码表示的低 24 位。令 `D = 6*Lo`：

| 偏移量 | 内容 |
|---|---|
| 0 | `RIFF` |
| 4 | `uint32` `36 + D` |
| 8 | `WAVE` |
| 12 | `fmt ` |
| 16 | `uint32` 16 |
| 20 | `uint16` 1（PCM） |
| 22 | `uint16` 2（声道数） |
| 24 | `uint32` 输出采样率 |
| 28 | `uint32` 6 * 输出采样率 |
| 32 | `uint16` 6（块对齐） |
| 34 | `uint16` 24（位数） |
| 36 | `data` |
| 40 | `uint32` `D` |
| 44 | 样本数据 |

`D` 始终为偶数，因此末尾不需要填充字节。

如果 `37 + D > 0xFFFFFFFF`，则无法将输出表示为 WAV 文件，MUST 拒绝写入。这是参考写入器（`wavio::fits32`）执行的大小检查，会为一个可能的填充字节预留空间。

## 12. 错误处理

CD 层是普通 PCM，不会受到扩展数据错误的影响。解码器拒绝解码扩展数据时，播放器 SHOULD 退回播放 `data` 块中的 16 位音频。

| 条件 | 必需行为 | 参考程序退出状态（说明性内容） |
|---|---|---|
| 自检失败（第 13 节；参考解码器会在读取输入前运行自检） | MUST NOT 解码 | 4 |
| 不是 RIFF/WAVE 文件；没有 `data` 块；不是 16 位双声道整数 PCM | 不是 LAE Lossy 文件。MUST NOT 解码 | 1 |
| 没有 `LAE ` 块，或 `LAE ` 块主体为空 | 普通 CD 音频；没有扩展数据需要解码 | 1 |
| `LAE ` 块主体 < 8 字节，或 CRC 不匹配 | MUST 在解析任何字段之前拒绝 | 3 |
| 魔数或版本不是 `LAE1` / 5 | MUST NOT 解码（未知版本） | 1 |
| V3–V11 任一检查失败 | MUST 拒绝 | 3 |
| V12 检查失败（抖动标志） | MUST 拒绝 | 3 |
| V13 检查失败（CD 长度不匹配：CD 层经过编辑或未对齐） | MUST 拒绝 | 3 |
| 输出采样率不适用于该路径（第 11.1 节）；在 V13 后、流记录前检查 | MUST 拒绝 | 1 |
| 流记录超出有效载荷范围；解码流头部无效（第 5.3 节）；`nseg outside [1, 8]` | MUST 拒绝 | 3 |
| 输出超过 WAV 大小上限（第 11.8 节） | MUST 拒绝 | 1 |
| 解码期间触发 `CORRUPT`（第 7.4、7.5、8.3、9.4 节） | MUST 报告流已损坏，且 MUST NOT 交付输出。参考解码器会删除已写入的文件 | 3 |

解码器对任何输入都 MUST 保持内存安全。参考解码器会在使用头部字段访问数据前验证每个字段，并钳制超范围的解码值。

参考解码器包含两个仅供编码器使用的钩子 `LEAKOUT` 和 `CLIPMAP`。只有编码器构建解码器时（`LAE_ENCODER_HOOKS`）才会编译这些钩子，它们不属于格式。

## 13. 自检哈希

自检用于检测不遵循第 2.2 节算术规则的构建版本。此类构建可能导致不同平台生成不同输出。测试流程如下：

1. 令 `L = 6*N = 3072`，`K = frames(L) = 7`。
2. 使用 `uint32` 算术，对 `i` 在 `[0, 3584)` 范围内构造系数 `X[i]`：

   `X[i] = (int32)((((i * 2654435761) mod 2^32) >> 7) mod 2000001) - 1000000`

   第 `m` 帧由 `X[512*m ... 512*m + 511]` 组成。
3. 使用 `Ls = L`，应用第 9.4 节的逆 MDCT，生成 3072 个 `int32` 值 `o[i]`。此处省略 `CORRUPT` 检查，因为不可能触发。
4. 按小端字节顺序，对 `o` 的字节计算 64 位 FNV-1a 风格哈希：

   ```
   h = 1469598103934665603                   // 0x14650FB0739D0383
   for each o[i]: for b = 0 ... 3: h = (h XOR (((uint32)o[i] >> 8*b) AND 0xFF)) * 1099511628211   (mod 2^64)
   ```

   初始值与参考实现一致（`src/mdct_tb.h`），**不是**标准 FNV-1a 偏移基数（14695981039346656037 = `0xcbf29ce484222325`）。实现 MUST 使用本文给出的值。
5. 结果 MUST 等于 `0x729b547fbdbfe203`。

解码器 SHOULD 在启动时执行此测试。若执行后得到不同值，MUST NOT 解码。

通过自检不能替代第 1.3 节的符合性测试。

*说明性内容。*参考实现的状态见 [docs/BUILD.md](../../docs/BUILD.md)：

* 解码器和编码器均可在 Windows（MSVC）和 Linux（GCC 13 的 `-O2`、`-O0`，以及 Clang 18）上构建并运行。解码器也已使用 GCC 构建为 32 位 SSE2 版本。
* 在 Linux 上，解码器输出在 256 次比较中有 256 次完全相同；编码器逐字节重现全部 16 个向量文件。
* ARM 平台尚未测试。
* 不支持 x87 构建；参考解码器的自检会拒绝这类构建。

## 14. 编码器端要素（说明性内容）

以下内容属于编码器。列出这些信息是为了帮助实现者理解比特流的含义；它们不影响解码。

除非另有来源说明，本节内容依据参考编码器源文件 `src/lae_enc.cpp`、`src/partition.h`、`src/pad_mirror.cpp`、`src/base_layer.cpp` 和 `src/routes.cpp`。

* **各层目标。**解码器在时域中相加三个部分（CD 路径、位深层和频率层）（第 11 节）。
  * 编码器从母带生成 CD 层，并在第 4.2 节标志所指示的块中添加 TPDF 抖动。
  * **CD 层派生**（`src/base_layer.cpp`）。将填充后的母带（第 4.1 节）转换为 FU，再通过第 10.4 节的整数半带抽取器，以采样率最高的级开始，抽取 `stages` 次至基础采样率；中间值仅限制在 `int32` 范围内。设抽取后的 FU 值为 `x`，第 11.2 节的抖动为 `delta`（标志为 0 的块中为 0），则每个 CD 样本为 `clamp((x + delta + 2048) >> 12, -32768, 32767)`。
  * **抖动判定**（`src/base_layer.cpp`）。对每个声道的每个 4096 个基础采样率样本的块，编码器会对抽取后的信号拟合 16 阶线性预测器，并计算预测残差的 RMS（单位为 LSB24）。若该 RMS 低于 128 LSB24（0.5 LSB16），且该块不是数字静音，则添加抖动。全零块永不添加抖动，因此 CD 层保留真正的零值。
  * **位深目标**（`src/routes.cpp`）。令 `v = 256 * CD - delta/16` 为以 LSB24 表示的 CD 路径，`B24 = (x + 8) >> 4` 为以 LSB24 表示的抽取母带，且不限制其满量程。位深目标为 `T = llround(lowpass(B24 - v))`，并限制在 `[-8388608, 8388607]`。低通滤波器是基础采样率下的零相位窗化 sinc FIR 滤波器（511 抽头，Kaiser 窗 β = 9），截止频率为 `fc`。当 `fc >= base/2 - 1` Hz 时省略该滤波器。
  * 位深层覆盖整个基础采样率频段。
  * **频率目标**（`src/routes.cpp`）。母带采样率下、单位为 LSB24 的频率目标为 `F = master - up(v + T)`，并限制在 `[-8388608, 8388607]`。`up` 使用第 10.1 节的半带表执行 `stages` 次二倍插值；编码器以 double 精度计算。
  * 频率层从检测到的 CD 截止频率以下开始：编码器向层编码器传入 `fc - 1000` Hz 作为起始频率（`src/lae_enc.cpp`）。`fc` 记录截止频率。
  * **截止频率检测**（`src/routes.cpp`）。编码器根据母带和插值后 CD 路径的平均互谱，从基础采样率奈奎斯特频率向下扫描至 15 kHz。在 CD 路径传递增益至少为 −0.1 dB 的最高频率处略微上方设定 `fc`。母带能量几乎为零的频点会被跳过。如果未找到此类频率，则令 `fc = 15000` Hz。
* **独立 CD 输入。**编码器选项 `cd=<file>` 接受独立提供的基础采样率 16 位双声道 CD。
  * 所提供的 CD 逐位成为 CD 层。它必须已与母带对齐，并且每声道恰好有 `ncd` 个样本；目前未实现自动对齐。
  * 此时所有抖动标志均为 0。
  * 使用相干性测试（阈值 0.98）寻找 CD 截止频率，不受 CD 增益影响；不使用传递函数测试。
  * 扩展数据编码母带与 CD 路径之差。
  * 边缘样本（第 4.1 节）仍取自编码器根据母带派生的 CD 层。
* **分区搜索**（`src/partition.h`）。
  * 搜索以根块为单位并行运行。线程数不会影响编码流（[docs/BUILD.md](../../docs/BUILD.md)）。
  * 搜索目标是满足所选模式的 D、C 占比要求（`src/partition_format.h`）。占比目标只存在于编码器中。
  * 解码器无需模式表。`mi`、`lv`、`wm` 和主头部的 `eq` 均为说明性字段。
  * 对给定的惩罚值 λD 和 λC，动态规划会遍历每个根块的所有子矩形，选择切分树和每个叶节点的层级。它会最小化估算比特数，并加上每个降级 D 单元（叶节点层级低于 D 的 D 单元）的 λD 惩罚，以及每个降级 C 单元（叶节点层级低于 C 的 C 单元）的 λC 惩罚。一个计量单位可以是一个单元（按单元数计算占比）；可以是该单元相对于该平面所有 D（或 C）类单元平均能量的能量值（按能量计算占比）；也可以取二者平均（单元数 + 能量）。仅当叶节点内所有单元均为 A 类时，该叶节点才归为 A 类。
  * 惩罚值通过在 10^-3 至 10^4 的对数范围内执行 7 轮二分搜索获得：先令 λD = 0 搜索 λC 直至达到 C 占比目标，再搜索 λD。对于 C 占比为 100% 的模式（keep、keep20），λC 固定为 10^9。采用“单元数 + 能量”度量时，两个占比中较小者必须达到目标。
* **模式。**每种方案有六种模式（`src/partition_format.h`）：

  | 索引 | 名称 | D 占比 | C 占比 | 说明 |
  |---|---|---|---|---|
  | 0 | max | 10% | 30% | |
  | 1 | 1 | 30% | 50% | |
  | 2 | 3 | 50% | 70% | |
  | 3 | 5 | 70% | 90% | |
  | 4 | keep | 90% | 100% | |
  | 5 | keep20 | 90% | 100% | 位深层使用规则 3（可选启用，文件较大） |

  方案 1 的两层都使用规则 1。方案 2 的频率层使用规则 2，位深层使用规则 1。
* **量化器。**编码器使用带死区的标量量化。对步长为 `2^s` 的叶节点系数 `x`，量化结果为 `q = sign(x) * floor(|x| / step + 0.5 - 0.30)`。死区 0.30 仅供编码器使用，不会传送。解码器按与 `q` 相同的符号，将 `(|q| + 0.20) * step` 重建（第 8.3 节）；重建偏移量 0.20 是格式常量。
* **泄漏补偿。**编码器获取解码后的频率层，并通过第 10 节的抽取器将其降至基础采样率（`src/lae_dec.cpp` 的 `LEAKOUT` 钩子），用于补偿位深目标。
  * 首次完成编码后，编码器会解码已写入的文件，并在基础采样率下单独获得频率层。
  * 使用零相位窗化 sinc 低通滤波器（2047 抽头，Kaiser 窗 β = 9）对该泄漏进行滤波，截止频率设为 `fc - 1150` Hz，即低于频率层起始频率 150 Hz；然后在生成位深目标前，从 `B24 - v` 中减去滤波结果。沿用第一遍得到的截止频率 `fc`。
  * 随后仅重新编码位深层，并再次写入文件。保留第一遍的频率层。
  * v5 始终启用泄漏补偿。
* **削波。**唯一的输出保护是解码器最终硬限幅器（第 11.7 节）。参考编码器通过 `CLIPMAP` 钩子执行一次诊断解码，并报告限幅器处理的样本数。此报告不会存入文件。
* **信号分析。**编码器分析使用 `src/fft.h` FFT 模块。第 9.3 节的逆 MDCT 由 `src/mdct_tb.h` 单独实现。
