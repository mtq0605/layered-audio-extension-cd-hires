[English](SPEC.md) | **中文**（以英文版为准）

**状态**：正式，容器版本 5。
**适用范围**：LAE Lossy（LAEY），即 LAE（Layered Audio Extension）格式系列的有损层级，容器版本 5。
**本文许可**：CC BY 4.0（见第 15 节）。版权所有 (c) 2026 mtq0605。

第 14 节、第 15 节以及所有标记为*说明性*的文字均不具有规范性。

凡本文未作说明或存在歧义之处，以参考解码器为规范依据。其文件如下：

* `src/lae_dec.cpp`

编码器的分区搜索位于 `src/partition.h`。解码器不需要该文件。尚未规定的事项列于附录 C。

该格式系列称为 LAE，包含两个层级：

* 有损层级 LAE Lossy（LAEY），由本文规定；
* 无损层级 LAE Lossless（LAES）：由 [spec/lossless/SPEC.md](../lossless/SPEC.zh.md)（正式，有效载荷版本 2）规定，该规范取代设计文档 [spec/lossless/DESIGN.md](../lossless/DESIGN.zh.md)。

RIFF 块标识符为 `LAE `，末尾带一个空格。块魔数为 `LAE1`（第 4 节）。魔数标明格式：`LAE1` = LAEY（本规范）；`LAE2` = LAES，即无损层级，另有其规范。解码器应告知用户所识别的格式；LAEY 解码器遇到 `LAE2` 时报告这是 LAES 文件，并且不对其解码（CD 层仍可播放）。

## 1. 范围与符合性

### 1.1 范围

LAE Lossy 文件是包含两部分的 RIFF/WAVE 文件（WAV 形式，第 3.1 节）或 FLAC 流（FLAC 形式，第 3.4 节）：

* **CD 层**。普通的 16 位双声道 PCM，基础采样率为 44 100 Hz 或 48 000 Hz：WAV 形式中是 `data` 块，FLAC 形式中是音频帧。任何 WAV 或 FLAC 播放器均可原样播放。48 kHz 时这一层称为核心层，规则相同。
* **扩展数据**。WAV 形式中是音频之后一个标识符为 `LAE ` 的块，FLAC 形式中是音频之前 ID 为 `LAE1` 的 APPLICATION 元数据块，其中携带两个层：
  * **位深层**：在基础采样率下将 CD 层向 24 位分辨率扩展，L、R 两个声道各一个平面；
  * **频率层**：将带宽扩展至基础采样率 × 2、× 4 或 × 8 的母带采样率。该层以中/侧（M、S）平面存储，并按频率区段拆分为数据流：每个区段一条流，若编码器选项 `g` 对该层再编码一次，则为两条；每条流是一条区段记录，各区段在频率上可以重叠（第 5.2 节和第 9.5 节）。

  扩展数据还可以另外携带最多八个**扩展包**，每个扩展包由各自的母带对着同一个 CD 层生成（第 5.6 节）。解码器用 CD 层加恰好一个扩展包解码，扩展包由用户选择。

**分发方式与文件扩展名。**

* `.wav` 表示 WAV 形式，`.flac` 表示 FLAC 形式；所有 WAV 或 FLAC 播放器都能播放 CD 层（个别系统自带解码器的限制见第 3.4 节）。
* `.lae` 是该格式自有的文件扩展名。`.lae` 文件可以是两种形式中的任一种；读取方按内容区分，从不按文件名区分（第 3.4 节）。

解码器可生成以下输出，均以 24 位双声道 PCM 写入。

| 路径 | 内容 | 输出采样率 |
|---|---|---|
| 24 位路径 | CD + 位深层 + 频率层 | 母带采样率 / 2^d，其中 0 ≤ d < stages（d = 0 时为母带采样率） |
| 16 位路径 | CD + 频率层 | 母带采样率 / 2^d，其中 0 ≤ d < stages |
| CD + 位深路径（"cd24"） | CD + 位深层 | 基础采样率 |

选择低于母带采样率的输出采样率时，起始频率等于或高于输出奈奎斯特频率的频率层数据流被跳过，不予解码（第 5.4 节）。随后使用第 10 节的半带抽取器将结果降至所选采样率。

无损层级 LAE Lossless（LAES）不在本文中规定；它由 [spec/lossless/SPEC.md](../lossless/SPEC.zh.md)（正式，有效载荷版本 2）规定。

### 1.2 解码模型（说明性）

所有重建均在时域中进行。操作顺序如下：

1. 对每个编码平面进行范围解码，每次处理 8 帧组成的一行，并对其系数反量化（第 6 至 8 节）。
2. 以严格的 IEEE-754 双精度算术执行教科书形式的逆 MDCT，并进行重叠相加（第 9 节）。
3. 形成基础信号：4096 × CD − 再生成的 TPDF 抖动 + 16 × 位深层。结果以 1/16 LSB24 为单位（第 11.2 节）。
4. 使用整数半带滤波器每级进行 2 倍插值，直至母带采样率。滤波器使用 Q31 系数、64 位累加，并对每个输出样本舍入一次。
5. 经整数 M/S 逆变换后，加上 16 × 频率层。
6. 可选地使用相同的半带系数表抽取至所选采样率。
7. 进行一次最终舍入至 24 位，然后应用硬限幅器。

在 cd24 路径中，省略步骤 4 至 6。

### 1.3 符合性

符合规范的解码器必须满足第 3 至 13 节中适用于解码器的每项要求，包括第 4.3 节和第 12 节的验证与拒绝规则，以及对任何输入均保持内存安全的要求。此外，对于 [tests/vectors/MANIFEST.md](../../tests/vectors/MANIFEST.md)（附录 B）所列的每个一致性测试向量和每条路径，解码器必须生成一个输出 WAV 文件（文件头和样本，第 11.8 节），其 SHA-256 与所列值一致。

清单主表列出每个 SHA-256 值的前 16 个十六进制数字；完整的 64 位数字值列于清单的"Full SHA-256 values"一节。

一致性测试向量检验第 3 至 13 节定义的过程。严格遵循这些章节并使用 `src/mdct_tables.h` 中 MDCT 表（第 9.2 节）的实现，预期会产生所列输出；凡本文未作说明或存在歧义之处，以参考解码器为准。

只要每个输出字节都完全一致，解码器的内部结构可不同。例如，解码器可以对整条音轨解码而不采用流式处理，也可以并行解码各数据流。

### 1.4 术语

关键词"MUST"（必须）、"MUST NOT"（不得）、"REQUIRED"（必需）、"SHALL"（必须）、"SHALL NOT"（不得）、"SHOULD"（应）、"SHOULD NOT"（不应）、"RECOMMENDED"（推荐）、"MAY"（可）和"OPTIONAL"（可选）按 BCP 14（RFC 2119 和 RFC 8174）的规定解释，当且仅当它们如此处所示以全大写形式出现时适用。

### 1.5 浮点与伪随机元素（说明性）

* 仅有的浮点阶段是系数重建（第 8.3 节）和逆 MDCT（第 9 节）。二者均使用严格的 IEEE-754 双精度。
* 量化为零的系数重建为零，除非使用了可选的零级（第 8.4 节）。
* 解码器中唯一的伪随机序列是抖动再生成（第 11.2 节）。它重现编码器加入 CD 层的抖动。

## 2. 符号与算术

### 2.1 整数算术

* `int16`、`int32` 和 `int64` 表示 16、32 和 64 位二进制补码有符号整数。`uint8`、`uint16`、`uint32` 和 `uint64` 表示无符号整数。
* 文件中所有多字节数值均为**小端序**。
* 对有符号值，`a >> k` 为算术移位，即向下取整地除以 2^k。对无符号值，它为逻辑移位。
* 整数上的 `a / b` 表示截断除法。本规范凡使用该运算之处，操作数均为非负，或该除法为精确除法。
* 对正整数，`ceil(a / b)` 等于 `(a + b - 1) / b`。
* `uint32` 值的运算按模 2^32 进行。`uint64` 值的运算按模 2^64 进行。
* 本规范注明 `int64` 之处，该运算必须至少以 64 位有符号算术执行。
* `min`、`max` 和 `clamp(x, lo, hi) = min(max(x, lo), hi)` 取其通常含义。

### 2.2 浮点算术

系数重建（第 8 节）和逆 MDCT（第 9 节）使用 IEEE-754 binary64（"double"）。适用以下规则：

* 每次加法、减法和乘法必须单独舍入至 binary64，采用"舍入到最近，平局取偶"方式。
* 不得使用融合乘加收缩。
* 不得使用扩展精度中间值（例如 x87 80 位寄存器）。
* 不得进行重新结合、重新排序或任何"快速数学"变换。
* 运算必须按本规范所写的顺序求值：从左至右，遵循括号。
* `int32` 到 double 的转换是精确的。
* `2^s` 表示 2 的 s 次幂的精确 double 值。

*说明性。*对于 C 和 C++，以下编译器设置可满足上述规则：

* GCC 和 Clang：`-ffp-contract=off`，且不使用 `-ffast-math`。
* 32 位 x86 上的 GCC 和 Clang：另加 `-msse2 -mfpmath=sse`。
* MSVC：`/fp:precise`，即 MSVC 的默认设置；不能使用 `/fp:fast`。在 32 位 x86 上另加 `/arch:SSE2`，这也是 MSVC 的默认设置。

不支持生成 x87 浮点代码的构建（第 13 节）。参考实现的构建命令见 [docs/BUILD.md](../../docs/BUILD.zh.md)。

### 2.3 舍入函数

* `llround(x)` 将 double 舍入至最接近的整数，**平局时远离零**。这是 C 语言的 `llround` 函数。
* 对 `int64` 值，`rq31(a) = (a + 2^30) >> 31`。它将 a / 2^31 舍入至最接近的整数，平局时向 +∞ 舍入。
* 最终输出舍入为 `int64` 上的 `(x + 8) >> 4`（第 11.7 节）。

### 2.4 单位

* `LSB24` 是 24 位信号的一个步长。满量程为 ±2^23 LSB24。
* `LSB16` 等于 256 LSB24。
* **精细单位**（FU）等于 1/16 LSB24。一个 LSB16 等于 4096 FU。
* 第 11 节的所有时域阶段均以 FU 运算，注明信号以 LSB24 为单位之处除外。
* 位深层和频率层的逆 MDCT 输出（`D_c`、`m`、`s`）以 LSB24 为单位；它们在进入 FU 信号时乘以 16。最终输出 `o_c`（第 11.7 节）以 LSB24 为单位。

## 3. 文件结构

LAE Lossy 文件有两种形式：WAV 形式（第 3.1 至 3.3 节），这是默认形式；FLAC 形式（第 3.4 节）。两种形式携带相同的 CD 层和相同的扩展数据字节。第 4 至 13 节提到 `LAE ` 块时，对 FLAC 形式指由各 `LAE1` 块拼接而成的扩展数据（第 3.4 节）。

### 3.1 RIFF/WAVE

LAE Lossy 文件是 RIFF/WAVE 文件。前 4 个字节必须为 `RIFF`，第 8 至 11 字节必须为 `WAVE`。各块自偏移量 12 起依次排列。每个块由以下部分组成：

* 4 字节标识符；
* `uint32` 主体大小 n；
* n 个主体字节；
* 若 n 为奇数，另加一个填充字节。

**解码器解析规则**（参考读取器的行为；含关键词的条目为要求，其余条目描述参考读取器）：

* 必须自偏移量 12 起按顺序解析各块，直至文件末尾。不使用偏移量 4 处的 RIFF 大小字段。
* 若某块主体超出文件末尾，则将其截断为实际可用的字节。
* 必须跳过未知块。
* 若某块标识符出现多次，使用最后一次出现者。
* `fmt ` 块主体必须至少为 16 字节。其字段为：
  * 格式标记，主体偏移量 0 处的 `uint16`；
  * 声道数，偏移量 2 处的 `uint16`；
  * 采样率，偏移量 4 处的 `uint32`；
  * 每样本位数，偏移量 14 处的 `uint16`。
* 若格式标记为 0xFFFE（WAVE_FORMAT_EXTENSIBLE）且主体至少为 26 字节，则以主体偏移量 24 处的 `uint16` 取代格式标记。这是子格式 GUID 的前两个字节。
* 有效格式标记必须为 1（整数 PCM）。每样本位数必须为 16，声道数必须为 2。必须存在 `data` 块。

**编码器要求**。编码器必须按以下顺序写入：

1. `fmt ` 块（PCM、2 声道、基础采样率、16 位）；
2. 包含 CD 层的 `data` 块；
3. `LAE ` 块。

RIFF 大小必须涵盖所有块。不识别 `LAE ` 块的播放器会跳过该块并播放 CD 层。

参考解码器不将 `fmt ` 的采样率与第 4 节的 `base` 字段进行比较。编码器必须将 `base` 的值写为 `fmt ` 的采样率。是否要求解码器拒绝二者不一致的情形，将在后续修订版中规定。

### 3.2 CD 层（`data` 块）

`data` 块保存交错排列的小端序 `int16` 样本，顺序为 L、R、L、R，依此类推。立体声帧数为

`ncd = floor(floor(dlen / 2) / 2)`

其中 `dlen` 为 `data` 主体大小。不构成完整立体声帧的尾部字节被忽略。`ncd` 必须等于 `nb - 2*pb`（第 4 节）。

CD 层是普通 PCM，扩展数据绝不修改它。

CD 层与扩展数据之间唯一的绑定检查即为此长度检查。CD 层被改动而长度不变时，无法检测出来。

### 3.3 `LAE ` 块

块标识符为四个字节 `0x4C 0x41 0x45 0x20`（`LAE `）。其 `n` 字节主体布局如下：

| 字节 | 内容 |
|---|---|
| `0 ... n-5` | 主头部、边缘样本、抖动标志和编码流（第 4 节和第 5 节） |
| `n-4 ... n-1` | 字节 `0 ... n-5` 的 `uint32` CRC-32，小端序 |

块主体必须至少为 8 字节。参考解码器将 0 字节的块主体视为不存在 `LAE ` 块（第 12 节）。

CRC-32 为 IEEE 802.3 CRC，参数如下：

* 反射多项式 `0xEDB88320`（常规形式 `0x04C11DB7`）；
* 初始值 `0xFFFFFFFF`；
* 输入和输出均反射；
* 最终异或值 `0xFFFFFFFF`。

ASCII 字符串 `123456789` 的 CRC 为 `0xCBF43926`。参考算法为：

```
crc = 0xFFFFFFFF
for each byte b: crc = T[(crc XOR b) AND 0xFF] XOR (crc >> 8)
crc = crc XOR 0xFFFFFFFF
where T[i] = i iterated 8 times through: c = (c AND 1) ? 0xEDB88320 XOR (c >> 1) : (c >> 1)
```

解码器必须在解释块主体的任何其他字节**之前**验证 CRC。唯一的例外是格式标识：解码器可在 CRC 检查之前读取块主体的前 4 个字节（`LAE1` 或 `LAE2`），仅用于识别格式（见引言）；其他每个字节都只在 CRC 验证之后才予以解释。参考解码器即如此处理：它在 CRC 检查之前将 `LAE2` 块报告为 LAES 文件（`src/lae_decoder.h`）。单个 CRC 涵盖整个扩展数据。

本文其余部分中，**有效载荷**指字节 `0 ... n-5`，即不含 CRC 的块主体。偏移量均相对于其起始位置。

超出有效载荷末尾的字段属于错误。参考读取器对此类字段返回 0，随后的验证必然失败。

### 3.4 FLAC 形式

WAV 形式（第 3.1 节）是 LAE Lossy 文件的默认形式。文件也可以是一个 FLAC 流（RFC 9639）：CD 层就是 FLAC 的音频，扩展数据放在 APPLICATION 元数据块里。容器版本仍是 5：扩展数据的字节与 WAV 形式相同，只有容器不同。结构：

```
"fLaC" | STREAMINFO | VORBIS_COMMENT、PICTURE（可选） | ID 为 "LAE1" 的 APPLICATION 块（1 个或多个） | 其他元数据块（可选） | 音频帧 = CD 层
```

* **STREAMINFO**：2 声道，16 位，基础采样率（44 100 或 48 000），CD 层的帧数（不得为 0），CD 层的 MD5（必须存在且正确；RFC 9639 规定它按交错的 16 位小端序样本计算）。解码器发现 MD5 缺失（全 0）或不正确时，不得使用扩展数据：这段音频不是生成扩展数据时所用的 CD 层。此时参考工具拒绝该文件；播放器可以把 FLAC 音频当作普通 CD 音频播放。
* **扩展数据**就是第 3.3 节 `LAE ` 块的主体，逐字节相同：以魔数 `LAE1` 开头（第 4 节），以它的 CRC-32 结尾。它被切成每段不超过 2^24 − 5 字节的若干段，每段是一个 APPLICATION 块的数据，块的 4 字节 ID 是 `LAE1`（0x4C 0x41 0x45 0x31），已由 IANA 登记在 FLAC Application Metadata Block IDs 登记表中（RFC 9639 第 12.2 节；2026-10-31）。写入方把这些块放在 STREAMINFO 之后、VORBIS_COMMENT 和 PICTURE 块（如有）之后，连续排列，中间不夹其他块。读取方把所有 ID 为 `LAE1` 的 APPLICATION 块的数据按文件顺序拼接起来，不论它们位于元数据块中的什么位置。
* **标签和图片**（可选）：最多一个 VORBIS_COMMENT 块，任意数量的 PICTURE 块（RFC 9639 第 8.6 和 8.8 节）。写入方把它们放在 `LAE1` 块之前，使播放器无需跳过扩展数据即可读到。一套标签描述整个文件（CD 层、位深层和频率层）；扩展数据中没有任何内容引用它们，它们不参与解码。
* **音频帧**存放 CD 层，左右声道独立编码：每个帧头的声道分配都是 0b0001，不做声道间去相关。在这种声道分配之内，CD 层的任何合法 FLAC 编码都可以。
* **不写 SEEKTABLE 和 CUESHEET 块**。扩展数据整段存放在音频帧之前；不与音频帧交错，文件中没有指向扩展数据内部位置的表。

**与 WAV 形式等价**。解码后的 FLAC 音频就是第 3.2 节的 CD 层，拼接起来的各段就是第 3.3 节 `LAE ` 块的主体。第 4 至 13 节对这一对数据原样适用，因此同一次编码的两种形式在每条路径上解出的输出样本都相同。两种形式之间互相转换不丢失任何内容。

**验证，按以下顺序：**

1. FLAC 结构：STREAMINFO 位于最前，2 声道，16 位，有样本数，至少一个 `LAE1` 块。
2. 每个音频帧：帧头 CRC-8、整帧 CRC-16、块长在 STREAMINFO 规定的范围内、总数等于样本数。
3. MD5。
4. 第 4.3 节对扩展数据和 CD 层的检查。

第 2、3、4 项中任何一项不通过，文件即为损坏：解码器不得解码扩展数据（参考解码器退出状态为 3）。没有 `LAE1` 块的 FLAC 文件是普通 FLAC 音频；带 `LAE2` 块的 FLAC 文件是 LAES 文件（[spec/lossless/SPEC.md](../lossless/SPEC.zh.md) 第 8 节）。一种格式的读取方遇到另一种格式时，必须说明遇到的是哪种格式，并且不得按自己的格式解码。

**文件名。**`.flac` 表示 FLAC 形式，`.wav` 表示 WAV 形式；`.lae` 两种都可以（参考编码器未另行指定时写 WAV 形式）。读取方必须按内容判断（前 4 个字节是 `fLaC`，或 `RIFF` … `WAVE`），从不按文件名判断。

*说明性（其他解码器）：*完整实现 RFC 9639 的 FLAC 解码器都能播放 CD 层并跳过 APPLICATION 块（2026-11-10 用 GStreamer `flacdec` 核对：其输出与 WAV 形式的 CD 层相同）。Windows 自带的 FLAC 解码器（Media Foundation，资源管理器也使用它）不识别第一个音频帧位于文件约 4 MiB 之后的 FLAC 文件（在 LAES 的 FLAC 文件上测得；见 [COMPATIBILITY.md](../COMPATIBILITY.zh.md)）。LAEY 的扩展数据在几十秒音乐之后就超过 4 MiB，因此大多数 FLAC 形式的 LAEY 文件在那里无法播放；WAV 形式可以。

*说明性（参考实现）：*`src/lae_flacmeta.h` 读取结构和标签，不做解码；`src/laey_flac.h` 用 FLAC 读取器 `src/laes_flac.h` 从 FLAC 帧解出 CD 层并核对 MD5；`src/lae_enc.cpp` 用帧写入器 `src/laes_flac_enc.h` 写出 FLAC 形式。参考写入器使用固定块长 4096、两个独立编码的声道、最高 12 阶的 LPC、最高 15 的精度和最高 8 的 Rice 分区阶数（在 44.1 / 48 kHz 下属于 FLAC 的 streamable subset）。参考读取器只解码声道独立编码的帧。在一段 10 秒片段上实测（352.8 kHz / 24 位，模式 3，方案 s1）：CD 层以 FLAC 帧存放占 434 056 字节，PCM 为 1 764 000 字节；整个文件 2 078 616 字节，WAV 形式为 3 408 562 字节（61.0 %）；位深层和频率层在两种形式中字节相同，每条路径的解码输出都相同。

*说明性（被其他程序改过的文件）：*重新编码文件的 FLAC 编码器（例如 `flac` 1.3 和 1.5 的默认设置）通常保留 APPLICATION 块和 STREAMINFO 中的 MD5，但用左右声道去相关来编码音频帧；这样的文件不符合本节，参考解码器拒绝它。参考工具 `lae_repair` 解码这些帧，用 STREAMINFO 的 MD5 核对音频，再用独立声道重新编码，并像解码器一样核对结果；扩展字节保持原样。用 `flac --keep-foreign-metadata` 压缩的 WAV 形式文件，把各个块（包括 `LAE ` 块）放在 ID 为 `riff` 的 APPLICATION 块中；按本规范，它是普通的 FLAC 音频。`lae_repair`（或 `flac -d --keep-foreign-metadata`）能还原出原来的 WAV 文件，逐字节相同。`flac` 1.5.0 拒绝大于 16 MiB 的块，所以这种情况只出现在 `LAE ` 块不超过 16 MiB 的文件上（[COMPATIBILITY.md](../COMPATIBILITY.zh.md)）。

## 4. 主头部

有效载荷以十三个小端序 `int32` 字段开头。

| 偏移量 | 名称 | 含义 | 有效值 |
|---|---|---|---|
| 0 | `magic` | 块魔数，字节 `L A E 1` | `0x3145414C` |
| 4 | `version` | 容器版本 | `5` |
| 8 | `rate` | 母带采样率（Hz） | `base * 2^stages` |
| 12 | `base` | 基础（CD 层）采样率（Hz） | `44100` 或 `48000` |
| 16 | `stages` | 基础采样率与母带采样率之间的倍频程级数 | `1 ... 3` |
| 20 | `Lm` | 母带长度，每声道样本数 | `1 ... 2000000000 - 2*P` |
| 24 | `P` | 母带采样率下的填充，每侧样本数 | `1 ... 65536`，为 `2^stages` 的倍数 |
| 28 | `fc` | 检测到的 CD 截止频率（Hz） | 仅供参考 |
| 32 | `mi` | 分区模式索引（第 14 节） | `0 ... 5` |
| 36 | `eq` | 编码器使用的切分类型（0 = 不等分，≠ 0 = 等分） | 仅供参考 |
| 40 | `wm` | 编码器使用的占比度量（0 = 单元，1 = 能量，2 = 单元 + 能量） | 仅供参考 |
| 44 | `nb` | 基础采样率下填充后的长度，每声道样本数 | `(Lm + 2*P) >> stages` |
| 48 | `pb` | 基础采样率下的填充，每侧样本数 | `P >> stages` |

主头部之后依次为：

| 偏移量 | 大小（字节） | 内容 |
|---|---|---|
| 52 | `8*pb` | 边缘样本：`4*pb` 个小端序 `int16` 值（第 4.1 节） |
| `52 + 8*pb` | 4 | `ndf`，`int32`：抖动标志字节数 |
| `56 + 8*pb` | `ndf` | 抖动标志（第 4.2 节） |
| `56 + 8*pb + ndf` | 可变 | 流记录（第 5 节） |

### 4.1 边缘样本

基础采样率信号定义在每声道 `nb` 个样本的填充时间轴上。索引 `[pb, pb + ncd)` 保存 CD 样本。

两侧各 `pb` 个样本以交错立体声 `int16` 对的形式存放在边缘区域中，记为 `edge[2*j + c]`：

* `j` 取 `[0, pb)` 内的值时给出前部填充；
* `j` 取 `[pb, 2*pb)` 内的值时给出尾部填充。

填充在两端扩展信号，其内容由编码器选择。解码器使用所存储的值，不进行任何计算。

*说明性。*参考编码器在母带两端各镜像填充 `P = 4096` 个样本，以端点样本为轴反射（整样本对称，`tools/reference/pad_mirror.cpp`）。它由填充后的母带派生 16 位基础采样率信号（第 14 节），并将该信号最前和最后的 `pb` 个立体声样本存为边缘样本（`src/lae_enc.cpp`）。

### 4.2 抖动标志

令 `nbk = ndf / 2`。标志为字节 `dfl[c*nbk + b]`，其中声道 `c` 取 `{0, 1}`，块 `b` 取 `[0, nbk)`。声道 0 的所有标志排在最前。

块 `b` 覆盖基础采样率下的填充索引 `[4096*b, 4096*b + 4096)`。

* 零字节表示该块未添加抖动。
* 任何非零字节表示添加了 TPDF 抖动（第 11.2 节）。

编码器应写入 0 或 1。

### 4.3 解码器必须执行的验证

解码器在使用任何字段访问数据之前，必须按以下顺序检查下列条件。任一检查失败时，解码器必须拒绝解码扩展数据（第 12 节）。

| # | 条件 |
|---|---|
| V1 | `LAE ` 块主体 ≥ 8 字节，且 CRC-32 匹配（第 3.3 节） |
| V2 | `magic == 0x3145414C` 且 `version == 5` |
| V3 | `base` 取 `{44100, 48000}` |
| V4 | `1 <= stages <= 3` |
| V5 | `rate == base << stages` |
| V6 | `0 < P <= 65536`，且 `P mod 2^stages == 0` |
| V7 | `pb == P >> stages` |
| V8 | `0 < Lm <= 2000000000 - 2*P` |
| V9 | `nb == (Lm + 2*P) >> stages` |
| V10 | `0 <= mi < 6` |
| V11 | 偏移量 52 之后至少还剩 `8*pb` 字节 |
| V12 | `ndf == 2 * ceil(nb / 4096)`，且 `ndf` 字段之后还剩 `ndf` 字节 |
| V13 | `ncd == nb - 2*pb`（第 3.2 节） |

*说明性。*由 V6、V7 和 V9 可得 `nb - 2*pb = floor(Lm / 2^stages)`。因此，结合 V13 有 `ncd = floor(Lm / 2^stages)`。

派生量：

* `Lp = Lm + 2*P`，即填充后的母带长度；
* `N = 512`；
* `ncd`（第 3.2 节）；
* `nbk`（第 4.2 节）。

## 5. 流记录与流顺序

### 5.1 流记录

抖动标志之后，有效载荷按固定顺序包含流记录。每条**流记录**由以下部分组成：

* 一个 `int32` 值 `nbytes`，必须至少为 40；
* `nbytes` 个流数据字节，必须完全位于有效载荷之内。

流数据由 40 字节的流头部及其后 `nbytes - 40` 字节的范围编码有效载荷组成。

### 5.2 流顺序

| # | 内容 |
|---|---|
| 1 | 位深流，声道 L（0） |
| 2 | 位深流，声道 R（1） |
| 3 | `nseg`，`int32`：每声道的频率区段数。必须满足 `1 <= nseg <= 8` |
| 4 | 平面 M 的 `nseg` 条频率流记录，区段 `0 ... nseg-1` |
| 5 | 平面 S 的 `nseg` 条频率流记录，区段 `0 ... nseg-1` |

解码器必须按顺序解析每条记录，包括其不解码其内容的记录，因为每条记录都根据前一条记录的结束位置定位。

最后一条 S 记录之后，有效载荷可以包含扩展包记录和一条主体名称记录（第 5.6 节）。不支持扩展包的解码器忽略最后一条 S 记录末尾与 CRC 之间的任何字节，与定义扩展包之前的参考解码器相同。编码器不得在那里写入其他任何字节；没有另给的母带和主体名称时，参考编码器不写入此类字节，CRC 紧接最后一条 S 记录（`src/lae_enc.cpp`）。

### 5.3 流头部

流头部由十个小端序 `int32` 字段组成。

| 偏移量 | 名称 | 含义 | 有效值 |
|---|---|---|---|
| 0 | `K` | 平面中的帧数 | `> 0`（须检查） |
| 4 | `N` | 每帧系数数 | `== 512`（须检查） |
| 8 | `k0` | 第一个编码频点 | `>= 0`（须检查） |
| 12 | `k1` | 最后一个编码频点之后的位置 | `k0 < k1 <= 512`（须检查） |
| 16 | `rate` | 平面信号的采样率 | 解码器不使用 |
| 20 | `L` | 平面的信号长度 | 解码器不使用 |
| 24 | `cw` | `CW + 256 * rule` | 编码器必须在低字节中写入 `CW = 8`（不检查）。`rule = (cw >> 8) & 255`（第 8.2 节） |
| 28 | `lv` | 分区模式索引 | 解码器不使用 |
| 32 | `eq` | 切分类型：0 = 不等分切分，≠ 0 = 等分切分（第 7 节） | 任意 |
| 36 | `plen` | 范围编码有效载荷长度 | `== nbytes - 40`（须检查） |

关于流头部字段的说明：

* 参考解码器不检查 `cw` 的低字节。它始终使用宽度为 8 的单元。
* `K` 应等于 `frames(Ls)`（第 9.1 节）。对位深流，`Ls` 为 `nb`；对频率流，`Ls` 为 `Lp`。
* 若 `K` 小于 `frames(Ls)`，缺少的帧按零解码。若 `K` 较大，多出的帧永远不会被请求。
* 参考编码器写入 `rate` 和 `L` 的确切值将在后续修订版中说明。

对每条被解码的流，必须执行标记为"（须检查）"的检查。对被跳过的流（第 5.4 节），仅检查 `nbytes >= 40` 以及其是否位于有效载荷之内。

### 5.4 各路径的流选择

**位深流**在 24 位路径和 cd24 路径中解码，在 16 位路径中跳过。

**频率流**在 cd24 路径中跳过。在 24 位和 16 位路径中，当输出采样率为 `rate >> d`（`rate` 为主头部中的母带采样率，第 4 节）时，当且仅当频率流的 `k0` 小于 `kcut` 时对其解码，其中

`kcut = 512 >> d`。

参考解码器以 `lround(512 * (orate/2) / (rate/2))` 计算出相同的值。

在参考解码器中，`k0` 在记录被读取消耗之前从流头部读出。若记录位置剩余字节少于 16，则 `k0` 取 0。此类记录随后必然被第 5.1 节的记录检查拒绝。

选中的 M 流构成 M 信号，选中的 S 流构成 S 信号（第 9.5 节）。若**未选中任何 M 流**，则完全省略频率层，包括任何选中的 S 流（第 11.5 节）。

*说明性。*频点以母带采样率表示：512 个频点中的第 k 个频点的中心位于 `(k + 1/2) * (rate/2) / 512`。参考编码器每个倍频程存储一条流，使用编码器选项 `g` 时存储两条（`src/lae_dec.cpp` 中的注释）。解码器仅依赖 `k0 < kcut` 判断。

### 5.5 系数平面几何结构

一条流描述平面 `X[m][k]`，其中 `m` 取 `[0, K)`，`k` 取 `[0, 512)`。`[k0, k1)` 之外的频点为零。几何结构定义于 `src/partition_format.h`。

* 频点 `[k0, k1)` 分组为 `nc = ceil((k1 - k0) / 8)` 个宽度为 `CW = 8` 个频点的**单元**。
* 单元 `cc` 覆盖频点 `kb = k0 + 8*cc` 至 `min(k1, kb + 8) - 1`。因此最后一个单元可能窄于 8 个频点。
* 单元分组为 `ROOTF = 16` 个单元 × `ROOTT = 8` 帧的**根块**。高频边缘处和音轨末尾处的根块可能更小。

### 5.6 扩展包

本节不改变没有扩展包的文件的任何规则：这类文件及其解码完全按其他各节的规定。

**模型**。一个文件有一个 CD 层（第 3.2 节）和一个或多个**扩展包**。每个扩展包是一份完整的容器版本 5 扩展数据（主头部、边缘样本、抖动标志、位深流和频率流；第 4、5 节），整套由一个母带对着这个 CD 层生成。

* **包 0** 就是其他各节规定的第 3.3 节的有效载荷，即主体。
* **包 1 … 8** 可选，每个包放在一条包记录里。

各包互相独立。一个包中没有任何内容引用另一个包、由另一个包预测或与它共用参数；去掉一条包记录，其余每个包照常可解，内容不变。解码器用 CD 层加恰好一个包解码。

**包记录**。包 0 最后一条 S 流记录之后，有效载荷可以依次包含最多 8 条包记录。一条包记录是：

| 字段 | 大小（字节） | 内容 |
|---|---|---|
| 标记 | 4 | 字节 `L P A K` |
| `n` | 4 | `uint32`：本记录中其后的字节数 |
| `nl` | 1 | 名称的字节数，`0 … 255` |
| 名称 | `nl` | 发行方给这个包起的名称，UTF-8；在选择包的地方显示 |
| 包的有效载荷 | `n - 1 - nl` | 一份完整的容器版本 5 有效载荷（第 4、5 节），从它的 `magic`（`LAE1`）到它最后一条 S 流记录的末尾，不含 CRC |

要求：

* 第 3.3 节的那一个 CRC-32 覆盖整个有效载荷，包括各条包记录。包记录没有自己的校验值。
* 包的有效载荷本身必须满足第 4、5 节的每一条规则。它的 `base` 必须等于包 0 的 `base`。它的 `rate`、`stages`、`Lm`、`fc`、模式和各条流属于它自己，可以与包 0 不同。验证 V13 用文件的 CD 层对它检查：`ncd == nb - 2*pb`。
* 包的有效载荷中不得再包含包记录。
* 编码器不得在包记录之间写入任何内容，包记录不得多于 8 条。
* 包记录中没有其他内容：没有偏移、延迟、增益、时间戳、哈希、位置表或类型码。所有包记录使用同一个标记。

**主体名称记录**。在最后一条包记录（没有包记录时，在包 0 最后一条 S 流记录）与 CRC 之间，编码器可以写入一条主体名称记录，此外不得写入其他内容：

```
"LNAM" | 1 字节 nl | nl 字节：包 0（主体）的名称，UTF-8
```

它给包 0 一个用于显示的名称，作用与包记录中的名称字段对包 1 至 8 的作用相同。这条记录是可选的；没有它，包 0 就没有名称。解码器读完包列表之后读取它（接下来四个字节是 `LNAM`，并且其后在 CRC 之前至少还有 `1 + nl` 个字节）；不认识它的解码器在同一位置结束包列表并忽略它。与所有名称一样，它只用于显示：不选择任何内容，也不附带任何含义。包的名称只存放在有效载荷中，不得在标签或任何其他容器层结构中重复。

**解码**。支持扩展包的解码器从调用方取得一个**包号** `k`，默认为 0。

1. 验证 CRC（V1），并按第 4、5 节的结构（52 字节的头部、`8*pb` 字节的边缘样本、`ndf` 和抖动标志、两条位深流记录、`nseg`、`2*nseg` 条频率流记录）找到包 0 最后一条 S 流记录的末尾，每个长度都对照有效载荷检查。
2. 从那里开始读取包记录，条件是：至少还剩 9 个字节；接下来四个字节是 `LPAK`；`1 <= n`，且记录没有超出有效载荷；`1 + nl + 52 <= n`；包的有效载荷以 `magic` `LAE1` 和 `version` 5 开头；它的 `base` 等于包 0 的 `base`。第一条不满足其中任何一项的记录结束这个列表；这不是错误。最多读取 8 条。
3. `k = 0`：完全按其他各节的规定解码包 0。`k >= 1`：列表中不足 `k` 条时，拒绝这个请求；否则对包 `k` 的有效载荷原样执行第 4 至 11 节，CD 层用文件的 CD 层。

解码器不得把不同包的流混合使用，也不得自行选择包：不按设备能力、网络、负载、响度、内容或记录中的任何字段选择。包由用户选择（在菜单、设置或参数中）；名称只用于显示，从不驱动任何处理。解码器不得把这个选择写回文件。

不支持扩展包的解码器是符合规范的容器版本 5 解码器：它读取包 0，并忽略包 0 最后一条 S 流记录之后的字节（第 5.2 节），因此播放的是 CD 层加包 0。

其他选择（按倍频程的输出采样率，第 11.1 节；24 位、16 位和 cd24 路径）在选中的包之内适用。播放器应列出每个包的 `rate` 和名称。

**其他载体**。在 FLAC 形式（第 3.4 节）中，包记录是扩展数据的一部分，随扩展数据切分到各个 `LAE1` APPLICATION 块中；其余不变。在 CD-Extra 封装（[spec/cdx/SPEC.md](../cdx/SPEC.zh.md)）的扩展文件中，扩展块原样携带，包括包记录。

*说明性（参考实现）：*`src/lae_decoder.h`（`Decoder::pack`、`packs`、`bodyEnd`、`scanPacks`）、`src/lae_dec.cpp`（选项 `pack=<n>`）、`src/lae_enc.cpp`；liblae（`lae_pack_count`、`lae_pack_info`、`lae_select_pack`，`src/lae_api.h`）；Java：`java/src/com/lae/laey/LaeDecoder.java` 和 `LaeDec.java`。编码器选项见第 14 节。

## 6. 范围解码器

每条被解码的流都有各自的范围解码器（`src/part_stream.h` 中的 `struct Dec`）。它在该流编码有效载荷的起始处初始化，该有效载荷位于流数据偏移量 40 处，长度为 `plen`。

### 6.1 状态与字节输入

* `range` 为 `uint32`，初始化为 `0xFFFFFFFF`。
* `code` 为 `uint32`，初始化为 0。
* `next()` 返回编码有效载荷的下一个字节。全部 `plen` 个字节被消耗后，它返回 0。

### 6.2 初始化

```
repeat 5 times: code = (code << 8) | next()        // uint32: the first byte is shifted out
```

*说明性。*参考编码器写入一个前导 `0x00` 字节，即被移出的那个字节。

### 6.3 自适应二元判决

概率 `p` 为 `uint16`，以 1/2048 为单位保存 0 比特的概率。其初始值为 1024。

```
bit(p):
  bound = (range >> 11) * p                         // uint32
  if code < bound:  range = bound;  p = p + ((2048 - p) >> 5);  b = 0
  else:             code = code - bound;  range = range - bound;  p = p - (p >> 5);  b = 1
  while range < 2^24:  range = range << 8;  code = (code << 8) | next()
  return b
```

自适应移位量固定为 5。

### 6.4 旁路（直接）比特

```
direct(n):                                          // n >= 1, most significant bit first
  v = 0
  repeat n times:
    range = range >> 1
    b = (code >= range) ? 1 : 0
    if b: code = code - range
    v = (v << 1) | b
    while range < 2^24:  range = range << 8;  code = (code << 8) | next()
  return v
```

### 6.5 二叉树

`tree(pr, nbits)` 通过概率数组 `pr`，以最高有效位优先的顺序解码一个 `nbits` 位的值。它使用节点 `1 ... 2^nbits - 1`：

```
node = 1
repeat nbits times:  node = 2*node + bit(pr[node])
return node - 2^nbits
```

### 6.6 整数模型 `U`

`U` 模型包含两个数组 `tree[64]` 和 `mant[64]`，所有概率均初始化为 1024。`U(model)` 根据位长解码一个非负整数 `v < 2^31`：

```
len = tree(model.tree, 5)                           // 0 ... 31
if len <= 1: return len
top  = bit(model.mant[len])
nr   = len - 2
rest = (nr > 0) ? direct(nr) : 0
return 2^(len-1) + top*2^nr + rest                  // uint32
```

### 6.7 终止

参考编码器在流末尾刷出四个字节。解码器不得要求任何终止模式：这些字节的取值不做检查。

**流正好在最后一个字节处结束**。一条流的最后一个符号（第 7 节遍历的结束）解码完成时，`next()` 必须已把编码载荷的 `plen` 个字节各返回一次，并且不得在此之后再被调用。编码器必须这样写出每一条流；参考编码器写出的流总是满足这一点。有一条流提前或推后结束的文件不是符合规范的文件。

解码器可以把这样的文件当作损坏的文件拒绝（第 12 节）。播放库 `liblae` 自 v5-2026-11-07 起拒绝这样的文件：它对每个文件做一次检查，把每条流从头解码到尾；一条流提前或推后结束时，打开失败，播放器只播放 CD 层 / 核心层。超出 `plen` 的读取返回 0（第 6.1 节）；不拒绝这种流的解码器用这些零字节解码它。*说明性：*自 2026-11-15 起，命令行解码器 `lae_dec` 和 Java 解码器也拒绝这样的文件：`lae_dec` 在写出任何内容之前，把所选扩展包的每条流都解到最后，不符合时以退出码 3 结束，并打印 "LAE chunk damaged (entropy stream <i> does not end at its last byte): refusing to decode; the CD audio itself still plays"；Java 库在打开文件时检查主体，其他扩展包在第一次选中时检查。

### 6.8 模型持久性

一条流的所有自适应模型都在打开该流时创建一次。它们在整条流中持续存在，跨越根块和行的边界。

容器版本 5 未定义随机访问点。每条流都从其开头解码。

## 7. 分区语法

符号遍历由 `src/part_stream.h` 中的 `Walker` 实现。几何结构辅助函数位于 `src/partition_format.h`。

### 7.1 每条流的模型与状态

| 名称 | 数量 | 初始值 | 用途 |
|---|---|---|---|
| `TierP` | 4 个上下文 × 4 个节点 | 1024 | 层级，2 位树。上下文 = 前一叶节点的层级 |
| `ExpZero[t]` | 4（使用 t = 1 ... 3） | 1024 | 指数差为零 |
| `ExpSign[t]` | 4（使用 t = 1 ... 3） | 1024 | 指数差的符号 |
| `ExpU[t]` | 4 个 `U` 模型（使用 t = 1 ... 3） | 1024 | 指数差的绝对值 − 1 |
| `ZlP` | 4 个上下文 × 8 个节点 | 1024 | 零级索引，3 位树。上下文 = 层级 |
| `CoefU` | 3 × 13 个 `U` 模型 | 1024 | 系数幅值 |
| `prevTier` | | 0 | 前一叶节点的层级，包括 A 层级叶节点 |
| `prevE` | | 12 | 前一非 A 叶节点的指数 |

### 7.2 辅助函数

```
cuts(w, equal):                    // admissible cut positions of an extent w
  if w < 2:   return []
  if equal:   return [floor(w / 2)]
  return [1, 2, ..., w - 1]

posBits(n): smallest b >= 0 with 2^b >= n
```

### 7.3 流遍历

根块按行以时间递增顺序访问，每行 8 帧。在一行之内，根块以频率递增顺序访问。

```
decode_plane(hdr):
  nc = ceil((k1 - k0) / 8)
  for M0 = 0; M0 < K; M0 += 8:
    rt = min(8, K - M0)
    set X[M0 ... M0+rt-1][0 ... 511] = 0
    for C0 = 0; C0 < nc; C0 += 16:
      rf = min(16, nc - C0)
      node(0, rf, 0, rt)           // cell range [f0, f1), frame range [t0, t1), relative to the root
```

### 7.4 节点

每个节点或沿一个方向切分为两部分，或为叶节点。切分比特、方向比特和位置比特均为旁路比特。

```
node(f0, f1, t0, t1):
  cf = cuts(f1 - f0, eq != 0);  ct = cuts(t1 - t0, eq != 0)
  if cf != [] or ct != []:
    split = direct(1)
    if split = 1:
      if ct = []:      dir = 0                   // frequency cut
      else if cf = []: dir = 1                   // time cut
      else:            dir = direct(1)
      cc = (dir = 0) ? cf : ct
      nb = posBits(|cc|)
      pi = (nb > 0) ? direct(nb) : 0
      if pi >= |cc|: CORRUPT; pi = |cc| - 1
      p = cc[pi]
      if dir = 0: node(f0, f0+p, t0, t1); node(f0+p, f1, t0, t1)
      else:       node(f0, f1, t0, t0+p); node(f0, f1, t0+p, t1)
      return
  leaf(f0, f1, t0, t1)
```

### 7.5 叶节点

每个叶节点携带其自身的层级、指数和零级索引。这些值仅在叶节点处传送；内部节点不携带任何内容。

```
leaf(f0, f1, t0, t1):
  tier = tree(TierP[4*prevTier ...], 2)          // 0 = A, 1 = B, 2 = C, 3 = D
  prevTier = tier
  if tier = 0: return                            // all coefficients of the leaf stay 0

  if bit(ExpZero[tier]) = 1:  d = 0
  else:
    neg = bit(ExpSign[tier])
    a   = U(ExpU[tier])
    d   = neg ? -(a + 1) : (a + 1)
  if prevE + d < 0 or prevE + d > 34: CORRUPT; d = clamp(prevE + d, 0, 34) - prevE
  E = prevE + d;  prevE = E

  z = tree(ZlP[8*tier ...], 3)                   // zero-level index 0 ... 7
  s    = shift(E, tier, rule)                    // Section 8.2
  step = 2^s
  cm   = CoefU[(tier - 1)*13 + min(12, floor(E / 2))]

  for m = M0+t0 ... M0+t1-1:                     // frames
    for cell = C0+f0 ... C0+f1-1:                // cells, increasing frequency
      kb = k0 + 8*cell;  nbins = min(k1, kb + 8) - kb
      for j = 0 ... nbins-1:
        a = U(cm)
        if a > 0: neg = direct(1); q = neg ? -a : a
        else:     q = 0
        zs = (q = 0 and z > 0) ? direct(1) : 0
        X[m][kb + j] = dequant(q, z, zs, step)   // Section 8.3
```

上下文选择：

* 系数模型由叶节点的层级和指数选择。
* 层级上下文是解码顺序中前一叶节点的层级。
* 指数编码为相对于前一非 A 叶节点指数的差值。

### 7.6 损坏流处理

`CORRUPT` 将该流标记为损坏。参考解码器按所示方式钳制出错的值，并继续处理而不越界访问内存。解码结束时，它丢弃输出（第 12 节）。由于此时输出绝不交付，钳制后的值没有规范性影响。尽管如此，解码器必须对任何输入保持内存安全。

参考解码器只解码一条流中所请求路径和输出采样率所需的那些行，也只计算其所需的那些逆 MDCT 输出样本。因此，从未需要的部分中的 `CORRUPT` 情形可能未被检测出来。是否要求解码器在整条流中检测 `CORRUPT`，还是仅在其所需部分中检测，将在后续修订版中规定。

## 8. 系数解码与反量化

本节的表和函数定义于 `src/partition_format.h`。

### 8.1 层级

| 层级 | 代码 | `TB[tier]`（相对于叶节点指数的位数） |
|---|---|---|
| A | 0 | 0（不编码系数；全部为零） |
| B | 1 | 2 |
| C | 2 | 4 |
| D | 3 | 8 |

### 8.2 精度规则

步长指数 `s` 由叶节点指数 `E`、层级以及该流的 `rule = (cw >> 8) & 255` 计算得出。常量为 `TB = {0, 2, 4, 8}`、`TB16 = {0, 0, 4, 8}` 和 `STEPMAX = 8`。

| `rule` | `s = shift(E, tier, rule)` | 预期用途（说明性） |
|---|---|---|
| 1 | `max(0, min(E, 8) - TB[tier])` | 方案 1 的两个层；方案 2 的位深层。高电平块：B 18 / C 20 / D 24 位 |
| 2 | `max(0, min(E - TB[tier], 8 - TB16[tier]))` | 方案 2 的频率层。高电平块：B 16 / C 20 / D 24 位 |
| 3 | `max(0, min(E, 6) - TB[tier])` | keep20 模式的位深层。高电平块：B 20 / C 22 / D 24 位 |
| 0 或任何其他值 | `min(8, max(0, E - TB[tier]))` | 默认规则（容器版本 4 的公式） |

容器版本 5 的编码器写入规则 1、2 或 3。其他值保留。尽管如此，解码器必须对这些值应用表的最后一行，与参考解码器一致。

`rule` 值是每条流的字段。最后一行为该字段的每个取值都给出确定的解码方式；其公式即容器版本 4 所用的公式。容器版本 4 的文件本身由检查 V2（第 4.3 节）拒绝。保留的 `rule` 值是否需要改为拒绝，将在后续修订版中规定。

每条规则都满足 `0 <= s <= 8`。因此，任何量化步长都不粗于 CD 层的步长 1 LSB16。

*说明性。*编码器由叶节点的峰值推导 `E`。在参考编码器中，`E` 是叶节点内各单元的单元指数的最大值（`src/partition.h`）。单元指数的计算方法将在后续修订版中说明。

### 8.3 重建

`dequant(q, z, zs, step)` 计算 `v`，并将 `llround(v)` 作为 `int32` 存入平面：

```
if q > 0:       v = ((double)q + 0.20) * step
else if q < 0:  v = ((double)q - 0.20) * step
else if z > 0:  v = (zs = 1 ? -1.0 : 1.0) * ZC[z] * step      // evaluated left to right
else:           v = 0.0
if v > 1073741823.0 or v < -1073741823.0: CORRUPT; v = clamp(v, -1073741823.0, 1073741823.0)
X = llround(v)
```

* `0.20` 是最接近 0.20 的 binary64 值（`0x1.999999999999ap-3`）。重建偏移量 `RECOFF = 0.20` 是格式常量。
* 上述每次加法、减法和乘法都单独舍入至 binary64（第 2.2 节）。
* `llround` 在平局时远离零舍入。这对 0.5 等零级值有影响。

量化器死区**仅属于编码器**。它不被传送，也不影响解码。参考编码器使用 0.30 的死区（第 14 节）。

### 8.4 零级

叶节点的零级索引 `z` 从二进制有理数常量表中选择 `ZC[z]`，表中所有值均可用二进制精确表示：

| `z` | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| `ZC[z]` | 0 | 1/32 | 1/16 | 3/32 | 1/8 | 3/16 | 1/4 | 3/8 |

* 若 `z = 0`，量化为零的系数重建为 0。
* 若 `z > 0`，叶节点的每个零系数都携带一个旁路比特 `zs`。该比特为该系数的真实符号（1 = 负）。若 `zs = 1`，该系数重建为 `-ZC[z] * step`，否则重建为 `ZC[z] * step`。

参考编码器仅在启用可选的 `zs` 编码器选项时才写入 `z > 0`。该选项默认关闭。解码器必须支持 `z` 的所有取值。

## 9. 逆 MDCT

该变换由 `src/mdct_tb.h` 实现。

### 9.1 帧布局

该变换是采用正弦窗的 MDCT，每帧 `N = 512` 个系数，重叠 50 %。

对长度为 `Ls` 的信号：

* 填充序列为 `[N 个零 | Ls 个信号样本 | 零]`；
* 帧数为 `frames(Ls) = ceil(Ls / N) + 1`；
* 帧 `m` 覆盖填充位置 `[m*N, m*N + 2N)`；
* 信号样本 `i` 位于填充位置 `i + N`。

| 信号 | `Ls` | 采样率 |
|---|---|---|
| 位深，声道 c | `nb` | 基础采样率 |
| M、S | `Lp` | 母带采样率 |

### 9.2 常量表

令 `M = N/2 = 256`。各表由以下生成公式定义（`tools/gen_mdct_tables.cpp`）：

| 表 | 大小 | 公式 |
|---|---|---|
| `WIN[n]` | 1024 | `sin(pi * (n + 1/2) / (2*N))` |
| `PRE_C[n]`、`PRE_S[n]` | 256 | `-2*pi * (n + 1/8) / (2*N)` 的 `cos`、`sin` |
| `POST_C[k]`、`POST_S[k]` | 256 | `-2*pi * (k + 1/8) / (2*N)` 的 `cos`、`sin` |
| `FFT_C[k]`、`FFT_S[k]` | 128 | `-2*pi * k / M` 的 `cos`、`sin` |
| `BITREV[i]` | 256 | 将 `i` 的 8 个比特逆序排列（整数） |
| `SCALE` | 1 | `1 / sqrt(M) = 2^-4 = 0x1p-4`（精确） |

前置和后置旋转因子均为 `exp(-i * 2*pi * (n + 1/8) / (2*N))`。PRE 表和 POST 表由同一表达式生成，因此值完全相同。

*说明性。*这种旋转因子形式即 FFmpeg `libavcodec/mdct.c` 所用的形式（第 15.3 节）。

精确值为 `src/mdct_tables.h` 中的十六进制 double 字面量，由 `tools/gen_mdct_tables.cpp` 生成。用主机数学库重新计算的值可能在最后一位上不同。解码器必须使用 `src/mdct_tables.h` 中的值。`src/mdct_tables.h` 的内容将在后续修订版中作为本文的规范性附录重列。

### 9.3 通过 M 点复数 FFT 计算 DCT-IV

`DCT4` 是正交归一化的 DCT-IV，其逆变换即其自身：

$$
X[k] = \sqrt{\frac{2}{N}} \sum_{n=0}^{N-1} u[n] \cos\left(\frac{\pi}{N}\left(n + \frac{1}{2}\right)\left(k + \frac{1}{2}\right)\right)
$$

在以下过程中，公式中的输入 `u[n]` 称为 `c`，输出 `X[k]` 称为 `u`。必须严格按以下方式计算。每个乘积 `x*y` 先舍入，然后每个和或差再舍入，按所写顺序进行。

```
DCT4(c[0 ... N-1]) -> u[0 ... N-1]:
  for n = 0 ... M-1:
    a = c[2n];  b = c[N-1-2n]
    re[n] = a*PRE_C[n] - b*PRE_S[n]
    im[n] = a*PRE_S[n] + b*PRE_C[n]
  FFT(re, im)
  for k = 0 ... M-1:
    yr = (re[k]*POST_C[k] - im[k]*POST_S[k]) * SCALE
    yi = (re[k]*POST_S[k] + im[k]*POST_C[k]) * SCALE
    u[2k]     = yr
    u[N-1-2k] = -yi

FFT(re, im):                                     // radix-2, decimation in time, M = 256
  for i = 0 ... M-1:                             // bit-reversal permutation
    j = BITREV[i]
    if i < j: swap(re[i], re[j]); swap(im[i], im[j])
  for len = 2, 4, ..., M:
    step = M / len;  h = len / 2
    for i = 0; i < M; i += len:
      for k = 0 ... h-1:
        wr = FFT_C[k*step];  wi = FFT_S[k*step]
        xr = re[i+k+h];  xi = im[i+k+h]
        tr = xr*wr - xi*wi
        ti = xr*wi + xi*wr
        re[i+k+h] = re[i+k] - tr;  im[i+k+h] = im[i+k] - ti
        re[i+k]   = re[i+k] + tr;  im[i+k]   = im[i+k] + ti
```

### 9.4 逆变换、重叠相加与输出舍入

累加器 `y` 是覆盖各填充位置的 double 数组，初始化为 `+0.0`。各帧按 `m` 递增顺序处理。每个位置按帧顺序累加其贡献：

```
for m = 0 ... frames(Ls)-1:
  c[k] = sum over planes of (double) X_plane[m][k]   // exact (Section 9.5); 0 if no plane has frame m
  u = DCT4(c);  s = m*N
  for n = 0 ... N/2-1:                               // unfold [u2, -u2r, -u1r, -u1], window, add
    y[s + n]        += u[N/2 + n]       * WIN[n]
    y[s + N/2 + n]  += (-u[N-1-n])      * WIN[N/2 + n]
    y[s + N + n]    += (-u[N/2-1-n])    * WIN[N + n]
    y[s + 3N/2 + n] += (-u[n])          * WIN[3N/2 + n]
```

帧 `m` 加入后，位置 `[s, s + N)` 处的样本即为最终值。`[0, Ls)` 中的输出样本 `i` 为

```
v = y[i + N]
if v > 1073741823.0 or v < -1073741823.0: CORRUPT; v = clamp(v, -1073741823.0, 1073741823.0)
o[i] = (int32) llround(v)
```

该变换必须严格按第 9.3 节和第 9.4 节给出的结构计算。任何其他因式分解通常都会改变输出比特。

*说明性。*此要求针对的是算术运算。以其他方式得到逐比特相同结果的实现，例如跳过全零帧（第 9.5 节），满足此要求（第 1.3 节）。

*说明性。*编码器使用的正向变换如下：

1. 对 2N 个样本加窗。
2. 将其折叠为 `[-c_r - d, a - b_r]`，即 `u[n] = -z[3N/2-1-n] - z[3N/2+n]` 和 `u[N/2+n] = z[n] - z[N-1-n]`。
3. 应用 `DCT4` 和 `llround`。

### 9.5 平面求和

每个 IMDCT 信号在变换前对所选平面求和：

* 位深声道 c：其唯一的位深平面；
* M：所选的 M 区段；
* S：所选的 S 区段。

同一信号（M 或 S）的各区段在频率上可重叠（编码器可以对相同频点编码两次，例如用于在静音单元中抵消升采样后的 CD 层）；其各流的系数平面逐系数相加。每个平面值为 `int32`，绝对值至多为 1073741823，且每个信号至多有 8 个此类平面。因此其 double 和是精确的，求和顺序无关紧要。

若某平面所属的流少于 `m + 1` 帧，则该平面对帧 `m` 的贡献为零。全零帧的变换只贡献零，因此可跳过。

## 10. 半带插值与抽取

### 10.1 系数表

半带滤波器为对称的奇数长度 FIR 滤波器。仅存储奇数抽头 `h[1], h[3], ..., h[half]`，以 Q31 格式的 `int32` 值表示。中心抽头为 `2^30`。存储的抽头在此列为 `ht[t] = h[2t+1]`（`src/halfband.h`）。

```
Table 0 (base*1 <-> base*2), half = 79, 40 values:
 682938002, -225979149, 133607419, -93347908, 70491357, -55579122, 44978765, -36999032,
 30747123, -25707634, 21562088, -18102637, 15187220, -12714693, 10610315, -8816912,
 7289329, -5990851, 4890848, -3963205, 3185274, -2537151, 2001191, -1561677,
 1204578, -917388, 688994, -509581, 370536, -264370, 184638, -125854,
 83405, -53473, 32940, -19306, 10605, -5322, 2321, -771
Table 1 (base*2 <-> base*4), half = 15, 8 values:
 668035431, -184994700, 75935913, -29954182, 10005932, -2547898, 417025, -26609
Table 2 (base*4 <-> base*8), half = 11, 6 values:
 656183834, -156920197, 47052629, -10858972, 1477097, -63479
Table 3 (base*8 <-> base*16), half = 9, 5 values (defined in halfband.h; not used in container v5):
 644456397, -132671512, 28454516, -3484033, 115544
```

每张表中存储的抽头之和都恰好为 2^29。因此每个插值器和抽取器的直流增益恰好为 1。

对给定的一对采样率，插值器和抽取器使用同一张表。表 `k` 连接 `base*2^k` 与 `base*2^(k+1)`。

### 10.2 边界延拓

设输入长度为 `n`，`[0, n)` 之外的输入索引以端点样本为轴反射（整样本对称），然后钳制：

```
mirror(i, n):
  if i < 0:   i = -i
  if i >= n:  i = 2*(n - 1) - i
  return clamp(i, 0, n - 1)
```

### 10.3 2 倍插值

输入 `x` 的长度为 `n`。输出 `y` 的长度为 `2n`。表 `k` 有 `T` 个存储抽头。

```
y[2m]     = x[m]
y[2m + 1] = rq31(2 * A),   A = sum_{t=0}^{T-1} ht[t] * ( x[mirror(m - t, n)] + x[mirror(m + 1 + t, n)] )      // int64
```

### 10.4 2 倍抽取

输入 `x` 的长度为 `n`。输出 `y` 的长度为 `floor(n / 2)`。

```
y[i] = rq31( x[2i]*2^30 + sum_{t=0}^{T-1} ht[t] * ( x[mirror(2i - 1 - 2t, n)] + x[mirror(2i + 1 + 2t, n)] ) )      // int64
```

每个输出样本仅舍入一次。由于整数累加是精确的，求和顺序无关紧要。

第 8.3 节和第 9.4 节的数值界限本身并不能排除这些累加器发生 `int64` 溢出：

* 在 `|D_c[i]| <= 1073741823` 时，`B_c[i]`（第 11.2 节）的绝对值可能超过 2^34 FU。
* 表 0 各抽头绝对值之和超过 2^30。
* 因此，第 10.3 节的最坏情况累加值超过 2^63。

**64 位回绕（自 2026-11-15 起**）。半带插值（第 10.3 节）、与频率层的混合（第 11.5 节）、半带抽取（本节）和最终舍入（第 11.7 节）中，所有的和与积都按 64 位二进制补码、对 2^64 取模计算：放不下的结果回绕。舍入使用算术右移（`rq31`：加 2^30，再右移 31 位；最终舍入：加 8，再右移 4 位）。因此，对于其他检查都未发现的损坏流，每个解码器给出同一个回绕后的值。参考解码器不检测这种回绕。有效流不会回绕的保证上限尚未给出（附录 C 第 5 项）。

## 11. 重建流程

除另有说明外，本节中的所有信号均按声道 `c` 取 `{0 = L, 1 = R}` 分别处理，以 FU 为单位，并以 `int64` 计算。

### 11.1 路径与输出采样率

| 路径 | `d` | 输出采样率 | `Po`（输出偏移） | `Lo`（输出长度） |
|---|---|---|---|---|
| 24 位、16 位 | `0 <= d < stages` | `rate >> d` | `P >> d` | `Lm >> d` |
| cd24 | — | `base` | `pb` | `nb - 2*pb`（= `ncd`） |

对 24 位和 16 位路径，所请求的输出采样率若不具有 `rate >> d`（其中 `0 <= d < stages`）的形式，必须予以拒绝。

### 11.2 基础信号与抖动再生成

使用两个 xorshift32 生成器，每声道一个。其状态为 `uint32`：

* `g_0` 以 `0x12345678` 为种子；
* `g_1` 以 `0x12345678 + 0x9E3779B9 = 0xB06BD031` 为种子。

种子是格式常量，不被传送。

```
xs(g): g = g XOR (g << 13); g = g XOR (g >> 17); g = g XOR (g << 5); return g
```

对每个声道 `c`，按顺序对每个填充后的基础索引 `i = 0, 1, ..., nb - 1`：

```
g_c = xs(g_c);  u1 = (g_c >> 20) AND 0xFFF
g_c = xs(g_c);  u2 = (g_c >> 20) AND 0xFFF
delta_c[i] = (dfl[c*nbk + floor(i / 4096)] != 0) ? (u1 + u2 - 4096) : 0
```

生成器对**每个**索引前进两步，包括填充部分和标志为 0 的块。结果是位于 `[-4096, 4094]` FU 内的三角概率密度抖动，约为 ±1 LSB16。

CD 样本 `x_c[i]` 为：

* `i < pb` 时，取 `edge[2*i + c]`；
* `pb <= i < pb + ncd` 时，取 `cd[2*(i - pb) + c]`；
* 其他情况，取 `edge[2*pb + 2*(i - pb - ncd) + c]`。

其中 `cd` 为第 3.2 节的交错 `int16` 数据。基础信号为

```
B_c[i] = 4096 * x_c[i] - delta_c[i] + 16 * D_c[i]         for i in [0, nb)
```

* `D_c` 是声道 `c` 位深平面的逆 MDCT 输出（第 9 节，`Ls = nb`），以 LSB24 为单位。
* 在 16 位路径中，省略 `16 * D_c[i]` 项。抖动仍被减去。

### 11.3 插值至母带采样率

在 24 位和 16 位路径中，对 `B_c` 进行 `stages` 次插值（第 10.3 节）。第 `k = 0, 1, ..., stages-1` 级使用表 `k`。结果为 `U_c`，长度为 `nU = nb * 2^stages`。

### 11.4 频率层（M/S 逆变换）

`m[i]` 和 `s[i]` 是所选 M 平面之和与所选 S 平面之和的逆 MDCT 输出（`Ls = Lp`），以 LSB24 为单位。对 `[0, Lp)` 中的 `i`：

```
r      = m[i] - (s[i] >> 1)
F_0[i] = 16 * (r + s[i])                              // L
F_1[i] = 16 * r                                       // R
```

若未选中任何 S 平面，则 `s[i] = 0`。

### 11.5 混合

对 `[0, Lp)` 中的 `i`：

```
Z_c[i] = (i < nU ? U_c[i] : 0) + F_c[i]
```

若未选中任何 M 平面，则 `F_c[i] = 0`。频率层在此处于时域中相加。

### 11.6 抽取至输出采样率

在 24 位和 16 位路径中，对 `Z_c`（长度 `Lp`）进行 `d` 次抽取（第 10.4 节）。第 `k = 0, 1, ..., d-1` 次抽取使用表 `stages - 1 - k`。结果为 `Y_c`。

在 cd24 路径中，`Y_c = B_c`。

### 11.7 最终舍入与硬限幅器

对 `[0, Lo)` 中的 `i`：

```
v = (Y_c[Po + i] + 8) >> 4                             // FU -> LSB24, round half up
o_c[i] = clamp(v, -8388608, 8388607)                   // hard limiter
```

### 11.8 输出文件

输出由 44 字节的标准 WAV 文件头及其后的 `Lo` 个立体声帧组成。每帧依次包含 `o_0[i]` 和 `o_1[i]`。每个值写为 3 个小端序字节，即其二进制补码表示的低 24 位。令 `D = 6*Lo`：

| 偏移量 | 内容 |
|---|---|
| 0 | `RIFF` |
| 4 | `uint32` `36 + D` |
| 8 | `WAVE` |
| 12 | `fmt ` |
| 16 | `uint32` 16 |
| 20 | `uint16` 1（PCM） |
| 22 | `uint16` 2（声道数） |
| 24 | `uint32` 输出采样率 |
| 28 | `uint32` 6 × 输出采样率 |
| 32 | `uint16` 6（块对齐） |
| 34 | `uint16` 24（位数） |
| 36 | `data` |
| 40 | `uint32` `D` |
| 44 | 样本数据 |

`D` 始终为偶数，因此其后没有填充字节。

若 `37 + D > 0xFFFFFFFF`，输出无法以 WAV 表示，必须予以拒绝。这是参考写入器的大小检查（`wavio::fits32`），其中为一个填充字节留出了余量。

16 位路径同样生成 24 位文件。

## 12. 错误处理

CD 层是普通 PCM，绝不受扩展数据中错误的影响。解码器拒绝解码扩展数据时，播放器应退回为将 `data` 块作为 16 位音频播放。

| 条件 | 要求的行为 | 参考退出状态（说明性） |
|---|---|---|
| 自检失败（第 13 节；参考解码器在读取输入之前运行自检） | 不得解码 | 4 |
| 不是 RIFF/WAVE 文件；无 `data` 块；不是 16 位双声道整数 PCM | 不是 LAE Lossy 文件。不得解码 | 1 |
| 无 `LAE ` 块，或 `LAE ` 块主体为空 | 普通 CD 音频。没有需要解码的扩展数据 | 1 |
| `LAE ` 块主体 < 8 字节，或 CRC 不匹配 | 必须在解析任何字段（格式标识除外，第 3.3 节）之前拒绝 | 3 |
| 块主体的前 4 个字节为 `LAE2`（LAES 文件；在 CRC 检查之前读取，第 3.3 节） | 不得解码；报告这是 LAES 文件 | 1 |
| 魔数或版本不是 `LAE1` / 5 | 不得解码（未知版本） | 1 |
| V3–V11 中任一项失败 | 必须拒绝 | 3 |
| V12 失败（抖动标志） | 必须拒绝 | 3 |
| V13 失败（CD 长度不同：CD 层被编辑或未对齐） | 必须拒绝 | 3 |
| 输出采样率对该路径无效（第 11.1 节）；在 V13 之后、流记录之前检查 | 必须拒绝 | 1 |
| 包号 `k >= 1`，而文件中没有对应的包记录（第 5.6 节） | 必须拒绝该请求 | 1 |
| FLAC 形式：帧检查失败，或 MD5 缺失或不正确（第 3.4 节） | 不得解码扩展数据 | 3 |
| 流记录超出有效载荷；被解码流的流头部无效（第 5.3 节）；`nseg` 超出 `[1, 8]` | 必须拒绝 | 3 |
| 某条流没有正好在其最后一个字节处结束（第 6.7 节） | 可以拒绝；`liblae` 拒绝（自 v5-2026-11-07 起），`lae_dec` 和 Java 解码器也拒绝（自 2026-11-15 起） | 3 |
| 输出超过 WAV 大小上限（第 11.8 节） | 必须拒绝 | 1 |
| 解码期间触发 `CORRUPT`（第 7.4、7.5、8.3、9.4 节） | 必须报告该流已损坏，且不得交付输出。参考解码器删除其已写入的文件 | 3 |

解码器必须对任何输入保持内存安全。参考解码器在使用每个头部字段访问数据之前对其进行验证，并钳制超出范围的解码值。

参考解码器包含两个仅供编码器使用的钩子 `LEAKOUT` 和 `CLIPMAP`。它们仅在编码器构建解码器时（`LAE_ENCODER_HOOKS`）才被编译进来，不属于格式的一部分。

## 13. 自检哈希

自检用于检测不遵循第 2.2 节算术规则的构建。此类构建会产生因平台而异的输出。测试如下：

1. 令 `L = 6*N = 3072`，`K = frames(L) = 7`。
2. 以 `uint32` 算术对 `[0, 3584)` 中的 `i` 构造系数 `X[i]`：

   `X[i] = (int32)((((i * 2654435761) mod 2^32) >> 7) mod 2000001) - 1000000`

   帧 `m` 由 `X[512*m ... 512*m + 511]` 组成。
3. 以 `Ls = L` 应用第 9.4 节的逆 MDCT，得到 3072 个 `int32` 值 `o[i]`。省略 `CORRUPT` 检查，因为此处不可能触发。
4. 按小端序对 `o` 的各字节计算 64 位 FNV-1a 式哈希：

   ```
   h = 1469598103934665603                   // 0x14650FB0739D0383
   for each o[i]: for b = 0 ... 3: h = (h XOR (((uint32)o[i] >> 8*b) AND 0xFF)) * 1099511628211   (mod 2^64)
   ```

   该初始值是参考实现所用的值（`src/mdct_tb.h`）。它**不是**标准 FNV-1a 偏移基数（14695981039346656037 = `0xcbf29ce484222325`）。实现必须使用此处给出的值。
5. 结果必须等于 `0x729b547fbdbfe203`。

解码器应在启动时运行此测试。运行此测试且得到不同值的解码器不得解码。

通过自检并不能替代第 1.3 节的符合性测试。

*说明性。*参考实现的状态（[docs/BUILD.md](../../docs/BUILD.zh.md)）：

* 解码器和编码器可在 Windows（MSVC）和 Linux（GCC 13 的 `-O2` 和 `-O0`，Clang 18）上构建并运行。解码器还以 GCC 构建为 32 位 SSE2 版本。
* 在 Linux x86 上，每个解码器输出（按构建、向量和路径）的 SHA-256 在 256 次比较中有 256 次与清单一致，且编码器逐字节重现全部 16 个一致性测试向量文件。
* 在 Linux ARM64（aarch64；GCC 13 的 `-O2` 和 `-O0`，Clang 18 的 `-O2`）上，每个解码器输出的 SHA-256 在 192 次比较中有 192 次与清单一致，且编码器（GCC 13，`-O2`）逐字节重现全部 16 个一致性测试向量文件。其他 ARM 平台尚未测试。
* 不支持 x87 构建；参考解码器的自检会拒绝此类构建。

## 14. 编码器端要素（说明性）

以下要素属于编码器。列出它们是为了使实现者能够理解比特流的含义。它们不影响解码。

除引用其他来源之处外，本节的陈述均基于参考编码器源文件 `src/lae_enc.cpp`、`src/partition.h`、`tools/reference/pad_mirror.cpp`、`src/base_layer.cpp` 和 `tools/reference/routes.cpp`。

* **各层目标**。解码器在时域中将三部分（CD 路径、位深层、频率层）相加（第 11 节）。
  * 编码器由母带派生 CD 层，并在第 4.2 节中标记的块内添加 TPDF 抖动。
  * **CD 层派生**（`src/base_layer.cpp`）。将填充后的母带（第 4.1 节）转换为 FU，并使用第 10.4 节的整数半带抽取器抽取 `stages` 次至基础采样率，采样率最高的一级最先进行；中间值仅限制在 `int32` 范围内。设 `x` 为抽取后以 FU 表示的值，`delta` 为第 11.2 节的抖动（标志为 0 的块中为 0），则每个 CD 样本为 `clamp((x + delta + 2048) >> 12, -32768, 32767)`。
  * **抖动判定**（`src/base_layer.cpp`）。对每个声道的每个 4096 个基础采样率样本的块，编码器对抽取后的信号拟合一个 16 阶线性预测器，并计算预测残差以 LSB24 表示的 RMS。若该 RMS 低于 128 LSB24（0.5 LSB16）且该块不是数字静音，则对该块加抖动。全零块从不加抖动，因此 CD 层保留真正的零值。
  * **位深目标**（`tools/reference/routes.cpp`）。令 `v = 256 * CD - delta/16` 为以 LSB24 表示的 CD 路径，`B24 = (x + 8) >> 4` 为以 LSB24 表示的抽取后母带，后者不限制在满量程内。位深目标为 `T = llround(lowpass(B24 - v))`，限制在 `[-8388608, 8388607]` 内。该低通滤波器是基础采样率下的零相位窗函数 sinc FIR 滤波器（511 抽头，Kaiser 窗 β = 9），截止频率为 `fc`。当 `fc >= base/2 - 1` Hz 时省略该滤波器。
  * 位深层覆盖基础采样率频带。
  * **频率目标**（`tools/reference/routes.cpp`）。母带采样率下以 LSB24 表示的频率目标为 `F = master - up(v + T)`，限制在 `[-8388608, 8388607]` 内。`up` 使用第 10.1 节的半带系数表进行 `stages` 次 2 倍插值；编码器以双精度计算。
  * 频率层从检测到的 CD 截止频率以下开始：编码器向层编码器传入 `fc - 1000` Hz 作为起始频率（`src/lae_enc.cpp`）。`fc` 记录该截止频率。
  * **截止频率检测**（`tools/reference/routes.cpp`）。编码器根据母带与插值后 CD 路径的平均互谱，从基础采样率的奈奎斯特频率向下扫描至 15 kHz。它将 `fc` 设在 CD 路径传递至少为 −0.1 dB 的最高频率略上方。母带几乎没有能量的频点被跳过。若未找到此类频率，则 `fc = 15000` Hz。
* **独立 CD 输入**。编码器选项 `cd=<file>` 接受单独提供的基础采样率 16 位双声道 CD。
  * 所提供的 CD 逐比特成为 CD 层。编码器将母带置于 CD 的时间轴上，按整数个母带样本以及一个母带样本的若干分之一移动母带；CD 从不移动（[README](../../README.zh.md) 第 4.3 节）。文件中不存储任何对齐信息，解码不变。
  * 此时所有抖动标志均为 0。
  * CD 截止频率以相干性测试（阈值 0.98）代替传递测试来确定；相干性测试不依赖于 CD 的增益。
  * 扩展数据编码母带减去 CD 路径。
  * 边缘样本（第 4.1 节）仍取自编码器由母带派生的 CD 层。
* **扩展包**（第 5.6 节）。参考编码器用 `master2=<file>` … `master9=<file>` 接受另给的母带，每个母带带 `master<n>align=<offset>`（它在 CD 层时间轴上的位置，写法同 `cdalign=`），并可带 `master<n>name=`、`master<n>accept` 和 `master<n>edge=pad|cut`。
  * CD 层由第一个母带派生；带 `cd=` 时就是给定的 CD（第一个母带照旧先对齐到它）。每个另给的母带都用独立 CD 输入（`cd=`）的对齐方法，各自对齐到这个 CD 层。某次对齐需要在 CD 层之前或之后补数字静音时，取各母带所需的最大值，给 CD 层补一次，每个母带补同样的静音。CD 层本身的样本从不改动。
  * 然后每个对齐后的母带各自单独对着最终的 CD 层编码。它的包有效载荷与 `lae_enc <that master> cd=<the CD layer> cdalign=0` 写出的 `LAE ` 有效载荷逐字节相同。
  * 包 0 和 CD 层，就是对同一个 CD 层不带另给母带时编码器写出的内容。
  * `master1name=<name>`（最多 255 字节）给主体起名：编码器在最后一条包记录之后写出第 5.6 节的主体名称记录。不带这个选项时什么都不写，输出不变。没有另给的母带时也可以使用。
  * `master<n>part2=` … `master<n>part5=`（n = 1 … 9；自 2026-11-18 起，`src/name_parts.h`）是名称可选的位置 2 到 5，自由文字，没有固定含义。编码器把填了的接在名称后面，写成 `<名称> - <位置2>, <位置3>, <位置4>, <位置5>`（没填的跳过；没有名称时只写后面几项，用 `, ` 隔开），作为该包的名称（n = 1 是主体）。名称和这些位置合起来最多 255 字节。文件里只有合起来的这一段文字：第 5.6 节不变，不标出任何位置，解码器照原样显示、不拆开。输出与把同样文字直接写进 `master<n>name=` 逐字节相同。
  * 当前版本中，另给的母带不能与 `noise=`、`resume` 或 `cdcheck` 同时使用。
* **形式**。输出文件名以 `.flac` 结尾或带选项 `--form=flac` 时，参考编码器写出 FLAC 形式（第 3.4 节），其他情况（包括 `.lae`）写出 WAV 形式。`--form=wav` 或 `--form=flac` 必须与 `.wav` 或 `.flac` 的文件名一致；只有 `.lae` 可以自由选择。WAV 形式与增加 FLAC 形式之前的编码器输出逐字节相同。`lae_enc tag` 不重新编码即可写入新标签，形式保持不变。
* **分区搜索**（`src/partition.h`）。
  * 搜索按根块并行进行。线程数不影响编码后的流（[docs/BUILD.md](../../docs/BUILD.zh.md)）。
  * 搜索以所选模式的 D 和 C 占比目标为目标（`src/partition_format.h`）。占比目标仅存在于编码器中。
  * 解码器不需要模式表。除 `mi` 的范围检查（V10）之外，`mi`、`lv`、`wm` 以及主头部的 `eq` 仅供参考。
  * 对给定的惩罚值 λD 和 λC，一个覆盖每个根块所有子矩形的动态规划选择切分树和每个叶节点的层级。它使估计比特数加上每个被降级的 D 单位（处于低于 D 层级的叶节点中的 D 单元）的 λD 以及每个被降级的 C 单位（处于低于 C 层级的叶节点中的 C 单元）的 λC 之和最小。一个单位为一个单元（按单元计占比），或该单元相对于该平面所有 D（或 C）单元平均能量的能量（按能量计占比），或二者的平均（单元 + 能量）。仅当叶节点的所有单元均为 A 时，该叶节点才为 A 层级。
  * 惩罚值通过在 10^−3 至 10^4 之间的对数尺度上进行 7 步二分搜索求得：先在 λD = 0 时搜索 λC，直至满足 C 占比目标，然后搜索 λD。对于 C 占比为 100 % 的模式（keep、keep20），λC 固定为 10^9。采用"单元 + 能量"占比度量时，两个占比中较小者须满足目标。
* **模式**。每种方案有六种模式（`src/partition_format.h`）：

  | 索引 | 名称 | D 占比 | C 占比 | 备注 |
  |---|---|---|---|---|
  | 0 | max | 10 % | 30 % | |
  | 1 | 1 | 30 % | 50 % | |
  | 2 | 3 | 50 % | 70 % | |
  | 3 | 5 | 70 % | 90 % | |
  | 4 | keep | 90 % | 100 % | |
  | 5 | keep20 | 90 % | 100 % | 位深层使用规则 3（需主动启用，文件较大） |

  方案 1 的两个层均使用规则 1。方案 2 的频率层使用规则 2，位深层使用规则 1。
* **量化器**。编码器使用带死区的标量量化。步长为 `2^s` 的叶节点中的系数 `x` 量化为 `q = sign(x) * floor(|x| / step + 0.5 - 0.30)`。死区 0.30 仅由编码器使用，不被传送。解码器以 `q` 的符号重建 `(|q| + 0.20) * step`（第 8.3 节）；重建偏移量 0.20 是格式常量。
* **泄漏补偿**。编码器获取经第 10 节抽取器降至基础采样率的解码后频率层（`src/lae_dec.cpp` 的 `LEAKOUT` 钩子），并用其补偿位深目标。
  * 第一次完整编码之后，编码器解码所写入的文件，并在基础采样率下单独获得频率层。
  * 它用零相位窗函数 sinc 低通滤波器（2047 抽头，Kaiser 窗 β = 9）对该泄漏进行滤波，截止频率为 `fc - 1150` Hz，即比频率层起始频率低 150 Hz，并在形成位深目标之前从 `B24 - v` 中减去所得结果。保留第一遍的截止频率 `fc`。
  * 随后仅重新编码位深层，并再次写入文件。保留第一遍的频率层。
  * 在容器版本 5 中，泄漏补偿始终开启。
* **削波**。唯一的输出保护是解码器的最终硬限幅器（第 11.7 节）。参考编码器使用 `CLIPMAP` 钩子运行一次诊断解码，并报告受限幅器影响的样本数。该报告不存储在文件中。
* **信号分析**。编码器的分析使用 FFT 模块 `src/fft.h`。第 9.3 节的逆 MDCT 另行实现于 `src/mdct_tb.h`。
